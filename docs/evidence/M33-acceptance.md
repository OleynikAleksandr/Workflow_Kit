## Отказы и недоступные вопросы

- **`question-stale`, проверено.** Прямой POST ответа на закрытый вопрос 2 Claude и на
  закрытый блокирующий вопрос 2 Codex — `409 {"code":"question-stale","message":"На вопрос уже
  ответили"}`; наружу ничего не ушло, итог в лентах не изменился.
- **Маршрут ответа для асинхронного вопроса, проверено.** POST на закрытый и на ожидающий
  асинхронный вопрос — `409 question-unavailable` «Ответ на этот вопрос отправляется
  сообщением».
- **Вопрос без канала ответа, проверено.** Процесс хука вопроса «Size» убит. Через 2 мин 1 с
  (срок восстановления 2 мин) вопрос стал `answerable: false` с причиной «Ответьте в
  приложении Claude: хук вопроса завершился»; карточка без кнопки «Отправить», выбор
  недоступен, есть «Открыть чат провайдера». Родной диалог в терминале остался рабочим. Esc
  отменил вопрос, карточка — «Вопрос отменён», в транскрипте «[Request interrupted by user
  for tool use]».
- **Заглушка C0, не проверено вживую.** Демон повторяет ожидающий запрос новому подписчику
  (L1): блокирующий вопрос появился в ленте сразу с содержимым, заглушка не возникла. Покрыто
  тестами T006.
- **Секретный вопрос Codex, не проверено вживую.** Способ получить от модели вопрос с
  `isSecret` репликой не известен. Покрыто тестами слушателя на подставном демоне (T006).

## Находки

- **Инструменты вопроса Codex зависят от модели и режима.** Тред, начатый в режиме плана на
  `gpt-5.6-luna`: блокирующий `request_user_input` есть. Обычный режим на `gpt-5.6-luna`:
  модель ответила «Не могу вызвать `request_user_input_async`: этот инструмент недоступен».
  Обычный режим на `gpt-6.1-sol`: `request_user_input_async` есть, вызов возвращает
  `{"accepted":true}`, ход завершается, текст `agentMessage` повторяет вопрос
  («Which color do you prefer?\n- Blue\n- Red»).
- **ChatGPT не показывает асинхронный вопрос** (пользователь, скриншот): ни текста
  `agentMessage`, ни карточки, только «Работал на протяжении 7s». Ответить из ChatGPT можно
  только обычным сообщением, зная вопрос из панели. Блокирующий вопрос ChatGPT показывает и
  принимает ответ.
- **Хуки Codex тестового проекта не были одобрены.** Стенд создал проект в обход панели, и
  одобрения `hooks.state."…".trusted_hash` для его `.codex/hooks.json` не было. Во время
  проверки ChatGPT показал окно «Проверка хуков» с четырьмя новыми хуками Kit, пользователь их
  одобрил. Вероятная причина того, что демон не вызывал хук SessionStart для тредов стенда
  (T008 и T014), — неодобренные хуки, а не начало треда через RPC; повторно не проверялось.
  В проектах панели хуки Kit одобряет `approveHooks` по нажатию пользователя
  (`provider-codex/hooks.md`).
- **Наблюдения без дефекта.** У асинхронного вопроса текст вопроса виден в ленте дважды:
  сообщением агента и карточкой после него (так задано в 2.7). Исход `unknown` своего ответа
  панель показывает как «Ответ отправлен. Какой ответ принят, провайдер не сообщил», а после
  перезагрузки страницы — «Ответ дан в приложении»: попытка живёт в странице, ответ панели
  агенту не приписывается (принцип 3).

## Отклонения стенда

- Строка журнала сессий Codex `<project>/.workflow-kit/local/sessions.jsonl` для тредов
  стенда дописана стендом (`client: 'codex'`, `service: null`): хук SessionStart не сработал
  (см. «Находки»), а без строки маршрут ответа отвечает `404 unknown-session`.
- Треды Codex начаты стендом через RPC, а не в приложении ChatGPT; приложение открывало их
  как обычные чаты демона.

## Расход живых ходов

- Haiku: 2 хода из 3 (три вопроса в одном ходе; вопрос «Size»).
- Codex: 2 хода `gpt-5.6-luna` (тред плана; обычный режим без асинхронного инструмента) и
  3 хода `gpt-6.1-sol` (вопрос 1, сообщение «Blue», сообщение «Friday»). Ходы Sol заменили
  остаток ходов Luna с согласия пользователя («Да, до 3 ходов Sol»).
