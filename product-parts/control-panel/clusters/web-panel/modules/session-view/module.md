# Модуль: session-view

Часть `control-panel`, кластер `web-panel`. Алиас импорта: `#session-view`.

## Назначение

Тело экрана сессии и «Ревью плана» в боковой панели (спецификация вехи 2,
разделы 6, 8.3, 9.3, 10; макет, шаги 5–10): строка активности агента,
карточка выбора пути, карточка плана с кнопками, подтверждение выпуска.

## Публичный интерфейс для бэкенда (`src/index.ts`)

- `SESSION_VIEW_PREFIX` — `/session-view/`.
- `SESSION_VIEW_ASSETS_DIR` — абсолютный путь к `src/`.
- `sessionViewMount() → { prefix, dir }` — монтирование для `http-server`
  (подключает `cli`, `createApp`).

## Подключение к панели

`session-view.js` — расширение панели (`PANEL_EXTENSIONS` в
`panel-shell`): `install(shell)` заполняет слоты `sessionBody` и
`sessionReview` (`registerSlot`). Стили — `session-view.css`, подключены в
`index.html` панели.

## Файлы

| Файл | Содержание |
| --- | --- |
| `session-model.js` | чистые модели: `activityView(state, projectId, key)` (раздел `channel`: `working` — «работает над ответом» с таймером хода, `holding` — «ждёт вашего решения в панели» с причиной, `waiting` — «ждёт вашего сообщения», нет записи — «ещё не присылал хуков»; «Оркестратор» у владельца плана в режиме `orchestrated`; причина последнего решения автопилота), `choiceView` (раздел `workflow.choice`: сессии, держащей ход ради выбора, или любой сессии проекта; оркестрация — у обоих приложений), `planView` (раздел `workflow.plan`: только у сессии-владельца или у всех, пока владельца нет; полоса, «в main N из M», задачи с состоянием, меткой режима и исполнителем, кнопки фазы, `delivery` — автопилот ждёт «Подтвердить выпуск»), `reviewView` (раздел `review`: виден до выбора пути), `timer`, `REASON_LABELS`, `ACTION_BUTTONS` |
| `session-view.js` | DOM: строка активности (таймер тикает раз в секунду; очередь спящего агента — «уйдут агенту со следующим сообщением в чате»), карточка выбора («Выбрать» → `POST …/workflow/choose { session, generation, option }`), карточка плана («Начать выполнение плана», «Пауза», «Продолжить», «Принять план» и «Закрыть план» с подтверждением, «Нужны исправления» — поле текста → `…/workflow/fixes { text, session }`), «Подтвердить выпуск» (слова пользователя → `…/workflow/confirm-delivery`), переключатель «Ревью плана» (`POST …/sessions/:key/review { on }`); «Сообщение агенту» — поле и «Отправить агенту» → `POST …/sessions/:key/message { text }` (под строкой активности; подсказка: ChatGPT получит его со следующим сообщением в чате, ожидающий агент Claude — сразу); введённый текст хранится в полях по сессии и переживает опрос |
| `session-view.css` | вид карточек по макету: `.work`, `.choice`, `.opt`, `.plan-card`, `.tasks`, `.cols` (две колонки шире 1100 px), переключатель `.sw` |

## Инварианты

- Чистая логика в `session-model.js` без DOM; покрыта `node --test`.
- Текст в DOM — только через `textContent`; ширина полосы — через CSSOM.
- Решения пользователя уходят только кнопками; ошибки показываются над
  экраном с подсказкой Kit.
