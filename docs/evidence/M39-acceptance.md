## Сквозные проверки T010

`autopilot/test/lifecycle-real.test.ts` — после ручного запуска, последовательно:
- одно нажатие «Начать выполнение плана» записывает разрешение до первого сообщения; повторное
  нажатие нового запуска не создаёт;
- после первой задачи служба перезапускается (новые объекты на тех же файлах): `recoverAll`,
  вызванный дважды, ставит одно продолжение («goes on after a restart … recover»);
- вопрос агента посреди задачи держит запуск в `waiting/question`, ответ возвращает его без
  траты попытки;
- поставка: продолжение называет `task:start D1 --autopilot-run <runId>` и готовый JSON
  ожидания с `ciPolicyDigest`; агент отправляет SHA на `ci/auto` и сообщает ожидание; служба
  читает CI сама, зелёный CI — сообщение «CI is green», агент коммитит поставку;
- служба сама принимает (коммит `chore: accept scope auto (autopilot run <id>)`), закрывает,
  отправляет финальный SHA на `ci/auto`, читает его CI и публикует ровно его: `main` bare
  равен финальному SHA, квитанции `authorize, ci, accept, close, ci-stage, ci, publish`;
- агент получил ровно четыре сообщения, все от службы: старт, восстановление, поставка,
  зелёный CI; каждая задача и каждый служебный коммит — по одному; в истории нет «пользователь
  проверил»; дерево чистое; поздний `Stop` законченного запуска ничего не делает.

`lifecycle-real.test.ts` — остановка во время ожидания CI: разрешение отозвано окончательно
(`user-stop`, `resumable=false`); зелёный CI, ответ на вопрос и шаг завершения после
остановки ничего не продолжают; поставка осталась `IN_PROGRESS` для ручной работы; запуск не
возобновляется.

`autopilot/test/orchestrated-real.test.ts` — полный автопилот:
- план рекомендует оркестрацию, провайдер умеет исполнителей — выбран `orchestrated`, старт —
  сообщение оркестратора, Kit считает обе независимые задачи готовыми; оркестратор выдаёт
  назначения, ход с работающими исполнителями — ожидание `waiting-for-executors`, не ход без
  прогресса;
- провайдер без исполнителей — `sequential` с причиной в квитанции выбора.
Исполнители, их рабочие копии и интеграция здесь не запускались: это тесты самого Kit.

## Найденное

- Дефект T007, подтверждён на бандле: «Продолжить» идущего запуска (`runs.resume` возвращает
  `null` не для паузы и не для блокировки) ставит второе сообщение рядом с продолжением после
  перезапуска; повторный старт отвечает без `runId`. Модульный тест T007 этого не видел:
  подставной `beforeResume` всегда возвращал запуск. Исправлено отдельной задачей F001
  (`plan:extend`, `fixes: T007`, коммит `b123993`): «Продолжить» идущего запуска возвращает
  его `runId` и не ставит сообщение, пока владелец работает или у него в очереди уже есть
  продолжение; повторный старт называет тот же запуск. `lifecycle-real.test.ts` теперь
  проверяет: перезапуск службы и «Продолжить» дают одно сообщение.
- Наблюдение, не исправлялось: если агент закончит первый ход после старта, ничего не начав,
  срабатывает защита старта M11 («Агент закончил ход, не начав первую задачу», кнопка
  «Начать заново»). Фаза запуска при этом остаётся «Выполняет задачи». Реальный агент сразу
  начинает задачу или назначения, поэтому в сквозных проверках этого нет. Нужна ли в
  автопилоте своя блокировка вместо кнопки — решение пользователя.
