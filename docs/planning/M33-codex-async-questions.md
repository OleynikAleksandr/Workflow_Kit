## 2.7. Codex: асинхронный вопрос

В обычном режиме агент Codex спрашивает инструментом `request_user_input_async`. Ход не ждёт:
вопрос приходит в элементе истории `agentMessage` (поле `questions: [{ title, options }]`,
`options` — строки или `null`), а ответ — новое сообщение пользователя. Kit показывает такой
вопрос карточкой; «Отправить» отдаёт выбранный ответ агенту обычным сообщением через прежнюю
доставку панели, как текст из поля ввода.

### Контракт (`provider-registry`)

- `ChatQuestion.reply?: 'message'` — ответ на вопрос уходит агенту обычным сообщением; нет поля —
  ответ маршрутом ответа (2.1). У вопроса с `reply: 'message'` нет `delivery` и `answers`.
- Пределы и нормализация — общие (2.1): вопрос сверх пределов показывается обрезанным с
  `answerable: false` и причиной `QUESTION_TOO_LARGE_REASON`.

### Показ (`provider-codex`)

- Источник — тот же опрос ленты (`thread/turns/list`, `thread/items/list`), без слушателя.
  Элемент `agentMessage` с непустым `questions` даёт вопрос:
  - `id` — `async:<id элемента>`; `at` — время элемента;
  - `afterMessageId` — сообщение этого элемента; если его текст пуст (сообщения в ленте нет) —
    предыдущее сообщение ленты или `null`;
  - части по порядку: `id` — `q<номер>`, `header` — пустая строка, `question` — `title`,
    `options` — подписи из `options` с пустым описанием, `multiSelect: false`,
    `allowOther: true` (ответ — свободное сообщение);
  - `reply: 'message'`, `answerable: true`.
- Состояние: `pending`, пока в ленте после этого элемента нет сообщения пользователя; иначе
  `answered` без `answers` (ответ — то сообщение, оно видно в ленте). Чьё это сообщение (панель,
  приложение ChatGPT, автопилот), Kit не различает. `cancelled` не бывает.
- Вопросы истории переживают перезапуск службы. Страница отдаёт их вместе с блокирующими
  вопросами слушателя, от старых к новым, не больше `QUESTIONS_PAGE_MAX`.
- `answerQuestion` для id `async:` — отказ `question-unavailable` «Ответ на этот вопрос
  отправляется сообщением»: ничего не передаётся.
- Текст вопросов и ответов в журналы не пишется.

### Карточка (`session-chat`)

- Ожидающий асинхронный вопрос стоит в ленте после своего сообщения (`afterMessageId`), а не в
  конце: агент может продолжать ход. Строка состояния диалога из-за него не меняется.
- Пустой `header` — без метки заголовка.
- «Отправить» (и Ctrl/⌘+Enter) собирает текст ответа: одна часть — выбранная подпись или свой
  текст; несколько частей — строки «<вопрос> — <ответ>». Текст уходит маршрутом сообщения
  панели (`POST /api/projects/:id/sessions/:key/message`, тело `{ text }`): очередь, будящая
  доставка и прямой ход — как у поля ввода.
- После успешной отправки — «Ответ отправлен сообщением», кнопки нет; карточка закрывается,
  когда лента покажет сообщение пользователя. Ошибка отправки — текст под карточкой, выбор
  сохранён, повтор той же кнопкой.
- Закрытый вопрос — компактно: вопрос и «Ответ дан сообщением».
- Защиты от второго ответа нет: если ответили и в приложении, и в панели, агент получит два
  сообщения, как при двух репликах.

### Принципы

Ответ уходит только по нажатию «Отправить» (принцип 1). Автопилот асинхронные вопросы не
отвечает; его сообщение после вопроса закрывает карточку, как любое сообщение пользователя.

## Поведение на ОС

| Что | macOS | Linux | Windows |
| --- | --- | --- | --- |
| Вопрос из истории | опрос ленты через сокет демона | так же | через `codex app-server proxy` |
| Карточка и отправка | общий код панели и маршрут сообщения | так же | так же; x64 и ARM64 |

Поведение одинаково на трёх ОС; отличается только транспорт к демону. Новых вызовов программ ОС
нет.
