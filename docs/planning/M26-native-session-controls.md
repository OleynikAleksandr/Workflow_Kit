# M26: нативное управление параметрами ChatGPT

## Цель и согласование

В 0.11.0 параметры открывают длинный список всех настроек. Пользователь сравнил его
с родным приложением и 13.11.2026 попросил: «Ты не мог бы повторить полностью то,
как это сделано в родном десктопе?» В панели выбрано: спецификация и план без ревью.
Уточнение пользователя: круговую стрелку и «Подробнее» исключить; при нажатии
названия модели отдельный список появляется под полем ввода.

Результат: компактная карточка усилия с ползунком, выбор модели из карточки,
переключатель скорости и отдельная кнопка доступа с нативным меню. Изменяются реальные
настройки той же сессии. Эталон — два нативных скриншота пользователя; первый скриншот
фиксирует проблему Kit. Источники, размеры и неизвестные состояния —
[визуальный контракт](../design/M26-native-controls-reference.md).

## 1. Принципы

- Копировать и геометрию, и сценарий действий: четыре назначения не собираются
  в общий длинный список. Отдельной панели настроек или нового экрана проекта нет.
- Подписи, каталоги и доступность сообщает адаптер по общему контракту. Общая панель
  не проверяет имя провайдера и не сопоставляет нативные пресеты с RPC самостоятельно.
- Эффективные значения приходят после чтения провайдера. Предварительный вид ползунка
  во время жеста не считается сохранённой настройкой; ошибка восстанавливает фактическую.
- Чтение, очередь, принадлежность сессии, кэши, работа без каталогов, подтверждение
  полного доступа и изменение только следующего хода сохраняют гарантии M25.
- Нативные пункты доступа описывают подтверждение действий. Нельзя просто переименовать
  старые filesystem-профили в «Запрашивать разрешение» и «Подтверждать за меня».
- Источники истины — текущие скриншоты, контракты и пробы. Файлы фирменных шрифтов
  не распространяются; используется стек системного шрифта и существующая библиотека значков.

## 2. Решение

### 2.1. Первый этап: зафиксировать соответствие нативному поведению

T001 сохраняет исходные PNG и замеры, проверяет на отдельных временных тредах:
пресеты доступа и их effective permissions/approval policy/reviewer; каталог моделей,
порядок усилий и описание ускорения. Рабочий чат пользователя
для изменения разрешений не используется. Тестовые треды и папки удаляются.

Пробы 13.11.2026 при планировании только читали каталоги существующего демона:
permissionProfile/list содержит три id без описаний; model/list сообщает defaultReasoningEffort
и serviceTiers.description. У Sol сейчас «2x speed, increased usage», у Terra «1.5x speed».
Исходы T001 и точная таблица RPC — [проверенный контракт](../design/M26/access-preset-contract.md).
Пробы подтвердили штатный auto_review; сброс и справка исключены пользователем.

Для каждого нативного пресета нужна проверенная таблица: id, точный RPC-запрос,
состояние после чтения, ограничения allowed и метод распознавания текущего состояния.
Если нативное «Подтверждать за меня» требует отдельного штатного режима проверяющего,
он должен поддерживаться протоколом: Kit не отвечает на approval-запросы за пользователя.
Нет полного проверяемого соответствия — T001 записывает причину и блокирует scope;
не продолжать с ложными подписями или урезанным результатом без решения пользователя.

### 2.2. Строка управления

Слева под текстом ввода — отдельная кнопка доступа рядом с «+»; справа — контекст,
молния ускорения, модель, приглушённое усилие и стрелка. Микрофон остаётся у правого края.
Доступ не дублируется в правой строке. Для полного доступа — оранжевый щит и подпись
«Полный доступ» в округлой плашке, как на эталоне. Настоящий неизвестный набор —
«Особые разрешения»; ни один стандартный пресет не отмечен выбранным.

Геометрия основного поля и рабочие Enter/Stop/очередь M24 сохраняются; при перестановке
«+»/микрофона меняется только размещение, их функция остаётся прежней. Лимиты M25
сохраняются рядом со строкой управления, не занимая место внутри карточки усилия.
Claude остаётся информационной строкой; Kimi и провайдеры без новой презентации —
прежним вариантом. Разметка определяется данными контракта, не provider === codex.

### 2.3. Карточка усилия

- Якорь — правый переключатель модели/усилия. Основной вид: молния слева сверху,
  текущее усилие по центру; ниже — модель со стрелкой вправо;
  внизу — дискретный ползунок с отметками. Без заголовков «Скорость», «Модель», «Усилие».
- Настольный ориентир — 255×97 CSS px при масштабе 100 %, радиус около 18 px,
  внутренние отступы около 12 px; окончательные замеры сверяются с PNG 2×.
  Шрифт основного текста 14 px/400, подпись модели около 12 px, приглушённая.
- Ползунок показывает только поддерживаемые усилия выбранной модели. Порядок:
  low, medium, high, xhigh, max, ultra; неподдерживаемых фиктивных точек нет.
  Текущая подпись обновляется при жесте, запрос уходит один раз по отпусканию.
  Нажатие точки — одно изменение; pointercancel/Esc отменяют несохранённый жест.
- Клавиатура: стрелки — соседний вариант, Home/End — крайний; изменение фиксируется
  после завершения клавиатурного действия, без повторов из-за опроса. Одна выбранная
  отметка, aria-valuetext содержит название усилия; минимум и максимум соответствуют каталогу.
- Нет каталога усилий — соответствующий контрол отключён с причиной;
  остальные доступные настройки работают. Нет текущего усилия — «Нет данных», не первая точка.
- Нажатие названия модели открывает отдельный список под полем ввода пользователя,
  с текущей отметкой и прокруткой списка при необходимости. Список не встраивается
  внутрь карточки усилия; карточка закрывается. Выбор закрывает список. Серверные
  поправки несовместимых усилия/скорости видны и перечитываются.
- Смена обычного/планового режима M25 остаётся доступной в компактном разделе списка
  моделей. Основная карточка на эталоне от этого не растёт.

### 2.4. Скорость

Молния в карточке — переключатель стандартной/быстрой скорости. Выбранное состояние
имеет нативную подложку; молния в строке видна при фактическом ускорении. По hover,
фокусу и отдельному touch-нажатию доступна подсказка о скорости и расходе лимитов.
Множитель берётся из serviceTiers.description выбранной модели; «1,5×» не зашивается
для всех моделей. Переводится только известный формат, незнакомый текст не искажается.
Нет тарифа priority — ускорение отключено с причиной, обычная скорость остаётся доступна.

### 2.5. Доступ

Отдельная плашка открывает меню шире карточки усилия. Вверху «Как подтверждать действия
ChatGPT?»; ниже три строки со значком, основной подписью,
объяснением второй строкой и отметкой текущего значения:

| Подпись эталона | Объяснение эталона |
| --- | --- |
| Запрашивать разрешение | Всегда запрашивать разрешение перед изменением внешних файлов и использованием интернета |
| Подтверждать за меня | Запрашивать подтверждение только для потенциально небезопасных действий |
| Полный доступ | Неограниченный доступ к интернету и любым файлам на вашем компьютере |

Полный доступ окрашен оранжевым вместе со щитом и отметкой; цвет читаем в обеих темах.
Смена до полного доступа по-прежнему требует явного подтверждения с «Продолжить» и
«Отмена» внутри поповера. До него POST не отправляется; отмена ничего не меняет.
Запрещённые политикой пресеты видны с причиной, их нельзя выбрать.

### 2.6. Контракт и сервер

`provider-registry/src/parameters.ts`: обратно совместимое описание презентации
`SessionParameters.presentation?`: layout = effort-card, speedHint?,
access = { value, label, tone, options, reason? }. Нативные access options используют
opaque value, label, description, icon из фиксированного набора, disabled/reason/confirm.
Новый optional `ParameterChange.access` — id пресета; его нельзя смешивать с legacy
permissions в одном запросе. Точные типы и допустимые значения фиксирует T002 по T001.
Отсутствие presentation оставляет существующее поведение; значения чужой версии не ломают UI.

`provider-codex`: формирует presentation из реальных каталогов и состояния. Распознаёт
access по всему проверенному набору настроек, а не только filesystem-профилю. Один
запрос изменения пресета передаёт только необходимые permissions/approval/reviewer-поля
из таблицы T001. Все поля перечитываются; несовпадение — parameters-unavailable с причиной,
успех не выдумывается. Отклонённый/неизвестный пресет — parameter-invalid до записи.
Подтверждение полного доступа проверяется на сервере, не только в DOM.

Маршруты сохраняют проверку принадлежности сессии и очередь по provider/localId.
Аудит записывает фактически изменённые поля пресета. Legacy permissions для старого
клиента сохраняются. Смена модели/усилия/скорости не переписывает access, policy или
режим; выбор пресета не меняет модель, effort, speed и developer instructions.
Тред, загруженный только для изменения, выгружается; идущий ход не меняется.

### 2.7. DOM, размещение и взаимодействие

Новые небольшие файлы session-chat: effort-card.js, access-menu.js, parameter-popover.js,
их чистая модель и отдельный parameters.css; не раздувать parameters.js за 400 строк.
parameters.js сохраняет опрос/POST/поколения, а composer.js размещает отдельные контролы.
Стили подключаются штатным ресурсом модуля; CSP не ослабляется, текст — через textContent.

Открыт один поповер: карточка усилия, отдельный список моделей или меню доступа. Esc
закрывает его и возвращает фокус к вызвавшему контролу. Клик вне закрывает; фокус/черновик
не теряются из-за 5-секундного опроса. Во время POST все изменяющие контролы одной сессии
заблокированы; GET не затирает несохранённый жест, ответ старого поколения не меняет новую сессию.

Поповеры привязаны к якорю и visualViewport. Карточка усилия и доступ предпочитают
место над якорем; список моделей — под полем ввода. Если с предпочтительной стороны
нет места, поповер размещается с другой, оставаясь внутри окна. На узком экране
его ширина ограничена viewport, без горизонтального overflow и обрезки.
Список доступа переносит объяснения; при низкой высоте прокручивается тело, кнопки остаются
доступны. Coarse pointer — цели не меньше 44×44 px и ползунок, пригодный для пальца;
на touch карточка может быть выше эталона, настольные размеры не навязываются клавиатуре iPad.
Подсказки доступны без hover. Ошибки и notes показываются возле ввода, выбранные настройки
берутся из ответа сервера. Сбой GET сохраняет последние данные и прежние причины M25.

## 3. Поведение на ОС

| Что | macOS | Linux | Windows x64 и ARM64 |
| --- | --- | --- | --- |
| Карточка, ползунок, меню доступа | одинаковые ES-модули; проверка пользователя также на iPad | те же модули | те же модули |
| Чтение/изменение настроек | транспорт демона M25, общий доступ active | тот же RPC, общий доступ unsupported | существующий proxy; общий доступ active |
| Пресеты доступа | проверенная таблица RPC и ограничений | та же семантика с injected linux | та же семантика с injected win32 и путями Windows |
| Размеры и touch | обе темы; visualViewport и реальные touch-проверки iPad | адаптивный браузерный код | тот же код, обе архитектуры |

Платформа передаётся параметром, новых программ ОС не планируется. При необходимости
такого вызова — одновременно обновить allowlist и объяснить поведение всех трёх ОС.
Контракты модулей и матрица OVERVIEW обновляются в тех же коммитах, что и код.

## 4. Проверка и критерии готовности

- T001 даёт полное доказанное соответствие доступа или блокирует работу, без ложного эквивалента.
- Тесты: чтение/запись пресетов на injected darwin/linux/win32; сохранение других настроек,
  подтверждение/запрет полного доступа, особое состояние, ошибки read-back, legacy API;
  реальные каталоги усилий/дефолтов, один POST на жест, отмена, повторы клавиатуры, stale.
- Браузер: рабочие ползунок/точки/модель/скорость/доступ/режим, все причины отказов,
  отсутствие POST до подтверждения, ошибка POST/GET, focus/черновик, частичный каталог.
- Сравнение эталона и результата при одинаковых состоянии, теме, 100 % и DPR 2; отдельно
  светлая тема, 200 % и 1920×1080, 1280×800, 1024×768, 768×400, 375×667.
  Длинное общее меню отсутствует; основной настольный поповер близок к 255×97 CSS px.
- Дизайн-QA: design-qa.md с совместным сравнением эталона и рендера; P0/P1/P2 исправлены,
  итог passed. Приложенные изображения не заменяют проверку действий и ошибок JavaScript.
- Живая проверка: macOS и iPad — пользователь; Windows — проверяющий на Windows;
  Linux — только CI. Эмуляция touch/viewport не объявляется проверкой настоящего iPad.
- Локальная 0.12.0 установлена штатно, doctor ok; браузер читает реальный установленный API.
  CI SHA поставки зелёная на macOS, Linux, Windows x64/ARM64; автоматическая проверка
  отделена от пользовательской приёмки. Main публикуется после приёмки/закрытия по команде.

## 5. Границы и поставка

Сессии Claude остаются только для чтения параметров; Kimi, вложения, микрофон и механизм
Stop/отправки/очереди не расширяются. Параметры идущего хода не меняются. Автоматическое
одобрение запросов собственной логикой Kit не входит; нативный пресет требует штатного API.

M25 принята и закрыта по прямой команде пользователя до начала M26.
T001–T005 реализованы; визуальный итог — [Design QA](../../design-qa.md), passed.
Круговой стрелки и «Подробнее» нет. Модели показываются отдельным списком под вводом.
Старое название T001 в истории содержит «сброс», но его актуальные критерии исключают
эту функцию; завершённая запись истории не переписывается. Приёмка/закрытие M26 —
отдельные решения пользователя после поставки и CI.

Поставка двухэтапная: T006 устанавливает локальную 0.12.0 без push; её коммит — SHA поставки.
Затем вне задач пользователь либо агент по его прямой команде отправляет этот SHA на
ci/m26-native-session-controls. T007 начинается только после зелёной CI точного SHA,
записывает хеш/URL/четыре результата, функциональных файлов не меняет. До T007 scope не
принимается. Порядок должен быть согласован при выборе плана; разрешение на git push
не подменяется самим выбором режима исполнения.
