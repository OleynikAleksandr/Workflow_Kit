# M40: полный автопилот и план без блока `automation`; конец запуска

Часть [спецификации M40](M40-user-decisions.md).

## Цель и согласование

17.11.2026 пользователь проверял выпуск 0.15.1 на тестовом проекте T001 в режиме «Полный
автопилот» и сообщил два дефекта: «наш кит непрерывно передавал» одно и то же сообщение
агенту, и «когда агент полностью закончил работу, и я принял план и закрыл его, карточка
автопилота продолжала работать и предлагать нажать паузу или остановить автопилот».
Пользователь поручил исправить. Исправление — задача T004A этого scope.

## 1. Что произошло

- План тестового проекта не содержал блока `automation`. Для такого плана (политика
  `legacy`) `runs.beginExecution` не создаёт разрешение запуска.
- `run-prepare.ts`, шаг запуска: scope принадлежит запуску, разрешения нет → запуск плана
  выполняется заново при каждой сверке, то есть после каждого законченного хода агента.
  Агент каждый раз получал сообщение «Workflow Kit: the user started the plan…». Запись
  запуска дошла до ревизии 196.
- После ручной приёмки и закрытия scope в проекте нет. Шаг видит «scope нет» и остаётся в
  фазе `preparing`: карточка «Готовит спецификацию и план» с кнопками «Пауза» и
  «Остановить автопилот» не исчезает.
- Текст подготовки полного автопилота (`preparationText('full')`) не сообщает агенту, что
  плану нужен блок `automation`. Агент узнаёт об этом только из отказов.

Причина та же, что у остальных дефектов M40: служба знает требование и состояние сама, но
не применяет их, а ждёт правильных действий агента.

## 2. Решение

### 2.1. Требование названо заранее

Текст подготовки в режиме `full` называет требование: предложение плана содержит блок
`automation` (вид каждого критерия приёмки, эффекты задач delivery, CI, публикация), поля —
в `scripts/workflow schema scope:propose`. Без блока полный автопилот план не запустит.

### 2.2. Предложение без `automation` не выбирается и не запускается

В режиме `full` служба проверяет предложение до ревью и выбора режима. Предложение без
блока `automation` возвращается автору одним сообщением с точным указанием, чего не хватает.
Попыток не больше двух (счётчик — в записи запуска). После второй запуск останавливается с
причиной `automation-missing`; карточка называет причину по-русски и предлагает продолжить
вручную: обычные карточки ревью и выбора режима работают как без автопилота.

Уточнения при реализации:

- Есть ли в предложении блок, службе сообщает Kit: `scope:proposal` получает поле
  `automation` (Kit 2.4.4). Раньше Kit этого не отдавал, а читать `.harness/**` служба не
  вправе. Kit до 2.4.4 поля не сообщает: для такого проекта проверка идёт после выбора
  режима — план без блока не запускается, запуск останавливается с той же причиной.
- Предложение возвращается ответом на конец хода владельца (продолжение хука Stop), до
  ревью: ревью начинается в том же решении, поэтому проверка стоит перед ним.
- Остановка — финальная фаза `stopped` с причиной, а не `blocked`: заблокированный запуск
  держал бы барьер и мешал обычному автопилоту задач при ручном продолжении. Карточка
  остановленного службой запуска показывает причину без кнопок, пока план тот же.

### 2.3. План запускается один раз

Запуск плана записывается квитанцией в журнале запуска (scope и ревизия). Повторная сверка
находит квитанцию и сообщение о запуске второй раз не отправляет. Если разрешение получить
нельзя (план без `automation` — причина `automation-missing`; план запущен, а разрешение Kit
не записал — `authorization-missing`), запуск останавливается с причиной; повторов нет.
Сообщение о запуске плана агент получает ровно один раз на scope.

### 2.4. Запуск заканчивается вместе со своим scope

Запуск, у которого был scope, заканчивается, когда этого scope больше нет: пользователь
принял и закрыл его вручную (`lastClosed` называет scope запуска) либо scope заменён другим.
Фаза — `finished` с причиной `closed-manually`; карточка автопилота исчезает. Публикацию
такой запуск не выполняет: пользователь вмешался вручную, кнопка «Опубликовать на GitHub»
остаётся. Ручная приёмка без закрытия запуск не заканчивает, но повторной приёмки запуск не
делает.

Запуск, у которого scope ещё не было, по-прежнему ждёт предложения плана (фаза
`preparing`): отсутствие scope до выбора режима — обычное состояние.

## 3. Поведение на ОС

| Что | macOS | Linux | Windows |
| --- | --- | --- | --- |
| Проверка предложения, квитанция запуска, конец запуска | общий Node-код службы, запись журнала запуска атомарно | то же | то же, x64 и ARM64 |
| Тексты агенту и карточки | одинаковы | одинаковы | одинаковы |

Поведение одинаково на всех ОС. Программы ОС не вызываются, пути не сравниваются.

## 4. Проверка

Автоматические тесты модуля `autopilot` (и панели — для текста карточки):

- `full`, предложение без `automation`: автор получает одно сообщение с требованием; ревью,
  выбор режима и запуск плана не выполняются; после второго такого предложения запуск
  остановлен с причиной `automation-missing`.
- Текст подготовки `full` содержит требование блока `automation`; тексты `after-start` и
  ручного режима не меняются.
- Несколько сверок подряд после запуска плана: сообщение о запуске отправлено один раз.
- Разрешение получить нельзя: запуск остановлен с причиной, сообщений о запуске больше нет.
- Scope запуска принят и закрыт вручную: запуск в фазе `finished`, состояние панели не
  содержит карточки автопилота, публикация не выполнена.
- Запуск без scope (подготовка) после этих изменений ведёт себя как раньше.
