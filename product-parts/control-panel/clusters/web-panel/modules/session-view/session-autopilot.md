# session-view: автопилот сессии и кнопки под автопилотом (M48 T005)

Часть контракта [module.md](module.md). Спецификация —
[M48](../../../../../../docs/planning/M48-session-autopilot.md), раздел 3.5.

## Карточка автопилота сессии

- Модель `session-autopilot-model.js` (без DOM), DOM — `session-autopilot-card.js`, стили — в
  `run-card.css` (`.sv-ap-modes`, `.sv-ap-review`, `.sv-ap-effect`, `.sv-waits`).
- `sessionAutopilotView(state, projectId, key, isReviewer?)` — из раздела состояния
  `autopiloting.sessions[projectId][key]`: `{ known, revision, mode, review, reviewState,
  reviewShown, reviewLine, effect }`; у ревьюера и архивной сессии карточки нет.
  - Переключатель ревью виден, пока ревью меняется (`reviewState` `open`, `running` или
    неизвестно); `running` — строка «Ревью идёт: снимите флажок, чтобы отменить его.», `reviewed` —
    «План прошёл ревью…», `closed` — без строки (способ выбран).
  - `effect` — что сделало последнее переключение (строка службы, T002).
- Часть `autopilot` сайдбара (перед `run`) — `sessionAutopilotCard`: заголовок «Автопилот сессии»,
  три кнопки режима «Выкл · После старта · Полный» (`SESSION_MODES`, `aria-pressed` у режима
  сессии), флажок «Ревью спецификации и плана», строка `effect`, подсказка
  `SESSION_AUTOPILOT_TEXTS.hint` («Настройки» задают значения только для новых сессий).
  - Нажатие — `POST /api/projects/:id/sessions/:key/autopiloting { expectedRevision, mode | review }`.
  - Отказ (`sessionRefusal`: `settings-stale`, `review-closed`, `review-locked`, иначе «Не
    сохранено: …») хранится в `cardNotes` до следующего нажатия и показан на карточке; верное
    значение приходит со следующим опросом.
  - Сессия без записи (`known: false`) — карточка один раз читает `GET` того же адреса (первое
    чтение берёт значения Settings), кнопки выключены до ответа.
- Состояние запуска — прежняя карточка `run` (M39) сразу под карточкой сессии.

## Кнопки, которые нажимает автопилот

`autopilotPresses(state, projectId)` — пока запуск проекта идёт (`liveRun`: фазы от `preparing` до
`publishing` и `waiting`; пауза, блокировка, остановка и конец — `null`):

| Поле | Когда | Что панель делает |
| --- | --- | --- |
| `choice` | полный запуск до старта | вместо карточки выбора способа — строка (`autoChoice`): «Автопилот сам выберет способ выполнения и запустит план», в ревью — «Идёт ревью плана…», после возврата предложения (`returned` сводки) — «Автопилот вернул план агенту: в нём нет описания для автопилота…» |
| `start` | то же | у плана нет «Начать выполнение плана», строка «План запустит автопилот.» |
| `delivery` | начатый запуск с разрешением Kit | нет «Подтвердить выпуск» |
| `accept` | `grant.accept` и нет ожидания ручной приёмки | нет «Принять план» («Нужны исправления» остаётся) |
| `close` | `grant.close` | нет «Закрыть план» |
| `publish` | `grant.publish` | нет «Опубликовать на GitHub» (`panel-shell/publication.js`) |

`planView` фильтрует кнопки по этим полям и даёт `autopilotNote` для фаз `ready`, `acceptance`,
`accepted`: «Приёмку, закрытие и публикацию выполнит автопилот.» или «Приёмка — ваша (ручной
критерий); закрытие… выполнит автопилот.». `planView.autopilotingMode` — режим этой сессии (запись
сессии, без неё — Settings); `policyLine` спрашивает `…/autopiloting/policy?session=<key>`.

Без идущего запуска, на паузе, после блокировки или остановки — кнопки как раньше. Старая служба без
`grant` в сводке: скрывается только старт полного запуска.

## Итог запуска

`runView` у `completed`: без «Пауза», «Продолжить», «Остановить автопилот». План без публикации
(`local` сводки) — «Завершён: план принят и закрыт» (`LOCAL_LABEL`) и «Результат остаётся локальным:
публикация в плане не предусмотрена.» (`LOCAL_RESULT`); с публикацией — «Опубликовано» и SHA.

## Нажатия при занятом Kit

`kitWaitsView(state, projectId)` — из раздела `kitWaits` (служба, T004): ожидающие нажатия —
««Подтвердить выпуск» ждёт: агент выполняет команду Kit, нажатие применится, как только Kit
освободится.», не применённые — ««…» не применено: <причина>». Часть `waits` сайдбара (после вопроса
агента) — у каждой основной сессии проекта. Кнопки получают 202 и не показывают ошибку.

## Поведение на ОС

Одинаково на macOS, Linux и Windows x64/ARM64: браузерные ES-модули, без веток ОС.
