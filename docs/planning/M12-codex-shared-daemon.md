# M12. ChatGPT: один демон Codex для Kit, приложения и телефона

## Цель и согласование

У Codex чатом владеет один процесс app-server. Сейчас их два: демон Kit и встроенный процесс
приложения ChatGPT. Отсюда ограничения, которых нет у Claude и Kimi: чат ревьюера ChatGPT не
виден в приложениях, Kit не может написать в чат, открытый в приложении, после создания чат
приходится «выгружать» и ждать, а на телефоне чат, занятый другим процессом, не открывается.

Пробы 2026-11-11 (macOS, ChatGPT 26.1106, codex-cli 0.166) показали рабочую схему: приложение
ChatGPT подключается к этому же компьютеру по SSH и становится клиентом демона Kit. Тогда
Kit, ChatGPT на компьютере и ChatGPT на iPad и телефоне работают с одним чатом одновременно,
хуки Kit приходят для ходов с любого устройства.

Пользователь, 2026-11-11: «Вот это вот ограничение демона мешает нам в любых ситуациях… Нужно
попробовать найти решение»; после проб: «Да, теперь все работает именно так, как должно»;
«Пиши спецификацию и to-do plan, и не забудь, пожалуйста, вписать в спецификацию изменение
README файла касающегося настройки Workflow Kit. Поскольку ChatGPT для нормальной работы через
SSH нужно ж настраивать. Или мы можем это сделать из Workflow Kit, если можем, значит должны
это делать мы. Приступай.»

Результат вехи: на macOS у провайдера ChatGPT появляется режим «общий демон». Kit сам готовит
всё, что может; пользователю остаются два действия, которые Kit выполнить не вправе.

## 1. Принципы

1. **Что Kit может настроить сам — настраивает Kit.** Пользователь не вводит команд в
   терминале. Вручную остаются: включить «Удалённый вход» в настройках macOS (нужен пароль
   администратора) и подтвердить подключение в приложении ChatGPT.
2. **Запись только после предпросмотра.** Kit показывает каждый файл и строку, которые
   запишет, делает копии файлов до записи и проверяет результат после (как доверие папке).
3. **Режим не обязателен и обратим.** Без настройки и на других ОС ChatGPT работает как в
   0.6.4. «Убрать настройку» удаляет всё, что записал Kit.
4. **Режим опирается на недокументированное поведение ChatGPT.** Поэтому Kit раз в минуту
   проверяет, что схема жива, и при поломке сам возвращается к прежнему поведению с понятной
   причиной в панели.
5. **Доступ по SSH только с этого компьютера.** Ключ Kit принимается только с адресов
   `127.0.0.1` и `::1`.

## 2. Решение

### 2.1. Схема

- Демон Kit (`codex app-server --remote-control --listen unix://`) — единственный владелец
  чатов. Удалённое управление (телефон, iPad) держит он.
- Приложение ChatGPT имеет подключение SSH `wfk-local` к `127.0.0.1` и через
  `codex app-server proxy` становится клиентом демона.
- В SSH-сеансе с этого компьютера выставлена переменная `CODEX_SSH_SKIP_APP_SERVER_BOOT=true`
  и путь к `codex`: без неё приложение поднимает второй app-server на том же сокете.
- Чат Kit открывается в приложении ссылкой
  `codex://threads/<id>?hostId=remote-ssh-discovered%3Awfk-local` (значок глобуса у имени).
  Ссылка без `hostId` открывает локальную копию, где ввод заблокирован.

### 2.2. Настройка общего доступа (делает Kit)

Новый блок «Общий доступ к чатам» в настройках провайдера ChatGPT. Состояния:

| Состояние | Что видит пользователь |
| --- | --- |
| `unsupported` | причина (ОС, нет `codex`, нет приложения) |
| `not-configured` | кнопка «Настроить» |
| `needs-remote-login` | «Включите Удалённый вход» + кнопка «Открыть настройки macOS» + «Перепроверить» |
| `needs-connection` | кнопка «Добавить подключение в ChatGPT» + «Перепроверить» |
| `active` | «Работает», кто держит удалённое управление, «Убрать настройку» |
| `broken` | причина и что сделать; сессии работают по-старому |

«Настроить» показывает предпросмотр с токеном и после подтверждения записывает:

| Файл | Что | Примечание |
| --- | --- | --- |
| `~/.ssh/wfk_local`, `.pub` | ключ ed25519 без пароля (`ssh-keygen`) | права 600; существующий не перезаписывается |
| `~/.ssh/authorized_keys` | строка ключа с `from="127.0.0.1,::1"` и меткой `workflow-kit` | права 600 |
| `~/.ssh/config` | управляемый блок `Host wfk-local`: `HostName 127.0.0.1`, `User`, `IdentityFile`, `IdentitiesOnly yes`, `HostKeyAlias wfk-local`, `StrictHostKeyChecking accept-new` | между маркерами `# >>> workflow-kit >>>` и `# <<< workflow-kit <<<` |
| профиль оболочки входа | управляемый блок: если `SSH_CONNECTION` начинается с `127.0.0.1` или `::1` — путь к папке `codex` в `PATH` и `CODEX_SSH_SKIP_APP_SERVER_BOOT=true` | zsh — `~/.zshenv`; bash — `~/.bash_profile`, иначе `~/.profile`; другая оболочка — текст для ручной вставки |

Правила записи: копия файла до записи; повторное применение не дублирует блоки; чужие строки
не меняются; если в файле уже есть ручной блок пробы (`Host wfk-local` без маркеров) — Kit
показывает это в предпросмотре и заменяет его управляемым.

Проверка после записи и по «Перепроверить»:

1. порт 22 на `127.0.0.1` отвечает (`node:net`), иначе `needs-remote-login`;
2. `ssh -o BatchMode=yes wfk-local` выполняет `command -v codex` и печатает переменную —
   иначе `broken` с текстом ошибки;
3. приложение ChatGPT подключено: в списке процессов есть `ssh … wfk-local … codex app-server
   proxy`. Kit запоминает, что подключение было увидено; до этого — `needs-connection`.

«Добавить подключение в ChatGPT» открывает ссылку приложения с целью `connections/ssh/add`
(`alias=wfk-local`, имя «Workflow Kit», включить и активировать). Точный вид ссылки
устанавливает живая проба в задаче T001; если приложение ссылку не принимает, блок показывает
три шага: Настройки ChatGPT → Подключения → SSH → включить `wfk-local`.

«Убрать настройку» (с подтверждением): удаляет управляемые блоки, строку ключа и файлы ключа.
Подключение в ChatGPT и «Удалённый вход» пользователь выключает сам — блок говорит об этом.

Интерфейс: необязательная часть контракта провайдера `sharedAccess` (`state`, `preview`,
`apply(token)`, `recheck`, `remove`) и маршруты `/api/providers/:p/shared-access…`; состояние
входит в статус провайдера и в `wfk doctor`.

### 2.3. Сессии в режиме общего демона

Режим считается включённым, когда состояние `active` (или подключение уже было увидено и
проверки 1–2 проходят). Тогда:

- **Ссылки.** `desktop` — с `hostId`; `mobile` — прежняя. Проверка ссылок `open-link`
  принимает только `?hostId=remote-ssh-discovered%3A<alias>`.
- **Создание.** После первого хода чат не выгружается (`thread/archive` + `unarchive` и
  ожидание 90 с убраны), примечание «освобождается» не показывается.
- **Пробуждение.** У Codex появляется `wakeSession`: `thread/resume`, если чат не загружен, и
  `turn/start` с коротким служебным текстом; очередь отдаёт хук `UserPromptSubmit`. Kit будит
  только простаивающую сессию (как у Claude). «Сообщение агенту» из панели доходит без
  ожидания следующего хода.
- **Ревьюер.** Задание по-прежнему идёт первым сообщением (`detached`). Способ доставки
  задания становится явным свойством провайдера, а не проверкой наличия `wakeSession`.
  Чат ревьюера ChatGPT виден в приложениях; на карточке «Ревью плана» появляется «Открыть чат
  ревьюера». В дереве проекта ревьюер по-прежнему скрыт (решение 13.4).
- **Удалённое управление.** Правило M7 перевёрнуто: Kit не отдаёт его приложению. Если его
  держит приложение (запустилось раньше демона), панель показывает: «Закройте ChatGPT,
  дождитесь "подключён" и откройте снова».
- **Самопроверка** (раз в минуту, `maintain`): демон жив; нет второго `app-server --listen`
  от приложения; SSH-проверка проходит. При сбое — `broken`, новые ссылки без `hostId`,
  создание с выгрузкой, `wakeSession` отвечает `false`. Восстановление — автоматически.

### 2.4. Документы

- `README.md`: шаг 4 получает пункт «Общий доступ к чатам (macOS)» — зачем, один ручной шаг
  в macOS (Удалённый вход: только для своего пользователя), «Настроить» в панели, «Добавить
  подключение», перезапуск ChatGPT, как убрать; таблица шага 1 и «Особенности провайдеров в
  работе» — что даёт режим и что без него.
- `docs/installation.md`: «Что создаётся в каждой ОС» (файлы из 2.2) и «Если что-то не
  работает» (заблокированный ввод, «используется в другом сеансе», `broken`).
- `docs/architecture/OVERVIEW.md` (матрица ОС, известные ограничения), `module.md` модулей
  `provider-codex`, `provider-registry`, `cli`, `session-view`, `panel-shell`, `CHANGELOG.md`.

## 3. Поведение на ОС

| | macOS | Linux | Windows |
| --- | --- | --- | --- |
| Режим общего демона | поддерживается | `unsupported`: приложения ChatGPT для Linux нет | `unsupported` в этой вехе: нужен сервер OpenSSH с правами администратора, приложение требует `$SHELL`; не проверено |
| Запись файлов SSH и профиля | да | нет | нет |
| Сессии, ссылки, ревью | новое поведение при `active`, иначе как в 0.6.4 | как в 0.6.4 | как в 0.6.4 |
| Проверка ссылки с `hostId` | принимается | принимается (общий код) | принимается (общий код) |

Платформа передаётся параметром; ветки `linux` и `win32` (`unsupported`, прежние ссылки и
выгрузка) покрыты тестами с подставленной платформой. Новых программ одной ОС нет: `ssh` и
`ssh-keygen` есть на всех трёх; список процессов берётся существующей функцией.

## 4. Проверка

- Автоматические тесты:
  - настройка: предпросмотр, идемпотентность, копии, замена блока пробы, удаление, права
    файлов, выбор профиля оболочки, состояния по результатам проверок, `unsupported` на
    `linux` и `win32`;
  - сессии: ссылки с `hostId` и без, создание без выгрузки, `wakeSession` (загруженный и
    выгруженный чат, отказ вне режима), перевёрнутая передача управления, откат при `broken`;
  - `open-link`: допустимые и недопустимые ссылки; ревью: задание ChatGPT первым сообщением;
  - панель: состояния блока, кнопка чата ревьюера.
- CI: macOS, Linux, Windows x64 и ARM64.
- Живая проверка, macOS — пользователь: настройка с нуля из панели (после удаления пробных
  строк); новая сессия открывается с глобусом на Mac и на iPad одновременно; автопилот и
  выбор режима (удержание `Stop`); полное ревью с ревьюером ChatGPT и открытие его чата;
  «Сообщение агенту» в простаивающую сессию; перезагрузка Mac; обновление и перезапуск
  ChatGPT; «Убрать настройку». Windows — проверяющий на Windows: ничего не изменилось, блок
  показывает `unsupported`. Linux — только CI.

## 5. Границы

- Windows и Linux — без режима; отдельная веха после проб на Windows.
- Kit не включает «Удалённый вход», не закрывает и не перезапускает ChatGPT, не меняет его
  настройки и базу.
- Облачный режим ChatGPT не поддерживается: хуки проекта там не запускаются.
- Известные риски (в документе приёмки): ChatGPT при своём перезапуске может завершить демон
  (Kit поднимает его снова); пользователь может открыть локальную копию чата из «Недавних» —
  ввод там заблокирован, панель и README объясняют, что открывать нужно из Kit.
