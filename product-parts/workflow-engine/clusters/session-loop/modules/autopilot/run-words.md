# Модуль autopilot: «стоп» и «пауза» распознаёт служба (M40 T006)

Часть контракта [модуля autopilot](module.md). Спецификация —
[M40](../../../../../../docs/planning/M40-user-decisions.md), раздел 2.4.

До M40 во время живого запуска служба после любого сообщения пользователя отправляла
продолжение и просила агента самому выполнить `wfk session run pause|stop`. Теперь слово
пользователя читает служба: остановка не зависит от того, поймёт ли его агент.

## Распознавание слова (`src/run-words.ts`)

`runWord(text) → 'stop' | 'pause' | null`:

- текст нормализуется `normalize('NFC')` и `toLowerCase()` (без учёта локали), пробелы по краям
  обрезаются;
- берётся первое слово (до первого пробельного символа), с него снимается пунктуация в начале и
  в конце — всё, что не буква и не цифра (`\p{L}`, `\p{N}`);
- `стоп`, `stop`, `останови`, `остановись`, `остановить` → `stop`;
  `пауза`, `pause`, `приостанови` → `pause`; любое другое слово → `null`.

«Стоп», «Stop.», «пауза, посмотрю», «СТОП!», «„Стоп“» — слова; «а когда стоп?», «стопка»,
«не останавливай» — нет. Другие формулировки по-прежнему понимает агент и вызывает
`wfk session run pause|stop` (`RunControl.byOwner`).

## Сервис слов

`createRunWords({ control, tell, log? }) → RunWords`:

- `received(projectId, key, text) → { action, runId, settled } | null` — сообщение пользователя
  в момент, когда его получила служба. `null`: первое слово другое; в проекте нет живого запуска;
  сессия `key` — не владелец запуска; запуск уже на паузе (для «паузы»). Иначе запуск остановлен
  или поставлен на паузу, а `tell` ставит в очередь сессии контекст для агента
  (`WORD_TEXTS.stop|pause(runId)`): «запуск остановлен (поставлен на паузу) словом пользователя,
  Workflow Kit сделал это сам; ответьте пользователю и закончите ход». Контекст не будит сессию:
  он доставляется вместе с самим сообщением пользователя (в ответе хука UserPromptSubmit или при
  доставке очереди в конце хода).
- `settled` — обещание, которое выполняется, когда Kit записал паузу (`pause:set --on`) или отзыв
  разрешения запуска (`autopilot:revoke`, причина `user-stop`). Вызывающий его не ждёт.

Где вызывается (модуль `cli`, `session-wiring.ts`):

| Откуда сообщение | Когда читается |
| --- | --- |
| Панель, `POST /api/projects/:id/sessions/:sid/message` | после проверки сообщения, до передачи агенту и до постановки в очередь — в том числе когда агент занят (`onUserMessage` маршрута канала агента) |
| Текст, набранный в приложении провайдера | в хуке UserPromptSubmit, до `channel.prompt` |

Сообщения `Workflow Kit:`, ревьюера и напоминания через эти точки не проходят.

## Барьер действует сразу (`RunControl.byWord`)

`byWord(projectId, key, action) → { run, settled } | null` пишет барьер в журнал запуска **вне
очереди проекта** (`KeyedMutex`), не дожидаясь идущего автоматического шага:

- `stop` — фаза `stopped`, причина `user-stop`, `pausedFrom` — фаза, из которой остановлен
  (у запуска на паузе или заблокированного — его прежняя `pausedFrom`); `actions.halt` выключает
  продолжения автопилота проекта; отзыв разрешения (`autopilot:revoke`) идёт следом в очереди
  проекта. Остановленный запуск — не живой: конец хода владельца отпускается без продолжения;
- `pause` — фаза `paused`, причина `user-pause` (как кнопка «Пауза»); пауза Kit — следом в
  очереди проекта.

Кнопки панели (`pause`, `stop` с `runId` и `expectedRevision`) и `byOwner` не меняются.

### Автоматические шаги за барьер не заходят

- Сервис завершения (`run-complete.ts`) перед каждым шагом (`step`), перед билетами приёмки и
  закрытия, перед push ветки CI и перед публикацией перечитывает запуск (`runMayDecide`):
  остановленный, поставленный на паузу, заблокированный или отозванный запуск ничего не начинает.
- `RunJournal.advance(root, runId, change)` — запись автоматического шага (сервисы подготовки,
  ходов, ожиданий, завершения, старта и предложения без `automation`). Ведёт себя как `update`, но
  не снимает барьер, поставленный пользователем, пока шаг выполнялся:
  - запуск остановлен (финальная фаза) — результат шага записывается (квитанции, билеты,
    `completion`), фаза, причина и `nextAction` остаются прежними;
  - запуск на паузе — результат записывается, фаза остаётся `paused`, а `pausedFrom` получает
    фазу, в которую шаг хотел перейти: после «Продолжить» запуск идёт дальше с неё. Блокировка
    шага паузу не заменяет; проверенный конец запуска (финальная фаза) паузу заканчивает.
- `update` остаётся для действий пользователя и службы над самим запуском (пауза, стоп,
  «Продолжить», отзыв).

Так начатое действие — коммит приёмки, закрытие, push — заканчивается с записью результата, а
следующее (продолжение хода, выбор режима, старт задачи, приёмка, закрытие, публикация) не
начинается.

## Текст продолжения

`TURN_TEXTS.userMessage` (сообщение пользователя в ходе живого запуска) по-прежнему предлагает
агенту `wfk session run pause|stop`, но только для просьбы «другими словами»: «стоп» и «пауза»
первым словом до этого текста не доходят.

## Поведение на ОС

| Что | macOS | Linux | Windows |
| --- | --- | --- | --- |
| Распознавание слова | `normalize('NFC')`, `toLowerCase()` без локали, классы Unicode `\p{L}`, `\p{N}` | то же | то же, x64 и ARM64 |
| Барьер и журнал запуска | атомарная запись файла запуска под блокировкой проекта | то же | то же |
| Пауза Kit и отзыв разрешения | команды Kit через `kit-runner` | то же | то же |

Поведение одинаково на всех ОС, ветвей по платформе и вызовов программ ОС нет.
