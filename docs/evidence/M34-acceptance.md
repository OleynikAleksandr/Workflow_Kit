## Живая проверка на установленной 0.14.1

macOS, 15.11.2026, codex-cli 0.169.0, ChatGPT Desktop, `gpt-6.1-sol`. Проект
`/Volumes/Backup/R001` создан пользователем в панели, сессия ChatGPT создана панелью. Задача:
одностраничное приложение «Список покупок», три уточняющих вопроса с вариантами по одному,
дожидаясь ответа. Ответы давал пользователь в панели и в ChatGPT.

Агент записывал хронологию только через API службы (`/api/state`, лента сессии каждые 2 с):
состояние канала, очередь, id, состояние и ответы вопросов, начала последних сообщений
ленты. Журналы службы и транскрипты не читались. Время — UTC.

## Итог по критериям

| Критерий | Итог | Уровень |
| --- | --- | --- |
| Ответ на асинхронный вопрос при идущем ходе доходит до агента без `Stop` | весь опрос — один ход; каждый ответ дошёл за 3–8 с, агент сразу задал следующий вопрос | проверено (API службы) |
| Очередь канала пуста | `queued 0`, `pending 0` на всех снимках | проверено (API службы) |
| Лента читаема | ответы в ленте — текстом («В браузере»), без обёртки `<send_user_message_question_reply>` | проверено (API службы) |
| Закрытые карточки показывают ответ | у всех трёх вопросов `answers` с выбранным вариантом | проверено (API службы) |
| Ответ из панели и ответ из ChatGPT | оба способа; итог — пользователь: «Да, я проверил всё. Теперь работает отлично в чат GPT.» | проверено (пользователь) |
| Закрытие карточки ChatGPT после ответа панели | подтверждено общей фразой пользователя выше | проверено (пользователь) |
| Свой текст из панели | все три ответа в данных совпали с подписями вариантов; ответ своим текстом в хронологии не виден | не проверено вживую; покрыто тестами T001–T003 |

Какой ответ дан в панели, а какой в ChatGPT, API службы не различает; пользователь
подтвердил оба способа. Расход: 1 ход `gpt-6.1-sol` из 2.
