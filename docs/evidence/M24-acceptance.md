## T009: типизированный тайм-аут клиента Kimi (13.11.2026)

База — `08cbfec0`. Дефект T004, обнаруженный полной проверкой T005: клиент терял
признак HTTP timeout, и Stop иногда возвращал interrupt-failed (502). Проверка Date.now
не заменяет происхождение ошибки. Новый детерминированный тест воспроизвёл 502 вместо
504 задолго до общего дедлайна, без ожидания случайной гонки.

KimiError сохраняет kind=transport и новый timedOut. Признак берётся из TimeoutError /
AbortError (в том числе вложенного cause) либо уже истёкшего сигнала запроса. Исходная
ошибка/stack/data не копируются. API-ответы и похожие слова в обычной ошибке этот признак
не получают. Stop преобразует типизированный timeout в ProviderError interrupt-timeout
(504 с подсказкой); обычный сетевой отказ остаётся interrupt-failed (502).

Дедлайн, запрет replay abort, барьер и очередь не менялись. Тесты проверяют сохранение
барьера/очереди, отсутствие повторного POST, разные имена/тексты ошибки, обёрнутый cause,
общую ошибку после срабатывания сигнала и обычный transport error до дедлайна.

```sh
node --test product-parts/provider-runtime/clusters/provider-adapters/modules/provider-kimi/test/client.test.ts product-parts/provider-runtime/clusters/provider-adapters/modules/provider-kimi/test/interrupt.test.ts
npm run typecheck
```

Целевые проверки: 21/21; typecheck прошёл. Полный набор Kimi и обязательные проверки
запускаются до коммита. Их окончательное подтверждение — результат
`scripts/workflow commit --task T009`, точный SHA хранит история Kit.

Поведение одинаково на macOS/Linux/Windows x64/ARM64, новых программ ОС нет.
Реальная служба, установленная версия и пользовательские сессии не менялись. Живая
остановка провайдера и CI других ОС не приписываются тестам с подставным fetch/сервером.

Полный целевой набор Kimi прошёл: 130/130; platform-guard тоже прошёл.

## T006: компактный ввод, Enter/Stop и интеграция (13.11.2026)

База — `213461259666d37dc17cd6e26f6c78c2a7080b35` (T009). Точный коммит T006
после проверок фиксирует `scripts/workflow history`; собственный SHA не вписывается
внутрь того же коммита. Реализация находится только в session-chat, дополнены его
контракт и матрица ОС. panel-shell/view-model.js и завершённые задачи не менялись.

Единая рамка содержит SVG «+», растущее поле, Enter/Stop и микрофон. Параметры справа
под рамкой информационные: модель из SessionInfo выбранной сессии, остальные данные
пока отсутствуют и представлены «—»/нейтральным кольцом. Плюс/микрофон отключены с
пояснениями, разрешений/запросов не вызывают. Статические Lucide 0.468.0 SVG с исходной
лицензией, без установки пакетов. Области кнопок 44×44 px, coarse pointer — поле 16 px.

Waiting/holding/unknown используют Enter; working — Stop. Обычный Enter во время
working вставляет строку, Ctrl/⌘+Enter и кнопка «В очередь» используют прежний маршрут
M18. Локальная HTTP-отправка не имитирует working. Замок запросов исключает дубли;
успех очищает только ту же ревизию черновика, включая защиту при изменении текста и
возврате к прежнему. Ошибки/Stop оставляют новый ввод и ленту.

Stop ждёт подтверждения API. Только подтверждённое поколение становится waiting;
ответ старого запроса не скрывает Stop нового хода. stale-turn даёт нейтральную подпись
и GET /api/state для актуальной цели: существующий shell.api сохраняет code, но не
error.current. Более новое состояние слота имеет приоритет. Повторного POST без
нового нажатия нет. Причина недоступности видна текстом, timeout/error — с подсказкой.
Барьер, очередь и реальные адаптеры остаются ответственностью T002–T005/T008/T009.
