# M45: доставка сообщений в терминал Claude и карточки без автопилота

## Цель и согласование

Пользователь 19.11.2026, после перезагрузки Mac и возобновления сессии из панели: «набрал в
диалоге Workflow Kit и отправил. И никуда мое сообщение не пришло… я там выбрал режим и он тоже
мигает как непринятый»; «сообщения вообще в десктопе ты получил и прочитал после того, как я
нажал „Стоп“»; «опять я отправил в диалог workflow кит нашей сессии поручение составить
спецификацию и план, и оно никуда к тебе не пришло». На предложение исправить эти пункты и два
вчерашних (карточка «Подтвердить выпуск» при выключенном автопилоте сессии, медленный хук
SessionStart) — поручение составить спецификацию и план.

Результат: сообщение из панели либо доходит до Claude, либо панель явно говорит, что не дошло,
и сохраняет текст; смена параметров не оставляет в терминале открытое меню или набранную
команду; сообщения из десктопа не ждут меню панели; режим не мигает, когда он уже стоит;
карточка поставки есть и без автопилота сессии.

Причины (код `provider-claude`):

- Нативный хост параметров (M27–M30, `pty/parameter-engine.ts`) читает каталог моделей и меняет
  параметры, набирая `/model` в терминале. Каталог этой версии CLI (2.1.328) не прочитан
  (`models: []`), поэтому чтение повторяется (`DISCOVERY_TRIES = 3` на ключ, раз в 30 с, заново
  после каждого запуска хоста). Меню живёт до `expires` (55 с).
- Сообщение десктопа (Remote Control) хост не видит: оно ждёт, пока меню закроется.
- Сообщение панели отменяет транзакцию (`yieldToUser`, до 2 с на уборку), но уборка срабатывает,
  только если поле ввода равно команде (`f.input === this.command`) или кадр — меню, которое
  хост отправил. Иначе транзакция заканчивается с `unsafe` и набранной командой в поле, а
  `sendDirect` всё равно вставляет текст и жмёт Enter: текст уходит в меню или вслед за `/model`.
- `sendDirect` считает сообщение доставленным, как только скрипт забрал файл `.text`
  (`MESSAGE_SENT`); начался ли ход (хук `UserPromptSubmit` с этим текстом), никто не проверяет.
- Режим «мигает»: пожелание панели (`wanted`) остаётся после отмены «без повтора», хотя Claude
  уже в нужном режиме (`mode: auto`).
- Карточка «Подтвердить выпуск» строится только из итога хода автопилота сессии
  (`plan-cards.js`: `last.reason === 'delivery-confirmation'`); при выключенном автопилоте сессии
  (`autopilot.ts`: `!entry.enabled` → `release`) карточки нет, хотя Kit ждёт решения.

## 2. Принципы

- Терминал Claude — общий для десктопа, iPad и панели. Хост панели пишет в него только при
  свободном терминале с пустым полем ввода и всегда возвращает его в такое состояние.
- Сообщение пользователя не теряется молча: либо доставлено (подтверждено хуком), либо панель
  показывает «не доставлено» с причиной, а текст остаётся в поле ввода панели.
- Решение пользователя видно в панели всегда, когда Kit его ждёт, независимо от автопилота.

## 3. Решение

### 3.1. Нативный хост параметров (`provider-claude`: `pty/parameter-engine.ts`, хосты)

- Уборка после отмены: меню, открытое хостом (`model`, `effort`, `fast`, `switch`, а также кадр
  `dialog` сразу после набранной им команды), закрывается Escape; поле, которое начинается с
  набранной хостом команды, очищается. Транзакция заканчивается, только когда кадр `idle` и поле
  пусто, или после трёх попыток уборки — тогда `unsafe` и строка журнала службы.
- Сообщение Remote Control: хост читает лог Claude (`--debug-file`, путь у хоста уже есть) и при
  строке `[bridge:repl] Ingress message type=user` отменяет транзакцию как ввод пользователя
  (`userInput`). Меню хоста без шага дольше 10 с закрывается (запасной путь, если формат лога
  изменится).
- Чтение каталога: неудача на той же версии CLI и модели не повторяется после рестарта хоста
  (ключ неудачи в файле каталога); панель показывает выбор без каталога, как сейчас.
- Пожелание параметра, которое уже действует (значение Claude равно пожеланию), снимается после
  любой отмены: режим не мигает.

### 3.2. Доставка сообщения панели (`provider-claude/direct.ts`, `agent-channel`, `cli`)

- Перед записью `.text` — состояние хоста: не `idle` или поле не пустое → не вставлять; сообщение
  идёт в очередь канала (как для занятой сессии) и доставляется хуком.
- После `MESSAGE_SENT` маршрут `POST …/sessions/:sid/message` ждёт хук `UserPromptSubmit` этой
  сессии с тем же текстом до 8 с. Есть — `{ sent: true }`. Нет — `{ sent: false, undelivered:
  { reason } }`, строка журнала службы; канал не помечает сессию `working`.

### 3.3. Панель (`session-chat`, `session-view`)

- Ответ `undelivered`: под полем ввода «Сообщение не дошло до Claude: <причина>», текст остаётся
  в поле, кнопка «Повторить»; рядом — «Стоп» (Escape), если терминал занят.
- Карточка «Подтвердить выпуск» в проекте `decisions: host`: следующая задача плана — поставка
  в TODO, а живого разрешения запуска на неё нет (сводка `autopiloting`), — карточка есть при
  любом состоянии автопилота сессии. То же условие для владельца плана, что и сейчас.

## 4. Поведение на ОС

| Что | macOS | Linux | Windows |
| --- | --- | --- | --- |
| Хост параметров | `session.exp` + Node-хост, общий `parameter-engine.ts` | то же | `pty/host.ts` + ConPTY (`win-host.ts`), тот же `parameter-engine.ts` |
| Лог Claude для Ingress | файл `--debug-file`, чтение Node | то же | то же; пути через `path`, CRLF в логе допустим |
| Ожидание хука после вставки | служба, общий код | то же | то же |
| Панель | общий ES-код | то же | то же |

Новых программ ОС нет. Чтение лога — тот же файл, что хост уже передаёт Claude; ветки ОС нет.

## 5. Проверка

- `provider-claude`: движок параметров на записанных кадрах — уборка меню и набранной команды
  после отмены (`dialog`, непустое поле), отмена по строке Ingress, предел 10 с, каталог без
  повторов после рестарта, снятие действующего пожелания; `direct.ts` — отказ вставлять в занятый
  терминал. Ветки `win32` и `linux` — с подставленной платформой.
- `agent-channel`/`cli`: маршрут сообщения — подтверждение хуком, `undelivered` через 8 с,
  очередь при занятом терминале.
- `session-chat`/`session-view`: модель «не доставлено» с «Повторить»; карточка поставки без
  автопилота сессии.
- CI: macOS ARM64, Linux x64, Windows x64 и ARM64 для точного SHA на
  `ci/M45-claude-terminal-delivery`.
- Живая проверка (macOS — пользователь): после возобновления сессии из панели сообщения панели и
  десктопа доходят сразу; смена режима не мигает; поставка без автопилота показывает карточку.
  Windows — проверяющий (сообщения панели в сессии `win-host`); Linux — CI.

## 6. Границы

- Не входит: медленный хук SessionStart на macOS CI (1,9 с при лимите теста 2 с) — причина не
  установлена, локально 0,5 с; отдельное измерение. Причина, по которой CLI 2.1.328 не отдаёт
  каталог моделей, — отдельная задача M30-линии; здесь только без повторов.
- Не входит: перехват сообщений десктопа или изменение Remote Control Claude.

## Уточнения реализации

- **T001, уборка (19.11.2026).** Расширенная уборка из 3.1 (Escape любому кадру `dialog` после своей
  команды, очистка поля по префиксу команды) нарушила бы правила M28, которые охраняют тесты
  `parameter-engine.test.ts`: чужой черновик `/model foreign draft` не стирается, чужой диалог
  разрешений и чужое меню не получают Escape. Уборка осталась прежней (своё меню того же вида,
  ровно своя команда), добавлены предел в три клавиши и ожидание не дольше 1 с. Защиту от потери
  текста даёт удержание: `yieldToUser()` не отдаёт `.text`, пока терминал `unsafe` с непустым полем
  (до 10 с), а затем `sendDirect` отдаёт сообщение очереди (T002). Плюс пауза 3 с после ввода
  пользователя (`INPUT_QUIET_MS`). Подробно — `provider-claude/native-parameters.md`, «Уступка
  терминала (M45/T001)».
