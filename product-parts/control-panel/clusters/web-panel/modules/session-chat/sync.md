# session-chat: состояние чтения ленты и восстановление (M32)

Часть контракта [module.md](module.md). Спецификация — `docs/planning/M32-codex-connection.md`,
разделы 2.6–2.8; поле `sync` и коды 503 — `provider-registry` (`chat.md` того модуля).

## Модель (`src/chat-model.js`)

- `syncView(sync, hadFull)` → `{ state, error, replace, full }`:
  - нет `sync` (Claude, Kimi) или `ready` — обе строки скрыты, страница заменяет ленту;
  - `loading` — строка состояния `SYNC_LOADING_TEXT` («Загружаем диалог…»); страница заменяет
    ленту, только пока полного снимка ещё не было (`hadFull = false`): идущий проход не
    подменяет показанный полный снимок частью истории;
  - `partial` или `gaps` — строка состояния с `reason` (нет — `SYNC_PARTIAL_TEXT`), новые
    сообщения приходят;
  - `reconnecting` / `unavailable` — служба отдаёт полный последний снимок; `reason`
    (нет — `RECONNECTING_TEXT` / `UNAVAILABLE_TEXT`) — в строке ошибки.
- `errorText(error)`: для `TRANSIENT_CODES` (`codex-reconnecting`, `codex-unavailable`, HTTP 503
  без снимка) — собственная строка службы без подсказки; остальные ошибки — как раньше.
- 30 секунд считает служба: `unavailable` и его текст приходят от неё, общий для всех вкладок.

## Карточка (`src/session-chat.js`)

- Над лентой — строка состояния `.sc-state` (`role=status`, приглушённая), под лентой — строка
  ошибки `.sc-error`. Других строк нет: служебные строки под вводом (`.sc-status`, M28) не
  появляются, успех восстановления сообщения не показывает — строки просто скрываются.
- Ошибка чтения (502, 503, сеть) оставляет узлы сообщений, пузыри очереди, черновик, фокус и
  прокрутку; лента без снимка остаётся пустой. Повторную отправку карточка не делает: опрос —
  только `GET …/messages` раз в 3 с.
- Восстановление — тем же опросом, без перезагрузки страницы; полный снимок заменяет ленту по
  `id` с сохранением неизменённых узлов.
- Параметры (M28/M29) не меняются: фоновый `GET` параметров при ошибке тих и сохраняет
  последние подтверждённые значения, `POST` не повторяется, ошибки действий пользователя и
  `FAILURE_SHOW_MS` прежние ([parameters.md](parameters.md)).

## Проверки

- `test/chat-model.test.ts` — `syncView` для всех состояний, ответы без `sync`, `errorText` 503.
- `test/m32-recovery.browser.js` — настоящий слот на сервере исходников :48762 (запуск —
  `test/run-browser.mjs`, глобальный Playwright с Chromium): 503 без снимка, `ready`,
  `reconnecting` и 503 со снимком, `unavailable`, `loading` поверх полного снимка, `partial` с
  новым ответом, снова `ready`; на каждом шаге — черновик, фокус, прокрутка, пузырь очереди,
  узлы сообщений, нет строк под вводом и запросов `POST`. Темы светлая и тёмная, ширина
  375/768/1280. Регрессия — `test/m28-composer.browser.js` для Claude, Codex и Kimi.
