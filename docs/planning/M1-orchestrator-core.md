# Веха 1 — ядро оркестратора

Статус: спецификация scope `m1-orchestrator-core` (после ревью архитектуры и
плана). Провайдеры и их проверенные факты — [M1-providers.md](M1-providers.md).
Временные документы (`docs/planning/**`): после приёмки вехи (`accept`)
действующее содержание переносится в `docs/architecture/**`, документы
удаляются. В DOCS раунда они не удаляются: на них опирается задача выпуска.

## 1. Цель

Workflow Kit — оркестратор поверх родных приложений Claude и ChatGPT/Codex,
без своего чата. Веха 1 переносит сквозной путь прототипа на настоящую основу:
бэкенд-служба (установщик, автозапуск, любая ОС), проекты, собственная
структура Kit в папке, провайдеры Claude и Codex с общим контрактом,
веб-панель для Mac и iPad. Каждая задача даёт видимый в панели результат
(раздел 12); веха принимается визуально на Mac и iPad (раздел 11).

## 2. Границы

Входит: бэкенд, установщик и автозапуск (macOS, Linux, Windows), запускатель
`wfk` и значок «Workflow Kit», реестр проектов, структура Kit v1,
предпросмотр доверия (что будет записано и какие точки автозапуска уже есть в
папке), провайдеры Claude и Codex, панель с карточкой «Система».

Не входит: сканер доверия с согласием по каждому риску, раскладка окон,
авторизация панели вне Tailscale, перенос процесса Workflow Kit (план,
команды), приёмка на настоящих Windows и Linux (раздел 3, D4).

## 3. Решения

- D1. Проект независим от harness-ai: структура, шаблоны и установщик пишутся
  здесь заново. Код прототипа не копируется, берутся проверенные приёмы.
- D2. Node 24, TypeScript исполняется напрямую (type stripping;
  `erasableSyntaxOnly`, `verbatimModuleSyntax`, импорты с `.ts`). Точка входа
  `bin/wfk.mjs` сначала проверяет версию Node, затем загружает
  модуль `cli` (раздел 4). Runtime-зависимостей нет. Dev: `typescript`,
  `@types/node`; тесты `node --test "product-parts/**/test/*.test.ts"`. JS панели
  проверяется через JSDoc и `checkJs`.
- D3. Панель — статические HTML/CSS/ES-модули без сборки; опрос `/api/state`
  раз в 3 с.
- D4. Возможности провайдера и службы зависят от ОС, версии CLI, входа и
  наличия `expect`; панель показывает недоступное с причиной. Матрица ОС:

| Возможность | macOS | Linux | Windows |
| --- | --- | --- | --- |
| Бэкенд, панель, проекты, структура | да | да | да |
| Автозапуск | LaunchAgent | systemd user или XDG autostart | ключ `HKCU\…\Run` |
| Claude: доверие, сессии, окружение (pty) | да | если есть `expect` | нет (Q1) |
| Codex: демон, доверие, хуки, сессии | да | да | нет (Q2) |
| Проверено на устройстве в вехе 1 | да | нет | нет |

- D5. Процессы сессий и окружений Claude отделены от службы (своя группа,
  вывод в файл, без переменных `CLAUDE*`) и переживают её перезапуск.
- D6. Сессии регистрирует хук SessionStart обоих провайдеров (раздел 7);
  итоговый список строит сам провайдер из журнала хука и своих записей.
- D7. Записи в чужие конфиги — только по кнопке, после предпросмотра, с
  копией файла до и проверкой после. Предпросмотр выдаёт токен; запись
  принимает только этот токен (защита от подмены между показом и записью).
- D8. Сеть: служба слушает все интерфейсы и принимает запрос, только если и
  адрес клиента, и локальный адрес сокета — loopback или Tailscale
  (`100.64.0.0/10`, `fd7a:115c:a1e0::/48`). Заголовок `Host` — из списка
  (`127.0.0.1`, `localhost`, адреса и MagicDNS-имя Tailscale, найденные по
  интерфейсам); `Origin` изменяющих запросов совпадает с `Host`, тело —
  JSON. Остальное — 403. Секреты в URL не кладутся.
- D9. Процессы — только по своим записям: pid, время старта, командная строка,
  boot id. Перед сигналом всё сверяется; остановка — TERM, ожидание, проверка,
  KILL. `expect` сообщает pid дочернего `claude`. Никаких `pkill` по шаблону.
- D10. Свои JSON пишутся атомарно (tmp + rename). Действия над проектом и
  провайдером идут под мьютексом; долгие действия (доверие, сессия, демон) —
  операции: POST сразу отдаёт `operationId`, ход виден в `/api/state`,
  кнопка заблокирована, повторное нажатие не запускает второе действие.
- D11. Опрос только читает: статусы берутся из файлов и кэша (mtime, TTL);
  внешние программы (`--version`, `app-server`) — при старте и по кнопке
  «Обновить», не на каждый опрос.
- D12. Окружение службы: `install` сохраняет в `config.json` абсолютные пути
  к `node`, `claude`, `codex`, `expect` и PATH login-shell; служба передаёт
  этот PATH дочерним процессам. Карточка «Система» показывает найденные пути.

## 4. Модули и файлы

Кодовая база устроена как в Harness AI: части продукта → кластеры → модули.
Модуль — каталог
`product-parts/<part>/clusters/<cluster>/modules/<module>/` с `module.md`
(контракт модуля), `src/` (код) и `test/` (тесты `*.test.ts`). У части —
`product-part.md`, у кластера — `cluster.md`. Контракт модуля меняется в том
же коммите, что и `src/**` модуля; точка входа `bin/wfk.mjs` относится к
модулю `cli`. Модули обращаются друг к другу только через `src/index.ts`
модуля (импорт через `#`-алиасы поля `imports` в `package.json`). Лимит
файла — 400 строк.

| Часть / кластер | Модуль | Обязанность |
| --- | --- | --- |
| `backend-core` / `runtime` | `cli` | `bin/wfk.mjs`; команды `serve`, `open`, `install`, `uninstall`, `service start/stop/status`, `doctor`, `link`, `hook` |
| `backend-core` / `runtime` | `data-store` | каталоги по ОС, конфиг, атомарная запись, журнал событий, мьютексы, операции |
| `backend-core` / `http-api` | `http-server` | HTTP, фильтр доступа, реестр маршрутов, раздача панели |
| `backend-core` / `projects` | `project-registry` | реестр проектов, проверка путей и имён, выбор папки |
| `backend-core` / `projects` | `kit-structure` | шаблоны, установка и проверка структуры, приём хука |
| `provider-runtime` / `provider-contract` | `provider-registry` | контракт, реестр провайдеров, журнал хука, маршруты провайдеров |
| `provider-runtime` / `provider-contract` | `process-supervisor` | запуск, учёт и остановка процессов (D5, D9) |
| `provider-runtime` / `provider-adapters` | `provider-claude`, `provider-codex` | провайдеры ([M1-providers.md](M1-providers.md)) |
| `control-panel` / `web-panel` | `panel-shell` | каркас панели, «Система», проекты, структура |
| `control-panel` / `web-panel` | `provider-cards` | карточки провайдеров из контракта |
| `system-service` / `deployment` | `service-installer` | развёртывание, автозапуск, запускатель и значок, статус службы |

Внешние программы вызываются через внедряемый исполнитель; тесты идут на
подставных программах, подставном HOME и переопределённых `WFK_DATA_DIR`,
`WFK_PORT` и никогда не трогают настоящие `~/Library/LaunchAgents`,
`~/.claude.json`, `~/.codex`.

## 6. Данные

- Конфиг и реестр: macOS `~/Library/Application Support/Workflow Kit`, Linux
  `$XDG_CONFIG_HOME/workflow-kit`, Windows `%LOCALAPPDATA%\Workflow Kit`.
  Состояние и журналы (Linux `$XDG_STATE_HOME/workflow-kit`), приложение
  (Linux `$XDG_DATA_HOME/workflow-kit`); на macOS и Windows — в том же
  каталоге. Переопределение: `WFK_DATA_DIR` (тесты, dev-экземпляр рядом со
  службой).
- Файлы: `config.json` (порт 4747, корень новых проектов
  `~/WorkflowKitProjects`, пути программ), `projects.json`,
  `events.jsonl` (ротация по 5 МБ), `sessions/claude.json` и
  `sessions/codex.json` (записи панели), `logs/` (служба, журналы pty и
  debug сессий), `backups/` (копии чужих конфигов, последние 10 на файл),
  `app/` (раздел 9). Права каталога 0700, файлов 0600.
- Пути проектов — внутри домашней папки по `realpath` (на Windows без учёта
  регистра). Имя проекта: без `/`, `\`, `..`, ведущего `-`, зарезервированных
  имён Windows; Unicode в NFC. Выбор папки — списком; ошибку доступа macOS
  (TCC, например `~/Documents`) панель показывает с подсказкой.

## 7. Структура Kit в папке проекта (v1)

- `AGENTS.md` — свой раздел между `<!-- wfk:begin -->` и `<!-- wfk:end -->`.
  Чужие разделы (например, `workflow-kit:begin` Harness) и текст вне своих
  маркеров не трогаются. `CLAUDE.md` с `@AGENTS.md` создаётся, если файла
  нет; если есть без `@AGENTS.md` — предупреждение.
- Хук SessionStart: в `.claude/settings.json` и `.codex/hooks.json`
  дописывается команда, не зависящая от машины:
  `[ -x "$HOME/.local/bin/wfk" ] && "$HOME/.local/bin/wfk" hook session-start --client <claude|codex>; exit 0`.
  Запись Codex добавляется только в конец списка (одобрение позиционное).
  Логика — в бэкенде (`wfk hook`): ничего не печатает в stdout, папку
  проекта берёт из `$CLAUDE_PROJECT_DIR` или ищет вверх от `cwd`, дописывает
  одну строку в `.workflow-kit/local/sessions.jsonl` (`client`,
  `session_id`, `transcript_path`, `cwd`, `source`, `model`,
  `permission_mode`, служебная метка `WFK_SERVICE_SESSION`, время), всегда
  выходит с кодом 0 за 2 с.
- Соглашение об архитектуре: раздел Kit в `AGENTS.md` описывает дерево
  `product-parts/<part>/clusters/<cluster>/modules/<module>/` (`module.md`,
  `src/`, `test/`; `cluster.md`, `product-part.md`; связи модулей только
  через публичный вход модуля; контракт модуля меняется вместе с кодом).
  Установка создаёт `product-parts/README.md` (соглашение кратко), если
  каталога нет, и шаблоны `.workflow-kit/templates/product-part.md`,
  `cluster.md`, `module.md` (разделы: назначение, публичный интерфейс,
  инварианты, зависимости). Существующий код не переносится.
- `.workflow-kit/manifest.json` — версия и sha256 управляемых фрагментов:
  текст своего раздела, нормализованная запись хука, свои файлы целиком.
  `.workflow-kit/local/` добавляется в `.gitignore` своим блоком.
- Проверка: `ok`, `missing`, `modified`, `outdated`, `newer`; невалидный
  JSON — отказ без перезаписи. Установка идемпотентна; изменённое
  пользователем без явного запроса не перезаписывается.

## 9. Установщик, запуск и автозапуск

- `node bin/wfk.mjs install` (из клона репозитория при Node 24):
  копирует `bin`, `product-parts`, `package.json` в `app/<версия>/`, записывает
  `app/current.json` (без симлинков), сохраняет пути программ (D12), ставит
  запускатель `wfk` (`~/.local/bin/wfk`; Windows — `wfk.cmd` в каталоге
  данных и PATH пользователя), значок «Workflow Kit» (macOS
  `~/Applications/Workflow Kit.app`, Windows — ярлык в «Пуске», Linux —
  `.desktop`), регистрирует автозапуск и запускает службу. Повтор обновляет
  версию; `uninstall` снимает автозапуск, запускатель и значок, данные
  остаются. `wfk link` ставит запускатель на текущий клон (разработка).
- Автозапуск после входа пользователя (связке ключей Claude и Codex нужен
  вход; при FileVault панель недоступна до входа):
  macOS — LaunchAgent `ai.workflowkit.backend` (`RunAtLoad`, `KeepAlive`,
  `AbandonProcessGroup`, PATH из D12, абсолютный node); Linux — systemd user
  unit с `KillMode=process`, без systemd — XDG autostart; Windows — ключ
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, скрытое окно, без
  прав администратора.
- Старт при запуске интерфейса: значок и `wfk open` проверяют
  `/api/health`; если бэкенд молчит — запускают службу, ждут готовности и
  открывают панель в окне приложения (Chrome/Edge `--app=`, иначе браузер).
- `wfk doctor --installed` — проверка установленной службы (для выпуска).

## 10. HTTP API

- `GET /api/health`; `GET /api/state` — проекты, провайдеры, операции,
  «Система» (служба, автозапуск, пути, каталог данных, версии, события).
- `GET /api/folders?path=`; `POST /api/projects` `{name}`;
  `POST /api/projects/open` `{path}`; `DELETE /api/projects/:id` —
  только из списка; при живых сессиях или окружении — отказ со списком.
- `GET|POST /api/projects/:id/structure`.
- `GET /api/projects/:id/providers/:p/trust/preview`,
  `POST .../trust` `{token}`, `POST .../hooks/approve` `{command, hash}`.
- `POST .../sessions`, `.../sessions/:sid/resume`, `.../sessions/:sid/stop`.
- `POST /api/providers/:p/actions/:a`, `POST .../providers/:p/actions/:a`
  (проектные), `POST /api/refresh`. Долгие POST отдают `operationId` (D10).

## 11. Визуальная приёмка вехи

На Mac после `install`, перезагрузки и входа; на iPad — по адресу Tailscale:

1. Значок «Workflow Kit» открывает панель в окне приложения; «Система»:
   служба работает, автозапуск зарегистрирован, пути программ найдены.
2. Создать проект; открыть существующую папку выбором из списка.
3. Структура: «нет» → «Установить» → «ok»; правка `AGENTS.md` вне раздела
   Kit — «ok», внутри — «modified»; раздел Harness в `AGENTS.md` цел.
4. Claude: предпросмотр доверия → «Доверять» → «доверено»; «Создать сессию»
   → открывается в Claude Desktop (Mac) и в приложении Claude (iPad).
5. Codex: статус демона; доверие с предпросмотром; «Одобрить хук» с
   командой и хешем; «Создать сессию» → открывается в ChatGPT на Mac и iPad.
6. Сессия, начатая в родном приложении (iPad), появляется в списке.
7. `wfk service stop` + значок — служба поднимается; сессия Claude после
   перезапуска службы жива.
