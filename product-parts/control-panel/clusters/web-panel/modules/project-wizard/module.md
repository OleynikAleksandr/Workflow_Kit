# Модуль: project-wizard

Часть `control-panel`, кластер `web-panel`. Алиас импорта: `#project-wizard`.

## Назначение

Мастер проекта в панели (спецификация вехи 2, раздел 7; макет, шаги 3–5):
имя или папка → предпросмотр с действиями, хуками, изменениями и выборами →
«Создать и открыть в <провайдер>» — по кнопке на каждого провайдера реестра
(одно согласие) → шаги подготовки с
«Отменить подготовку» → чат первой сессии открывается сам на том
устройстве, где нажата кнопка.

## Публичный интерфейс для бэкенда (`src/index.ts`)

- `PROJECT_WIZARD_PREFIX` — `/project-wizard/`.
- `PROJECT_WIZARD_ASSETS_DIR` — абсолютный путь к `src/`.
- `projectWizardMount() → { prefix, dir }` — монтирование для
  `http-server` (подключает `cli`, `createApp`).

## Подключение к панели

`project-wizard.js` — расширение панели (`PANEL_EXTENSIONS` в
`panel-shell`): `install(shell)` заполняет слот `newProject`
(`registerSlot`); маршруты `#/new` и `#/open` показывают мастер. Из
оболочки берутся `api`, `ApiError`, `createFolderPicker`, `showError`,
`dom`. Стили — `project-wizard.css`.

## Файлы

| Файл | Содержание |
| --- | --- |
| `wizard-model.js` | чистые модели: `previewView(preview, now)` (заголовок, путь, действия, хуки `hooks` — заголовок «Хук Kit для <имя>», файлы записи, добавляемый текст или команда, короткий хеш, заметка; «Изменения в папке · N файлов», блокировка с командами, заметки, истёк ли токен), `choiceViews`, `validAnswers` (ответы только из вариантов), `buttonViews` (кнопка на каждый элемент `preview.providers` в его порядке: имя из `label`, буква из `mark`; выключены с причиной: блокировка, провайдер недоступен, нет ответа на обязательный выбор), `providerActionViews(state, buttons)` (включённые действия `scope: 'provider'` раздела `providers`: `primary` — у провайдеров с выключенной кнопкой, `more` — у остальных), `actionsKey(state)`, `findRun`, `runView` (заголовок, `providerLabel` из записи запуска, шаги с отметками ✓ / спиннер / ○ / – / ✕ и заметками, `canCancel`, ошибка с подсказкой и `errorCode`, ключ и id созданной сессии `session`), `listedSessionKey(state, projectId, session)` (ключ сессии запуска в дереве или `null`), `chatTarget(links, maxTouchPoints)` (ссылка устройства: http(s) — в новой вкладке, ссылка приложения — на месте), `filesLabel`, `STEP_MARKS`; своего списка провайдеров в модуле нет |
| `project-wizard.js` | DOM мастера: шаг имени (`POST /api/setup/preview { mode: 'create', name }`, «Изменить расположение папки для проектов» ведёт в «Настройки») или выбор папки (`{ mode: 'open', path }`); предпросмотр с выборами (переключатели), хуками (текст и хеш, которые одобряет согласие) и кнопками провайдеров (`POST /api/setup/apply { token, provider, choices }`; устаревший предпросмотр перезапрашивается сам с пояснением); запуск, отклонённый с `hooks-changed` (хук изменился после предпросмотра и не одобрен), сам показывает новый предпросмотр папки (`{ mode: 'open', path }` — папка уже создана) с пояснением; «Повторить» после создания проекта тоже идёт через `open`; подготовка из раздела `setup` (`POST /api/setup/:op/cancel`, «Повторить», «Закрыть»); после успеха — чат открывается сам (ссылка https — в новой вкладке; ссылка приложения ChatGPT — вместе с сессией через `ctx.openSession`, M3-autostart R5), проект становится выбранным в дереве (`ctx.selectProject`), панель переходит к сессии, когда она появится (`ctx.openSession`, без него — `ctx.navigate`) — сессия ищется по `localId` или `remoteId` запуска и открывается под ключом из дерева (`listedSessionKey`: у Claude после хука `SessionStart` ключ — его собственный id, M7 замечание 1); кнопок «Открыть чат» и «Перейти к сессии» нет (решение пользователя 2026-11-06); действия уровня провайдера из раздела `providers` показаны у любого провайдера (только включённые): у выключенной кнопки — кнопками (например «Запустить демон» или «Подключить к ChatGPT» Codex), у готового провайдера — под «Действия провайдеров» (`POST /api/providers/:p/actions/:a`, через 3 с предпросмотр перечитывается; отказ `action-disabled` — действие уже не нужно — ошибкой не показывается, предпросмотр перечитывается); пока кнопка провайдера выключена, предпросмотр того же запроса перечитывается раз в 5 с (`PREVIEW_RECHECK_MS`) без сброса выборов, панель перерисовывается только при смене кнопок, хуков или действий |
| `project-wizard.css` | выборы, хуки предпросмотра, список файлов, отметки шагов |

## Инварианты

- Чистая логика в `wizard-model.js` без DOM; покрыта `node --test`.
- До нажатия кнопки ничего не пишется: предпросмотр только читает.
- Провайдеры, их имена и буквы мастер берёт из предпросмотра и раздела `providers`: новый
  провайдер реестра появляется в мастере без правки модуля.
- Текст в DOM — только через `textContent`.
- Каждый вход в мастер начинает с чистого листа: пустое имя, нет ответов, операции и флагов
  прошлого запуска (раунд R8).
- Переход к сессии проверяется при каждом состоянии, а не только при изменении записи подготовки:
  сессия может появиться в списке позже.
