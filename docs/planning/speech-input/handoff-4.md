## 17. Проверки, которые действительно нужны

Не писать тесты, зеркалящие каждую строку кода. Приоритет — потеря данных, порядок событий, реальные границы и интеграция.

### 17.1. Детерминированные тесты

| Область | Обязательные случаи |
|---|---|
| Протокол helper | Разбитый frame, объединённые frames, неверная длина, EOF, stderr не ломает stdout |
| Порядок потока | Feed до ready, Stop после последнего feed, double Stop, Cancel во время finalize |
| Владелец поля | Старый dictationId, события после dispose, переключение сессии |
| Текст | Замена tentative, отсутствие повторов committed, вставка в середину, исходное выделение, пустой результат |
| Ручные правки | Правка во время потока сохраняется, поздний final игнорируется |
| Отправка | Enter/queue/send guard при active speech, draftRevision защищает новый текст от старого ответа |
| Доступ | Чужой/отсутствующий Origin, неверный Host/порт, remote stream в локальном режиме |
| Модели | Неверный checksum, partial не считается installed, безопасное удаление, неподдерживаемая capability |
| Ресурсы | Crash helper, close соединения, shutdown, ограниченная очередь |

Mock helper пригоден для проверки UI/state machine. Он не доказывает поддержку реального streaming Voxtral.

### 17.2. Ручная приёмка на русском

Использовать несколько собственных фраз пользователя, например:

- «Создай отдельный модуль распознавания речи для Workflow Kit».
- «Версия один точка пятнадцать, порт восемь тысяч восемьсот восемьдесят».
- «Проверь файл package.json, затем открой GitHub и настройки macOS».
- Разговорная фраза с паузами, самокоррекцией и повтором.
- Русский текст с английскими названиями моделей и техническими терминами.

Проверить:

1. Запись 10–20 секунд: несколько изменений текста до Stop.
2. Запись около минуты: паузы и последняя фраза не теряются.
3. Запись 5 минут: отставание не накапливается.
4. Stop во время слова: поведение последнего фрагмента приемлемо.
5. Повторный start: новая диктовка добавляется в выбранное место.
6. Выделение части существующего текста: заменяется только оно.
7. Ручная правка/вставка: не стирается поздним результатом.
8. Переключение чата: чужой черновик не меняется.
9. Работающий агент: mic Stop не останавливает ответ агента.
10. Question card: ответ остаётся ответом на вопрос.
11. Отказ разрешения: понятное сообщение без зависшего состояния.
12. Отмена при системном запросе разрешения: поздно полученный микрофон освобождается.
13. Закрытие панели/службы: индикатор микрофона исчезает, worker завершается.
14. Смена модели: фактически используется новая модель.
15. Режим без сети после установки: распознавание продолжает работать.

Не предполагать, что речевые команды «точка», «новая строка» автоматически интерпретируются как управляющие команды редактора. Если нужна такая функция, это отдельный словарь/режим и отдельное требование.

### 17.3. Проверки репозитория

В исследованном package.json есть:

    npm run typecheck
    npm run test:app
    npm run test:kit
    npm run check:platforms

Запускать применимые команды после проверки актуальных скриптов и требований AGENTS.md. Проверки сборки Rust/helper добавить отдельно. В рамках подготовки этого документа эти проверки не выполнялись: код не менялся.

Не запускать длительные полные тесты повторно без причины. Сначала targeted tests, затем обязательные общие проверки.

### 17.4. Что приложить к результату реализации

- версия macOS и архитектура Mac;
- способ запуска UI и версия браузера/оболочки;

- фактический compute backend;
- холодный/тёплый start, задержка текста, время finalize;

## 18. Критерии готовности

Первая версия готова, когда одновременно выполнены условия:

- [ ] На поддерживаемом Mac можно скачать модель из интерфейса Kit.
- [ ] Установка Handy отдельно не требуется.
- [ ] Выбор модели сохраняется после перезапуска.
- [ ] Микрофон начинает и прекращает диктовку повторным нажатием.
- [ ] Текст появляется в поле до Stop.
- [ ] Stop завершает хвост и оставляет редактируемый черновик.
- [ ] Диктовка не отправляет сообщение.
- [ ] Все пути отправки учитывают active/finalizing speech.
- [ ] Агентский Stop работает независимо.
- [ ] Ручные правки и текст другого диалога не перезаписываются.
- [ ] Есть обработка permission denied, ошибки модели и падения helper.
- [ ] После остановки освобождается микрофон.
- [ ] Нет неограниченной очереди аудио и скрытого batch fallback.
- [ ] Проверена русская речь и техническая смешанная лексика.
- [ ] Windows/Linux и мобильный UI не ломаются.
- [ ] Веса/записи не попадают в репозиторий.
- [ ] Лицензии и происхождение donor-кода документированы.
- [ ] Пользователь запускает поставку без среды разработки Rust/Python.
- [ ] Поддерживаемые архитектуры Mac указаны честно.

## 22. Краткая постановка для новой сессии

> Изучи этот документ и актуальные инструкции Workflow Kit. Подготовь отдельную спецификацию и план модуля диктовки для macOS, используя Handy как донора и Voxtral Mini 4B Realtime как основной движок. Сначала подтверди нативный поток на выбранном Mac, затем подключай его к существующему composer и управлению моделями. Сохрани поведение «микрофон — начало / микрофон — остановка», появление текста во время речи и отдельную ручную отправку. Не переноси целиком Tauri/React-приложение, не используй системный paste, не меняй чужую задачу и не обещай real-time без измерения. Руководствуйся текущим поручением пользователя относительно перехода от плана к реализации.
