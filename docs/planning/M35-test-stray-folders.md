# M35: тест порога автосжатия не оставляет папок в корне проекта

## Цель и согласование

После каждого запуска `npm test` на macOS и Linux в корне репозитория появляются три пустые
папки с именами вида `\var\folders\…\wfk-acw-XXXXXX\data`, `…\data\backups` и
`…\data\logs`. Их создаёт вариант `win32` теста
`product-parts/backend-core/clusters/runtime/modules/cli/test/auto-compact-context.test.ts`.
Папки пустые, поэтому git их не видит, но они засоряют корень проекта и копятся с каждым
запуском. После M35 тесты не оставляют в корне ничего, а этот случай ловит отдельная
проверка.

Пользователь, 15.11.2026: «Можешь их удалить?» — 267 пустых папок удалены из корня. Затем:
«Можешь поправить тест?» и «без ревьювера, готов спецификацию, план, выполняй вплоть до
сборки нового релиза и публикации его на GitHub».

## 1. Факты

- **[проверено]** В корне было 267 пустых папок: 89 запусков по три (`data`, `data\backups`,
  `data\logs`), ни одного файла, других имён с `\var` нет. Удалены 15.11.2026 (`rmdir`).
- **[проверено]** Источник — вариант `win32` теста `auto-compact-context.test.ts` на macOS и
  Linux. Тест передаёт службе `WFK_DATA_DIR = path.join(tmp, 'data')` — путь POSIX из
  `os.tmpdir()` — и подставляет `platform: 'win32'`. `resolveDataDirs` (`data-store`) для
  `win32` берёт `path.win32.resolve`, и путь превращается в
  `\var\folders\…\wfk-acw-XXXXXX\data`. `ensureDataDirs` создаёт папки с такими именами
  относительно текущей папки процесса тестов, то есть корня репозитория. Блок `finally`
  удаляет только настоящую временную папку.
- **[проверено]** `path.win32.resolve('/var/folders/ab/T/wfk-acw-x/data')` в Node 24 даёт
  `\var\folders\ab\T\wfk-acw-x\data`.
- Вне Windows вариант `win32` уже проверяет только одно утверждение и выходит раньше
  (`if (platform === 'win32' && process.platform !== 'win32') return;`): чтение путей Windows
  проверяется по-настоящему только в CI на Windows.
- Ветка `win32` функции `resolveAutoCompactWindow` проверяется на всех ОС в
  `auto-compact-window.test.ts` с подставленной платформой и подставленным чтением файлов.
- Другие тесты, вызывающие `createApp`, не подставляют чужую платформу вместе с настоящей
  папкой данных: других папок такого вида в корне не было.

## 2. Решение

### 2.1. Тест (`cli/test/auto-compact-context.test.ts`)

- Каждый вариант выполняется только на своём семействе ОС: `win32` — только на Windows,
  `darwin` и `linux` — только вне Windows (симметричный `skipOn`). Причина пропуска называет
  пути: варианту `win32` вне Windows — «Windows paths of a POSIX temp folder»,
  `darwin`/`linux` на Windows — «POSIX paths of a Windows temp folder», как сейчас.
- Ранний выход варианта `win32` вне Windows удаляется: он больше не нужен. На Windows вариант
  `win32` выполняет все утверждения, как и сейчас.
- Защита от повтора: тест в том же файле после вариантов проверяет, что в текущей папке
  процесса нет ни одной записи с `wfk-acw-` в имени. Проверка не зависит от ОС. Если
  пропуск снова уберут, проверка упадёт на macOS и Linux.

### 2.2. Код продукта

Не меняется. `resolveDataDirs` правильно работает на своей платформе: служба никогда не
запускается с чужой платформой. Контракты `data-store` и `cli` не меняются.

## 3. Поведение на ОС

| Что | macOS | Linux | Windows |
| --- | --- | --- | --- |
| Вариант `darwin` | выполняется | выполняется | пропущен, как сейчас |
| Вариант `linux` | выполняется | выполняется | пропущен, как сейчас |
| Вариант `win32` | пропущен (было: выполнялся частично и оставлял папки в корне) | пропущен (так же) | выполняется полностью; x64 и ARM64 |
| Проверка «нет записей `wfk-acw-`» | выполняется | выполняется | выполняется; x64 и ARM64 |

Меняется только тест. Поведение службы на трёх ОС одинаково и не меняется, новых вызовов
программ ОС нет: `tools/platform-guard/allowlist.json`, `docs/architecture/OS-MATRIX.md` и
разделы ОС в `module.md` не меняются.

## 4. Проверка

- Автоматически: `npm run typecheck`, `npm run check:platforms`, `npm test`. После `npm test`
  на macOS в корне репозитория нет записей с `wfk-acw-` и с `\var` в имени (агент в T001 и
  ещё раз в поставке).
- CI: macOS, Linux, Windows x64 и ARM64 для точного SHA поставки. На Windows вариант `win32`
  выполняется полностью.
- Поставка 0.14.2: сборка Kit, установка, `wfk doctor --installed`, `/api/health` показывает
  0.14.2. Живая проверка в панели не нужна: код службы и панели не меняется.
- По ОС: macOS — агент (тесты и установка), приёмка — пользователь; Linux — CI; Windows — CI,
  проверяющий на Windows не нужен: меняется только тест.

## 5. Границы

- Общая проверка «тесты не оставляют записей в корне» для всех тестов (отдельный шаг после
  `npm test`) — не входит, отдельное решение.
- Поведение `resolveDataDirs` с чужой платформой не меняется.
- Остатки тестов во временной папке ОС (`os.tmpdir()`) не рассматриваются.
