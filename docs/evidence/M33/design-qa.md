# M33 T007: карточка вопроса агента — сверка дизайна

Спецификация — [M33](../../planning/M33-agent-questions.md), раздел 2.5. Эталон — карточка
вопроса Claude Desktop (снимок пользователя 15.11.2026, тёмная тема): заголовок-метка части,
текст вопроса, варианты с подписью и описанием, «Other» со своим текстом, кнопка «Submit»
справа внизу. Карточка Workflow Kit собрана в токенах панели (`--card`, `--card-line`,
`--active`, `--active-line`, `--teal`, `--input`, `--muted`, `--error`), без новых цветов.

## Прогон

15.11.2026, macOS, изолированный Chromium (Playwright), владеемый сервер исходников
`test/run-browser.mjs` (порт 48762), сценарий `test/m33-question.browser.js` на настоящем
расширении `session-chat` с подставной оболочкой: лента отдаёт страницу с вопросами, ответ
записывается и отвечает заданным режимом. Две конфигурации — по 26 проверок, обе зелёные:

| Конфигурация | Тема | Ширина | Клавиша отправки | Итог |
| --- | --- | --- | --- | --- |
| dark-wide | тёмная | 1280 | Ctrl+Enter | 26/26 |
| light-narrow | светлая | 390 (узкая, iPad/телефон) | ⌘+Enter | 26/26 |

Проверено:

- строка состояния «Агент ждёт вашего ответа»; ожидающий вопрос — последний в ленте, над полем
  ввода; закрытый — после своего сообщения, компактно: вопрос и доказанный ответ;
- «Отправить» выключена, пока у каждой части нет ответа; одно нажатие по варианту ничего не
  отправляет; кнопки «Пропустить» нет;
- радиокнопки (одна часть), флажки (`multiSelect`), «Свой вариант» заменяет выбор одной части;
- выбор переживает опрос ленты (3,4 с);
- сетевая ошибка — повтор с тем же `attemptId`; тело — ответ каждой части;
- `question-timeout` — кнопки нет, «Ответ отправлен, ждём подтверждения»; закрытие без
  `answers` — «Ответ отправлен. Какой ответ принят, провайдер не сообщил», выбор панели не
  подставлен;
- `question-invalid` — строка ошибки под карточкой, новая попытка той же кнопкой с новым
  `attemptId`; `question-stale` — сразу итог «Ответ дан в приложении»;
- неотвечаемый вопрос — варианты видны без выбора, причина и «Открыть чат провайдера»;
- сенсорные цели (варианты, «Отправить», поле своего текста) не меньше 44 px; без
  горизонтальной прокрутки; поле ввода диалога работает; ошибок страницы нет.

## Сверка с эталоном

| Элемент Claude Desktop | Карточка Workflow Kit |
| --- | --- |
| Метка части (header) | пилюля `sc-q-header` над текстом вопроса |
| Варианты с описанием | строки-метки 44 px с радиокнопкой или флажком, описание приглушённое |
| «Other» со своим текстом | «Свой вариант» и поле текста, видимое после выбора |
| «Submit» справа | «Отправить» справа; в узкой раскладке — во всю ширину |
| «Skip» | нет: у ответа нет контракта пропуска (раздел 5 спецификации) |
| Итог после ответа | компактная карточка: вопрос и ответ, «Ответ дан в приложении», «Вопрос отменён» |

Живой вид в Claude Desktop и ChatGPT рядом с панелью подтверждает пользователь в T008.

## T013: вопрос, на который отвечают сообщением

Асинхронный вопрос Codex (`reply: 'message'`, спецификация M33 раздел 2.7). Та же карточка, те же
токены; отличия: карточка стоит после своего сообщения агента (лента может идти дальше), метки
нет (у вопроса нет заголовка), строка «Агент ждёт вашего ответа» не появляется, после отправки —
«Ответ отправлен сообщением», закрытая — «Ответ дан сообщением», а сам ответ виден в ленте
сообщением пользователя.

(⌘+Enter) — 20/20, light 390 (Ctrl+Enter) — 20/20; сценарий T007 после изменений — 26/26 в

## Поведение на ОС

Карточка — общий ES-код панели; одинакова на macOS, Linux и Windows (x64, ARM64). Ctrl+Enter и
⌘+Enter работают на всех ОС. Браузерный прогон — macOS; Windows — проверяющий на Windows,
Linux — CI (модельные тесты).
