# M21: Пакет восстановления целиком за один ход (Claude и Codex)

## Цель и согласование

Агент новой сессии должен получать пакет восстановления Kit целиком вместе с первым
сообщением, без отдельных шагов чтения. Сейчас это не так:

- **Claude.** Вывод хука SessionStart длиннее 10 000 символов Claude Code уносит в файл,
  а агенту отдаёт превью ~2 КБ (`<persisted-output>`). В роли planning пакет весит около
  10 000 символов, поэтому агент видит только `state`, `next` и начало `schema`. Превью
  начинается с заголовка пакета, и агент по правилу AGENTS.md не вызывает `recover`.
- **Codex / ChatGPT.** Вывод хука длиннее ~10 000 байт Codex обрезает посередине
  (`…N tokens truncated…`). Кроме того, Kit сам подтверждает в Codex только свои хуки `wfk`,
  а хук Harness `scripts/workflow hook session-start --client codex` — нет. У пользователя
  без приложения Harness AI этот хук, по коду, остаётся неподтверждённым и не запускается.

Решения пользователя (2026-11-12):

- «Хорошо, пока ставим все как есть» — Kit остаётся отдельным проектом harness-ai, здесь
  лежит его бандл.
- «Для меня самым неприемлемым является необходимость пользователю что-то подтверждать… Либо
  мы умеем их подтверждать автоматически, либо надо искать какой-то другой способ.»
- «Давай исправим Claude и Codex, а с кими будем разбираться потом. Подготовь спецификацию и
  план для реализации этих исправлений в… Harness AI. И выполни и пересобери новый релиз…
  Harness AI, а потом и нашего Workflow Kit.»
- В панели выбраны спецификация и план без перекрёстного ревью.

## 1. Принципы

- Kit (Harness Workflow Kit) меняется в harness-ai своим scope; этот репозиторий получает
  новый бандл и меняет только свой код.
- Весь пакет приходит в контекст при старте сессии; ссылки на файлы и дочитывание —
  только запасной путь, о котором пакет говорит явно.
- Пользователь ничего не подтверждает: Claude подтверждений хуков не требует, хуки Codex
  подтверждает Kit тем же механизмом, что и сейчас (`hooks/list` → `config/value/write`).
- Ничего не теряется молча: неполный пакет говорит, что он неполный и что делать.
- Kimi в работу не входит: у Kimi нет хука Harness, SessionStart Kimi контекст не добавляет.

## 2. Проверенные факты (2026-11-12)

| Провайдер | Лимит вывода хука | Что проверено |
| --- | --- | --- |
| Claude Code 2.1.322 | 10 000 символов UTF-16 (`F$e = 1e4`) на **каждый** хук; длиннее — файл и превью ~2 КБ. Тот же порог у `initialUserMessage`. Настройки лимита нет. | 4 записи SessionStart: три по 9 900 символов кириллицы (18 241 байт) — модель увидела все три; 10 050 — только превью. Порядок частей в контексте не совпал с порядком записей. |
| Codex 0.167.2 | ~10 000 байт на **каждый** хук, середина вырезается, полный текст — в `$TMPDIR/hook_outputs/`. Подтверждение хуков Codex: Codex запускает проектный хук, только если в `~/.codex/config.toml`
записан `trusted_hash` его ключа `<файл>:<событие>:<группа>:<индекс>`. Хеш меняется при любом
изменении записи хука, ключ — при смене её позиции.

## 3. Решение

### 3.1 Kit 2.2.3 (harness-ai)

Выполняется в harness-ai отдельным scope по его правилам; документы Kit там —
`docs/architecture/workflow-kit/WorkflowKitRecovery.md` и `WorkflowKitInstallation.md`.

**Части пакета** (`workflow-recovery`, новый `recovery-parts.ts`):

- Пакет собирается как сейчас (`assemblePacket`), затем режется на части не длиннее
  9 500 единиц UTF-16 (`string.length`, как считает Claude Code), включая заголовок части.
- Резка по границам разделов `## `; раздел длиннее части режется по строкам, строка длиннее
  части — по символам без разрыва суррогатной пары.
- Первая строка каждой части:
  `# Workflow recovery packet — part K/N · revision R · head H · digest D`, где `D` — первые
  12 hex-символов SHA-256 полного текста пакета. Части с одинаковым `digest` — один пакет.
- Если пакету нужно больше N частей, часть N заканчивается строкой
  `Packet incomplete: it needs M parts, N delivered. Run \`scripts/workflow recover --format text\`.`

**Хук** (`workflow-kit-cli.ts`, `workflow-recovery-facade.ts`, `recovery-commands.ts`):

- `hook session-start --client claude --part K/N` (1 ≤ K ≤ N ≤ 16) выводит часть K. Если
  части K нет (пакет короче), ответ без `additionalContext`.
- Неверный `--part` — ответ без `additionalContext` и строка в stderr; код выхода 0, сессия
  не блокируется (как сейчас при ошибках).
- Без `--part` — весь пакет одной строкой, как в 2.2.2 (Codex и совместимость).
- `HARNESS_WORKFLOW_RECOVERY=host` работает как раньше: контекста нет.

**Установщик** (`installer-provider-hooks.ts`, inspect/doctor):

- Claude: N = 6 записей SessionStart подряд,
  `"$CLAUDE_PROJECT_DIR/scripts/workflow" hook session-start --client claude --part K/6`
  (до 57 000 символов). Все прежние группы Kit (метки `scripts/workflow` и
  `hook session-start`) заменяются, чужие хуки остаются на месте.
- Codex: одна запись, команда прежняя (`scripts/workflow hook session-start --client codex`),
  к записи добавляется `"additionalContextLimit": 65536`. Единицу поля (байты или токены)
  задача в harness-ai проверяет пакетом ~60 КБ и записывает в документ Kit.
- inspect и doctor сравнивают все группы Kit, а не первую (`extractSessionStartHook`).
- `install --update` проекта на 2.2.2 переписывает записи на новые.

**Управляемый раздел AGENTS.md:** вместо «Unless a workflow recovery packet is already in your
context» — «The recovery packet arrives at session start (Claude: in parts K/N). Unless the
whole packet is in your context — every part with one digest, no `<persisted-output>`, no
truncation marker — run `scripts/workflow recover --format text`.»

**Выпуск:** версия Kit 2.2.3, бандл `dist/workflow-kit/workflow.mjs`.

### 3.2 Workflow Kit (этот репозиторий)

**Подтверждение хука Harness в Codex** (`provider-codex`: `src/hooks.ts`, `src/trust.ts`):

- Константа `HARNESS_CODEX_HOOK_COMMAND = 'scripts/workflow hook session-start --client codex'`.
- `approveHooks` вместе с хуками Kit подтверждает хук SessionStart, чья команда точно равна
  этой константе, с хешем из свежего `hooks/list` (любые поля записи, в том числе
  `additionalContextLimit`, входят в хеш Codex и нового правила не требуют).
- Общий статус `kitHook` — `approved`, только когда подтверждены хуки Kit и хук Harness, если
  он есть в `.codex/hooks.json`. Хуки с другими командами по-прежнему не подтверждаются.
- Новых карточек, кнопок и текстов ошибок нет: подтверждение идёт тем же путём, что и сейчас.

**Бандл 2.2.3** (`kit-bundle`): `vendor/workflow-kit-2.2.3.mjs.gz` и `PROVENANCE` с коммитом
harness-ai; `KIT_VERSION`, `KIT_SHA256`, `KIT_SOURCE_COMMIT`; упоминания 2.2.2 в коде, тестах и
документах (предпросмотр «Kit старше 2.2.3 — Обновить процесс»). Проекты получают новые хуки
существующей кнопкой «Обновить процесс» (`install --update`).

## 5. Проверка

- harness-ai: тесты нарезки (каждая часть ≤ 9 500, склейка частей без заголовков равна пакету,
  пустые части без вывода, общий `digest`, большой раздел режется по строкам, строка
  «Packet incomplete» при нехватке частей), CLI `--part`, установщик (6 записей Claude,
  поле Codex, миграция с 2.2.2, чужие хуки на месте), inspect/doctor.
- Этот репозиторий: тесты `approveHooks` (хук Harness подтверждается вместе с хуками Kit,
  чужая команда — нет, статус `kitHook`), ветка `win32` для ключей с подставленной платформой;
  тесты бандла 2.2.3.
- CI: macOS, Linux, Windows x64 и ARM64.
- Живая проверка: macOS — пользователь (новая сессия Claude из панели: в транскрипте все части
  inline, агент называет `digest` и число частей без чтения файлов; новая сессия Codex из
  панели: пакет без «truncated output», без подтверждений); Windows — проверяющий на Windows;
  Linux — CI.
