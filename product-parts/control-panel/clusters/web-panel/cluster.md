# Кластер: control-panel / web-panel

## Назначение

Веб-панель по спецификации M24 (макет вехи 2 исторический по раскладке): изменяемая боковая панель (320 px по умолчанию, M24) (логотип, версия,
шестерёнка, строка подготовки, меню «Ваши проекты», дерево «проект →
сессии», место «Ревью плана», индикаторы связи) и экран справа (первый
запуск, новый проект, проект, сессия, архив, «Настройки»). Служебные
карточки — «Система», «Структура Kit», провайдеры — живут в «Настройках».

## Модули

| Модуль | Обязанность |
| --- | --- |
| [panel-shell](modules/panel-shell/module.md) | раскладка, маршруты, опрос состояния, дерево, экраны, «Настройки», реестр карточек, «Система», структура, экран «Домой» iPad |
| [project-wizard](modules/project-wizard/module.md) | мастер проекта: предпросмотр, одно согласие, подготовка, открытие чата |
| [session-view](modules/session-view/module.md) | экран сессии: активность агента, выбор пути, карточка плана, «Ревью плана» |
| [session-chat](modules/session-chat/module.md) | карточка «Диалог» экрана сессии: лента, компактный ввод, отправка/очередь и Stop ответа (M18/M24) |

Раскладка M24: план/карточки процесса под деревом слева, диалог заполняет правую
область. Enter/Stop и очередь используют состояние канала, модель берётся из SessionInfo;
плюс/микрофон пока отключены, недоступные параметры не выдумываются. При ширине до 680 px сайдбар выдвижной. Оболочка ограничена viewport;
сайдбар и лента прокручиваются независимо, другие экраны — внутри main.

## Границы

- Файлы модуля лежат в его `src/` и отдаются сервером как есть (без сборки).
- Другие модули подключаются как расширения панели (`PANEL_EXTENSIONS`,
  `install(shell)`): карточки «Настроек» — через реестр карточек
  (`registerCard`, `registerCardGroup`), мастер и экран сессии — через
  слоты раскладки (`registerSlot`: `newProject`, `sessionBody`,
  `sessionReview`, `sessionSidebar`, `sessionChat`). Сервер монтирует их каталоги под префиксами
  `/project-wizard/`, `/session-view/`, `/session-chat/`.
- `session-chat` не импортирует код службы и говорит с оболочкой только через
  слот `sessionChat` и объект `shell` расширения; данные берёт из маршрутов
  службы.
- Состояние только читается из `GET /api/state`; действия — через POST с
  `Content-Type: application/json` (Origin браузер ставит сам).
