# M20: сессия, которую ведёт приложение (0.9.2)

> **Состояние: отложено, не реализовано.** Пользователь, 2026-11-12: «Причина еще может быть
> в том, что я эту сессию… начал не в Workflow ките, а в Claude Desktop. Если причина именно в
> этом, то конкретно эту причину можно не исправлять. Это не штатная ситуация была.» Оба
> дефекта возникают только у сессии, начатой вне панели и получившей копию в терминале
> панели; у сессии, созданной панелью, процесс один. Документ оставлен как разбор причины.

## Цель и согласование

Сессию Claude, которую пользователь ведёт в приложении вне панели, Kit не должен путать со
своей копией: ни после перезапуска службы, ни при щелчке по карточке сессии.

Живая проверка 0.9.1 (macOS, 2026-11-12) показала два дефекта:

1. **Первое сообщение после перезапуска службы получает копия.** Признак «сессию ведёт
   приложение» (`SessionActivity.external`, M19) живёт в памяти службы. После перезапуска
   (каждое обновление Kit) до первого хука сессия не считается внешней: панель будит свою
   копию, и та забирает очередь.
2. **Щелчок по сессии открывает другой чат.** Ссылки сессии берутся из записи панели — это
   Remote Control копии (`session_…` процесса панели). У чата приложения свой Remote Control:
   в транскрипте сессии два разных `bridgeSessionId`, а панель показывает только свой.

Пользователь, 2026-11-12: «Да, это нужно исправить. Я это вижу, когда клацаю мышкой сейчас на
сессию в панели, открывается совсем другая сессия. Сделай новый скоб, внеси исправление, собери
новый релиз, я заранее его принимаю…»; в панели выбрано «спецификация и план без ревью»;
«Как только создашь план, его реализацию поручи сабагентам Opus 5.5 Medium».

## 1. Принципы

- Правила M19 не меняются: внешней сессии панель текст не вставляет, её не будит и сама не
  возобновляет; сообщение ждёт в очереди ближайшего хука.
- Признак внешней сессии переживает перезапуск службы.
- Щелчок по внешней сессии никогда не открывает копию панели.
- ChatGPT и Kimi работают как в 0.9.1.

## 2. Решение

### 2.1. Признак внешней сессии на диске (agent-channel, cli)

- `AgentChannelOptions.initialExternal?: (key: string) => boolean | undefined` — значение
  `external` для нового слота (сейчас всегда `false`). Хук по-прежнему задаёт его заново.
- `cli` хранит признаки в файле `channel-external.json` каталога состояния службы
  (`dataDirs.state`): объект `{ "<ключ сессии>": true | false }`. Файл читается при запуске
  службы и переписывается атомарно, когда `external` сессии меняется (`onChange` канала);
  хранится не больше 500 последних ключей. Нечитаемый или отсутствующий файл — пустой набор,
  ошибка записи — строка в журнале, работа продолжается.
- После перезапуска слот сессии, созданный постановкой сообщения в очередь, получает
  сохранённый признак: для внешней сессии `createDirectMessage`, `wakeIdle` и пробуждение для
  ревью не трогают копию панели с первого же сообщения.

### 2.2. Ссылки внешней сессии (provider-claude, provider-registry)

- Чтение транскрипта (`createBridgeReader`) помнит последний `bridgeSessionId` и последний
  отличный от него предыдущий. Новый метод отдаёт последний идентификатор, не равный
  заданному (идентификатору записи панели), или `null`.
- `SessionInfo.outsideLinks?: SessionLinks` — ссылки сессии в том виде, как её ведёт процесс
  вне панели. Claude заполняет поле для записи панели, когда в транскрипте есть идентификатор
  Remote Control, отличный от `record.remoteId`; ссылки строит `sessionLinks`. Для сессии без
  записи панели поле не нужно: её `links` уже взяты из транскрипта.
- `links` записи панели не меняются: по ним работает «Продолжить» и сессии, которые ведёт
  панель.

### 2.3. Щелчок по внешней сессии (panel-shell)

Для внешней сессии (`SessionRow.external`):

- щелчок по карточке, автооткрытие и кнопка открытия чата берут ссылки из `outsideLinks`;
- если `outsideLinks` нет, панель ничего не открывает в приложении и не показывает ссылку
  копии; строка состояния: «Сессию ведёт приложение Claude вне панели: откройте её чат в
  приложении. Сообщения придут агенту с ближайшим хуком»;
- после «Продолжить» (панель запустила свой процесс, хуки с меткой) сессия перестаёт быть
  внешней, и ссылки снова берутся из `links`.

### 2.4. Ошибки и тексты

| Случай | Что видит пользователь |
| --- | --- |
| Внешняя сессия, у приложения включён Remote Control | щелчок открывает чат приложения |
| Внешняя сессия без Remote Control | строка состояния из 2.3, приложение не переключается |
| Файл признаков не записался | ничего; строка в журнале службы |

## Поведение на ОС

| Что | macOS | Linux | Windows |
| --- | --- | --- | --- |
| `channel-external.json` в каталоге состояния | одинаково: путь из `dataDirs.state`, `path.join` | то же | то же, x64 и ARM64 |
| `outsideLinks` из транскрипта | одинаково | одинаково | одинаково |
| Открытие ссылки службой | `claude://claude.ai/code/session_…` (как сейчас) | ссылку открывает браузер панели | как на macOS |

Новых программ ОС решение не вызывает; `tools/platform-guard/allowlist.json` не меняется.

## 4. Проверка

- Тесты agent-channel и cli: слот берёт `initialExternal`; признак пишется при смене, читается
  при запуске; после «перезапуска» (новый канал с тем же файлом) сообщение внешней сессии
  Claude не будит копию и не вставляется; испорченный файл не мешает запуску.
- Тесты provider-claude: транскрипт с двумя идентификаторами даёт `outsideLinks` на тот, что
  не равен записи панели, независимо от порядка строк; с одним — поля нет.
- Тесты панели: внешняя сессия открывается по `outsideLinks`; без них ничего не открывается
  и показана строка состояния; обычная сессия открывается как раньше.
- CI: macOS, Linux, Windows x64 и ARM64.
- Живая проверка: macOS — пользователь (щелчок по сессии, которую ведёт приложение, открывает
  её чат; первое сообщение после `wfk service restart` приходит в чат приложения); Windows —
  проверяющий на Windows; Linux — CI.

## 5. Границы

- Не проверено, что ссылка `claude://claude.ai/code/session_…` чата приложения открывает в
  Claude Desktop именно локальный чат, а не его удалённое представление; собственная ссылка
  локального чата приложения (`claude://claude.ai/epitaxy/local_…`) Kit не известна.
- Уже запущенные копии сессий Kit не останавливает.
- Сессия, о которой служба не получила ни одного хука, внешней не считается (как в 0.9.1).
