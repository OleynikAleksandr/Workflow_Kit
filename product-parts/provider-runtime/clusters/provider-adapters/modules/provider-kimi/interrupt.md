# Kimi: Stop текущего ответа

Контракт [модуля](module.md), общий протокол —
[M24-turn-interruption](../../../../../../docs/design/M24-turn-interruption.md),
факты API — [M8](../../../../../../docs/planning/M8-kimi-protocol.md).

## Граница управления

Контроллер использует только rt.server.own(): действующий сервер Kit, совпадающий
supervisor processId/pid и порт. Не вызывает ensure/requireReady/requireServer, не
запускает/перезапускает сервер, не использует takeover/reload/shutdown. Сервер приложения
и сторонний процесс не получают команду. Capability требует доступного Kimi; фактическая
доступность зависит от сессии. listSessions обновляет кэш локальной проверки замка и
supervisor; interruptAvailability читает только этот кэш (срок свежести 6 с), без RPC.
Архив, вопрос/разрешение, чужой/нечитаемый замок и неизвестный владелец дают причину отказа.

Строгая проверка замка требует version=1, token, pid, hostname, startedAt, живой процесс
после загрузки системы и совпадающий pid сервера Kit. Чужой хост не считается простоем.
ENOENT означает отсутствие замка, прочая ошибка чтения — unknown. Поля identity замка
составляют отпечаток, который сравнивается перед действием и при подтверждении.
Обычный sessionIdle и прежнее чтение замков не изменены.

## Порядок Stop

1. Проверить свежий кэш и сериализовать действие с sendMessage в turn-gate. Инвалидировать
   старые неотправленные промпты и разбудить задержки повторов. Если уже летевшая отправка
   оказалась принятой, вернуть stale до abort: её новое поколение нельзя останавливать
   прежней целью. Уже отправленный HTTP-запрос задним числом не отменяется.
2. Заново проверить тот же сервер, сессию и папку (cwd либо workspace). GET сессии обязан
   дать busy/main_turn_active/archived/pending_interaction правильных типов.
3. Прочитать новейший пользовательский prompt id через messages?role=user&page_size=100;
   injection не подходит. При работающем ходе собственного замка связать prompt id,
   workspace и отпечаток замка с turnRef. Native turn id из Interrupt не выдумывается:
   у UserPromptSubmit его нет, target.nativeTurnId должен быть null.
4. Повторить проверки после preflight IO, непосредственно перед единственным
   POST /api/v1/sessions/{id}:abort {}. Изменение prompt id/замка/workspace даёт stale;
   диалог, архив или чужой/неизвестный владелец — unavailable. Отсутствие нового id
   нельзя заменить текстом промпта или busy:false чужого сервера.
5. Требовать явно boolean aborted в ответе. aborted:true подтверждает принятие команды,
   но stopped:true возвращается только после двух последовательных наблюдений: тот же
   prompt/workspace, busy=false, main_turn_active=false и свободный замок. Это учитывает
   трёхсекундную задержку освобождения замка Kimi. Изменившийся ход не объявляется stopped.

У API abort адресатом служит сессия, условной команды по turn id у подтверждённого M8
нет. Защита строится на сериализации записей Kit и проверке идентичности до/после abort;
она не добавляет серверной атомарности для произвольных внешних обращений к тому же API.
При новом промпте в подтверждении возвращается stale без повторного abort. Проверка
живого Kimi, включая Remote Control и эту гонку, остаётся обязательной приёмкой.

## Idle, ошибки и повторы

Если этот turnRef уже был связан с работающим промптом предыдущей попыткой, тот же
prompt в стабильном idle с last_turn_reason=completed даёт already-idle без нового
abort. Неизвестный idle не объявляется подтверждённой остановкой. aborted:false без
такого доказательства не даёт успеха. Успешный результат: proof=provider-state,
nativeTurnId=null. Общий канал T002 завершает свой ход без зависимости от нового хука.

Общий предел адаптера — interruptWaitMs (8 с), опрос — interruptPollMs (200 мс).
Абсолютный deadline передаётся каждому HTTP-запросу и повторно проверяется после чтения
токена; abort имеет retryAuth=false, поэтому 401 не повторяет разрушительную команду.
Истёкший preflight не отправит запоздалый abort, даже если транспорт проигнорировал отмену.
Тайм-аут — ProviderError interrupt-timeout (504, подсказка); другой сбой — interrupt-failed;
40931 — unavailable без takeover. HTTP-маппинг ошибки исправлен T008.

Внутренний turn-gate отменяет ожидающие повторы 40931/transport/reload старой отправки.
Канал сохраняет недоставленный outbox/очередь и общий барьер; новая явная отправка получает
новый билет и идёт после Stop. Барьер плана снимает штатное «Продолжить», не адаптер.
История и процессы сохраняются, назначения исполнителей Kit не отменяются.

## ОС и проверки

Одинаково на macOS, Linux и Windows x64/ARM64. Папки проверяются с context.platform,
пути замков — path.join, никаких новых программ ОС. Тесты используют настоящий локальный
HTTP-клиент/подставной сервер и временные файлы; injected darwin/linux/win32 проверяет
алгоритм и сравнение папок, не запуск Kimi на всех ОС. Живая macOS — пользователь,
Windows — проверяющий на Windows, Linux — только CI. Подробности — M24-acceptance.

Если aborted:true уже получен предыдущей попыткой, эта привязанная к тому же промпту
квитанция сохраняется для явной повторной проверки после тайм-аута. Стабильный idle
тогда подтверждает interrupted без повторного abort; last_turn_reason=completed
подтверждает естественное завершение как already-idle. Новый промпт эту квитанцию
использовать не может. Потерянная квитанция и неизвестный idle успехом не считаются.
