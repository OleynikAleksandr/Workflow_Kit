# Workflow Kit: запуск и отдельный экземпляр для разработки

Часть [руководства по установке 0.10.0](../installation.md). Подробности перенесены
без изменения поведения, чтобы основное руководство помещалось в лимит документа.

## Запуск из исходников и разработка

Из корня локального репозитория можно запустить сервер без установки:

```sh
node bin/wfk.mjs serve
```

Сервер печатает адрес и работает до `Ctrl+C`, без значка и автозапуска, с теми же данными и
портом, что установленная служба; второй экземпляр — с
[отдельными данными и портом](#отдельный-экземпляр-для-разработки). Проверки разработки:

```sh
npm ci
npm run typecheck
npm test
```

Тесты работают во временных каталогах с подставными провайдерами и не трогают ваши конфиги,
службу и порт 4747. `npm run check:platforms` проверяет, что код рассчитан на macOS, Linux и
Windows; CI повторяет все проверки на macOS, Linux, Windows x64 и ARM64. Правила разработки —
в [AGENTS.md](../../AGENTS.md).

## Отдельный экземпляр для разработки

Чтобы не занимать данные и порт установленной службы, задайте свои.

macOS/Linux:

```sh
WFK_DATA_DIR="$HOME/wfk-dev-data" WFK_PORT=4848 node bin/wfk.mjs serve
```

Windows PowerShell (лучше в отдельном окне терминала):

```powershell
$env:WFK_DATA_DIR = "$env:TEMP\wfk-dev-data"
$env:WFK_PORT = "4848"
node bin/wfk.mjs serve
```

После работы удалите переменные: `Remove-Item Env:WFK_DATA_DIR, Env:WFK_PORT`.

Данные Kit будут отдельными, но это не полная изоляция провайдеров:
служба всё ещё может использовать установленные `claude`/`codex`/`kimi` и их
пользовательское окружение. Для автоматических тестов проект подставляет
программы и временное окружение отдельно.
