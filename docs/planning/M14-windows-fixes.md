# M14. Исправления по живой проверке Windows (релиз 0.8.1)

## Цель и согласование

Живая проверка 0.8.0 на Windows 11 (виртуальная машина, пользователь-администратор,
2026-11-11) подтвердила схему M13: приложение ChatGPT подключается по SSH (`wfk-local`) к
демону Kit, сессия Kit открывается в ChatGPT на Windows. Найдено восемь дефектов
(`docs/evidence/M13-acceptance.md`, «Находки живой проверки на Windows») и два замечания
пользователя.

Пользователь, 2026-11-11: «Я открываю скоп и Еще два замечания. Первое. Можно ли Workflow Kit
открывать не в Edge, а в Chrome? И второй при выборе диска папки, вернее, в которую писать
проекты, присутствует только диск C. А нужно иметь выбор любого диска.»

## 1. Принципы

1. Kit не меняет системные настройки Windows (UAC, терминал по умолчанию): он называет причину
   и что сделать.
2. Каждое изменение — для macOS, Linux и Windows; ветки ОС с платформой параметром и тестом.
3. Подключение приложения ChatGPT засчитывается только тогда, когда оно действительно может
   работать (демон Kit работает), а не по одному процессу в списке.

## 2. Решение

### 2.1. Мелькающие окна `git` (находка 8)

`git-publish/src/git.ts`, `runGit`: `execFile('git', …)` получает `windowsHide: true`, как все
остальные запуски Kit (`process-supervisor`, `service-installer`). Тест: параметры `execFile`
содержат `windowsHide: true`. Проверка по коду: других `execFile`/`spawn` без `windowsHide`
в `product-parts/**/src` нет (кроме `pty-host`, где окно задаёт ConPTY).

### 2.2. UAC выключен (находка 1)

- Codex на Windows не запускает демон из процесса с полными правами: «start the Windows daemon
  from a non-elevated terminal; shared clients must not inherit administrator privileges».
  При `EnableLUA = 0` с полными правами работает всё, и демон Kit не поднимается никогда.
- `provider-codex`: `startDaemon` распознаёт этот текст и отвечает ошибкой `daemon-elevated`:
  «Codex не запускает демон с правами администратора: на этом компьютере выключен контроль
  учётных записей (UAC)», подсказка — включить UAC (`EnableLUA = 1`) и перезагрузить Windows;
  статус провайдера показывает ту же причину.
- Диагностика общего доступа (`WINDOWS_PROBE_SCRIPT`) читает `EnableLUA`; новая проверка
  `elevation` («контроль учётных записей»): `0` → `fail`. `windowsVerdict`: сразу после проверок
  `codex` и сведений Windows → `broken` с той же причиной и подсказкой (`wfk doctor`
  предупреждает).

### 2.3. Ложное «Работает» (находка 2)

- Подключение приложения засчитывается (и `connectionSeenAt` записывается) только когда демон
  Kit работает (`rt.daemon().running`).
- Windows: строка процесса из `WINDOWS_PROBE_SCRIPT` получает возраст процесса в секундах
  (`CreationDate`); подключение засчитывается, если процессу `ssh.exe … wfk-local … app-server
  proxy` не меньше 15 с (`CONNECTION_MIN_AGE_S`) — неудачные попытки приложения живут меньше.
- macOS — то же правило про демон; возраст процесса не проверяется (ложных срабатываний не
  было).

### 2.4. Карточка «Общий доступ к чатам» (находки 3–6)

- Блок шага администратора (`adminNote`, команда, «Показать скрипт») — только в состояниях
  `needs-admin-setup`, `broken` и в `not-configured` со скриптом отката; при `active` и
  `needs-connection` его нет.
- Команда запуска переносится по ширине карточки (`white-space: pre-wrap`,
  `overflow-wrap: anywhere`) и не обрезается.
- `sharedSummary`: причина и подсказка соединяются через точку, если причина ею не кончается.
- Заметка операции («Настройка выполняется…», «Удаление настройки выполняется…») убирается,
  как только операция закончилась; ошибка операции остаётся.

### 2.5. Команда `wfk` после установки на Windows (находка 7)

Установщик дописывает папку Kit в пользовательский PATH (`SetEnvironmentVariable`), но уже
открытое приложение Windows Terminal выдаёт новым вкладкам старое окружение. Итог установки на
Windows печатает: «Команда wfk появится в новом окне терминала; если Windows Terminal был
открыт, закройте его полностью. Сейчас: & "<путь>\wfk.cmd" open». То же — в README и
`docs/installation.md` («Запускатель и PATH»). Проверка после перезагрузки — в приёмке.

### 2.6. Браузер панели (замечание 1)

`service-installer/src/open.ts`, `browserPlan` на Windows: сначала Chrome
(`Google\Chrome\Application\chrome.exe` в Program Files, Program Files (x86), LOCALAPPDATA),
затем Edge — как на macOS и Linux. Окно — то же окно приложения `--app=` со своим профилем.

### 2.7. Папка проектов на любом диске (замечание 2)

- Сейчас выбор папки и проекты ограничены домашней папкой (`resolveInsideHome`,
  `outside-home`). Новое правило — «разрешённые корни»: домашняя папка и корни других
  локальных дисков.
- `project-registry`: `allowedRoots(scope)`:
  - Windows — домашняя папка и корни дисков `A:\`…`Z:\`, кроме системного (`%SystemDrive%`),
    которые отвечают на `stat` (без вызова программ); на системном диске — по-прежнему только
    домашняя папка;
  - macOS — домашняя папка и тома `/Volumes/*`, кроме ссылки на загрузочный том;
  - Linux — домашняя папка, `/media/<пользователь>/*`, `/run/media/<пользователь>/*`, `/mnt/*`.
- `resolveInsideRoots` заменяет `resolveInsideHome` в выборе папки, создании и открытии
  проекта и в мастере (`project-setup/preview.ts`): путь внутри одного из корней (сам корень
  другого диска допустим как место для проектов, сам проект — папка внутри корня); иначе
  `outside-roots` «Папка вне домашней папки и других дисков».
- `GET /api/folders` отдаёт `roots` (`name`, `path`, `kind`: `home` | `drive`); `parent` у
  корня — `null`. Выбор папки (`panel-shell/src/folder-picker.js`) показывает переключатель
  корней («Домой», «D:\», «E:\»…).
- Риск: панель доступна по Tailscale без авторизации; другие диски становятся видны в выборе
  папки так же, как сейчас домашняя папка (только имена подпапок).
- Сделано (T005): диск, не ответивший за 1,5 с, пропускается; корни кэшируются на 5 с, чтобы
  один показ папки не ждал такой диск дважды. Корень диска выбирается только как папка для
  проектов («Настройки»); проект и мастер — папка внутри корня. Код ошибки `outside-home`
  заменён на `outside-roots`, `resolveInsideHome` — на `resolveInsideRoots`.

## 3. Поведение на ОС

| Что | macOS | Linux | Windows |
| --- | --- | --- | --- |
| Окна `git` | не видны и раньше | не видны и раньше | `windowsHide`: окна больше не мелькают (x64 и ARM64) |
| UAC и демон | не нужно: UAC — понятие Windows | не нужно | `daemon-elevated`, проверка `elevation`, состояние `broken` с подсказкой |
| Подключение ChatGPT | засчитывается при работающем демоне | `unsupported` | при работающем демоне и возрасте `ssh.exe` ≥ 15 с |
| Карточка общего доступа | исправления общие (панель) | карточка «Недоступно» | то же, плюс блок администратора только в нужных состояниях |
| Сообщение о `wfk` после установки | как раньше | как раньше | напоминание про новое окно и прямая команда |
| Браузер панели | Chrome, затем Edge, Chromium (как раньше) | как раньше | Chrome, затем Edge |
| Папка проектов | домашняя и `/Volumes/*` | домашняя, `/media`, `/run/media`, `/mnt` | домашняя и корни других дисков |

## 4. Проверка

- Автоматические тесты: `windowsHide` у `runGit`; `daemon-elevated`; проверка `elevation` и
  вердикт; правило подключения (демон, возраст); модель и карточка; порядок браузеров на
  `win32`; `allowedRoots` и `resolveInsideRoots` на `win32`, `darwin`, `linux` с подставленной
  файловой системой; маршрут `/api/folders` с `roots`.
- CI: macOS, Linux, Windows x64 и ARM64.
- Живая проверка: Windows — проверяющий (окна не мелькают, Chrome, диск `D:`, карточка, `wfk`
  после перезагрузки); macOS — пользователь (выбор папки на внешнем томе, карточка «Работает»);
  Linux — только CI.

## 5. Границы

- iPad не видит компьютер с Windows (нужна привязка по QR-коду или SSH) — проверка пользователя
  впереди, не входит в работу.
- Kit не включает UAC и не меняет терминал по умолчанию сам.
- Сетевые диски и общие папки — только если Windows показывает их буквой диска.
