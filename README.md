# Workflow Kit

Workflow Kit — локальное приложение для управления проектами и работой агентов
в **Claude, ChatGPT/Codex и Kimi Code**. Диалог и выполнение задач идут в приложениях
провайдеров; Kit ведёт проекты, сессии, планы, ревью и процесс выполнения.

**Текущая версия: 0.6.1. Основная проверенная платформа — macOS.**
На Linux предусмотрены бэкенд и интеграции провайдеров, но живой проверки нет.
С версии 0.5.0 на Windows 11 (x64 и ARM64) реализованы те же возможности, что
на macOS: сессии Claude и ChatGPT/Codex, ревью, план и автопилот. Они проверены
тестами, живая проверка на Windows ещё впереди. С версии 0.6.0 третий провайдер —
Kimi Code. Подробнее — [поддержка ОС](docs/installation.md#поддержка-ос).

## Как это работает

Один процесс Node.js запускает бэкенд, HTTP API и раздаёт веб-панель.
Панель открывается по адресу [http://127.0.0.1:4747/](http://127.0.0.1:4747/).
После установки процесс работает в фоне и запускается при входе пользователя.
Закрытие окна панели не останавливает службу.

Kit использует локальные программы Claude Code, Codex и Kimi Code. Сессии открываются
в родных приложениях, а инструкции процесса передаются агентам через хуки.
В управляемые проекты устанавливается Harness Workflow Kit 2.2.2.

Основные возможности:

- Создание и подключение проектов, подготовка папки и первая сессия через мастер.
- Выбор Claude, ChatGPT/Codex или Kimi Code для сессии, имена, архивирование и открытие чатов.
- Спецификация и план, последовательное выполнение или встроенные подагенты провайдера.
- Перекрёстное ревью плана: Claude проверяет план ChatGPT и наоборот, план Kimi проверяет ChatGPT;
  служба пересылает замечания и ответы, панель показывает ход и журнал ревью.
- Автопилот задач с остановками для пользовательских решений, выпуска и приёмки.
- Публикация на GitHub — отдельное действие после приёмки и закрытия плана.
- Веб-панель на Mac или компьютере с Windows и удалённо на iPad/телефоне через Tailscale.

Это приложение для локального компьютера: публикация репозитория на GitHub
не запускает службу в облаке. Для удалённой работы компьютер со службой
должен оставаться включённым и доступным.

## Установка с нуля

Готовых установочных пакетов `.dmg`, `.pkg`, `.exe`, `.msi`, `.deb` и `.rpm`
в репозитории нет. Установщик входит в исходники и запускается через Node.js.

1. Установите **Node.js 24 или новее** и **Git**. Проверьте в терминале:

   ```sh
   node --version
   git --version
   ```

2. **Скачайте репозиторий на свой компьютер.** С Git:

   ```sh
   git clone https://github.com/OleynikAleksandr/Workflow_Kit.git
   cd Workflow_Kit
   ```

   Или на [странице репозитория](https://github.com/OleynikAleksandr/Workflow_Kit)
   выберите **Code → Download ZIP**, распакуйте архив и откройте терминал
   в распакованной папке `Workflow_Kit-main`. При переходе командой `cd`
   заключайте путь с пробелами в кавычки.

3. В **корне скачанной папки**, где находятся `package.json` и `bin`, выполните:

   ```sh
   node bin/wfk.mjs install
   ```

   Установщик создаст отдельную копию приложения, запускатель, значок и
   автозапуск, затем запустит службу. `npm ci` для установки не требуется:
   у приложения нет runtime-зависимостей npm.

4. Откройте значок **Workflow Kit** в списке приложений либо выполните
   в новом терминале:

   ```sh
   wfk open
   wfk doctor --installed
   ```

   `open` запускает службу при необходимости и открывает панель.
   Если команда `wfk` не найдена, см. [запускатель и PATH](docs/installation.md#запускатель-и-path).

Для работы агентов отдельно нужны установленные и авторизованные **Claude Code**
(`claude`, версия 2.1.0+) и/или **Codex** (`codex`); для сессий Claude на macOS
и Linux нужен `expect`, на Windows он не нужен, а Codex нужен версии 0.160+.
Третий провайдер — **Kimi Code** (`kimi`, версия 2.5.2+, вход `kimi login`): пока открыто
приложение Kimi Code, Kit работает через его сервер, иначе запускает свой `kimi web`. Хук
Kit приложение подхватывает только после своего перезапуска. Щелчок по сессии Kimi открывает
её проект в приложении без нового пустого чата (macOS и Windows). Скоуп в сессии Kimi идёт только
последовательно, ревьюером Kimi не бывает. Живая проверка Kimi — только на macOS.
На Windows устанавливайте из обычного терминала, не от имени администратора.
Для открытия чатов нужны соответствующие приложения Claude Desktop, ChatGPT и Kimi Code. Отсутствие провайдера не запрещает запуск панели: она показывает
недоступные возможности и причину. Для перекрёстного ревью нужны оба провайдера пары (для плана Kimi — ChatGPT).
Когда открыто приложение ChatGPT, служба передаёт ему удалённое управление Codex
(демон в это время не держит чатов), чтобы его чаты открывались и на iPad.

Подробности для каждой ОС, каталоги данных, доступ с iPad, обновление,
удаление и диагностика — в [руководстве по установке](docs/installation.md).

## Первая работа с проектом

1. Откройте панель и мастер проекта, выберите папку и провайдера первой сессии.
2. Просмотрите подготовительные действия и подтвердите их. Kit подготовит
   проект и откроет сессию. Для коммитов Git должна быть настроена ваша личность.
3. Опишите задачу в чате провайдера. Для разработки агент запрашивает решение:
   план с ревью, без ревью или «Просто обсуждаем».
4. При выборе ревью дождитесь обмена замечаниями. Затем выберите режим
   выполнения плана и запустите его в панели.
5. Следите за задачами и строкой активности. Подтвердите выпуск, когда он нужен,
   проверьте результат и примите его. Закрытие плана — отдельное действие.
6. Если у ветки проекта есть удалённый репозиторий, после закрытия плана
   нажмите «Опубликовать на GitHub» на экране проекта (или попросите агента:
   `wfk project publish`). Пока план открыт, публикация не выполняется.

Сессия ревьюера скрыта из дерева проекта; её ответы доступны в журнале
основной сессии. При ошибке запуска ревью панель показывает причину и повтор.

## Запуск из исходников и разработка

Из корня локального репозитория можно запустить сервер без установки:

```sh
node bin/wfk.mjs serve
```

Откройте адрес, напечатанный в терминале. Сервер работает до `Ctrl+C`;
значок и автозапуск при таком запуске не устанавливаются. Обычный `serve`
использует те же данные и порт, что установленная служба. Для второго
экземпляра нужны отдельные данные и порт — [пример](docs/installation.md#отдельный-экземпляр-для-разработки).

Для разработки и автоматических проверок дополнительно установите
зависимости из lock-файла:

```sh
npm ci
npm run typecheck
npm test
```

Тесты используют временные каталоги и подставные провайдеры; пользовательские
конфиги, службу и порт 4747 они не изменяют. `npm run check:platforms` проверяет,
что код и спецификации рассчитаны на macOS, Linux и Windows. CI на GitHub
выполняет проверку типов, тесты и эту проверку на macOS, Linux, Windows x64 и ARM64. Правила разработки проекта —
в [AGENTS.md](AGENTS.md).
