# Workflow Kit

Workflow Kit — локальное приложение для управления проектами и работой агентов
в **Claude, ChatGPT/Codex и Kimi Code**. Агенты работают в приложениях провайдеров; Kit ведёт
проекты, сессии, планы, ревью и процесс выполнения и показывает диалог каждой сессии:
читать переписку и писать агенту можно прямо в панели.

**Текущая версия: 0.14.4.** macOS, Windows 11 (x64 и ARM64) и Linux; что проверено
вживую на каждой ОС — в [поддержке ОС](docs/installation.md#поддержка-ос).

## Как это работает

Один процесс Node.js запускает бэкенд, HTTP API и раздаёт веб-панель.
Панель открывается по адресу [http://127.0.0.1:4747/](http://127.0.0.1:4747/).
После установки процесс работает в фоне и запускается при входе пользователя.
Закрытие окна панели не останавливает службу.

Kit использует локальные программы Claude Code, Codex и Kimi Code. Сессии открываются
в родных приложениях, а инструкции процесса передаются агентам через хуки.
В управляемые проекты устанавливается Harness Workflow Kit 2.2.7 — его исходники лежат в этом
репозитории (`product-parts/kit-core`), бандл собирается здесь же. Пакет восстановления
приходит агенту целиком при старте сессии — Claude частями (шесть хуков), ChatGPT одним
хуком с поднятым лимитом; хуки ChatGPT Kit подтверждает сам.

Основные возможности:

- Создание и подключение проектов, подготовка папки и первая сессия через мастер.
- Версия Kit на экране проекта; устаревший Kit и структура Kit (хуки проекта) обновляются
  кнопкой «Обновить Kit» — без мастера, без новой сессии и без подтверждений хуков ChatGPT.
- Выбор Claude, ChatGPT/Codex или Kimi Code для сессии, имена, архивирование и открытие чатов.
- Спецификация и план, последовательное выполнение или встроенные подагенты провайдера.
- Перекрёстное ревью плана: Claude проверяет план ChatGPT и наоборот, план Kimi проверяет ChatGPT;
  служба пересылает замечания и ответы, панель показывает ход и журнал ревью.
- ChatGPT на macOS и Windows: общий доступ к чатам — Kit, ChatGPT на компьютере, iPad и
  телефон работают с одним чатом, включая чат ревьюера
  ([настройка](docs/setup.md#шаг-4-chatgpt-codex)).
- **Диалог с агентом в панели** (с 0.9.0): переписка любой сессии Claude, ChatGPT и Kimi и
  поле ввода — см. [«Диалог с агентом»](docs/usage.md#диалог-с-агентом).
- Автопилот задач с остановками для пользовательских решений, выпуска и приёмки.
- Публикация на GitHub — отдельное действие после приёмки и закрытия плана.
- Веб-панель на компьютере (macOS, Windows, Linux) и удалённо на iPad/телефоне через Tailscale.

Это приложение для локального компьютера: для удалённой работы компьютер со службой должен
быть включён и доступен.

## Установка

Нужны Node.js, Git и хотя бы один провайдер — программа командной строки и приложение
(Claude, ChatGPT/Codex или Kimi Code), вход выполнен в обоих. **Сначала ставятся программы
провайдеров, потом Workflow Kit.** Затем:

```sh
git clone https://github.com/OleynikAleksandr/Workflow_Kit.git
cd Workflow_Kit
node bin/wfk.mjs install
wfk doctor --installed
```

Установщик копирует приложение, создаёт команду `wfk`, значок **Workflow Kit** и автозапуск
при входе в систему и запускает службу. Панель открывается значком или командой `wfk open`.

- [Установка шаг за шагом](docs/setup.md) — для новичка: терминал, Node.js и Git, Claude,
  ChatGPT, Kimi Code, проверка программ, панель на iPad и телефоне, частые ошибки.
- [Руководство по установке](docs/installation.md) — требования, что создаётся в каждой ОС,
  общий доступ к чатам ChatGPT, удалённый доступ, обновление, удаление и диагностика.

## Работа с проектом

1. В панели откройте мастер проекта, выберите папку и провайдера первой сессии; Kit
   подготовит проект и откроет сессию в приложении провайдера.
2. Опишите задачу агенту. Для разработки он спросит решение: план с ревью, без ревью или
   «Просто обсуждаем».
3. Выберите режим выполнения и запустите план в панели; следите за задачами, подтверждайте
   выпуск и принимайте результат. Закрытие плана и публикация на GitHub — отдельные действия.

**Диалог с агентом.** На экране сессии в панели — карточка «Диалог»: переписка сессии и
поле ввода. Ждущему агенту сообщение приходит сразу вашей репликой (Claude — в сессии,
которую ведёт панель, ChatGPT — при общем доступе к чатам). Если агент отвечает, сообщение
стоит в конце ленты пузырём «в очереди» и уходит в конце хода или сразу после Stop.

**Интерфейс 0.10.0 (M24).** План и карточки решений перенесены
под дерево проектов слева; ширина сайдбара меняется, диалог прокручивается внутри окна.
Ввод показывает Enter при ожидании и Stop во время работы; очередь доступна через
Ctrl/⌘+Enter и «В очередь». Stop сохраняет черновик/очередь и удерживает автоматическое
продолжение; доступность зависит от управляемой сессии провайдера. Плюс и микрофон пока
отключены, параметры показывают только имеющиеся данные. Реализация и автоматические
проверки завершены, веха принята —
[результаты и ограничения M24](docs/evidence/M24-acceptance.md).

Подробно — [работа с Workflow Kit](docs/usage.md): первый проект по шагам,
[диалог с агентом](docs/usage.md#диалог-с-агентом) и
[особенности провайдеров](docs/usage.md#особенности-провайдеров-в-работе).

**Параметры сессий 0.11.0 (M25).** Под вводом видны фактические модель, усилие,
режим, контекст и лимиты Claude/ChatGPT. Параметры ChatGPT меняются из меню;
полный доступ требует подтверждения. Для Claude данные контекста собираются
со следующего запуска или возобновления панелью; пользовательская строка состояния
сохраняется. Kimi показывает прежнюю строку. Веха принята;
проверки — в [доказательствах M25](docs/evidence/M25-acceptance.md).

**Нативные контролы M26.** Карточка усилия с ползунком и молнией скорости,
отдельный список моделей и отдельная плашка доступа у плюса заменяют общий длинный
список ChatGPT. Пресеты используют штатную проверку Codex; полный доступ требует
подтверждения. Сброс и «Подробнее» исключены по согласованию. Браузерные проверки
и сравнение с эталонами завершены — [Design QA](design-qa.md),
[результаты M26](docs/evidence/M26-native-controls.md). Выпуск 0.12.0; веха принята.

**Исправления M26/R2.** Бегунок усилия захватывается и перетаскивается мышью;
служебный зелёный подстрочник после смены параметров убран. Ошибки остаются видимыми.
Подробности — [результаты R2](docs/evidence/M26-native-controls.md#r2--t008-замечания-пользователя-после-0120).
Исправления — в 0.12.1; веха принята.

**Контролы Claude 0.13.0 (M27).** В управляемой беседе можно
выбирать модель, Effort и отдельный Ultracode через вложенные меню, а Auto/Manual/
Accept edits/Plan — отдельной кнопкой Mode, как в Claude Desktop. Нужны Claude
2.1.323+ и новый запуск/штатное возобновление панелью; старые и внешние host остаются
для чтения с причиной. Изменения действуют только в этой беседе и не меняют defaults.
Скорость доступна только при нативном разрешении аккаунта; в проверенном аккаунте
fast требует usage credits и не включается. Native roundtrip и визуальная проверка
завершены — [результаты M27](docs/evidence/M27-claude-native-controls.md),
[Design QA](design-qa.md). Выпуск 0.13.0; веха принята.

**Исправления контролов Claude (M28).** Кольцо контекста Claude считается от порога
автосжатия `autoCompactWindow`, как `/context` Claude; окно модели — второй строкой
подсказки. Stop активен весь ход и останавливает ответ одним Esc, в том числе в диалоге
разрешения (это отказ). Сообщение свободному агенту уходит сразу, сообщение во время ответа
видно пузырём «в очереди». Под полем ввода больше нет служебных строк ни у одного
провайдера: остаются только ошибки после ваших действий. Меню параметров Claude
показывает причину недоступности одной строкой, модель выбирается и без списка усилий, а
каталог Claude дочитывается, когда Claude свободен. Живая проверка на Claude
пройдена, Stop из приложения Claude не проверялся —
[результаты M28](docs/evidence/M28-claude-controls-fixes.md). Исправления Stop и доставки действуют
в сессиях, запущенных или возобновлённых панелью после установки 0.13.1. Выпуск
0.13.2; веха принята.

**Мгновенные контролы Claude (M29).** Пока автопилот ждёт вашего решения (кнопку плана,
ответ на вопрос о плане, ревью), сессия Claude, которую запустила панель, свободна: ход
закончен, сообщения из Claude Desktop и терминала уходят сразу, индикатор работы не крутится;
сообщение из панели будит её. Меню модели, усилия, режима и Ultracode открываются всегда,
и во время ответа: выбор сразу виден в строке с пометкой «применяется» или «применится,
когда Claude закончит ответ», а Kit применяет его в терминале сам, только для этой беседы.
В свободной сессии изменение подтверждается за 1–3 с; если Claude не принял выбор, под
вводом на 10 с появляется строка с причиной. Каталог моделей читается один раз на версию
Claude, `/fast` больше не открывается. Нужна сессия, запущенная или возобновлённая панелью
после установки 0.13.3 — [результаты M29](docs/evidence/M29-claude-controls-instant.md). Выпуск
0.13.3; веха принята.

**Без служебных строк в Claude Desktop (M30).** Смены модели и усилия из панели больше не
оставляют в ленте беседы в Claude Desktop строк `/effort`, `Cancelled` и «Kept model as»:
Kit читает и меняет усилие в меню `/model` Claude и закрывает его клавишей «только для этой
сессии». Видимая строка `/effort ultracode` остаётся только при явном переключении Ultracode.
У модели без выбора усилия меню говорит об этом прямо —
[результаты M30](docs/evidence/M30-claude-feed-quiet.md). Действует в сессиях, запущенных или
возобновлённых панелью после установки 0.13.4; выпуск 0.13.4; веха принята.

**Неначатый план в любой сессии (M31).** План, который агент предложил, но который ещё не
начат, принадлежит проекту, а не сессии: карточка выбора способа выполнения и карточка с
«Начать выполнение плана» видны в каждой сессии проекта, в том числе в новой сессии другого
провайдера или модели. Сессия, в которой вы нажали кнопку, становится владельцем плана, а
прежняя перестаёт ждать. Уже начатый план остаётся у своей сессии; другие показывают короткую
карточку «План выполняет сессия «…»» с кнопкой «Открыть сессию». Новая сессия не спрашивает о
ревью и не запускает его повторно для уже предложенного плана. Нужен Kit проекта 2.2.5
(«Обновить Kit») — [проверка M31](docs/evidence/M31-plan-in-any-session.md). Выпуск 0.13.5;
веха принята.

**Длинные диалоги ChatGPT и возврат связи (M32).** Лента сессии ChatGPT/Codex читает историю
порциями: длинная переписка с большими выводами команд больше не обрывает ленту, новые ответы
появляются без повторной загрузки всей истории. Слишком большой отдельный элемент заменяется
пометкой «Часть диалога Codex недоступна…», реплики до и после него видны. Если сокет демона
пропал, панель показывает «Восстанавливаем подключение к Codex…», через 30 секунд — совет
проверить демон, и сама продолжает работу, когда демон вернулся: лента, черновик, прокрутка
и очередь сохраняются, отправки и Stop не повторяются. Stop читает только состояние хода.
Дефект порядка байтов при подключении к демону Codex, найденный CI на Linux, исправлен в 0.13.7.
Реализация и автоматические проверки завершены —
[результаты M32](docs/evidence/M32-codex-history-recovery.md). Выпуск 0.13.7; веха принята.

**Вопросы агента в диалоге (M33).** Когда агент задаёт вопрос с вариантами ответа (Claude —
`AskUserQuestion`, ChatGPT — `request_user_input`), в диалоге панели появляется карточка
вопроса: выберите вариант или напишите свой и нажмите «Отправить» (или Ctrl/⌘+Enter). Один
щелчок по варианту ничего не отправляет. Вопрос остаётся и в Claude Desktop или ChatGPT:
отвечает та сторона, что успела первой, карточка второй показывает итог («Ответ дан в
приложении»), а опоздавший ответ панели получает отказ «На вопрос уже ответили». Если ответить
из панели нельзя (секретный ответ, сессия Claude запущена до обновления хуков проекта, хук
вопроса завершился), карточка называет причину и кнопку «Открыть чат провайдера». Асинхронный
вопрос ChatGPT (обычный режим, `request_user_input_async`) отвечается так же карточкой: ответ
сразу входит в идущий ход агента, как ответ из карточки ChatGPT, а если хода нет — начинает
новый (M34); в ленте ответ виден обычным текстом, закрытая карточка показывает выбранный
вариант. Для такого ответа нужен режим общего демона ChatGPT. Текст из поля ввода во время хода
по-прежнему ждёт конца хода: если агент ждёт ответа на вопрос, отвечайте карточкой. Для Claude нужна структура проекта v4 (прежнюю обновляет
«Обновить Kit», M38) и сессия, запущенная после обновления. Одобрения команд и правок Kit
по-прежнему не принимает. Живая проверка на macOS пройдена —
[результаты M33](docs/evidence/M33-acceptance.md); выпуски 0.14.0 (M33) и 0.14.1 (M34);
обе вехи приняты.

**Вопрос о плане не висит (M36).** Если на вопрос агента «спецификация и план?» вы ответили в
чате, а агент уже предложил план или план выбран, карточка вопроса закрывается сама — при
следующем окончании хода агента или при выборе способа выполнения. Решение о ревью при этом не
записывается: после предложения плана панель спросит «С ревью» или «Без ревью». Пока сессия
ждёт вашего ответа или ревью и служба может её разбудить (Claude, запущенный панелью, сессии
без удерживаемого хука), она получает не больше одного напоминания подряд вместо пустого хода
каждые 9 минут; ответ или сообщение из панели будят её, как раньше. Сессия, которую служба
разбудить не может, получает напоминание к каждому сроку, как прежде —
[спецификация M36](docs/planning/M36-plan-question-stale.md). Выпуск 0.14.3.

**Приёмка и закрытие плана из панели (M37).** После «Принять план» и «Закрыть план» агент
сессии-владельца получает сообщение и отвечает одной-двумя фразами; строка активности
показывает «План принят» и «План закрыт» вместо устаревшего «Ждёт приёмки». Kit закрывает план
только при чистой папке проекта, поэтому карточка выполненного или принятого плана заранее
показывает файлы вне коммитов и кнопку «Попросить агента убрать»: агент удаляет свои временные
файлы, коммитит документы, а код и чужие файлы не трогает и называет их вам. Отказ закрытия
называет мешающие файлы по-русски. Kit 2.2.6 («Обновить Kit») велит агенту класть входные
JSON команд в `.harness/inputs/` — эта папка не попадает в git и закрытию не мешает. Карточка
«Ревью плана» закрытого или заменённого плана больше не показывается. Сообщение получает
сессия, участвующая в процессе Kit; если такой нет, кнопка говорит, что файлы нужно убрать
самому. Реализация и автоматические проверки завершены —
[спецификация M37](docs/planning/M37-plan-close-flow.md), [проверка](docs/evidence/M37-acceptance.md). Выпуск 0.14.4.

**Структура Kit кнопкой (M38).** «Обновить Kit» обновляет и Kit, и структуру Kit проекта (хуки
Claude и ChatGPT, раздел `AGENTS.md`, шаблоны) одним коммитом; карточка появляется и ради одной
структуры («Структура Kit 3 → 4»). Так проект, созданный до 0.14.0, получает хуки вопроса
Claude: без них ожидающий вопрос в панели не виден. Изменённые вручную и не закоммиченные
файлы не трогаются — [спецификация M38](docs/planning/M38-kit-structure-update.md); войдёт в
выпуск 0.14.5.

## Запуск из исходников и разработка

`node bin/wfk.mjs serve` запускает сервер из репозитория без установки; `npm ci`,
`npm run typecheck`, `npm test` и `npm run check:platforms` — проверки разработки;
`npm run build:kit` собирает бандл Kit из `product-parts/kit-core`. Подробно —
[руководство](docs/installation.md#запуск-из-исходников-и-разработка), правила — [AGENTS.md](AGENTS.md).
