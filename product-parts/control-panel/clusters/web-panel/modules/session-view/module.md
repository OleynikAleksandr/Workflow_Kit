# Модуль: session-view

Часть `control-panel`, кластер `web-panel`. Алиас импорта: `#session-view`.

## Назначение

Карточки процесса выбранной сессии и «Ревью плана» в боковой панели (спецификация вехи 2,
разделы 6, 8.3, 9.3, 10; шаги 5–10 исторического макета; раскладка M24): строка активности агента,
карточка выбора пути, карточка плана с кнопками, подтверждение выпуска.

## Публичный интерфейс для бэкенда (`src/index.ts`)

- `SESSION_VIEW_PREFIX` — `/session-view/`.
- `SESSION_VIEW_ASSETS_DIR` — абсолютный путь к `src/`.
- `sessionViewMount() → { prefix, dir }` — монтирование для `http-server`
  (подключает `cli`, `createApp`).

## Подключение к панели

`session-view.js` — расширение панели (`PANEL_EXTENSIONS` в
`panel-shell`): `install(shell)` заполняет слоты `sessionSidebar` и
`sessionReview` (`registerSlot`). Стили — `session-view.css`, подключены в
`index.html` панели.

## Раскладка M24

`sidebar-view.js` регистрирует sessionSidebar, выбирает прежние модели без изменения правил
и сохраняет отдельные узлы карточек по проекту и сессии. Порядок: вопрос, ревью,
подтверждение выпуска, выбор, план, активность. Справа эти карточки больше не рисуются;
sessionBody остаётся совместимым слотом оболочки. Пустое состояние — компактная подпись.
Новый вопрос/действие отмечает кнопку скрытого сайдбара через data-needs-attention.

Таймер или прогресс не пересоздаёт остальные карточки. Черновики форм имеют составной
ключ проект+сессия; раскрытие записей журнала хранится по сессии и содержимому записи,
новая запись раскрывается по умолчанию. Оболочка сохраняет фокус полей при обновлении.
CSS карточек переносит длинные тексты и кнопки; размер колонок не зависит от ширины окна.
Существующие API, подтверждения и условия показа сохраняются.

## Поведение на ОС

Одинаково на macOS, Linux и Windows x64/ARM64: браузерные ES-модули, без веток ОС.
Карточки доступны и в desktop-сайдбаре, и в выдвижной панели iPad/телефона; таймеры
и правила выбора не зависят от вида устройства.

## Инварианты

- Чистая логика в `session-model.js` без DOM; покрыта `node --test`.
- Текст в DOM — только через `textContent`; ширина полосы — через CSSOM.
- Решения пользователя уходят только кнопками; ошибки показываются над
  экраном с подсказкой Kit.
