# M13. ChatGPT на Windows: общий демон Codex через SSH

## Цель и согласование

В 0.7.0 общий доступ к чатам ChatGPT (M12) работает только на macOS: приложение ChatGPT
подключается к этому же компьютеру по SSH и становится клиентом демона Kit. На Windows режим
показан как «Недоступно», и там остаются старые ограничения «единственного писателя»: чат
ревьюера не виден, Kit не пишет в чат, открытый в приложении.

Пользователь, 2026-11-11: «нам обязательно нужно выделить скоп для решения проблем Windows.
Чтобы работа ChatGPT и там была через SSH.»

Результат вехи: на Windows 11 (x64 и ARM64) тот же режим, что на macOS, с той же карточкой
«Общий доступ к чатам». Kit делает всё, что может без прав администратора, а шаги с правами
администратора собирает в один скрипт, который пользователь запускает сам.

## 1. Принципы

1. Как в M12: что Kit может настроить сам — настраивает Kit, после предпросмотра, с копиями
   файлов, с проверкой после записи и с «Убрать настройку».
2. Kit не повышает права. Шаги администратора — один скрипт PowerShell, который Kit пишет в
   каталог данных и показывает: «Запустите от имени администратора». Пользователь видит его
   текст до запуска.
3. Общий код M12 не дублируется: различия ОС — ветки с платформой параметром
   (`platform ?? process.platform`) в модулях `shared-*`, у каждой ветки `win32` — тест.
4. Режим на Windows включается только проверками, а не версией Kit: `active` — когда прошли
   все проверки и приложение подключилось; иначе — точное состояние с причиной. Если проба
   покажет, что схема на Windows не работает, проверки дадут `broken`/`unsupported`, а сессии
   останутся прежними.

## 2. Решение

### 2.1. Что известно и что надо проверить

Известно (код приложения ChatGPT 26.1106, общий для всех ОС; Kit 0.7.0):

- удалённая команда приложения по SSH — POSIX: `sh -c '…'`, требует исполняемый `$SHELL`,
  запускает `exec "$SHELL" -l -i -c …`, затем `/bin/sh -c "$CODEX_REMOTE_PAYLOAD"` и
  `codex app-server proxy`; `PATH` дополняется `$HOME/.local/bin`;
- Kit на Windows уже ходит к демону через `codex app-server proxy` (M5), значит, и удалённая
  команда приложения найдёт демон, если `codex` в `PATH` SSH-сеанса;
- Windows 11 имеет клиент OpenSSH; сервер OpenSSH — необязательный компонент, ставится с
  правами администратора; оболочку SSH-сеанса задаёт `HKLM\SOFTWARE\OpenSSH\DefaultShell`;
- у пользователя-администратора сервер OpenSSH читает ключи из
  `C:\ProgramData\ssh\administrators_authorized_keys` (только с правами SYSTEM и
  Administrators), а не из `~\.ssh\authorized_keys`;
- Git Bash (Git for Windows) уже нужен Kit для Claude и Kimi: в нём есть `sh.exe` и
  `bash.exe`, `/bin/sh` указывает на них.

Проверить на Windows (проба T001, проверяющий на Windows):

1. есть ли в приложении ChatGPT для Windows «Настройки → Подключения → SSH» и находит ли оно
   `Host` из `%USERPROFILE%\.ssh\config`;
2. принимает ли сервер OpenSSH с `DefaultShell` = Git Bash удалённую команду приложения (`sh -c`
   с POSIX-кавычками) и чем приходит `$SHELL`;
3. находит ли `codex app-server proxy` в этом сеансе демон Kit (тот же пользователь, тот же
   `CODEX_HOME`);
4. есть ли и как выглядит в списке процессов подключение приложения (`ssh.exe … wfk-local …`)
   и второй app-server, если переключатель не задан;
5. открывает ли ссылка `codex://threads/<id>?hostId=remote-ssh-discovered%3Awfk-local` чат
   подключения через пакет приложения (`OpenAI.Codex`) и работает ли iPad.

Если пункт 1 или 2 не проходит, веха заканчивается выпуском диагностики: карточка на Windows
называет точную причину, режим остаётся `unsupported`, итог записывается в документ приёмки.

### 2.2. Диагностика и проба (T001)

- Состояние общего доступа на `win32` перестаёт быть безусловным `unsupported`: проверки по
  порядку — `codex` и приложение ChatGPT найдены; служба `sshd` есть и запущена (PowerShell
  `Get-Service sshd`); `DefaultShell` указывает на `sh.exe`/`bash.exe` Git (чтение реестра
  `reg query`); файлы Kit на месте; SSH-проверка `ssh -F … wfk-local` с той же командой, что в
  M12; подключение приложения и второй app-server — по списку процессов CIM. Каждая неудача —
  своё состояние с причиной (`windowsVerdict`, T002), подсказка кончается текстом «Проверено: …
  Не прошло: … Не проверено: …». `DefaultShell` читается через PowerShell
  (`Get-ItemProperty`), а не `reg query`.
- `wfk doctor` на Windows печатает те же строки.
- Документ пробы `docs/evidence/M13-windows-probe.md`: шаги для проверяющего (команды,
  что ожидать, куда записать) по пунктам 2.1.

### 2.3. Настройка на Windows (T002)

Предпросмотр и запись, как в M12, плюс скрипт администратора:

| Что | Кто | Примечание |
| --- | --- | --- |
| ключ `%USERPROFILE%\.ssh\wfk_local` | Kit | `ssh-keygen` из OpenSSH Windows |
| блок `Host wfk-local` в `%USERPROFILE%\.ssh\config` | Kit | тот же текст, путь ключа — `~/.ssh/wfk_local` |
| блок профиля Git Bash `~/.bash_profile` (или первый существующий login-профиль) | Kit | `PATH` с папкой `codex.exe` в записи Git Bash и `CODEX_SSH_SKIP_APP_SERVER_BOOT=true` только для SSH с 127.0.0.1/::1 |
| строка ключа в `~\.ssh\authorized_keys` | Kit | для пользователя без прав администратора |
| скрипт `<данные>\shared-access-admin.ps1` | Kit пишет, пользователь запускает | ставит и запускает `sshd` (автозапуск), задаёт `DefaultShell` на `sh.exe` Git, для администратора дописывает строку ключа в `administrators_authorized_keys` и выставляет её права |

Новое состояние `needs-admin-setup`: файлы Kit на месте, шагов администратора нет (`sshd` не
работает, `DefaultShell` не Git или администратору отказано в ключе). Поле состояния `admin`
(`SharedAccessAdminStep`: `purpose`, `file`, `command`, `text`). Кнопки: «Скопировать команду
запуска» (главная), «Показать скрипт» (текст и путь), «Перепроверить». «Убрать настройку»
убирает записи Kit и скрипт и пишет `shared-access-admin-undo.ps1` для отката (`DefaultShell`,
если он тот же, и строка ключа; `sshd` Kit не удаляет — его ставил пользователь); новая
настройка удаляет скрипт отката.

Решения T002: администратора Kit узнаёт по `whoami /groups` (S-1-5-32-544 — членство, и при
урезанном токене UAC); `sh.exe` Git ищется рядом с `git.exe`, затем в Program Files и
`%LOCALAPPDATA%\Programs`; скрипт — UTF-8 с BOM, CRLF, только ASCII (Windows PowerShell 5.1
читает файл без BOM как ANSI); Kit не просит повышения прав сам (без `Start-Process -Verb
RunAs`).

### 2.4. Сессии и ссылки на Windows (T003)

- Режим включается на Windows тем же состоянием `active`; ссылки с `hostId`, создание без
  выгрузки, `wakeSession`, ревьюер первым сообщением — общий код M12.
- `open-link` на Windows передаёт ссылку с `hostId` пакету `OpenAI.Codex` (PowerShell) без
  потери параметра; тест с подставленной платформой.
- Передача управления M7 на Windows пропускается в режиме (уже общий код); распознавание
  второго app-server и подключения — по командным строкам CIM; собственный app-server
  приложения (пакет `WindowsApps\OpenAI.Codex…`) вторым не считается.
- `open('connections')` на Windows — тот же PowerShell пакета `OpenAI.Codex`;
  `open('remote-login')` — `not-supported`.

## 3. Поведение на ОС

| | macOS | Linux | Windows |
| --- | --- | --- | --- |
| Режим общего демона | как в 0.7.0 | `unsupported`: приложения ChatGPT нет | новый: диагностика, настройка Kit + скрипт администратора, `active` после проверок |
| Сервер SSH | «Удалённый вход» (пользователь) | — | OpenSSH Server, `DefaultShell` = Git `sh.exe` (скрипт администратора) |
| Профиль оболочки SSH-сеанса | zsh/bash, как в 0.7.0 | — | Git Bash login-профиль |
| Ключ в authorized_keys | `~/.ssh/authorized_keys` | — | обычный пользователь — `~\.ssh\authorized_keys`; администратор — `administrators_authorized_keys` (скрипт) |
| Список процессов | `ps` | — | CIM `Win32_Process` через PowerShell |
| Ссылка чата с `hostId` | `open` | — | PowerShell, пакет `OpenAI.Codex` |

Новых прямых вызовов программ одной ОС нет: PowerShell запускает общий помощник
`powershell` модуля `process-supervisor` (уже в `tools/platform-guard/allowlist.json`), реестр
читается из PowerShell.

## 4. Проверка

- Автоматические тесты (все ОС, платформа подставлена): состояния на `win32` по каждой
  проверке, предпросмотр и запись файлов Windows, текст скрипта администратора (ключ, права,
  `DefaultShell`), выбор файла ключа для администратора, откат, разбор CIM-строк подключения и
  второго app-server, ссылка с `hostId` в PowerShell-команде; macOS и Linux без изменений.
- CI: macOS, Linux, Windows x64 и ARM64.
- Живая проверка: Windows — проверяющий на Windows (проба T001 по документу пробы, затем
  настройка с нуля, сессия ChatGPT на Windows и на iPad одновременно, ревьюер ChatGPT, откат);
  macOS — пользователь (режим 0.7.0 не сломан); Linux — только CI.

## 5. Границы

- Kit не запускает ничего с правами администратора сам и не меняет политику выполнения
  скриптов системы (скрипт запускается с `-ExecutionPolicy Bypass` в команде, которую копирует
  пользователь).
- WSL как SSH-цель не рассматривается: в WSL свой `codex`, это не демон Kit.
- Если проба покажет, что приложение ChatGPT для Windows не умеет SSH-подключения или не
  работает с Git Bash, режим остаётся `unsupported` с причиной; обход — отдельная веха.
