# Установка и использование Workflow Kit

Руководство для версии **0.8.1**. Краткое описание приложения — в
[README](../README.md), изменения версий — в [CHANGELOG](../CHANGELOG.md).

## Поддержка ОС

| Возможность | macOS | Linux | Windows |
| --- | --- | --- | --- |
| Установщик, бэкенд, HTTP-панель | Реализованы, есть живые проверки | Реализованы, проверены тестами | Реализованы, проверены тестами |
| Интеграция Claude | Реализована | Реализована, нужен `expect` | Реализована через ConPTY (с 0.5.0) |
| Интеграция Codex | Реализована | Реализована | Реализована, Codex 0.160+ (с 0.5.0) |
| Интеграция Kimi Code (с 0.6.0) | Реализована, Kimi Code 2.5.2+ | Реализована, проверена тестами | Реализована, проверена тестами |
| Общий доступ к чатам ChatGPT (с 0.7.0) | Реализован, Kit настраивает сам | Нет: приложения ChatGPT нет | С 0.8.0: Kit и скрипт администратора, проверен вживую; нужен включённый UAC |
| Папка проектов вне домашней (с 0.8.1) | Тома `/Volumes/*` | `/media/<пользователь>/*`, `/run/media/<пользователь>/*`, `/mnt/*` | Другие диски; на системном — только домашняя папка |
| Подтверждение полного сценария на устройстве | См. документы приёмки | Нет | Установка и общий доступ (M13, M14) |

Поддержка Windows 11 (x64 и ARM64) появилась в 0.5.0 и повторяет возможности macOS:
сессии Claude и ChatGPT/Codex, ревью, выполнение плана и автопилот. Вживую проверены
установка и общий доступ ChatGPT, остальное — тестами. Контроль учётных записей (UAC)
должен быть включён. Тесты Linux имитируют команды ОС. Windows 10, Windows Server и WSL
отдельно не поддерживаются.
Kimi Code вживую проверяется только на macOS: на Linux и Windows статус провайдера
несёт пометку «на этой ОС не проверялся».

## Требования

- Node.js **24+**, доступный в терминале как `node`. Runtime-зависимостей npm
  нет; `npm ci` нужен для разработки и проверок.
- Git: для клонирования, подготовки управляемых проектов и коммитов их задач.
  Для коммитов нужна настроенная пользователем Git-личность.
- Claude Code (`claude`, 2.1.0+) и `expect` для Claude, Codex (`codex`) для
  ChatGPT/Codex, установленные отдельно и авторизованные средствами провайдера.
  Для ревью другим провайдером нужны оба. Kit их не скачивает и не авторизует.
  На Windows `expect` не нужен (Kit управляет терминалом Claude через встроенный
  ConPTY); нужны `claude.exe` (нативный установщик кладёт его в
  `%USERPROFILE%\.local\bin`) и `codex.exe` версии 0.160 или новее.
- Kimi Code (`kimi`, 2.5.2+) для сессий Kimi: `kimi login` и выбор модели. Пока открыто
  приложение Kimi Code, Kit работает через его сервер, иначе запускает свой `kimi web` на
  127.0.0.1. Хук Kit пишется в `config.toml` каталога Kimi (`~/.kimi-code` или
  `KIMI_CODE_HOME`), общий для всех проектов; Kimi читает его только при запуске (Kit напомнит
  перезапустить приложение). План Kimi идёт последовательно или с исполнителями (`Agent` в
  отдельных worktree); ревьюер плана Kimi — ChatGPT.
- Приложения Claude Desktop, ChatGPT и Kimi Code — для открытия чатов по ссылкам. Нужно
  именно **Kimi Code**, а не приложение «Kimi»: команды установки, вход и ссылки на загрузку —
  в README, раздел [«Установка шаг за шагом»](../README.md#установка-шаг-за-шагом). Проект
  Kimi служба открывает в приложении параметром `--workspace` (без нового пустого чата).
- Браузер для веб-панели. Tailscale нужен только для удалённого доступа.
- На macOS инструменты командной строки Xcode со `swiftc` позволяют установщику
  собрать отдельное окно приложения. Если сборка недоступна, создаётся значок,
  открывающий панель в браузере; причина указывается в отчёте установки.

Наличие программ проверяют `node --version`, `git --version`, `claude --version`,
`codex --version`, `kimi --version` и `expect -v`; отсутствующий провайдер панели не мешает.

## Получение локальной копии

В терминале выберите папку, в которой хотите хранить исходники:

```sh
git clone https://github.com/OleynikAleksandr/Workflow_Kit.git
cd Workflow_Kit
```

Альтернатива: на [GitHub](https://github.com/OleynikAleksandr/Workflow_Kit)
выберите **Code → Download ZIP**, распакуйте архив и перейдите терминалом
в полученную папку `Workflow_Kit-main`. Распакованная ZIP-копия не содержит
историю Git, поэтому для её обновления скачивайте новый архив.

Все команды `node bin/wfk.mjs …` ниже выполняются **из корня этой папки** (там
`package.json` и `bin`), в PowerShell тоже; путь с пробелами при `cd` берите в кавычки.

## Установка службы

```sh
node bin/wfk.mjs install
```

Установка выполняется для текущего пользователя. Не запускайте её через
`sudo` или из-под другого пользователя: служба должна видеть ваши провайдеры
и настройки. Windows-установщик не требует прав администратора.

Установщик:

1. Копирует приложение в `app/<версия>` пользовательского каталога данных.
2. Запоминает пути Node.js, программ провайдеров и окружение PATH.
3. Создаёт команду `wfk`, значок приложения и автозапуск при входе пользователя.
4. Запускает службу и ждёт ответа HTTP-проверки работоспособности.

Не задавайте `WFK_DATA_DIR` при обычной установке: с ним создаётся отдельный
экземпляр без системного значка, запускателя и автозапуска.

Установленная копия не зависит от дальнейшего перемещения исходников.
Сам Node.js остаётся внешней программой и должен быть доступен по сохранённому
пути. После изменения его расположения повторите установку из исходников.

## Запускатель и PATH

После установки откройте значок **Workflow Kit** либо новый терминал:

```sh
wfk open
wfk doctor --installed
```

Если `wfk` не найдена:

- **macOS/Linux:** установщик создаёт `~/.local/bin/wfk`. Добавьте
  `~/.local/bin` в PATH своей оболочки или запустите `~/.local/bin/wfk open`.
- **Windows:** установщик добавляет каталог запускателя в пользовательский PATH.
  Откройте новый терминал. Windows Terminal видит новый PATH только после полного
  закрытия всех его окон; установщик печатает и прямую команду запуска.
  Рядом с `wfk.cmd` лежат `wfk` (для Git Bash, где работает инструмент Bash Claude Code)
  и `wfk.mjs`, через который вызываются хуки Kit.
  Прямой вызов в PowerShell:

  ```powershell
  & "$env:LOCALAPPDATA\Workflow Kit\wfk.cmd" open
  ```

Из исходной папки также доступны `node bin/wfk.mjs open` и
`node bin/wfk.mjs doctor --installed`.

## Что создаётся в каждой ОС

| | macOS | Linux | Windows |
| --- | --- | --- | --- |
| Данные и настройки | `~/Library/Application Support/Workflow Kit` | `~/.config/workflow-kit` | `%LOCALAPPDATA%\Workflow Kit` |
| Копии приложения | `<данные>/app/<версия>` | `~/.local/share/workflow-kit/app/<версия>` | `<данные>\app\<версия>` |
| Состояние и журналы | В каталоге данных | `~/.local/state/workflow-kit` | В каталоге данных |
| Запускатель | `~/.local/bin/wfk` | `~/.local/bin/wfk` | `<данные>\wfk.cmd`, `wfk`, `wfk.mjs` |
| Значок | `~/Applications/Workflow Kit.app` | `~/.local/share/applications/workflow-kit.desktop` | «Пуск» → Workflow Kit |
| Автозапуск | LaunchAgent пользователя | systemd пользователя или XDG autostart | Ключ пользователя HKCU Run |

На Linux переменные `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_STATE_HOME`
могут изменить приведённые стандартные каталоги.

- **macOS:** LaunchAgent `ai.workflowkit.backend` запускает бэкенд при входе
  и поддерживает его работу; приложение показывает панель в собственном окне,
  а при недоступной сборке — в браузере.
- **Linux:** если доступен `systemctl --user`, ставится
  `workflow-kit.service` с перезапуском при сбое. Иначе используется
  `~/.config/autostart/workflow-kit.desktop` для входа в графическую среду.
  Панель открывается отдельным окном Chrome/Edge/Chromium или браузером
  по умолчанию. Это пользовательский автозапуск, работа до входа не настраивается.
- **Windows:** создаются `wfk-service.vbs` и `wfk-open.vbs`, ярлык в «Пуске»
  и запись `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.
  Бэкенд запускается без консольного окна при входе пользователя;
  системная Windows Service не создаётся. Панель открывается в окне
  Chrome (с 0.8.1), без него — Edge или браузера по умолчанию. Нужны доступные Windows Script Host
  и PowerShell; политика компьютера может ограничивать их запуск.
  Устанавливайте из **обычного** терминала, не от имени администратора: демон Codex
  с повышенными правами не работает, и `wfk install` предупреждает об этом. По той же причине
  UAC должен быть включён: при `EnableLUA = 0` любой процесс получает права администратора.
  Службу установщик останавливает штатно, запросом `POST /api/system/shutdown`.
  Хук Claude на Windows записывается в виде «программа и аргументы»
  (`node.exe` и `wfk.mjs`), хук Codex — с полем `commandWindows`. Поэтому проект,
  который открывают попеременно на Mac и на Windows, после смены ОС показывает
  структуру как «устарело»; обновление структуры переписывает хук под текущую ОС.
  Чаты ChatGPT открываются через приложение из Microsoft Store (`OpenAI.Codex`),
  сессии Claude — через ссылку `claude://` в Claude Desktop.

## Общий доступ к чатам ChatGPT

У Codex чатом владеет один процесс. Без настройки их два — демон Kit и процесс внутри
приложения ChatGPT, — поэтому чат не может быть одновременно открыт в Kit и в приложении. С
настройкой приложение ChatGPT подключается к этому же компьютеру по SSH (подключение
`wfk-local`) и работает через демон Kit, как и iPad с телефоном.

Карточка «Настройки» → «Общий доступ к чатам · ChatGPT» показывает состояние и кнопки:
«Не настроено» → «Настроить»; «Нужен «Удалённый вход»» → «Открыть настройки macOS»; «Нужно
подключение в ChatGPT» → «Открыть подключения ChatGPT»; «Работает»; «Не работает» — с причиной.
`wfk doctor` печатает то же состояние строкой «ChatGPT: общий доступ к чатам».

Что пишет Kit после предпросмотра (перед записью — копии файлов в каталоге `backups` данных):

| Файл | Что |
| --- | --- |
| `~/.ssh/wfk_local`, `~/.ssh/wfk_local.pub` | ключ ed25519 только для этого подключения (существующий не меняется) |
| `~/.ssh/authorized_keys` | строка ключа с `from="127.0.0.1,::1"`: войти им можно только с этого Mac |
| `~/.ssh/config` | блок `Host wfk-local` (127.0.0.1, ваш пользователь, этот ключ) |
| `~/.zshenv` (zsh) или первый из `~/.bash_profile`, `~/.bash_login`, `~/.profile` (bash) | блок: в SSH-сеансах с этого Mac — путь к `codex` и `CODEX_SSH_SKIP_APP_SERVER_BOOT=true`, чтобы ChatGPT не поднимал второй процесс Codex |

Блоки стоят между `# >>> workflow-kit >>>` и `# <<< workflow-kit <<<`; чужие строки Kit не
трогает. Для другой оболочки карточка показывает блок для ручной вставки. «Удалённый вход»,
подключение в приложении ChatGPT и сами настройки ChatGPT Kit не меняет. «Убрать настройку»
удаляет всё из таблицы.

Kit раз в минуту проверяет, что схема работает. Если что-то сломалось (например, ChatGPT после
обновления поднял второй процесс Codex), карточка показывает «Не работает», а сессии ChatGPT сами
возвращаются к прежнему поведению, пока проверка снова не пройдёт.

На Linux приложения ChatGPT нет: карточка показывает «Недоступно», чаты работают как раньше.

### Windows

Нужны Git for Windows (его `sh.exe` — оболочка SSH-сеансов), клиент OpenSSH и приложение
ChatGPT. Kit пишет те же ключ и `~/.ssh/config`, блок в `~/.bash_profile` (профиль Git Bash),
строку в `~/.ssh/authorized_keys` (если вы не администратор) и скрипт
`shared-access-admin.ps1` в каталоге данных. Скрипт Kit не запускает: в состоянии «Нужен шаг
администратора» карточка показывает его текст и команду для PowerShell, открытого от имени
администратора. Скрипт ставит и запускает сервер OpenSSH (`sshd`, автозапуск), задаёт
`DefaultShell` = `sh.exe` Git — это оболочка всех входов по SSH на компьютер — и
администратору дописывает ключ в `%ProgramData%\ssh\administrators_authorized_keys` с правами
только `SYSTEM` и `Administrators`. «Убрать настройку» удаляет записи Kit и скрипт и пишет
`shared-access-admin-undo.ps1`: он снимает `DefaultShell` и ключ, сервер OpenSSH остаётся.
`wfk doctor` печатает и строку «ChatGPT: проверки общего доступа» — что прошло и что нет.

## Панель и удалённый доступ

`wfk open` поднимает службу, если она не работает, и открывает
[http://127.0.0.1:4747/](http://127.0.0.1:4747/). Один процесс обслуживает
и веб-панель, и API; отдельно запускать фронтенд не нужно.
Закрытие панели не останавливает бэкенд.

Для доступа с iPad/телефона подключите компьютер и устройство к вашей сети
Tailscale. Служба печатает доступные адреса при `serve`; используйте адрес
компьютера в Tailscale с портом 4747. Адрес `127.0.0.1` на iPad относится
к самому iPad, а не к компьютеру со службой. Панель можно добавить на экран
«Домой». Открытие чата провайдера на мобильном устройстве может потребовать
нажатия по карточке сессии; полной одинаковой работы всех платформ не заявляем.

Панель принимает подключения только через loopback и Tailscale и не имеет
отдельного входа с паролем. Доступ к этой машине в Tailscale должен быть только
у доверенных пользователей. Публичное размещение HTTP-панели не предусмотрено.

## Управление, обновление и удаление

```sh
wfk service status
wfk service stop
wfk service start
wfk doctor --installed
```

Остановка службы не останавливает автоматически работающие процессы
провайдеров. Управляйте сессиями через панель и приложения провайдеров.

Для обновления Git-копии перейдите в исходную папку с чистым рабочим деревом:

```sh
git pull --ff-only
node bin/wfk.mjs install
wfk doctor --installed
```

Если есть локальные изменения или Git отказал, сначала сохраните и согласуйте
их; не сбрасывайте их ради обновления. Для ZIP скачайте и распакуйте новую
версию в другую папку, затем выполните `install` из неё.
Повторная установка перезапускает службу на новой версии и сохраняет данные.
Остаются текущая и одна предыдущая установленная версия. В открытых панелях
0.4.4+ смена версии вызывает автоматическую перезагрузку; при необходимости
перезагрузите окно вручную.

```sh
wfk uninstall
```

Удаление останавливает службу и снимает автозапуск, запускатель, значок
и установленные копии приложения. Настройки, реестр проектов, журналы,
сессии и резервные копии конфигов сохраняются; исходная папка репозитория
и папки ваших проектов этой командой не удаляются.

## Запуск из исходников и разработка

Из корня локального репозитория можно запустить сервер без установки:

```sh
node bin/wfk.mjs serve
```

Откройте адрес, напечатанный в терминале. Сервер работает до `Ctrl+C`;
значок и автозапуск при таком запуске не устанавливаются. Обычный `serve`
использует те же данные и порт, что установленная служба. Для второго
экземпляра нужны отдельные данные и порт — [пример](#отдельный-экземпляр-для-разработки).

Для разработки и автоматических проверок дополнительно установите
зависимости из lock-файла:

```sh
npm ci
npm run typecheck
npm test
```

Тесты используют временные каталоги и подставные провайдеры; пользовательские
конфиги, службу и порт 4747 они не изменяют. `npm run check:platforms` проверяет,
что код и спецификации рассчитаны на macOS, Linux и Windows. CI на GitHub
выполняет проверку типов, тесты и эту проверку на macOS, Linux, Windows x64 и ARM64. Правила разработки проекта —
в [AGENTS.md](../AGENTS.md).

## Отдельный экземпляр для разработки

Чтобы не занимать данные и порт установленной службы, задайте свои.

macOS/Linux:

```sh
WFK_DATA_DIR="$HOME/wfk-dev-data" WFK_PORT=4848 node bin/wfk.mjs serve
```

Windows PowerShell (лучше в отдельном окне терминала):

```powershell
$env:WFK_DATA_DIR = "$env:TEMP\wfk-dev-data"
$env:WFK_PORT = "4848"
node bin/wfk.mjs serve
```

После работы удалите переменные: `Remove-Item Env:WFK_DATA_DIR, Env:WFK_PORT`.

Данные Kit будут отдельными, но это не полная изоляция провайдеров:
служба всё ещё может использовать установленные `claude`/`codex`/`kimi` и их
пользовательское окружение. Для автоматических тестов проект подставляет
программы и временное окружение отдельно.

## Если что-то не работает

- `node` не найден или версия ниже 24: установите подходящий Node.js
  и откройте новый терминал.
- Не найден `bin/wfk.mjs`: проверьте текущую папку; команды выполняются
  из корня распакованного или клонированного репозитория.
- Порт занят: проверьте `wfk service status`; не запускайте второй обычный
  `serve` поверх установленной службы.
- Панель не открылась: выполните `wfk doctor --installed` и проверьте
  напечатанный адрес. `wfk open --url-only` запускает службу и печатает адрес
  без открытия браузера.
- Провайдер недоступен: прочитайте причину в мастере проекта, проверьте
  его установку, вход и возможности вашей ОС. На Windows Codex старее 0.160
  показан как «нужна новее версия»; обновите его и нажмите «Перепроверить».
- ChatGPT пишет «Этот чат открыт в другом приложении»: открыта локальная копия чата (без
  значка глобуса). Откройте чат из панели Kit — ссылка ведёт в копию подключения `wfk-local`.
- На iPad «Эта задача используется в другом сеансе Codex» при общем доступе: удалённое
  управление держит приложение ChatGPT на Mac (панель говорит об этом у провайдера). Закройте
  ChatGPT, подождите, пока демон станет «подключён», и откройте ChatGPT снова.
- Общий доступ «Не работает»: причина и что делать — в карточке; затем «Перепроверить» или
  «Настроить ещё раз».
- Windows, «Нужен шаг администратора» после скрипта: `Get-Service sshd` должен быть
  `Running`; затем «Перепроверить».
- Windows, у ChatGPT «демон не запускается», в приложении «socket hang up»: выключен UAC.
  В PowerShell от имени администратора:
  `Set-ItemProperty HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System -Name EnableLUA -Value 1`,
  затем перезагрузка.
- Автозапуск не работает: `wfk doctor --installed` проверяет запись
  автозапуска и версию отвечающей службы. Журнал службы — `logs/service.log`
  в каталоге состояния из таблицы выше.
