# M24: проверка раскладки в браузере

Часть [спецификации M24](../planning/M24-interface-polish.md). Проверяется реализованный
UI, не снимок старого экрана. Инструмент доступен основному агенту: Playwright MCP
(`browser_run_code_unsafe` для `page.route`/действий/замеров, `browser_evaluate`,
`browser_take_screenshot`). Установка DOM-пакетов и нового браузерного инструментария
не требуется. Node-тесты проверяют чистые модели, а не выдают себя за браузерные проверки.

## Изоляция и подставное состояние

Временный HTTP-сервер из `/tmp` отдаёт исходные статические ES-модули панели под штатными
URL (`/`, `/session-view/`, `/session-chat/`, `/project-wizard/`), с текущим CSP, без
запуска службы, провайдеров, сессий и автопилота. В Playwright до навигации поставить
`page.route` на `/api/**`: ответы `/api/state` и переписки — подставные, POST/DELETE
моделируются в памяти, неизвестный API-запрос отклоняется. Никакой запрос не проходит
в настоящую службу. Скрипт и JSON fixtures — в `/tmp`, не в runtime Kit и не в git.
Точные команды, соответствие URL и проверенные состояния записываются в evidence.

Формы fixtures берутся из отслеживаемых тестов моделей panel-shell/session-view/session-chat
и актуальных публичных типов. Это несколько **согласованных состояний**, а не один
невозможный снимок со всеми одновременно видимыми карточками:
- проект с нулём, одной и несколькими сессиями; многострочные имена разной высоты;
- вопрос о плане; предложение выбора режима; активное ревью с длинным журналом;
- ready/start-pending/running/paused/blocked/ready-for-acceptance/accepted план;
- подтверждение выпуска, форма исправлений, пустое состояние без плана;
- working/holding/waiting/unknown, поддерживаемый и недоступный Stop;
- лента пустая/длинная/неподдерживаемая, ошибка, длинный ввод и длинные подписи;
- мастер проекта на каждом длинном шаге, настройки, архив, раскрытые меню.

Переключения fixture имитируют опрос и переходы состояний; тестовые кнопки меняют только
подставную модель. Проверить сохранность фокуса, ввода и прокрутки, в том числе после
второго/третьего опроса. Не менять настоящие проекты, сессии, разрешения или демоны.

## Когда и что проверять

**T001 до коммита:** раскладка, перенос карточек, все слоты и условия показа; линии дерева
при разной высоте карточек/изменении ширины; drag/cancel/клавиатура/хранилище; drawer и
фокус; сохранность форм/журнала/ленты; прокрутка мастера/архива/настроек. Файлы T001
включают CSS session-chat, его контракт, `docs/evidence/M24-acceptance.md` и
`docs/evidence/M24/`. Исправления этих дефектов делаются в T001 до её завершения.

**T006 до коммита:** новый ввод и его состояния, фактические данные, микрофон/плюс,
Enter/Stop, очередь и holding, IME, ошибки/тайм-ауты, отсутствие дубликатов. Повторная
интеграционная проверка раскладки. Если найдена новая ошибка завершённой T001 — отдельный
fixes-раунд через Kit; T006 не меняет завершённую задачу и не выходит за список файлов.

Для обеих задач: размеры 1920×1080, 1280×800, 1024×768, 768×400, 375×667 CSS px; обе темы,
масштаб 200%, поворот/уменьшение окна. Замеры DOM: границы ввода и кнопок внутри viewport,
нет горизонтального/вертикального overflow страницы сессии, есть работающая внутренняя
прокрутка содержимого. Скриншоты в `docs/evidence/M24/` и результаты с SHA в
`docs/evidence/M24-acceptance.md`. Переходы экранной клавиатуры и реальный touch на iPad
остаются отдельной живой проверкой пользователя, не имитируются одним resize.

## Поведение на ОС

Одинаковый браузерный UI macOS, Linux и Windows x64/ARM64; модель не определяет ОС.
Локальная Playwright-проверка на Mac не объявляется живой проверкой Windows/Linux.
macOS/iPad — пользователь; Windows — проверяющий; Linux — CI, матрица по основному документу.
