## Конец плана (M37)

Спецификация — [M37](../../../../../../docs/planning/M37-plan-close-flow.md), раздел 2.4.

- **Файлы вне коммитов.** `planView` отдаёт `dirty` — пути из `plan.dirty` службы (фазы
  `acceptance` и `accepted`; без поля — пустой список). При непустом списке карточка плана под
  списком задач показывает блок `.sv-dirty`: предупреждение `sv-warn` «В папке проекта есть
  файлы вне коммитов: `a`, `b` (и ещё N). Пока они есть, план не закроется.» (до пяти путей,
  каждый — `code`) и кнопку «Попросить агента убрать» → `POST …/workflow/tidy { session }`,
  ошибка — «Не удалось попросить агента» с текстом службы. Кнопки «Принять план» и «Закрыть
  план» остаются активными; отказ закрытия на грязном дереве приходит от службы по-русски.
- **Карточка «Ревью плана».** `crossReviewView` отдаёт `current`: `scopeId` ревью равен
  `scopeId` открытого предложения проекта (`workflow.projects[id].proposal`, сравнение как в
  службе — предложение без id равно ревью без id) или активного scope (`.plan.scopeId`,
  `.scope.id`). `showsReview(data)` (`sidebar-view.js`): идущее ревью и карточка в сессии
  ревьюера — всегда; законченное ревью основной сессии — только при `!plan && current`. После
  закрытия плана и после предложения другого scope карточка исчезает; пустое состояние
  считается по тому же правилу.
- **Тексты.** Решение о ревью при «да»: «Следующий план этой сессии проверит ревьюер — так
  решено ответом на вопрос о плане.» `REASON_LABELS`: `accepted` — «План принят», `closed` —
  «План закрыт» (те же тексты, что `STOP_LABELS` автопилота); строка активности показывает
  метку службы.
- Тесты — `test/plan-close.test.ts`.
