# M3: всё нужное поднимается при старте службы

Скоуп `m3-autostart` (после закрытого `m3-fixes`).

## 1. Замечание

2026-11-07, после перезагрузки Mac: на главном экране индикатор ChatGPT оранжевый —
«демон не запущен». Демон Codex (`codex remote-control start`) Workflow Kit запускал только по
кнопке «Запустить демон», а после перезагрузки его никто не запускает.

## 2. Решение пользователя (2026-11-07)

Служба Workflow Kit — LaunchAgent, macOS запускает её при входе в систему; без службы панель
не работает ни на Mac, ни на iPad и телефоне. Поэтому всё, что нужно Workflow Kit, служба
поднимает при своём старте, без кнопок и подтверждений:

- **Демон Codex.** Codex установлен (не Windows), демон не работает или работает, но не
  подключён к ChatGPT (`disabled` / `errored`) — служба выполняет `codex remote-control start`.
  Подключается (`connecting`) или подключён — не трогает. Неудача пишется в журнал и
  повторяется: всего 3 попытки с паузой 30 с (сразу после входа в систему сеть и вход Codex
  могут быть ещё не готовы). Индикатор показывает обычное состояние демона.
- **Окружения Remote Control папок Claude.** Окружение, запущенное кнопкой проекта и не
  остановленное намеренно (`processId` есть, `stoppedAt` нет), процесс не жив — поднимается
  так же, как прерванные сессии (раунд R9); проекты из архива не трогаются.
- При остановке службы (в том числе при обновлении) демон Codex и процессы Claude не
  останавливаются.

## 3. Контракт

- `Provider.autostart?()` — поднять то, что провайдеру нужно на весь Mac, при старте службы;
  ответ — строка для журнала или `null`, если ничего делать не нужно. Codex — демон.
- Реестр: `autostart()` → `{ started: string[], errors }` по провайдерам.
- Claude `resumeInterrupted(project)` поднимает и прерванное окружение проекта; в ответе —
  `environment` среди id.

## 4. Раунд 2: удалённое управление держит приложение ChatGPT

Найдено 2026-11-07 при проверке 0.3.7: демон Codex запустился сам, но его соединение с ChatGPT
`errored`; журнал Codex (`~/.codex/logs_2.sqlite`, процесс демона) — `409 Conflict … "Remote
app server already online"`. Встроенный `codex app-server` приложения ChatGPT (тот же
`~/.codex`, та же установка) сам включает удалённое управление (`remoteControl/enable`) и уже
подключён; второе соединение сервер не пускает. Служба показывала это как «ошибка входа».

Решение:
- Зонд демона читает последнее предупреждение удалённого управления процесса демона в
  `logs_<N>.sqlite` (новейший файл, только чтение, `node:sqlite`); «Remote app server already
  online» при несоединённом демоне — `remoteOwner: 'app'`.
- Такое состояние — рабочее: индикатор «готов», подпись «через приложение ChatGPT»; создание
  сессий доступно (демон отвечает по сокету, треды общие в `~/.codex`, iPad видит их через
  приложение); действия демона нет (причина — соединение держит приложение ChatGPT); это не
  ошибка входа; автозапуск ничего не делает и не повторяет.
- Закроется приложение ChatGPT — демон сам переподключится (его повторы), состояние станет
  «демон подключён».

## 5. Раунд 3: создание сессии при соединении у приложения ChatGPT

Найдено пользователем 2026-11-07 (0.3.8, мастер проекта R002): индикатор ChatGPT готов, но шаг
«Первая сессия» остановился — «Демон Codex не подключён к ChatGPT». `createSession` проверяет
соединение демона отдельно (`errored` — отказ `codex-login`) и не учитывает `remoteOwner: 'app'`.
Решение: при `remoteOwner: 'app'` создание сессии идёт как при подключённом демоне.

## 6. Раунд 4: щелчок по карточке сессии ChatGPT открывает чат

Замечание пользователя (2026-11-07, 0.3.9): у сессии ChatGPT, как раньше у Claude, на экране
сессии ссылка «Открыть чат», а щелчок по карточке сессии чат не открывает — сессия в ChatGPT
не видна.

Решение:
- Щелчок (или Enter) по карточке сессии ChatGPT в дереве открывает её чат по ссылке для этого
  устройства (`codex://threads/<id>`: приложение ChatGPT на Mac, на iPad — приложение iPad) и
  показывает экран сессии. Открытие экрана по адресу, обновлению или из уведомления чат не
  открывает.
- «Открыть чат» убирается с экрана сессии и из меню сессии; в заголовке — строка «чат
  открывается щелчком по карточке сессии» (у сессии без ссылки — её пояснение).

## 7. Раунд 5: новая сессия открывается сама; удаление проекта удаляет треды ChatGPT

Пожелания пользователя (2026-11-07, 0.3.10):

1. Новая сессия, как только она появилась в дереве панели, «щёлкается» сама: экран сессии и,
   у ChatGPT, её чат в приложении (у Claude щелчок поднимает сессию, как раньше).
   - Мастер проекта переходит к сессии через `openSession(projectId, key)` контекста слотов;
     «Новая сессия» на экране проекта ждёт появления сессии этого провайдера в проекте
     (создана не раньше запроса, ожидание до 3 минут).
   - Автооткрытие чата — переходом по ссылке (`location.assign`): окно Workflow Kit на Mac
     отдаёт внешние ссылки системе и без жеста пользователя; щелчок по карточке — как в R4.
2. Удаление проекта с диска удаляет его треды в ChatGPT (раздел 11.1 `M3-fixes.md`, часть
   ChatGPT): перед удалением папки служба отдаёт демону `thread/delete { threadId }` для каждой
   сессии ChatGPT проекта (записи панели и журнал хуков из папки). Неудача (демон не запущен,
   ошибка треда) пишется в журнал и удаление проекта не отменяет. Уборка проекта только из
   списка (папка остаётся) треды не трогает. Claude — без изменений (облачные сессии Remote
   Control локально не удаляются).

## 8. Раунд 6: тред, занятый приложением ChatGPT, удаляется позже

Найдено пользователем 2026-11-08 (0.3.11): проект S002 удалён с диска, а тред «Склад — анализ
остатков» остался в ChatGPT. Журнал службы: `thread/delete` — «thread … already has an active
writer»: файл треда держит открытым встроенный `codex app-server` приложения ChatGPT (чат был
открыт). У S001 и H001 — «no rollout found»: файла треда уже нет.

Решение:
- «no rollout found» — тред уже удалён, это успех.
- Отказ «active writer» (и другой отказ, кроме «нет треда») — тред попадает в очередь
  удаления `sessions/codex-deleting.json` (id, проект, время). Служба повторяет
  `thread/delete` для очереди раз в минуту и при старте; удалённый или исчезнувший тред
  уходит из очереди, через 7 дней попыток — тоже (строка в журнале).
- Пока тред в очереди, приложение ChatGPT может его показывать: его отпускает переход к
  другому чату или закрытие приложения.

## 9. Раунд 7: удаление проекта убирает его следы в ChatGPT и Claude на Mac

Найдено 2026-11-08: тред S002 удалён (`thread/delete`), а строка «Склад — анализ остатков»
осталась в «Недавних» ChatGPT и после перезапуска. Приложение строит список по своему каталогу
`~/.codex/sqlite/codex.db` (таблица `local_thread_catalog`), `thread/delete` его не трогает. Проверено
с согласия пользователя: копия `codex.db`, удаление записей треда из `local_thread_catalog`,
`local_thread_catalog_scan_entries`, `thread_timeline_ledger` — после перезапуска ChatGPT строка
пропала, приложение работает.

Пользователь предложил отдельные папки настроек ChatGPT и Claude на каждый проект; отклонено:
приложение ChatGPT видит только `~/.codex`, удалённое управление — одно на установку, вход и общие
настройки пришлось бы размножать, облачные сессии Claude это не убирает.

Решение (согласие пользователя 2026-11-08 «Делай тогда так. Как предлагаешь»):
- ChatGPT: тред, удалённый демоном (или исчезнувший), убирается и из каталога приложения
  (`<CODEX_HOME>/sqlite/codex.db`, три таблицы выше). Перед записью — копия базы в
  `backups/codex.db-<время>/` (хранятся 5 последних), после — проверка, что записей нет. Нет
  базы или записей — ничего не пишется; ошибка — строка в журнале, удаление проекта идёт дальше.
  Список ChatGPT обновится после перезапуска приложения.
- Claude: удаление проекта с диска выполняет `claude purge <папка> -y` (транскрипты, память,
  история ввода, запись проекта в `~/.claude.json` — только на этом Mac; сессии claude.ai не
  удаляются). Ошибка — строка в журнале.

## 10. Раунд 8: без карточки «Сообщение агенту»

Решение пользователя 2026-11-08 («удали, пожалуйста, эту карточку. Она бессмысленна»): на экране
сессии больше нет карточки «Сообщение агенту» (поле и «Отправить агенту»). Писать агенту удобнее в
самом чате Claude или ChatGPT. Маршрут службы `POST …/sessions/:key/message` остаётся, панель его не
вызывает. Строка активности и карточка плана — без изменений. Новый релиз.
