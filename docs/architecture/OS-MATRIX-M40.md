# Матрица ОС: M40 (решения пользователя)

Часть [матрицы ОС](OS-MATRIX.md): строки вехи M40 перенесены сюда дословно, чтобы основной
документ оставался в пределах размера. Правила те же: каждое изменение дополняет таблицу в
том же коммите.

| Возможность | macOS | Linux | Windows |
| --- | --- | --- | --- |
| M40 T001: Kit 2.4.0 — режим `decisions` (`host`/`agent`), запросы решений (`USER_DECISION_REQUIRED`, реестр `.harness/workflow/local/decisions.json`), операции хоста `--decision` с билетом, `status.decisions`, источник `grant` | общий Node-код: JSON, sha256, Node IPC родителя; программы ОС не вызываются; корень билета — настоящий путь, сравнивает `sameRoot` службы | то же | то же, x64/ARM64; `sameRoot` без учёта регистра, `\` и `/`, имён 8.3; тесты с внедрённой `win32`/`linux` и путями, которых нет ни на одной ОС, и настоящий fork CLI |
| M40 T002: Kit 2.4.1 — барьеры Git: `pre-push` читает refs из stdin и проверяет целевой ref (`PUBLISH_SCOPE_OPEN`, `CI_PUSH_NOT_ALLOWED`, поле `automation.ci.task`); коммиты в обход Kit (`EXTERNAL_COMMITS`, `commits:adopt`, решение `adopt-commits`) | хук — `sh`-скрипт, stdin доходит до `scripts/workflow` без изменений; refs сравниваются как текст; список коммитов — из `git log`; кроме git программы ОС не вызываются | то же | то же, x64/ARM64: хук запускает `sh` из Git for Windows; `\r` в конце строки refs удаляется (тест CRLF); CRLF в сообщениях коммитов на разбор не влияет; тест отправляет push настоящим git через собранный CLI на каждой ОС в CI |
| M40 T003: Kit 2.4.2 — файловые барьеры: `commit --task` в main отклоняет пути вне `files` задачи (`TASK_FILES_OUTSIDE`); файл `--input`/`--digest` внутри проекта вне `.harness/inputs/` отклоняется до чтения (`INPUT_LOCATION`) | `path.posix`, регистр не учитывается; настоящий путь через `realpathSync.native` (ссылки) | `path.posix`, регистр учитывается; `realpathSync.native` | x64/ARM64: `path.win32` (оба разделителя, буквы дисков), регистр не учитывается, `realpathSync.native` раскрывает имена 8.3; тесты с внедрённой `win32`/`linux`/`darwin` и путями, которых нет ни на одной ОС (регистр, разделители, короткое имя, другой диск, ссылка) |
| M40 T004: Kit 2.4.3 — раздел правил агента (`AGENTS.md`) по режиму решений: в `host` нет ручных форм решений пользователя, есть блок «User decisions» и `wfk decision`; тексты recovery `next` и автопилота режима `host`; `task:block` регистрирует запрос `unblock` | тексты одинаковы; раздел пишется с окончаниями строк существующего файла | то же | то же, x64/ARM64 |
| M40 T004A: Kit 2.4.4 — `scope:proposal` сообщает `automation`; служба в полном автопилоте возвращает автору предложение без блока, запускает план один раз на scope (квитанция журнала запуска) и заканчивает запуск, чей scope принят и закрыт вручную (`finished`, карточки нет) | общий Node-код, атомарная запись журнала запуска; тексты одинаковы | то же | то же, x64/ARM64 |
| M40 T005: служба записывает решения пользователя операциями хоста (`decisions: host`) — источник решения хода в канале агента (`userSource`), сервис и журнал решений (`.workflow-kit/local/decisions.json`), `wfk decision <вид>`, кнопки приёмки, закрытия, выбора режима и подтверждения поставки (задачу стартует служба), решения запуска с источником `grant`, запросы решений в состоянии панели | общий Node-код: JSON, sha256, Node IPC родителя; журнал — атомарная запись с правами 0600; корень билета — `realRoot`/`sameRoot` | то же | то же, x64 и ARM64; `sameRoot` не учитывает регистр, `\` и `/`, раскрывает имена 8.3; права файла журнала не задаются; программы ОС не вызываются |
| M40 T006: «стоп» и «паузу» пользователя читает служба при получении сообщения (маршрут сообщений панели, хук UserPromptSubmit): первое слово после NFC и нижнего регистра без локали; барьер в журнале запуска сразу, автоматические шаги (продолжение, выбор, старт, приёмка, закрытие, публикация) за него не заходят, начатый шаг записывает результат | общий Node-код: `normalize('NFC')`, `toLowerCase()`, классы Unicode `\p{L}`/`\p{N}`; атомарная запись файла запуска | то же | то же, x64 и ARM64; ветвей по платформе нет, программы ОС не вызываются |
| M40 T007: `wfk session plan` решает служба — в «Полном автопилоте» сообщение пользователя, доставленное в текущий ход, регистрирует запуск без карточки (ревью из Settings), без него и при `off`/`after-start` — карточка, старый Kit — `kit-update-required`; `--authorized` убран из справки и не учитывается | общий Node-код: источник хода в памяти канала агента, журнал запуска — атомарная запись | то же | то же, x64 и ARM64; ветвей по платформе нет, программы ОС не вызываются |
| M40 T008: карточки решений Kit в панели (`unblock` с причиной, `approve-install` с точными командами, `adopt-commits` со списком SHA) по запросам состояния; кнопки плана передают `id` и дайджест запроса; мастер и «Обновить Kit» ставят Kit 2.4.0+ с `decisions: host`, Kit 2.3.x без ключа; раздел панели `AGENTS.md` (структура 6) — `action: prepare` и стоп службой | браузер панели, одинаково; установка — Node и `git` через `kit-runner` | то же | то же, x64 и ARM64; пути через `path`, программы ОС не вызываются; тексты структуры с LF |
| M40 T009: сквозные сценарии решений пользователя на bundle Kit 2.4.4 и фикстуре 2.3.3 со службой из тех же фабрик, что `wfk serve` (`autopilot/test/m40-*.ts`), доказательства `docs/evidence/M40-acceptance.md` | временная папка, git и локальный bare-репозиторий, Kit отдельным процессом | то же (CI) | то же (CI, x64 и ARM64); `rm` временной папки с `maxRetries`, пути через `path`, `node -e` без оболочки; программы ОС не вызываются |
