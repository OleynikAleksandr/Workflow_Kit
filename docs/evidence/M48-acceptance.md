## Причины (20.11.2026)

- Settings читались в момент каждого решения: смена посреди задания давала разное поведение на
  разных этапах, а ответ на вопрос о плане при полном автопилоте не нёс агенту номер запуска и
  требование блока `automation` (раздел 1 спецификации).
- A001 (`run-yXsvNrtYdu14`, Claude): предложение без `automation` автопилот вернул агенту
  (09:27:37), но до нового предложения (≈09:29:20) панель показывала ручную карточку выбора способа.
- B001 (`run-qlq6QnxAAyr0`, ChatGPT): план с `automation.publication: null` после закрытия
  блокировался с `no-upstream`; карточка законченного запуска предлагала «Продолжить» и
  «Остановить автопилот».
- 19.11 (M47): «Подтвердить выпуск», нажатое во время команды Kit агента, получило «Another
  workflow operation is running» (Kit `LOCKED`) и пропало.

## Поведение на ОС

Новых программ ОС и веток ОС нет (матрица — [OS-MATRIX-M48.md](../architecture/OS-MATRIX-M48.md)).
Файл сессии — имя без `:` (тест с `win32`), запись через временный файл и `rename` с повтором.
Предзагрузка сквозного сценария 3 узнаёт `git commit` по имени, полному пути (`git.exe`) и через
`cmd /c`; путь в `NODE_OPTIONS` — через `/`, потому что обратная косая черта в кавычках там —
экранирование.
