# M38: «Обновить Kit» обновляет и структуру Kit

## Цель и согласование

16.11.2026 пользователь заметил: интерактивный вопрос агента (`AskUserQuestion`), который
Claude Desktop показал в сессии проекта Workflow_Kit, в диалоге панели не появился. Разбор
показал: у проекта, созданного до M33, структура Kit (`wfk`) осталась версии 3, без хуков
вопроса, а в панели нет способа её обновить. Кнопка «Обновить Kit» обновляет только Kit
проекта (`scripts/workflow`), а установленную маршрутом службы структуру в проекте под
управлением Kit нечем закоммитить.

Решение пользователя, 16.11.2026, на предложение «1 — обход сейчас, 2 — исправление в
продукте»: «Делай и 1 и 2.» В панели выбраны спецификация и план без ревью. Обход сделан в
тот же день: структура 4 записана в Workflow_Kit маршрутом `POST /api/projects/:id/structure`;
три файла ждут коммита (задача T001).

После этой вехи:

- «Обновить Kit» обновляет Kit проекта и структуру Kit одним коммитом;
- карточка «Обновить Kit» появляется и тогда, когда Kit свежий, а структура устарела;
- карточка и `docs/usage.md` говорят, что именно обновляется и что новые хуки получают
  только сессии, начатые после обновления.

## 1. Факты

- Структура Kit (`kit-structure`, `STRUCTURE_VERSION` = 4 с M33, выпуск 0.14.0) — это
  управляемые фрагменты `wfk`: раздел `AGENTS.md`, хуки Claude и Codex, блок `.gitignore`,
  шаблоны, `.workflow-kit/manifest.json`. Версия 4 добавила Claude группы `PreToolUse` и
  `PermissionRequest` с `matcher: "AskUserQuestion"`.
- **[проверено]** Без хука `PreToolUse` Claude не пишет вызов вопроса в транскрипт, пока
  вопрос ждёт; строка появляется только вместе с ответом
  ([факты Claude, раздел 7](../design/M33-claude-question-facts.md)). Панель тогда видит вопрос
  только закрытым, а без `PermissionRequest` не может на него ответить.
- **[проверено 16.11]** `GET /api/projects/:id/structure`: Workflow_Kit — `outdated`,
  `installedVersion` 3 (фрагменты `agents-section` и `claude-hook`); Claude_01 и Codex_01 — 4
  (их создал мастер после выхода 0.14.0).
- «Обновить Kit» (`kit-update`) запускает только `install --update` бандлом приложения.
  Установщик Kit коммитит только файлы, которые записал сам (`commitInstall` в
  `workflow-installer/src/installer-install.ts`); структуру он не трогает. Карточка
  появляется только для Kit старше бандла (`kitAction`).
- **[проверено 16.11]** После «Обновить Kit» до 2.2.6 (коммит `4eabb66`) структура
  Workflow_Kit осталась версии 3.
- Карточку «Структура Kit» убрали из настроек 06.11 (`panel-shell/src/app.js`). Маршрут
  `POST /api/projects/:id/structure` кнопки не имеет и не коммитит. Мастер коммитит структуру
  только до того, как Kit управляет репозиторием (`project-setup/src/setup.ts`); в проекте с
  Kit он пишет «записана; изменения закоммитьте в задаче Kit».
- **[проверено 16.11]** `docs:commit` берёт только Markdown (`DOCS_ONLY`): файлы
  `.claude/settings.json` и `.workflow-kit/manifest.json` вне задачи закоммитить нельзя.
- `docs/usage.md` и `KIT_UPDATE_TEXT` карточки обещают: «Kit обновит свои файлы и хуки
  проекта одним коммитом». Это неверно для хуков `wfk`.
- Хук `pre-commit` проекта проводит служебный коммит (роль `kit-update`) по списку файлов
  журнала транзакции (`workflow-kit/src/kit-hooks.ts`).

## 2. Решение

### 2.1. Kit 2.2.7: `install --update --with <files>` (`kit-core`)

- Новая опция `--with <json|a,b>` (формат `--files` у `docs:commit`): файлы управляемой
  структуры приложения, которые служба записала перед обновлением. Опция работает только
  вместе с `--update`; без него — `USAGE` «--with needs --update.».
- Каждый путь — канонический путь от корня проекта (как `files` задач). Разрешены только
  `.workflow-kit/manifest.json` и пути из `fragments.*.path` этого манифеста в том виде, в
  каком он лежит на диске при запуске команды. Любой другой путь, отсутствующий или
  нечитаемый манифест — отказ `WITH_NOT_MANAGED` с именем пути; Kit при этом ничего не пишет:
  проверка идёт до записи своих файлов.
- Путь из `--with` без изменений вне коммитов молча выпадает: коммитить нечего.
- Коммит один, транзакция роли `kit-update`. Файлы — записанные Kit и оставшиеся пути
  `--with`, без повторов. Сообщение: Kit записал свои файлы — `chore: update workflow kit to
  <версия>`, как сейчас; записаны только пути `--with` — `chore: update the Workflow Kit
  structure`. Нечего коммитить — коммита нет (`commit: null`), как сейчас.
- `excluded` итога не содержит путей `--with`. Новое поле итога `with` — пути `--with`,
  которые вошли в коммит.
- `KIT_VERSION` = 2.2.7, бандл пересобирается `npm run build:kit` (vendor, `bundle-meta.ts`,
  `PROVENANCE`).
- Документы: строка и описание `install` в `WorkflowKitCommands.md`, `module.md`
  `workflow-installer` и `workflow-kit`. В `WorkflowKitInstallation.md` (27 416 байт) меняются
  только упоминания текущей версии, нового текста там нет.

### 2.2. Служба: `kit-update`, `kit-runner`, `cli`

- `kit-runner`: `install(root, { update, name, with })` передаёт `--with` JSON-массивом;
  `KitInstall` получает `with?: string[]`.
- `kit-update` получает от `cli` зависимость `structure: { check(root), install(root) }`
  (`checkStructure` и `installStructure` из `#kit-structure`) и `kit.run` (команда `status`
  Kit проекта).
- Раздел `kitUpdate`, запись проекта: новое поле `structure` — `{ status, installed,
  version, installable, kept }` для проекта с установленным Kit (`KIT_INSTALLED_STATES`), где
  `kept` — пути фрагментов `modified` и `newer`. Если проверка структуры не удалась или Kit не
  установлен, `structure: null`; при ошибке проверки добавляется `structureNote` с её текстом.
  Проверка идёт в `refreshOne` вместе с `inspect`: она только читает файлы, без отдельного
  процесса.
- `action: 'update'` — если `kitAction` даёт `update` или если у установленного Kit
  `structure.installable`.
- Порядок `update(project)`:
  1. Если `structure.installable`: `kit.run(path, ['status'])` проекта, поле `changes`.
     Ошибка команды или нет поля — структура пропускается с причиной «Kit не сообщил файлы
     вне коммитов», Kit обновляется дальше.
  2. Пути к записи — фрагменты `missing` и `outdated` и манифест. Если какой-то из них есть
     в `changes`, структура пропускается с причиной «файлы изменены и не закоммичены: <до пяти
     путей>, и ещё N». Чужие изменения не попадают в служебный коммит.
  3. Иначе служба сохраняет текущий текст этих файлов (или их отсутствие), вызывает
     `structure.install(path)` и переводит записанные фрагменты в пути (`manifest` —
     `.workflow-kit/manifest.json`).
  4. `kit.install(path, { update: true, with: <пути> })` — один коммит Kit и структуры. Kit
     свежий, а структура устарела — та же команда: Kit ничего своего не пишет и коммитит только
     структуру.
  5. Если Kit отказал или упал, служба возвращает сохранённые файлы структуры (текст на
     место, созданные файлы удаляются), структура остаётся прежней, `error` — как сейчас.
  6. Дальше как сейчас: `approveKitHooks`, `refreshOne`, `onUpdated`.
- `last` получает поля `structure` (`{ from, to, files }` или `null`) и `structureNote`
  (причина, по которой структура не обновлена, или `null`). В журнал службы —
  `kit: structure <проект> <из> → <в>` или `kit: structure skipped <проект>: <причина>`.
- Полный автопилот: маршрут `POST /api/projects/:id/kit/update` остаётся единственной точкой
  решения. Нажатие кнопки — согласие, других вопросов пользователю нет. Новых путей, которые
  требуют присутствия пользователя, нет.

### 2.3. Панель: карточка Kit (`panel-shell`)

- Заголовок до обновления:
  - Kit старше и структура устарела — «Kit 2.2.6 → 2.2.7, структура 3 → 4»;
  - только структура — «Структура Kit 3 → 4»;
  - только Kit — как сейчас.
- Текст до обновления (`KIT_UPDATE_TEXT`): «Kit обновит свои файлы, структуру и хуки
  проекта одним коммитом; сессии, начатые до обновления, получат новые хуки и пакет со
  следующей сессии.» Непустой `kept` даёт строку «Изменено вручную, не обновится: <пути>».
- Во время обновления — «Kit обновляется…», как сейчас.
- После обновления:
  - заголовок «Kit обновлён до 2.2.7», а если обновлена только структура — «Структура Kit
    обновлена до 4»;
  - текст «Коммит abc1234. Сессии, начатые до обновления, получат новые хуки и пакет со
    следующей сессии.»;
  - строки: строки хуков провайдеров, как сейчас, затем «Структура Kit 3 → 4: <файлы>» или
    «Структура Kit не обновлена: <причина>».
- `docs/usage.md`, раздел «Версия Kit проекта»: что обновляет кнопка, когда карточка
  появляется ради одной структуры, что хуки получают только новые сессии, и что вопрос Claude
  в сессии без хуков вопроса виден в панели только закрытым.
- `design-qa.md`: раздел M38 с тремя состояниями карточки.

## 3. Поведение на ОС

| Что | macOS | Linux | Windows |
| --- | --- | --- | --- |
| `install --update --with` (Kit 2.2.7) | `node <бандл>` через `kit-runner` | то же | то же; пути `--with` — канонические с `/` |
| Проверка и запись структуры | `kit-structure`, команды хуков — как в M33 | то же | то же; хук Claude — exec-форма `node.exe wfk.mjs` (M33) |
| Возврат файлов при отказе Kit | атомарная запись `writeFileAtomic` | то же | то же |
| Карточка Kit | одинаково | одинаково | одинаково |

Своих веток по ОС у изменений нет: пути строятся `path`-помощниками от корня проекта, Kit
получает канонические пути. Команды хуков по ОС уже рендерит `kit-structure`.

## 4. Проверка

- Автоматические тесты:
  - `workflow-installer` на временном git-репозитории с настоящим Kit. Kit и пути `--with` —
    один коммит, хук `pre-commit` проекта пропускает его. Только `--with` — сообщение
    `chore: update the Workflow Kit structure`. Путь вне манифеста и нечитаемый манифест —
    `WITH_NOT_MANAGED`, ничего не записано. `--with` без `--update` — `USAGE`. Путь без
    изменений выпадает. `excluded` без путей `--with`.
  - `kit-runner`: аргумент `--with`.
  - `kit-update`: поле `structure`; `action: 'update'` только ради структуры; порядок
    `status` → структура → `install --with`; изменённые файлы — пропуск с причиной; отказ Kit —
    файлы возвращены; отказ `status` — пропуск; `kept`.
  - Связка `kit-update` с настоящими `kit-structure` и бандлом на временном репозитории:
    структура 3 → 4 и Kit одним коммитом, дерево чистое.
  - `kit-card`: заголовки, тексты и строки раздела 2.3.
- CI: macOS, Linux, Windows x64 и ARM64 для точного SHA поставки.
- Живая проверка, macOS (агент и пользователь, с согласия пользователя):
  1. Одноразовый проект `~/WorkflowKitProjects/M38_live_<время>`: `git init`, файлы
     структуры 3 из коммита `304ae8d` этого репозитория, обычный коммит до Kit, Kit 2.2.6
     бандлом 2.2.6 из истории `kit-bundle/vendor`, регистрация маршрутом `POST /api/projects`.
     На карточке — «Kit 2.2.6 → 2.2.7, структура 3 → 4». «Обновить Kit» даёт один коммит,
     структура `ok`, дерево чистое.
  2. Новая сессия Claude в Workflow_Kit (после T001): агент задаёт `AskUserQuestion`, в
     диалоге панели появляется ожидающий вопрос и принимает ответ из панели.
  - Без согласия — «не проверено вживую», покрыто тестами.
- Windows (x64 или ARM64) — проверяющий на Windows: шаг 1 на проекте со структурой 3. До
  проведения — «не проверено вживую на Windows». Linux — только CI.

## 5. Границы

- Мастер для папки с Kit (`project-setup`, «записана; изменения закоммитьте в задаче Kit»)
  не меняется.
- Карточка «Структура Kit» в настройки не возвращается; `force` для фрагментов, изменённых
  вручную, остаётся только у маршрута структуры.
- Идущие сессии новых хуков не получают: Claude читает хуки при старте. Это описано, но не
  исправляется.
- Kimi не затронут: в структуре нет его хуков.
- Kit самого Workflow_Kit обновляется до 2.2.7 кнопкой после закрытия scope, не в задачах.
