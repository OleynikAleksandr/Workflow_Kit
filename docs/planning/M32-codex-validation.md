# M32: проверки истории и восстановления Codex

Часть [спецификации M32](M32-codex-history-recovery.md).

## 4. Проверка и приёмка

Обязательные сценарии автоматизации:

1. Совокупная история более 16 МиБ, включая outputs инструментов: последние сообщения
   доступны без полного read; новые ответы появляются. Отдельно одна большая реплика,
   большой tool output и много элементов одного хода. В одном ходе: короткая реплика →
   output >16 МиБ → короткий ответ; ОБЕ реплики видны, gap только внутри диапазона.
   Повторные poll не перечитывают gap, не меняют epoch/backoff и доступность Stop.
2. 0/1/100/101 сообщений, несколько страниц, изменение существующего item, переход в
   terminal, одинаковые timestamps, дубли, неверный/зацикленный курсор, смена истории.
   Проверить предел RPC/байтов/кэша и отсутствие повторного полного обхода при idle.
   На активном ходе с большим завершённым output измерять устойчивые байты каждого
   poll: завершённый output повторно не скачивается, читается только изменяемый хвост.
3. Размер кадра на границе/за границей, фрагменты суммарно за пределом, UTF-8 на границе
   TCP-chunks, обрыв тела, invalid JSON; типизированные ошибки и освобождение buffers.
4. Сокета нет до соединения, ссылка указывает на удалённую цель, цель заменена, разрыв
   посреди чтения, демон отсутствует долго и возвращается. Обновление без reload;
   независимые треды и параллельные вкладки не создают шторм повторов.
5. Подтверждённо безопасный retry чтения; после доставки изменяющего RPC и обрыва ответа
   число turn/start, turn/interrupt, config writes остаётся 1. Отказы auth/protocol не
   запускают сетевой бесконечный retry. Deadline и dispose проверяются fake clock.
6. Stop на длинной истории; устаревший turnRef; новый ход между чтениями; естественный
   completed; timeout и reconnect: остановка только доказанной цели. Probe ленты и Stop
   не resume/не start тред. Следующее явное сообщение использует excludeTurns.
7. UI: loading/reconnecting/ready/unavailable, сохранение draft/scroll/focus/queued;
   поддержка ответов без sync (Claude/Kimi); ошибка действия остаётся видима.
8. Injected darwin/linux/win32, proxy process fake и настоящий WebSocket на тестовом
   сокете; Windows x64/ARM64 покрываются CI, а не выдаются за локально проверенные.

Настроенный QUALITY уже CONFIGURED: typecheck, test, platform-guard и kit checks.
Тесты меняют только временные данные. Приёмочные результаты и ограничения записываются
в `docs/evidence/M32-codex-history-recovery.md`, отдельно от протокольной пробы T001.
macOS — пользователь: длинная существующая сессия, новые ответы, Stop и возвращение связи
после контролируемого перезапуска демона; iPad — сохранение поля и ленты.
Windows — проверяющий на Windows: те же сценарии плюс возврат proxy без видимого окна.
Linux — пока только CI. Непроведённая проверка имеет статус pending, не passed.

Результаты R1 (T005, автоматические проверки macOS и pending по ОС) —
[M32-codex-history-recovery.md](../evidence/M32-codex-history-recovery.md).

## Поставка, CI и разрешение пользователя

15.11.2026 пользователь ответил «Да: установка и CI до приёмки» на прямой вопрос о
локальной сборке/установке с подтверждением delivery и push только ветки
`ci/M32-codex-history-recovery`. Разрешение записано в approval предложения. Для M32 оно
разрешает противоречие AGENTS.md: CI до приёмки разрешён, публикация main остаётся
отдельной командой после приёмки и закрытия.

T006 (delivery, после DOCS и T005): task:start с --confirmed словами пользователя,
повышение patch-версии от актуальной базы, сборка, штатная локальная установка и
`wfk doctor --installed`, smoke установленной службы. Проверить версию и источник сборки,
результат записать в docs/evidence/M32/local-delivery.md и итоговый evidence.
Версию синхронно обновить в package.json/package-lock.json, CHANGELOG.md, README.md,
docs/installation.md и docs/usage.md. Активный ход пользователя не прерывать ради smoke.
Живые проверки macOS делает пользователь на установленной версии; Windows — проверяющий
на своей установленной сборке, Linux — CI. Непроведённое остаётся pending.

T007 (delivery, зависит от T006): push только ci/M32-codex-history-recovery без force,
CI на точном SHA T006, все четыре платформы зелёные. Сначала сверить remote; чужие
изменения не перезаписывать. Main не публиковать. Собственный коммит T007 меняет только
evidence/план; он не отправляется после DONE. Его CI выполняется при отдельной публикации
main после приёмки и закрытия. Критерий T007 относится именно к поставляемому SHA T006. Если CI упал, delivery не DONE; функциональный дефект исправлять
через fixes round Kit, затем повторить CI и при необходимости локальную установку.

T005 дополнительно измеряет суммарные payload-байты ≤32 МиБ на poll, число страниц ≤8,
end-to-end deadline ≤5с (fake clock), кэш как UTF-8 bytes; проверяет большой failed output,
gap элемента/диапазона, обе реплики того же хода и появление более нового ответа, shared server timer для Mac/iPad,
сбой без снимка 503, fresh Stop RPC без inflight, updateParameters resume excludeTurns.

Технический scope id с суффиксом -retry1 служит только повторной попытке ревью.
Точное разрешение пользователя на ci/M32-codex-history-recovery имеет приоритет
над шаблоном ci/<scope>; ни другой CI-ветки, ни дополнительного push это не разрешает.

DOCS явно обновляет docs/architecture/CONTRACTS.md: ChatPage.sync, HTTP 503
codex-reconnecting/codex-unavailable; проверяет согласованность routes.md и chat.md.
Размер session-chat/module.md проверять в T004/T005: его нынешний запас около 4,5 КБ.
