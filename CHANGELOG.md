# Changelog

Заметные изменения Workflow Kit, новые версии сверху. Даты — `YYYY-MM-DD`.
История восстановлена по коммитам выпуска и документам приёмки
[M1](docs/evidence/M1-acceptance.md), [M2](docs/evidence/M2-acceptance.md),
[M3](docs/evidence/M3-acceptance.md), [M4](docs/evidence/M4-acceptance.md).
Запись о функции не означает, что она проверена на всех ОС.

## [Unreleased]

## [0.9.2] - 2026-11-12

Пакет восстановления Kit приходит агенту целиком за один ход
([M21](docs/planning/M21-recovery-one-turn.md)).

### Changed

- Приложение ставит и обновляет в проектах Harness Workflow Kit 2.2.3: для Claude пакет
  восстановления приходит шестью хуками SessionStart (каждая часть меньше 10 000 символов,
  поэтому Claude Code не заменяет её коротким предпросмотром), для Codex у хука поднят
  `additionalContextLimit`, и пакет не обрезается посередине.

### Fixed

- В Codex хук Harness SessionStart (`scripts/workflow hook session-start --client codex`) не
  выполнялся, пока его не одобрит пользователь. Kit одобряет его вместе со своими хуками —
  только с точной командой; чужие и изменённые хуки по-прежнему одобряются в самом Codex.
- Мастер проекта для проекта с устаревшим Kit предлагал установку и получал
  `ALREADY_INSTALLED`; теперь он предлагает обновление до версии из бандла.

## [0.9.1] - 2026-11-12

Исправления диалога сессии по живой проверке 0.9.0 ([M19](docs/planning/M19-session-chat-fixes.md)).

### Fixed

- Сообщение из панели в сессию Claude, запущенную до обновления службы, терялось: старый
  сценарий принимал его за просьбу разбудить и печатал «Workflow Kit: новое сообщение из
  панели.». Текст теперь идёт отдельным управляющим файлом; сценарий, который его не знает,
  файл не забирает, и сообщение уходит в очередь.
- Сообщение из панели в сессию Claude, которую ведёт приложение вне панели, получала копия
  сессии в терминале панели. Процесс панели теперь помечает свои хуки; сессии с последним
  хуком без метки панель текст не вставляет и её не будит — сообщение приходит агенту из
  очереди с ближайшим хуком.
- Открытие экрана сессии больше не запускает второй процесс Claude для сессии, которую ведёт
  приложение; поднять её в панели можно кнопкой «Продолжить» на экране сессии.
- Лента Claude не показывает служебную сводку сжатия контекста репликой пользователя.

## [0.9.0] - 2026-11-12

Диалог любой сессии в панели ([M18](docs/planning/M18-session-chat.md)).

### Added

- Экран сессии Claude, ChatGPT и Kimi показывает карточку «Диалог»: реплики пользователя и
  агента (последние 100, длинные обрезаются), новые появляются без перезагрузки. Сессия
  по-прежнему открывается и в родном приложении.
- Поле ввода под диалогом. Ждущему агенту сообщение приходит сразу репликой пользователя:
  Claude — в сессии, запущенной панелью; ChatGPT — при общем доступе к чатам. Иначе оно
  встаёт в очередь и приходит агенту с ближайшим хуком; панель показывает, каким путём
  сообщение ушло.
- Маршрут `GET /api/projects/:id/providers/:p/sessions/:sid/messages`; необязательные методы
  провайдера `readMessages` и `sendDirect`.

### Changed

- Сообщение агенту из панели — до 20 000 знаков; автопилот и ревью работают как раньше.

### Fixed

- Тест публикации больше не портит настройки репозитория, когда его запускает проверка
  коммита из рабочей копии (`core.bare`).

## [0.8.4] - 2026-11-11

Команда `wfk` у агентов после обновлений по живой проверке 0.8.3 на Windows
([M17](docs/planning/M17-wfk-on-agent-path.md)).

### Fixed

- Агент ChatGPT не находил `wfk` («The term 'wfk' is not recognized»): демон Codex переживал
  обновления службы и хранил PATH без каталога Kit. Теперь служба всегда держит каталог `wfk` в
  своём PATH и в PATH программ, которые запускает (демон Codex, хост Claude, сервер Kimi), — и
  при первой установке, до того как его узнает PATH пользователя. macOS, Linux и Windows.

### Added

- Устаревший демон Codex (запущен не Kit или с прежним PATH): подсказка в статусе ChatGPT и
  действие «Перезапустить демон» с подтверждением; Kit сам ходы не обрывает.
- Раздел AGENTS.md новых проектов называет полный путь `wfk` для macOS и Linux, PowerShell и
  Git Bash — на случай, если оболочка агента его не находит.
- `wfk service restart`.

## [0.8.1] - 2026-11-11

Исправления по живой проверке 0.8.0 на Windows ([M14](docs/planning/M14-windows-fixes.md)).

### Fixed

- Windows: пока открыта панель, больше не мелькают окна терминала — `git` (опрос публикации)
  запускается без консольного окна (`windowsHide`).
- Windows: при выключенном контроле учётных записей (UAC, `EnableLUA = 0`) демон Codex не
  стартует. Kit теперь называет причину и команду исправления в статусе ChatGPT, карточке
  общего доступа и `wfk doctor` вместо «socket hang up».
- «Работает» в карточке общего доступа появляется только при работающем демоне и настоящем
  подключении приложения ChatGPT (на Windows — сеанс `ssh.exe` старше 15 с).
- Карточка «Общий доступ к чатам»: блок администратора — только в нужных состояниях, команда
  переносится по ширине, причина и подсказка разделены точкой, заметка операции не зависает.

### Changed

- Windows: панель открывается в окне Chrome, если он установлен, иначе в Edge.
- Windows: после установки Kit подсказывает, что `wfk` появится в новом окне терминала (Windows
  Terminal нужно закрыть целиком), и печатает прямую команду запуска.
- Папку проектов и проекты можно выбрать на другом локальном диске: на Windows — диски кроме
  системного (на нём — домашняя папка), на macOS — тома `/Volumes`, на Linux — `/media`,
  `/run/media`, `/mnt` (скрытые и служебные тома `com.apple.*` не показываются). В выборе папки
  появился переключатель дисков. Код ошибки `outside-home` заменён на `outside-roots`.

## [0.8.0] - 2026-11-11

### Added

- ChatGPT (Windows 11): общий доступ к чатам через SSH, как на macOS. Карточка «Общий доступ к
  чатам · ChatGPT» проверяет `codex`, приложение ChatGPT, клиент OpenSSH, Git for Windows,
  службу `sshd`, оболочку SSH (`DefaultShell`), `Host wfk-local`, SSH-сеанс и подключение
  приложения и называет точное состояние; `wfk doctor` печатает те же проверки.
- Kit на Windows после предпросмотра пишет ключ SSH, `~/.ssh/config`, блок профиля Git Bash,
  строку в `authorized_keys` (обычный пользователь) и скрипт администратора
  `shared-access-admin.ps1`. Скрипт Kit не запускает: карточка показывает его текст и копирует
  команду для PowerShell от имени администратора. Скрипт ставит и запускает сервер OpenSSH,
  задаёт `DefaultShell` = `sh.exe` Git, администратору дописывает ключ в
  `administrators_authorized_keys`. Новое состояние «Нужен шаг администратора».
- «Убрать настройку» на Windows удаляет записи Kit и пишет скрипт отката
  (`DefaultShell` и ключ; сервер OpenSSH остаётся).

### Changed

- Сессии ChatGPT в режиме общего демона на Windows идут общим кодом 0.7.0: ссылка чата с
  `hostId` открывается в приложении целиком, собственный процесс Codex приложения не считается
  «вторым app-server». macOS — как в 0.7.0, Linux — без общего доступа.

## [0.7.0] - 2026-11-11

### Added

- ChatGPT (macOS): общий доступ к чатам. Приложение ChatGPT подключается к этому же Mac по SSH
  (`wfk-local`) и работает через демон Codex, который ведёт Kit. Один чат одновременно открыт в
  Kit, в ChatGPT на компьютере, на iPad и телефоне; чат ревьюера ChatGPT открывается с карточки
  «Ревью плана»; сообщения панели будят простаивающую сессию ChatGPT сразу.
- Карточка «Настройки» → «Общий доступ к чатам · ChatGPT»: Kit после предпросмотра сам пишет
  ключ SSH, строку в `authorized_keys` (вход только с этого Mac), блок `Host wfk-local` в
  `~/.ssh/config` и блок профиля оболочки (zsh или bash), с копиями файлов; проверяет «Удалённый
  вход», SSH и подключение приложения; открывает настройки macOS и страницу подключений
  ChatGPT; «Убрать настройку» удаляет всё записанное. `wfk doctor` показывает состояние.

### Changed

- В режиме общего демона Kit не выгружает новый чат ChatGPT и не передаёт удалённое управление
  приложению ChatGPT; ссылка чата на Mac ведёт в копию подключения `wfk-local`. Если проверка
  (раз в минуту) не проходит, Kit сам возвращается к прежнему поведению. Linux и Windows — как
  в 0.6.4.

## [0.6.4] - 2026-11-10

## [0.6.3] - 2026-11-10

### Added

- Kimi Code: сессия Kimi ведёт скоуп с исполнителями, как Claude и ChatGPT. Панель предлагает
  режим «Параллельно»; оркестратор Kimi делает git worktree для задания и запускает

  исполнителям, и помощникам в последовательном режиме (они работают в основной папке и не
  коммитят). Существующие проекты получают новый текст обновлением структуры Kit.

## [0.6.2] - 2026-11-10

### Fixed

- Kimi Code: щелчок по сессии Kimi в панели открывает её проект в приложении Kimi Code без
  нового пустого чата. Служба запускает приложение с `--workspace=<папка>` (macOS —
  `open -n -a`, Windows — программа обработчика `kimi-code`), ссылка `kimi-code://` —
  запасной путь; на Linux и для новой сессии — ссылка, как раньше.
- Kimi Code: служба больше не теряет свой сервер `kimi web` после своего перезапуска
  (процесс меняет имя на `kimi-code`, учёт узнаёт его по времени запуска).
- Kimi Code: просьбу перезапустить приложение даёт только сервер приложения, с которым
  работает Kit; осиротевший сервер прежней версии ложной пометки не вызывает.

## [0.6.1] - 2026-11-10

### Fixed

- Kimi Code: пока открыто приложение Kimi Code, Kit создаёт рабочие области, сессии и
  сообщения через сервер приложения и свой `kimi web` не запускает. Приложение сразу
  показывает сессию из панели с первым сообщением и ответом и не заводит для папки
  вторую рабочую область. Появилось приложение — Kit переходит на него, когда закончатся
  ходы его сервера; закрылось — снова запускает свой сервер.
- Kimi Code: хук Kit начинает работать в сессиях сервера Kit сразу после записи — сервер
  перезапускается, если запущен раньше (Kimi читает хуки только при запуске).
- Kimi Code: если приложение Kimi Code запущено до записи хука, статус, мастер и сессии
  просят перезапустить приложение — без этого автопилот и ревью в его сессиях не работают.
- `wfk session title|plan` находит сессию Kimi с идущим ходом по её замку, даже если хуки
  не дошли до службы.

## [0.6.0] - 2026-11-10

### Added

- Третий провайдер — Kimi Code (`kimi` 2.5.2+): сессии из панели с первым сообщением,
  список, имя, архив и удаление; доверие папке и хук Kit в `config.toml` Kimi из мастера
  после предпросмотра; служба ведёт свой локальный сервер `kimi web` (запуск по
  требованию, действие «Перезапустить сервер Kimi»).
- Автопилот и ревью плана для сессий Kimi: следующее сообщение приходит промптом после
  конца хода, а не ответом на хук `Stop`; `Stop` подагента ничего не доставляет. План
  Kimi проверяет ChatGPT; сама сессия Kimi ведёт скоуп только последовательно.
- Открытие проекта в приложении Kimi Code по ссылке `kimi-code://` и Remote Control
  сервера Kit (действия «Включить/Выключить Remote Control Kimi»).
- `wfk status` и `wfk doctor` показывают программу `kimi`; `wfk hook turn-end`.

### Changed

- Списки и названия провайдеров в службе, мастере и панели берутся из реестра
  провайдеров, клиенты хука — тоже; порядок: ChatGPT, Claude, Kimi.
- Одобрение хука принимает текст и хеш, показанные в предпросмотре: изменённый за это
  время файл не перезаписывается.
- `wfk session title|plan` без указания клиента берёт единственную сессию проекта с
  идущим ходом, иначе отвечает `session-ambiguous` и просит `--client` и `--session`.
- Управляемый раздел `AGENTS.md` проектов получил пункт о Kimi Code и обновится.

### Fixed

- Остановленная служба больше не выполняет периодическое обслуживание провайдеров
  (повторы удаления, обслуживание, попытки автозапуска).

Kimi Code вживую проверяется только на macOS; на Linux и Windows — автоматические тесты.

## [0.5.0] - 2026-11-09

### Added

- Windows 11 (x64 и ARM64): сессии Claude через встроенный ConPTY (node-pty 1.1.0)
  вместо `expect`, с тем же поведением, что на macOS: имя, сообщения из панели,
  пробуждение, остановка, возобновление и окружение папки.
- Windows: сессии ChatGPT/Codex через демон Codex (`codex app-server proxy`),

- Windows: открытие чатов ChatGPT и сессий Claude службой, штатная остановка службы
  (`POST /api/system/shutdown`), предупреждение об установке с правами администратора.

### Changed

- Доверие к папке в `~/.claude.json` и `~/.codex/config.toml` учитывает ключи Windows
  без учёта регистра и вида косой черты.
