# M29: живая и браузерная проверка (T005)

Спецификация: [M29-claude-controls-instant.md](../planning/M29-claude-controls-instant.md),
раздел «5. Проверка». Дата: 14.11.2026, macOS (Apple Silicon), Claude Code 2.1.325.

## Стенд

- Одноразовый проект Kit в `~/WorkflowKitProjects/M29_live_*`, изолированная служба
  (`WFK_DATA_DIR` во временной папке, порт 0), настоящий `session.exp` под наблюдателем
  экрана; все действия идут через маршруты панели.
- Модель Haiku 5.5 (`settings.local.json` проекта), два коротких хода за итоговый прогон.
- Решатель канала держит каждый Stop, как автопилот при вопросе о плане
  (`hold`, `waiting-for-plan-start`).
- После прогона сессия, доверие, папка проекта и журнал Claude удалены; процессов не осталось.

## Найдено живой проверкой и исправлено в T005

1. **Диалог «Switch model?».** Claude 2.1.325 после `s` в разговоре с кэшем спрашивает
   «Yes, switch to <модель>» / «No, go back». Движок считал кадр неизвестным, отменял
   транзакцию и оставлял диалог открытым. Теперь кадр `switch` распознаётся
   (`parameter-screen.ts`), подтверждается Enter только для своей цели, иначе закрывается Esc.
2. **Модель в режиме plan.** В plan Claude показывает в statusline модель плана
   (Haiku → Sonnet 5.5), хотя строка «Set model to Haiku 5.5 for this session only» уже
   пришла. Движок ждал statusline 55 с и трижды повторял. Теперь модель подтверждает
   строка Claude с именем цели; усилия новой модели дочитывает фоновое обнаружение.
3. **Темп хоста.** На macOS `after 100` системного Tcl 8.5.9 длится около 250 мс (замер:
   `after 50` — 200 мс, `after 200` — 350 мс; `setTimeout(100)` в Node — 102 мс). Каждая
   клавиша занимала 3–4 опроса, около 1 с. Теперь Tcl не спит, а `interrupt-worker.ts`
   выдерживает 100 мс между опросами занятого хоста; движок сразу предлагает следующий шаг.

Хронология опросов до и после — `M29/t005-timing.json` (каждая строка: мс от выбора,
кадр или обмен с помощником).

## Итоговый живой прогон

Результат: [M29/t005-live.json](M29/t005-live.json).

| Что | Результат |
| --- | --- |
| Stop-хук при удержании | ответ за 1 мс, слот `holding`, экран свободен (`❯`, без «esc to interrupt») |
| Каталог при первом чтении | 8,8 с; меню модели — 13 моделей, усилия low…max |
| Ответ службы на выбор | 3–22 мс, сразу с `pending` «применяется» |
| Усилие medium | 2,4 с до подтверждения в панели |
| Режим plan / manual | 1,8 с / 1,0 с |
| Модель Haiku → Sonnet 5.5 (с диалогом) | 3,1 с |
| Модель Sonnet 5.5 → Haiku 5.5 | 2,6 с |
| Сообщение панели отпущенной сессии | `queued`, ход начался через 2,0 с (`WOKEN`) |
| Выбор усилия во время хода | `pending` «применится, когда Claude закончит ответ»; применён через 3,6 с после Stop |
| Строки ленты | одна `⎿ Cancelled` от первого чтения каталога (Esc в `/effort`); `/fast` и «Fast mode» нет |
| `~/.claude/settings.json` | хэш не изменился |

Время до подтверждения измеряет стенд: опрос `GET …/parameters` раз в 250 мс, поэтому
значения завышены не больше чем на 0,25 с. Первый переход на модель с диалогом
«Switch model?» — около 3 с; остальные изменения — до 2,6 с.

Пробный замер того же стенда (`M29/t005-timing.json`, один ход): усилие 2,6 с, Haiku 2,6 с,
plan 1,3 с, manual 1,8 с, усилие low 2,4 с; Sonnet 5,5 с — ещё с чтением усилий внутри
транзакции, вынесенным после этого замера в фоновое обнаружение.

Сообщение из Claude Desktop стенд не отправляет: оно идёт в собственный ввод Claude. Его
условие — свободный ход: Stop-хук отвечает сразу, на экране нет индикатора работы.
Пробуждение сообщением панели проверено напрямую.

## Браузерная регрессия

Сводка: [M29/t005-browser.json](M29/t005-browser.json). Chromium Playwright, DPR 2.

- Композер M28 (`m28-composer.browser.js`): 10 прогонов, 234 проверки — пройдено.
- Меню M28 (`m28-menu.browser.js`) с ожиданием M29 «меню открыты во время ответа»:
  6 прогонов (тёмная и светлая темы), 24 проверки — пройдено.
- Ожидающий выбор и откат (`m29-pending.browser.js`): 6 прогонов, 54 проверки — пройдено.

Скриншоты: `M29/menu-answering-{dark,light}.png` — меню модели открыто, пока Claude
отвечает; `M29/{light-375,dark-1280}-pending.png` — выбранная модель с пометкой ожидания;
`M29/{light-1280,dark-375}-failed.png` — строка отказа под вводом.

## ОС

- macOS — этот прогон агента; живая приёмка — пользователь после установки 0.13.3.
- Windows x64 и ARM64 — проверяющий на Windows повторяет живую проверку на поставке
  (ConPTY-хост `runHost` опрашивал занятый хост раз в 100 мс и раньше).
- Linux — пока только CI.
