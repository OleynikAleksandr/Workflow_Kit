# M19: исправления диалога сессии (0.9.1)

## Цель и согласование

Сообщение, отправленное из карточки «Диалог», не должно теряться и должно приходить тому
процессу Claude, в котором пользователь ведёт сессию.

Живая проверка 0.9.0 (macOS, 2026-11-12): пользователь отправил сообщение из панели в сессию
Claude, открытую в приложении. Панель показала «Отправлено агенту», в ленте появилась реплика
«Workflow Kit: новое сообщение из панели.», а ответил на неё процесс с устаревшим контекстом.
Текст сообщения пропал.

Причины (проверено по процессам и коду):

1. **Старый сценарий.** Сессию вёл `session.exp` версии 0.8.4, запущенный до обновления службы.
   Служба 0.9.0 положила в `<debug>.message` текст в новом формате (`text\n…`). Старый сценарий
   любой такой файл считает просьбой разбудить: печатает строку пробуждения и удаляет файл.
   Служба увидела, что файл забрали, и ответила `{sent:true}`; в очередь текст не попал.
2. **Копия сессии.** У сессии два процесса Claude с одним идентификатором: чат в приложении
   (его запустило приложение) и `claude --resume <id> --remote-control` в терминале панели.
   Копию создала панель: открытие экрана сессии без живого процесса панели вызывает
   `resume` (`reviveSession`). Прямая вставка и пробуждение печатают в терминал копии, поэтому
   отвечает копия, а чат в приложении сообщения не видит.

Пользователь, 2026-11-12: «Можешь сейчас посмотреть причину?», затем на вопрос «Открыть scope
исправлений для этих двух дефектов?» — «Да, открывай»; в панели выбрано «спецификация и план
без ревью».

## 1. Принципы

- Сообщение пользователя не теряется: если прямой путь не подтверждён, оно идёт в очередь.
- Kit не печатает в терминал своего процесса сессии, пока сессию ведёт другой процесс.
- Kit не запускает второй процесс сессии без явного действия пользователя, пока сессию ведёт
  другой процесс.
- Очередь, хуки, автопилот, ревью, ChatGPT и Kimi работают как в 0.9.0.

## 2. Решение

### 2.1. Отдельный управляющий файл для текста (provider-claude)

- `sendDirect` пишет текст в `<debug>.text` (через `<debug>.text.partial` и переименование):
  содержимое — очищенный текст без префикса. `<debug>.message` остаётся только для пробуждения.
- `session.exp` и `pty/host.ts` раз в секунду смотрят оба файла. `<debug>.text` — вставка
  bracketed paste и Enter, метка `MESSAGE_SENT`. `<debug>.message` — как раньше строка
  пробуждения и `WOKEN`; префикс `text\n` в нём больше не разбирается. Сначала читается
  `<debug>.text`: если текст вставлен, ждущий рядом `<debug>.message` удаляется без пробуждения
  (ход начнёт сообщение). Пустой `<debug>.text` удаляется без вставки.
- Сценарий старой версии `<debug>.text` не знает и не забирает. `sendDirect` по истечении
  `directWaitMs` удаляет файл и возвращает `false`; сообщение уходит в очередь, панель
  показывает «В очереди». Ничего не теряется.
- `wakeSession` не пишет `<debug>.message`, пока ждёт `<debug>.text` (сообщение само начнёт ход).

### 2.2. Метка процесса панели в хуках

- `session.exp` и `pty/host.ts` запускают `claude` с переменной окружения
  `WFK_PANEL_SESSION=1`. Хуки — дочерние процессы `claude` и наследуют её (так же служба уже
  получает `CLAUDE_PROJECT_DIR`).
- `wfk hook stop|prompt|turn-end` передаёт службе `panelProcess: true`, когда переменная равна
  `1`, иначе `false` (`cli/src/hook-service.ts`); метку несёт и `POST /api/hooks/turn-end`
  (провайдеры без удержания `Stop`).
- `agent-channel`: `HookInput.panelProcess: boolean`; `SessionActivity.external: boolean` —
  `true`, когда последний хук сессии пришёл без метки (каждый хук, в том числе `turn-end`,
  обновляет поле). Поле видно в `/api/state`.
- Контракт провайдера: необязательное `Provider.marksPanelProcess?: boolean`. У Claude — `true`;
  у ChatGPT и Kimi поля нет, и `external` для них ни на что не влияет.

### 2.3. Сессию ведёт другой процесс

Сессия считается внешней, когда у провайдера `marksPanelProcess` и `activity.external === true`.
Для внешней сессии:

- `createDirectMessage` не вызывает `sendDirect`: сообщение идёт в очередь, ответ маршрута
  `{queued}`. Его получит процесс, который ведёт сессию, с ближайшим хуком (конец хода,
  следующая реплика пользователя или удержанный Stop).
- `wakeIdle` (сообщения панели) и пробуждение для ревью (`deliverToSession` в
  `review-wiring.ts`, ответ `false`) не вызывают `wakeSession`; проверка — общая
  `ledOutside(provider, activity)` (`cli/src/direct-message.ts`).
- Панель не возобновляет сессию сама: `reviveSession` при открытии экрана ничего не делает.
  В строке состояния экрана — «Сессию ведёт приложение Claude вне панели; сообщения придут
  агенту с ближайшим хуком». Кнопка «Продолжить» — новая, в шапке экрана сессии
  (`resumeButton` в `panel-shell/src/session-screen.js`, действие `resumeSession`): по ней
  панель запускает свой процесс (`resume`), его хуки приходят с меткой, и сессия перестаёт быть
  внешней. `session-view` не менялся. В панели `SessionRow.external` — провайдер возобновляет
  сессии (`resume`) и `activity.external`.

Сессия без активности в канале (хуков ещё не было) и сессия, чей последний хук пришёл с
меткой, работают как в 0.9.0. Сессия под сценарием старой версии метки не ставит и считается
внешней: её сообщения идут в очередь, что безопасно.

### 2.4. Лента Claude

`readMessages` пропускает запись транскрипта с `isCompactSummary: true` (служебная сводка
сжатия контекста), чтобы она не выглядела длинной репликой пользователя.

### 2.5. Ошибки и тексты

| Случай | Что видит пользователь |
| --- | --- |
| Сценарий не забрал `<debug>.text` вовремя | «В очереди: придёт агенту с ближайшим хуком» |
| Сессия внешняя | то же; на экране сессии — строка из 2.3 |
| Сессия панели ждёт, сценарий новый | «Отправлено агенту» |

## Поведение на ОС

| Что | macOS | Linux | Windows |
| --- | --- | --- | --- |
| `<debug>.text` и `<debug>.message` | `session.exp` | `session.exp` | `pty/host.ts` (ConPTY), x64 и ARM64 |
| `WFK_PANEL_SESSION=1` у `claude` | `set env(...)` перед `spawn` в `session.exp` | то же | окружение процесса в `pty/host.ts` |
| Метка в хуке | `wfk hook` читает окружение | то же | то же (`wfk.cmd`) |
| Внешняя сессия: очередь, без возобновления | одинаково | одинаково | одинаково |

Новых программ ОС решение не вызывает; `tools/platform-guard/allowlist.json` не меняется.

## 4. Проверка

- Тесты provider-claude: `sendDirect` пишет `<debug>.text` и возвращает `false` с удалением
  файла, когда его не забрали; `wakeSession` при ждущем `<debug>.text`; разбор обоих файлов в
  `host.ts` (платформа подставлена); `session.exp` содержит оба файла и переменную; лента без
  `isCompactSummary`.
- Тесты agent-channel и cli: `panelProcess` из окружения хука; `external` по последнему хуку;
  прямой путь и пробуждение не вызываются для внешней сессии Claude и вызываются для ChatGPT
  без метки.
- Тесты панели: `reviveSession` не шлёт `resume` для внешней сессии; строка состояния.
- CI: macOS, Linux, Windows x64 и ARM64.
- Живая проверка: macOS — пользователь (сообщение из панели в сессию, открытую в приложении,
  приходит в чат приложения; в сессию панели — сразу; сессия со сценарием 0.9.0 или старше —
  в очередь); Windows — проверяющий на Windows; Linux — CI.

## 5. Границы

- Уже запущенные копии сессий Kit не останавливает: пользователь останавливает их в панели.
- Мгновенной доставки в чат приложения без хука нет: у приложения нет входа для вставки.
- Перезапуск старых сценариев при обновлении службы, Markdown, автопрокрутка и сворачивание
  реплик — не в этой работе.
