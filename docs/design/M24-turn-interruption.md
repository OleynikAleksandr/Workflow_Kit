# M24: контракт прерывания ответа

Обязательная часть [спецификации M24](../planning/M24-interface-polish.md).
Поведение на ОС, согласование и границы задаёт основной документ. Уточнено по ревью R1.

## 1. Общий контракт и канал (T002)

### Типы и возможности провайдера

`Provider.stopSession` завершает процесс/сессию; кнопка ответа его не вызывает. Добавить
capability `interruptTurn` и два необязательных метода в публичный контракт реестра:

```ts
interface InterruptTarget {
  turnRef: string;                 // поколение Kit, не текст команды
  nativeTurnId: string | null;     // если провайдер имеет id хода
}
type InterruptResult =
  | { status: 'interrupted' | 'already-idle'; stopped: true;
      proof: 'provider-event' | 'provider-state' | 'pty-marker';
      nativeTurnId: string | null }
  | { status: 'unavailable'; stopped: false; reason: string }
  | { status: 'stale'; stopped: false };
interface InterruptAvailability { available: boolean; reason: string | null }
// Эти необязательные методы добавляются в Provider:
interface InterruptProviderMethods {
  interruptAvailability?(project: Project, sessionId: string): InterruptAvailability;
  interruptTurn?(project: Project, sessionId: string,
    target: InterruptTarget): Promise<InterruptResult>;
}
```

`interruptAvailability` — дешёвое чтение текущих сведений адаптера, без запуска программ,
новых RPC и управления сессией при опросе. Оба метода необязательны; доступность требует
их наличия и capability. `interruptTurn` проверяет актуальную native-цель перед действием
и возвращает `stopped: true` только с подтверждением завершения этого хода. Исключения —
`ProviderError`; отсутствие подтверждения за 10 секунд — ошибка `interrupt-timeout`.
Общий код T002 должен работать с каждым вариантом результата без последующих правок
реестра/канала/cli в задачах адаптеров. Дедупликация запроса и общий тайм-аут — в T002.
Адаптеры T003–T005 реализуют этот контракт и свои ограниченные ожидания, не меняют его.

### Публичное состояние

Место публикации — `channel.interruptions`, объект по projectId и ключу сессии, рядом с
прежним `channel.sessions`. Запись `InterruptView`:

```ts
interface InterruptView {
  available: boolean;
  reason: string | null;
  turnRef: string | null;
  state: 'unknown' | 'working' | 'holding' | 'waiting';
  pending: boolean;
  barrier: boolean;
  result: 'interrupted' | 'already-idle' | 'stale' | 'failed' | null;
}
```

`cli` собирает записи известных сессий из имеющихся сведений реестра, канала и дешёвого
`interruptAvailability`; не добавляет сетевых опросов в `/api/state`. Канал — владелец
поколения, барьера и pending, адаптер — технической возможности и причины отказа.
Архивные/убранные записи исключены, ошибки чтения не выдают положительную доступность.
Если после перезапуска канал ещё не видел сессию, запись `unknown`, `turnRef: null`,
`available: false`, причина «Состояние текущего хода ещё не подтверждено». Панель не
угадывает busy/idle по последней реплике. Обычная отправка остаётся доступна по M18;
сведения уточняются следующим событием хода, без пробуждения агента ради опроса.

### Поколение хода

Обобщить поколение на клиентов с удержанием и без него. Новое поколение создаётся:
1. при новом `prompt` (хук `UserPromptSubmit`);
2. при принятом ответе `block` на `Stop`: доставка очереди, решение `continue`, напоминание;
3. при принятой отправке нового промпта через detached/sendDirect;
4. при подтверждённом прерывании — для инвалидирования старой цели и её поздних событий.

Связанный `prompt` собственной уже учтённой отправки подтверждает то же поколение,
а не создаёт второе. Для `block` учитывать ack/nack: неуспешная доставка не означает
начавшийся ход; повтор не создаёт второй ход. Native `turn_id` Codex приходит из хука,
а после старта без хука уточняется событием/RPC этого же хода. Поздние подтверждения
старого поколения не меняют состояние нового. Новый turnRef уникален и после рестарта
службы; ранее выданная ссылка не переиспользуется. Наблюдатели/повторы старого хода
инвалидируются при смене поколения. Порядок событий проверяется тестами, включая prompt
до ответа RPC и повторный хук собственной отправки.

### Действие панели и гонки

`POST /api/projects/:id/sessions/:key/interrupt { turnRef: string }`.
До эффекта проверить тело, проект, принадлежность, архив и техническую поддержку.
Ошибки: 400 `invalid-body`; 404 `unknown-session`; 409 `session-archived` или
`interrupt-not-supported` с причиной. Ошибка проверки не ставит чужую/архивную сессию
на паузу. После успешной проверки принадлежности и допустимости действия поставить
барьер продолжения **до** проверки поколения/idle и до ожидания RPC. Барьер сохраняется
при `already-idle`, `stale`, ошибке и тайм-ауте.

Совпадающая цель сериализуется по сессии с хуками, решателем и отправкой очереди.
Повтор pending разделяет один запрос к адаптеру; законченный повтор получает сохранённый
результат. Путь, который собирается отправить очередной `block`/detached prompt, проверяет
барьер непосредственно перед отправкой. Уже отправленное продолжение отменить задним
числом нельзя; обнаружение следующего поколения возвращает актуальное состояние.

HTTP 200 — подтверждённый результат `interrupted` или `already-idle`. Для `already-idle`
нужно подтвердить, что ожидаемый ход действительно завершён, а не считать неизвестное
состояние простоем. HTTP 409 `stale-turn` возвращает текущий `InterruptView`: новый ход
не прерывается старым запросом. Если это автоматическое продолжение, панель обновляет
turnRef и снова предлагает Stop без красного сообщения об ошибке; повтор требует нового
нажатия, скрытого прерывания другого хода нет. Барьер уже не даст следующего продолжения.
Для нового пользовательского хода также нельзя применять старый запрос.

Сбой адаптера — 502 `interrupt-failed`, отсутствие подтверждения за 10 секунд —
504 `interrupt-timeout`; причина/подсказка видны, черновик остаётся. На время запроса кнопка
недоступна с подписью «Останавливаю…». Pending публикуется состоянием; одна успешная
запись RPC/символа в pty ещё не даёт успеха. После тайм-аута кнопка допускает повторную
проверку, старый поздний ответ не перезаписывает новое поколение.

### Подтверждение и переход канала

После результата `stopped: true` канал **сам** завершает именно ожидаемый ход: отменяет
его наблюдатели/таймеры, переводит запись в `waiting`, сбрасывает hold, публикует результат
и инвалидирует turnRef. Это общий путь и для Claude/Codex, и для detached Kimi, не только
`channel.turnEnd`. Он не ждёт нового `Stop`: провайдер может его не вызвать. Поздний хук
того же завершения идемпотентен; новая работа не помечается завершённой старым результатом.
Следующая явная реплика после прерывания проходит прямой путь/очередь по правилам M18.

Источники доказательства:
- Claude: новый маркер прерывания в текущем pty-экране после команды (либо новый такой же
  маркер в переписке через уже существующий reader адаптера); нельзя принять старый
  `[Request interrupted by user]` или само эхо Esc за подтверждение. Дополнительно виден
  готовый ввод и нет активного хода/диалога. Без достоверной проверки — тайм-аут/ошибка.
- Codex: `turn/completed` с `status: interrupted` и совпадающим native turn id; если событие
  пропущено, `thread/read` подтверждает терминальное состояние **этого** id. Пустой ответ
  `turn/interrupt` не является подтверждением остановки. Естественное завершение того же
  хода до команды даёт `already-idle`, но не `interrupted`.
- Kimi: относящийся к этому ходу `Interrupt` и свободный замок, либо `:abort` с
  `{ aborted: true }` с последующим подтверждением idle. Сам HTTP 200 без результата
  и idle не достаточен; сопоставление защищает новый ход от старого события.

### Очередь, автопилот, ревью и исполнители

Барьер запрещает автоматический запуск через удержанный Stop, очередь, detached retry/
maintain и решатель. Очередь не удаляется и не отправляется до снятия барьера. При активном
плане ставится штатная пауза Kit, только если остановлена сессия-владелец; вне плана
прерывание тоже работает. Ошибка паузы видна, барьер сохраняется; успех всей операции
не объявляется, пока обязательная пауза не подтверждена. Новая явная реплика пользователя
снимает барьер доставки; пауза плана снимается только штатным «Продолжить». Отправка
очереди во время работы до нажатия Stop сама по себе барьер не снимает.

Stop не завершает задачу, не принимает/закрывает план и не отвечает на разрешения.
Kit не отменяет назначения исполнителей. Жизнь нативных подагентов зависит от провайдера:
они могут остановиться вместе с ходом оркестратора. Состояние назначений сохраняется;
восстановление идёт штатными `assignment:*`/recovery, без ложного обещания их продолжения.

Прерванный ход не засчитывается успешным ответом ревью и не запускает новый круг;
ревью получает видимую причину и существующее действие повторного запуска. Поздний Stop
не обходит барьер через слушателя ревью. Явная новая отправка и штатное продолжение
обрабатываются отдельно от фоновых сигналов; тесты покрывают каждый источник продолжения.

## 2. Адаптеры

### T003 — Claude

Управляемая Kit сессия: сигнал в существующем `pty/session.exp` (macOS/Linux) и
`pty/host.ts`/`win-host.ts` (Windows ConPTY); перед записью Esc повторно классифицировать
текущий экран в самом pty-host. Пока виден диалог разрешения, trust/imports/onboarding,
`DIALOG unknown`/«Esc to cancel» или достоверно не определён вид экрана, прерывание
недоступно с причиной «Claude ждёт решения в своём диалоге». Клавиши не отправляются.
Проверка выполняется при отображении доступности и непосредственно перед действием,
чтобы устаревшее состояние панели не дало отказ через Esc. Внешняя сессия недоступна.

Подтверждение — как в разделе 1, без зависимости от Stop hook. Процесс/Remote Control
сохраняются; следующая реплика доступна. Не использовать kill, архив или `stopSession`.
Не менять существующие решения M15 о диалогах ради Stop. Тесты macOS/Linux и win32:
working → подтверждённый waiting, отсутствие маркера/тайм-аут, старый маркер, диалог до
нажатия/появившийся между опросом и действием, отсутствие отправленной клавиши при отказе.
Перед расширением почти полного `module.md` вынести подробности pty/Stop в отдельный
документ модуля с ссылкой из краткого контракта; сохранить полный прежний контракт.

### T004 — Kimi

Сервер Kit, `POST /api/v1/sessions/{id}:abort`, проверка результата, хука и idle согласно
разделу 1 и `M8-kimi-protocol`. Чужую сессию не забирать `:takeover`; ложного успеха нет.
Тесты: interrupted/idle, чужой владелец, ошибка/тайм-аут, новый ход во время подтверждения,
отсутствие автопродолжения. Поведение одинаково на macOS/Linux/Windows; пути — через
инъекцию платформы. Почти полный `module.md` разделить, вынеся подробности в документ
модуля с ссылкой, без потери прежнего контракта.

### T005 — ChatGPT/Codex

До реализации подтвердить форму `turn/interrupt` и `turn/completed` локальной схемой/типами
установленного app-server. Native turn id — из хука/подтверждённого события или `thread/read`
управляемого демона; `interrupt` адресуется только ему. Проверить доказательства раздела 1.
Не удалять тред, не завершать демон, не менять общий доступ. Внешний тред без доступного
управления имеет видимую причину недоступности. macOS/Linux используют имеющийся транспорт,
Windows — существующий proxy; отсутствие приложения ChatGPT на Linux не скрывать.
Тесты: точный native id, completed interrupted, естественное завершение до вызова,
ошибка/тайм-аут, позднее событие старого хода, следующий промпт после Stop.

Capability объявляется только для реализованного управления; реальные ограничения
указываются явно. Тесты с подставным транспортом не заменяют живую проверку. Если
обязательный протокол не подтверждён, не считать задачу выполненной: назвать блокер.
Уже законченные адаптеры сохраняют свои коммиты; при необходимости дефекты оформляются
новым fixes-раундом, а не правкой завершённой задачи.
