# M29: мгновенное управление Claude и ход без удержания

## Цель и согласование

В 0.13.2 менять модель, усилие и режим Claude из панели почти невозможно:

- меню заблокировано надписью «Claude ещё отвечает», хотя агент давно ждёт кнопку;
- в свободной сессии каждое изменение идёт секунды, часто кончается ошибкой
  «Транзакция отменена без повтора»;
- в ленту попадают служебные `/effort`, `Cancelled`, `Fast mode OFF`.

Ещё одна связанная проблема: пока агент ждёт решения в панели, сообщение из Claude
Desktop не уходит, а встаёт в очередь Desktop.

Решение пользователя, 14.11.2026: «почему не сделать выбор всего этого внутри
Workflow Kit, без всяких фидбэков со стороны терминала? … Пользователь открывает
меню, … выбирает. И после этого эта команда уходит с нашего Workflow Kit в
терминал, а отображение меню … делать один раз при старте». Тогда же пользователь
выбрал в панели «спецификация и план без ревью».

## 1. Диагноз

Проверено на установленной 0.13.2, сессии C001, C002 и C003.

1. **Удержание Stop-хуком.** Пока автопилот ждёт решения пользователя, решатель
   канала отвечает `hold`, и Stop-хук держит ход Claude до 9 минут (`STOP_HOLD_MS`).
   Ждать он может кнопку «Начать выполнение плана», вопрос о плане, ревью или
   выбор режима. Для Claude ход в это время идёт: в терминале и в Desktop крутится
   индикатор («3m 49s · 34 tokens»). Desktop ставит сообщения пользователя в свою
   очередь. Хост видит на экране признак работы, пишет `status: busy` с причиной
   «Терминал Claude занят или не распознан», и служба блокирует все меню.
   Файл `.turn` при этом уже `idle`, потому что Stop-хук пришёл.
2. **Синхронная транзакция.** `POST …/parameters` ждёт до 25 с, пока хост:
   - откроет `/model`;
   - пролистает меню до первой строки и затем до нужной, проверяя каждый кадр;
   - нажмёт `s`;
   - дождётся ответа Claude и statusline;
   - после смены модели заново откроет `/effort` и пролистает его.

   Любой неожиданный кадр отменяет всё без повтора. Каталог моделей читается в
   каждом хосте заново, через меню `/model`, `/effort` и `/fast`. Отсюда записи
   `Cancelled` и `Fast mode OFF` в ленте.
3. **Команды с аргументом не подходят.** По документации Claude Code
   (code.claude.com/docs/en/model-config, проверено 14.11.2026) `/model <имя>`
   действует как Enter и сохраняет модель по умолчанию в пользовательских
   настройках. `/effort <уровень>` тоже сохраняет уровень. Только для одной сессии
   меняют клавиша `s` в меню, `/effort max` и `/effort ultracode on|off`. M27
   требует не трогать умолчания пользователя. Поэтому модель и усилие по-прежнему
   меняются через меню и `s`, но в фоне и коротким путём.
4. **Ответ на вопрос о плане не терялся.** «Ответ, который не дошёл» — это
   сообщение из Desktop, которое Desktop держал в своей очереди из-за удержания
   (пункт 1). Отдельного дефекта доставки нет.

## 2. Принципы

- Пользователь никогда не ждёт терминал. Меню открывается сразу, выбор виден сразу.
  Хост применяет изменение, когда ввод Claude свободен, и подтверждает его сам.
- Умолчания пользователя не меняются. Модель и усилие — только «для этой сессии»
  (`s`), режим — Shift+Tab, Ultracode — `/effort ultracode on|off`.
- Пока агент ждёт решения пользователя, сессия Claude под хостом панели свободна:
  ход закончен, в Desktop и терминале можно писать.
- Сессии, которые ведутся вне панели (`ledOutside`), а также Codex и Kimi
  работают как прежде.
- Контракты M24–M28 сохраняются: прерывание, очередь, барьер Stop, доставка
  сообщений панели, окно контекста.

## 3. Решение

### 3.1. Ход без удержания (agent-channel, cli)

- У `createAgentChannel` появляется опция `release?: { supports(ref): boolean;
  wake(ref): void }`. Cli передаёт:
  - `supports` — истина, когда у провайдера есть `wakeSession`, сессию запустила
    панель и она не ведётся вне панели (`!ledOutside`);
  - `wake` — существующий `wakeIdle(key)`.
- `stop()`: если решатель ответил `hold`, а `release.supports(ref)` истинно, то:
  - слот получает `waiting`, но сохраняет `holdReason` и `holdUntil` для панели и
    автопилота;
  - хук сразу отвечает пустым ответом;
  - ставится таймер на `holdUntil`. Если к сроку слот в том же поколении всё ещё
    ждёт, то при наличии `timeoutAnswer` напоминание встаёт в очередь
    (источник `reminder`) и вызывается `release.wake`; иначе `holdReason`
    просто снимается.
- `wake(key)` для такого слота заново спрашивает решатель с `woken: true`:
  - `continue` — текст встаёт в очередь (источник `autopilot`), затем
    `release.wake`;
  - `release` — снимает `holdReason`;
  - `hold` — продлевает ожидание.
- Новое сообщение очереди для такого слота, как и сейчас, будит сессию через
  `wakeIdle`. Хост вписывает короткий промпт, а хук `UserPromptSubmit` отдаёт
  очередь.
- Пользователь пишет из Desktop или терминала: обычный пользовательский ход,
  `holdReason` снимается (`setState`). Следующий Stop снова спросит решатель.
- `wakeIdle` пропускает слот в `waiting` с `holdReason` так же, как свободный.
  Барьер Stop (M24) по-прежнему задерживает служебные сообщения.
- Подписи автопилота («Ждёт «Начать выполнение плана»» и т. п.) не меняются.
  Индикатор работы в панели не крутится: состояние канала `waiting`.

### 3.2. Хост: желаемые параметры и каталог (provider-claude, pty)

- **Файл желаемых изменений.** `<debug>.parameters-wanted`, атомарная запись
  службой:
  `{ version: 1, hostId, sessionId, changes: { model?, effort?, mode?, ultracode? }, ids }`.
  - На каждое поле — последнее значение пользователя, `ids[field]` — UUID выбора.
  - Хост берёт поля по порядку: `model`, `ultracode`, `effort`, `mode`. Модель
    первой, потому что от неё зависят варианты усилия.
  - Начинает, только когда `ready()`: экран `idle`, ввод пуст, ход не идёт, режим
    распознан.
  - Результат каждого поля пишется в `.parameters-result` (`id` = `ids[field]`,
    `field`, `status`, `reason`).
  - `applied` удаляет поле из файла, только если `ids[field]` не сменился.
- **Повторы.** Отменённая транзакция (неожиданный кадр, ввод пользователя, начало
  хода) повторяется при следующем свободном вводе. Отмены из-за ввода
  пользователя и начала хода не считаются. Иные неудачи считаются: после трёх
  поле удаляется с результатом `failed` и причиной.
  - Срок у желаемого изменения не ограничен, пока жив хост: оно ждёт свободного
    ввода сколько угодно.
  - Устаревшие механизмы `.parameters-request` и `epoch` для желаемых изменений
    не используются. Чтение каталога остаётся внутренним.
- **Короткий путь модели.**
  - Меню `/model` открывается на текущей модели. Хост сравнивает номер
    выбранной строки с номером цели в кэше каталога и жмёт стрелки в нужную
    сторону, проверяя подпись строки перед `s`.
  - Цель в «More models» раскрывается Enter на этой строке, как сейчас.
  - Чтение всего меню сверху — только при обнаружении каталога.
  - После смены модели `/effort` открывается, только если варианты усилия этой
    модели ещё не известны.
- **Каталог один раз.**
  - Хост пишет `<debug>.parameters-catalog`:
    `{ version: 1, cliVersion, models, efforts: { [modelLabel]: { values, recommended } }, ultracode: { [modelLabel]: boolean } }`.
  - Служба копирует его в каталог данных (`claude-native-catalog.json`), а при
    запуске хоста кладёт копию рядом с debug-файлом.
  - Совпадает `cliVersion` — хост не открывает меню при старте. Иначе он читает
    каталог один раз при первом свободном вводе.
  - Варианты усилия другой модели дочитываются при первом переходе на неё.
  - `/fast` больше не открывается. Скорость только показывается по statusline
    с постоянной причиной «Скорость Claude меняется только в его приложении».
- **Режим не теряется.** Последний подтверждённый режим хранится в движке. Кадр
  без строки режима (меню, перерисовка) не делает его неизвестным. `ready()`
  требует распознанного режима только для транзакции режима.
- **Занятость по хукам.** `status` в снимке отражает экран, как прежде. Но после
  3.1 удержание уже не держит экран «занятым».

### 3.3. Служба: ответ сразу (provider-claude, provider-registry)

- `ParameterItem` получает `pending?: { value: string; label: string; note: string }`.
  `SessionParameters` получает `failures?: { field: ParameterId; value: string; reason: string; at: string }[]`
  за последние 60 с.
- `read()` собирает меню из каталога хоста или, пока его нет, из
  `claude-native-catalog.json` той же версии CLI. Опции не заблокированы из-за
  занятости.
  - `editable` ложно, только когда у сессии нет живого хоста 0.13.3+. Причина:
    «Управление доступно для сессий, запущенных панелью Workflow Kit 0.13.3 или
    новее».
  - `pending.note`:
    - «применяется» — Claude свободен;
    - «применится, когда Claude закончит ответ» — идёт ход;
    - «применится, когда поле ввода Claude опустеет» — черновик.
- `update()` проверяет значение по каталогу, сливает его в `.parameters-wanted` и
  возвращает `read()` с `pending` за время чтения файлов, без ожидания хоста.
  - Выбор текущего подтверждённого значения снимает ожидающее изменение этого
    поля.
  - Ошибки остаются только для неверных значений (400) и сессий без хоста (503).
- Результат `failed` попадает в `failures`, `pending` поля исчезает, строка
  показывает подтверждённое значение.
- Событие `provider.parameters.changed` пишется, когда служба видит
  подтверждение: значение statusline или режима сменилось на желаемое.
- Задержка от выбора до показа в панели — один запрос: служба читает только
  файлы.

### 3.4. Панель (session-chat)

- Меню модели, усилия, режима и Ultracode открываются всегда, когда `editable`.
  Сноска о занятости Claude не показывается.
- Выбор сразу ставит значение в строку под меню с приглушённой пометкой
  `pending.note` и тонким индикатором. Опрос параметров идёт раз в 1 с, пока есть
  `pending`, и как обычно без него.
- `failures` — одна строка под вводом: «Claude не принял <поле> <значение>:
  <причина>». Она исчезает через 10 с или при следующем выборе. Строка параметра
  возвращается к подтверждённому значению.
- «Транзакция отменена без повтора» и другие внутренние причины хоста в панели
  не показываются.

## 4. Поведение на ОС

| Что | macOS | Linux | Windows (x64 и ARM64) |
| --- | --- | --- | --- |
| Ход без удержания | одинаково: решение в канале, пробуждение хостом панели | одинаково | одинаково; хост `win-host.ts` вписывает промпт так же |
| Файлы `.parameters-wanted`, `.parameters-catalog` | атомарная замена `rename` | так же | `rename` с повтором при `EPERM`, как у `.turn` |
| Кэш каталога службы | каталог данных службы | так же | так же; пути через `path` и внедрённую платформу |
| Клавиши меню, Shift+Tab | expect-хост | expect-хост | ConPTY, те же последовательности `NATIVE_KEYS` |
| Меню панели | одинаково во всех браузерах | одинаково | одинаково |

Поведение одинаково на всех ОС. Ветки `win32` и `linux` покрываются тестами с
подставленной платформой.

## 5. Проверка

- **agent-channel.** Удержание с `release`: хук отвечает сразу, `holdReason`
  сохраняется. `wake` спрашивает решатель и ставит `continue` в очередь.
  Напоминание по сроку. Ход пользователя снимает ожидание. Без `release` всё как
  было. Барьер Stop.
- **cli.** `supports` для сессии панели, вне панели (`ledOutside`), Codex и Kimi.
  Очередь будит освобождённую сессию.
- **provider-claude.**
  - Движок на кадрах 2.1.325: короткий путь модели в обе стороны и в «More
    models», повторы и счёт неудач, порядок полей, слияние последнего выбора.
  - Каталог из файла без меню и перечитывание при другой версии CLI.
  - Отсутствие `/fast` и сохранение режима.
  - Служба: `pending` и его заметки, `failures`, ответ без ожидания хоста.
- **session-chat.** Браузерный сценарий: меню открыто во время хода, пометка
  «применится…», откат при ошибке, светлая и тёмная тема, ширины 375, 768 и 1280.
- **Живая проверка на macOS** (одноразовый проект Kit, модель Haiku, не больше
  двух коротких ходов):
  - вопрос о плане: Desktop-сообщение уходит сразу, индикатор не крутится;
  - смена модели, усилия и режима свободной сессии, подтверждение до 3 с;
  - выбор во время хода применяется после него;
  - хэш `~/.claude/settings.json` не меняется.
- **Windows:** проверяющий на Windows повторяет живую проверку на поставке.
  **Linux:** пока только CI.
- **CI:** macOS, Linux, Windows x64 и ARM64 для точного SHA поставки, на ветке
  `ci/<scope>` по команде пользователя.

## 6. Границы

- Не входит:
  - запуск Claude в режиме SDK (`stream-json`) и канал Remote Control;
  - включение Fast из панели;
  - изменения Codex и Kimi.
- Сессии, запущенные хостом 0.13.0–0.13.2, получают новое поведение после
  возобновления из панели.
- `OVERVIEW.md` (27 986 байт), `provider-claude/module.md` (27 925) и
  `CHANGELOG.md` (27 935) близки к лимиту 28 000. Новые абзацы требуют сжать
  старые.

## 8. Итог реализации (DOCS-R1)

Отличия от разделов 3.1–3.4, найденные при реализации и живой проверке:

- **Состояние отпущенного слота** (T001). Слот получает `holding` с `holdReason` и
  `holdUntil`, а не `waiting`: так уже показывается удержание detached-сессий, и панель
  менять не пришлось. Индикатор работы не крутится, Stop-хук отвечает за 1 мс.
- **Диалог «Switch model?»** (T005). Claude 2.1.325 после `s` в разговоре с кэшем спрашивает
  «Yes, switch to <модель>» / «No, go back». Хост подтверждает его Enter только для своей цели,
  иначе закрывает Esc и считает неудачу.
- **Подтверждение модели** (T005). В режиме plan statusline показывает модель плана
  (Haiku → Sonnet 5.5), поэтому модель подтверждает строка «Set model to <модель> for this
  session only». Усилия новой модели дочитывает фоновое обнаружение после транзакции;
  поле, которому нужен каталог, не обгоняется следующими (`WANTED_ORDER`).
- **Темп хоста** (T005). `after 100` системного Tcl 8.5.9 на macOS длится около 250 мс; паузу
  занятого хоста теперь выдерживает Node-помощник (`PACE_MS` = 100 мс), движок сразу
  предлагает следующий шаг. Клавиша заняла около 0,3 с вместо 1 с.

Живая проверка на macOS (Haiku, два хода): усилие 2,4 с, режим 1,0–1,8 с, модель 2,6–3,1 с
(с диалогом), пробуждение сообщением 2,0 с, выбор во время хода — через 3,6 с после Stop,
`~/.claude/settings.json` не изменился —
[доказательства](../evidence/M29-claude-controls-instant.md).
