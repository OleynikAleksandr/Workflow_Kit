# Приёмка M9 — исправления старта сессий Kimi, релизы 0.6.1 и 0.6.2 (2026-11-10)

- Спецификация: [M9-kimi-start-fixes.md](../planning/M9-kimi-start-fixes.md); scope
  `m9-kimi-start-fixes`, режим `sequential`.
- Причины (живая проверка 0.6.0 на проекте F001): два сервера Kimi и две рабочие области
  одной папки; хуки Kit не работали ни в одной сессии, потому что Kimi читает хуки только
  при запуске сервера, а Kit судил о них по `GET /api/v1/config`.
- Что сделано:
  - T001 `f34f6ac` — свой сервер Kit перезапускается по отпечатку блоков хука (у
    подхваченного после перезапуска службы — по времени); пометка «Перезапустите
    приложение Kimi Code», если оно запущено до записи хука.
  - T002 `2cad379` — пока работает приложение Kimi Code, все запросы идут на его сервер,
    свой `kimi web` не запускается; переход на приложение и возврат; действия сервера и
    Remote Control при сервере приложения выключены.
  - T003 `76f8f89` — `wfk session title|plan` находит ход Kimi по замку сессии без хуков.
  - DOCS `f66bd16` — документы раунда.
- Локально (macOS): `npm test` — 570 тестов, 569 прошли, 1 пропущен (не для macOS);
  проверка типов — без ошибок; `npm run check:platforms` — ok; `node bin/wfk.mjs install`
  (обновление с 0.6.0) и `wfk doctor --installed` — «всё в порядке», служба 0.6.1.
- CI: релизный коммит `7e48898` в ветке `ci/m9-kimi-start-fixes`,
  [запуск 42792351572](https://github.com/OleynikAleksandr/Workflow_Kit/actions/runs/42792351572) —
  успех на macOS ARM64, Linux x64, Windows x64 и Windows ARM64 (typecheck, тесты,
  `check:platforms`).

- Показывает ли интерфейс приложения сессию, созданную через его сервер другим клиентом
  (Kit), без перезагрузки окна.
- Чей pid стоит в замке хода сессии приложения (процесс приложения или его помощник):
  от этого зависит, когда Kit остановит свой сервер после появления приложения.

  в приложении по-прежнему ведёт на проект.

## Релиз 0.6.2 — раунд R2 (замечания живой проверки 0.6.1)

- Причины (живая проверка 0.6.1 на проекте O001): ссылка `kimi-code://open` всегда
  добавляет в проект пустой чат; служба теряла свой сервер `kimi web` из учёта процессов
  (процесс меняет имя), и осиротевший сервер давал ложную пометку о перезапуске приложения.
- Что сделано:
  - T005 `9c8b2e2` — проект Kimi открывается запуском приложения с `--workspace=<папка>`
    (macOS `open -n -a`, Windows `Start-Process` программы обработчика `kimi-code`), ссылка —
    запасной путь и способ для Linux и новой сессии; щелчок по карточке Kimi на компьютере
    идёт через службу.
  - T006 `1f3a48b` — `SpawnSpec.renames`: запись сервера Kimi узнаётся по времени запуска;
    `APP_RESTART_NOTE` — только от сервера приложения.
  - DOCS `7811549` (R2) и `6cebc4f` (R3) — документы раундов.
- Локально (macOS): `npm test` — 577 тестов, 576 прошли, 1 пропущен (не для macOS);
  проверка типов — без ошибок; `npm run check:platforms` — ok; `node bin/wfk.mjs install`
  (обновление с 0.6.1) и `wfk doctor --installed` — «всё в порядке», служба 0.6.2.
