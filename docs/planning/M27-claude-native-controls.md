# M27: нативное управление параметрами Claude

## Цель и согласование

13.11.2026 после приёмки M26 пользователь попросил: «А теперь давай разберемся
и сделаем то же самое для Claude!» В панели выбраны спецификация и план с ревью.
Нужен следующий результат: модель, усилие, скорость и режим доступа Claude
можно менять из диалога Workflow Kit в той же нативной беседе, с удобством
родного Claude Code. Новая веха начинается от принятой0.12.1, M26 закрыта.

Эталон — Claude Code в приложении Claude, включая представление управляемой
Remote Control-беседы. Снимки ChatGPT из M26 относятся к другому интерфейсу.
Факты/источники и открытые вопросы —
[исследование M27](../design/M27-claude-controls-facts.md).

## 1. Принципы

- Нативные названия, варианты, ограничения и эффекты сообщает адаптер Claude.
  Общая панель выбирает presentation layout, а не provider===claude.
- Применяется к выбранной беседе; успешный setter подтверждается новым native state.
  Модель в сообщении прошлого хода, optimistic echo, взятый файл команды и сохранённый
  default не доказывают, что целевая работающая сессия изменилась.
- Смена параметров не создаёт SDK-копию чата, не убивает/перезапускает идущий процесс,
  не очищает ввод и не одобряет за человека неожиданный диалог Claude.
- Scope минимальный: session-local управление. Не менять пользовательские defaults,
  settings других проектов, hooks, statusline, trust и MCP ради имитации setter.
  Если доступен только путь с иной областью сохранения, нужен отдельный договорённый
  пересмотр, до него операция недоступна. Это проверяется первым этапом.
- Сохраняются исправления M26/R2: успешные переключения без зелёного служебного
  подстрочника; ошибки читаемы. Реальный захват thumb проверяется отдельно от клика.
- История/очередь/Stop и Remote Control, контекст/лимиты Claude, пользовательская
  statusline и управление ChatGPT/Kimi сохраняют существующие гарантии.

## 2. Решение

### 2.1. Сначала доказать управление и получить эталоны

T001 работает только с исследованием и доказательствами, функциональные изменения
начинаются в T002. На момент планирования подтверждены CLI2.1.323 и read-only
адаптер M25. Общедоступный agents --json даёт список процессов, не setters.
Видимых окон Claude через CoreGraphics нет, открытые меню ещё не сняты.

На собственных временных native-сессиях зафиксировать для каждого контрола:
текущий state, каталог/disabled/reason, точный запрос, подтверждение, read-back,
момент применения, persistence, ограничения и изменение из родного приложения.
Проба сохраняет ту же local identity/историю и нужные Remote Control-связи.
Факты SDK streaming и PTY не смешиваются: setter другого SDK run не подходит.

Кандидаты по приоритету: доступный штатный структурный канал целевого процесса;
если его нет — типизированная транзакция существующего PTY host с разрешёнными
нативными командами и независимым подтверждением. Нельзя придумывать private
cloud API, читать токены из хранилищ или передавать shell-строку из HTTP в терминал.
Выбран ровно один проверенный путь для поддерживаемой комбинации версии/host;
неопознанный путь отказывает, не пробует автоматически другие способы.

Каналу предстоит доказать session-local эффект. Обычные /model, /effort и /fast
могут сохранять defaults; их наличие недостаточно. Не восстанавливать изменённый
user settings файл из старой копии: это может затереть параллельные изменения.
Если безопасного пути нет, T001 фиксирует блокер и останавливает scope до решения
пользователя; остальные задачи не выполняются с фиктивными контролами.

Для оформления сохранить composer и открытые нативные меню, версию, тему/DPR и
замеры. Если read-only захват не видит нужный экран, потребуется снимок пользователя.
Текст официальной документации достаточен для семантики, но не заменяет PNG для QA.
T001 уточняет визуальный контракт и эту спецификацию до первого функционального кода.
Отсутствие эталонов или доказанного основного setter — блокер, не формальная галочка.

### 2.2. Модель, усилие, скорость, Ultracode и режим

- Модель: список из актуального нативного каталога выбранной среды/аккаунта,
  текущая отметка, причины запретов. Alias/label не выдавать за точный effective id.
  После смены перечитать также effort/fast/mode: Claude может поправить связанный
  параметр. Не разрешать несуществующий вариант, невзирая на принятую строку CLI.
- Усилие: только уровни, поддерживаемые моделью и политикой. Порядок кандидатов
  low/medium/high/xhigh/max; native default/auto показывается отдельно от явно
  выбранного уровня. Старое неизвестное значение не превращается в первую точку.
- Ultracode не шестой effort и не синоним max. Если доступен в нативном эталоне,
  отдельный toggle и отдельное эффективное значение; его смена сохраняет effort,
  кроме доказанного нативного coupled-effect, который явно подтверждён до записи.
  Workflow Kit не создаёт свою оркестрацию вместо этого штатного флага Claude.
- Скорость: standard/fast, из native fast_mode и свежей доступности; отсутствие
  поля означает неизвестность. Подсказка отражает реальный расход/доступность без
  зашитого множителя. Если включение требует смены модели или дополнительного
  платного согласия, сначала конкретное подтверждение либо причина недоступности;
  ни автоматического согласия, ни платной генерации для простого read-back.
- Режим доступа: Manual/default, Accept edits/acceptEdits, Plan/plan, Auto/auto
  и только реально доступные данной поверхности дополнительные режимы. Plan —
  один native permission mode, отдельного независимого переключателя плана нет.
  manual нормализуется в default, исходный неизвестный режим не теряется.
  dontAsk не подставляется как Desktop Manual. Auto использует проверяющего Claude.
- Bypass не становится вариантом только потому, что CLI знает это слово. Если
  выбранная native/Remote Control поверхность запрещает его, Kit тоже не включает
  обходом через терминал. Уже установленный локально bypass читается как фактический
  режим. Где переключение действительно разрешено, до записи нужно confirmed и
  согласованное нативное предупреждение; ограничения managed policy сохраняются.

Точная таблица команд и read-back после T001 живёт в docs/design/M27/. Функциональные
задачи ссылаются на неё. Недоступность отдельных нативных опций честно объясняется;
отсутствие основного управления не считается завершением всей цели.

### 2.3. Контролы в composer

Постоянные контролы модели/усилия/скорости и отдельного native mode находятся
под вводом, как на зафиксированном эталоне Claude. Синий контекст и оформление
Claude M25 сохраняются. Габариты/выравнивание/popover hierarchy берутся из PNG T001;
размеры255×97 ChatGPT не являются требованием к Claude. Native отсутствующие элементы
не добавляются: никаких круговой стрелки, Подробнее или служебного success-текста.

Выбор модели и работа с усилием повторяют измеренный нативный сценарий; обычный
длинный список всех настроек не возвращается. Режимы сопровождаются родными
описаниями, выделением текущего и причиной отказа; ошибки показываются возле ввода.
Контекст и лимиты остаются отдельными информационными контролами, не теряются при POST.

Если нативное усилие представлено ползунком, использовать семантический range с
дискретными значениями: захват текущего thumb, движение в обе стороны, preview,
один POST после отпускания, включая отпускание вне дорожки. Оставить capture thumb
браузеру; документные listeners только завершают/отменяют жест. Неизменённые
атрибуты не переписываются при polling. Arrow/Home/End работают, Esc/cancel/blur
не отправляют запоздалый change. Если эталон иной, T001 фиксирует фактический контрол.

Один popup одновременно, Esc возвращает фокус, снаружи закрывается. Четыре стороны
ограничены visualViewport; при нехватке места перенос/прокрутка, а не обрезка кнопок.
Touch-цели не менее44px. На375px переносится группа целиком, названия читаемы.
Polling сохраняет DOM/focus/draft/несохранённый жест, POST блокирует изменяющие
контролы этой сессии. Старый GET/результат другой сессии не откатывает новый state.

### 2.4. Общий контракт и HTTP

Полная схема и HTTP-контракт — [контракт управления](../design/M27-claude-control-contract.md#24-общий-контракт-и-http).
Добавляется discriminated layout claude-controls, существующий effort-card/access
сохраняется. Claude использует items model/effort/speed/mode и, если подтверждён,
отдельный ultracode on/off. За запрос одно изменение плюс confirmed; GET только
читает метаданные, POST проверяет ownership/каталог/host и перечитывает результат.
Аудит — effective old/new, ошибки400/409/503/504 с явным mapping и читаемой причиной.

### 2.5. Native control и конкурентность

[Полный протокол](../design/M27-claude-control-contract.md#25-native-control-и-конкурентность)
обязателен: UUID/epoch/deadline, native read-back и единый арбитр parameters/send/Stop.
Операция начинается только на подтверждённом пустом idle без чужого диалога; busy,
черновик и stale дают отказ до записи. Управляющая команда не превращается в LLM
сообщение и не снимает барьер канала через хуки. Ни скрытых retries, ни kill/restart.

### 2.6. Внешние сессии и старые host

[Контракт совместимости](../design/M27-claude-control-contract.md#26-внешние-сессии-и-старые-host):
внешние/старые host остаются read-only с причиной, без скрытого захвата. Штатное
возобновление после остановки пользователем сохраняет local историю и mapping
Remote Control. Идущие процессы, ревьюер и рабочие беседы не используются в пробах.

## 3. Поведение на ОС

| Что | macOS | Linux | Windows x64 и ARM64 |
| --- | --- | --- | --- |
| Панель и новые controls | общий ES/CSS, две темы, touch | тот же код | тот же код |
| Текущий host | expect/Tcl + Node worker | expect/Tcl + Node worker | ConPTY + Node host |
| Управление | проверенный T001 канал, общий state machine | тот же контракт, injected linux | тот же контракт, injected win32 |
| Read/polling | снимки без программ/GUI | то же | то же, path helpers |
| Доступ native GUI | эталон Claude Code/Remote Control | браузер Kit; GUI не требуется для backend | GUI пользователя, ограничения поверхности те же |
| Проверки | локальные probes + пользователь | CI, без заявления live | CI x64/ARM64; отдельный проверяющий |

Платформа — параметр platform ?? process.platform, пути — path helpers, LF.
Каждая linux/win32 ветвь тестируется с injected platform. Новые вызовы программ
дописываются в tools/platform-guard/allowlist.json вместе с поведением двух других ОС.
OVERVIEW OS matrix и module contracts обновляются в том же коммите, что код.

## 4. Проверка и критерии готовности

- T001: визуальные PNG и проверенная таблица setters/read-back/persistence; доказана
  та же сессия. При невозможности — конкретный блокер до T002, не урезанная готовность.
- Host: idle/busy/draft/dialog/unknown, stale epoch, параллельные POST/send/Stop,
  UUID/deadline/cancel, поздний ACK и ошибка снимка; нет случайных клавиш/LLM-сообщений.
- Native: переключение и новый подтверждённый state, обратная смена в Claude,
  следующий безопасный тестовый ход, сохранение unrelated полей и defaults.
- Правила: модели/effort/fast/modes по каталогу, ultracode отдельно, auto policy,
  недоступный bypass, требуемое подтверждение, сбой read-back, legacy host/sessions.
- UI: все контролы, причины/ошибки, без зелёного success; drag точно из thumb центра
  в обе стороны с preview до release, после polling и вне трека. Также keyboard,
  touch и cancel; тест ожидания stable layout перед замером.
- Dark/light: 1920×1080,1280×800,1024×768,768×400,375×667;200% CSS-эквивалент отдельно.
  Эмуляция клавиатуры/visualViewport не называется проверкой настоящего iPad.
- Design QA: одновременно открыть нативный эталон и рендер одинакового состояния/
  плотности, проверить типографику/геометрию/цвета/значки/текст; P0/P1/P2 исправлены,
  корневой design-qa.md: passed. Артефакты в docs/evidence/M27/.
- Regression M26/R2: ChatGPT модель/effort/доступ, drag и quiet success сохраняются;
  Kimi fallback, Enter/Stop/очередь, statusline/лимиты Claude проверены.
- Полный профиль typecheck/npm test/platform-guard и Kit checks; без ослабления
  assertions/тайм-аутов. Новые зависимости не нужны по умолчанию; если без них
  нельзя, до установки явно согласовать изменение approval/QUALITY.
- Поставка0.13.0: штатная установка, doctor installed, настоящий API/панель,
  тестирование установленного ES/CSS с изолированным I/O и безопасная native проба.
  CI четырёх платформ зелёная на точном SHA поставки, пользовательская приёмка отдельно.
- Живую macOS/iPad проверяет пользователь, Windows — проверяющий, Linux — только CI.

## 5. Границы и поставка

Только параметры Claude Code управляемых бесед; consumer chat/Cowork, новые способы
оркестрации, облачный Claude runtime, перенос на SDK-host и полная миграция lifecycle
не входят. Если T001 требует такую смену архитектуры, зафиксировать границу и запросить
решение по конкретному варианту до кода. Отсутствие нативной функции на выбранной
поверхности показывается честно, не реализуется обходом запрета.

T006 после DOCS и подтверждения пользователя устанавливает локальную0.13.0 без push;
его коммит — SHA поставки. Вне задач этот SHA по прямой команде пользователя
отправляется в ci/m27-claude-native-controls. T007 начинается только после проверки
headSha и четырёх зелёных jobs; меняет доказательства, не делает push.
План/ревью/выбор режима не считаются разрешением на main publication, приёмку
или закрытие. Main публикуется только отдельным действием после принятия и закрытия.
В этом ходе только спецификация и scope:propose, выполнения задач нет.

## 6. План

Все work-задачи parallelSafe:false: одна нативная среда, общий host/protocol,
зависимые контракты и DOM. Последовательный режим рекомендован. После предложения
план проверяет другой провайдер через штатную панель; отдельные reviewer-чаты
или сообщения вручную не запускаются. QUALITY/DOCS Kit добавляет по профилю.
