# M15: предложения новых функций и первый запуск Claude

## Цель и согласование

Живая проверка 0.8.1 на Windows (2026-11-11) дважды не дала создать первую сессию Claude:

1. Claude не прошёл свой первый запуск и показывал выбор темы («Syntax theme: Monokai
   Extended»). Kit этот экран не распознал и ждал ссылку Remote Control 2 минуты, затем
   написал «Claude не сообщил ссылку Remote Control».
2. Claude Code 2.1.319 показал рекламное предложение «Try the new fullscreen renderer?» с
   вариантами «1. Yes, try it» и «2. Not now». Kit клавиш не нажимает, остановил процесс и
   отправил пользователя в предпросмотр доверия, где такого вопроса нет. Пользователь этот
   вопрос не видел: Kit запускает Claude в скрытом терминале.

Решение пользователя, 2026-11-11: Kit сам отвечает «Not now» на такие предложения («Отлично,
это подходит. Делай исправление.»). Выпуск — 0.8.2.

## 1. Принципы

- На вопросы о доверии, импортах CLAUDE.md и любые незнакомые диалоги Kit по-прежнему клавиш
  не нажимает: процесс останавливается с текстом диалога.
- Исключение одно — **предложение новой функции**: вопрос, начинающийся с «Try the new …» или
  «Would you like to try …», среди вариантов которого есть «Not now». Kit выбирает «Not now»
  и ничего не включает. Ни на что другое Kit не отвечает.
- Один запуск отвечает не больше чем на 3 предложения; то же предложение после ответа — уже
  незнакомый диалог (остановка), чтобы не уйти в цикл.
- Экраны первого запуска Claude (выбор темы, способ входа) Kit не проходит сам: вход —
  решение пользователя. Kit сразу называет причину.

## 2. Решение

### 2.1. Распознавание (Windows `screen.ts`, macOS и Linux `dialogs.tcl`)

Новые виды диалога, те же шаблоны на обеих сторонах (слова с промежутком до 16 символов, как
сейчас):

- `promo` — `Try${G}the${G}new|Would${G}you${G}like${G}to${G}try` и вариант
  `(\d)\.${G}Not${G}now`; проверяется после `imports` и `trust`;
- `onboarding` — `Syntax${G}theme|Choose${G}the${G}text${G}style|Select${G}login${G}method`.
  Экран выбора темы не печатает «Enter to confirm», поэтому шаблон `onboarding` добавляется в
  общий шаблон диалога (`DIALOG`, `dialog_pattern`) — иначе остаётся ожидание до тайм-аута.

### 2.2. Ответ «Not now»

- После тишины экрана (как сейчас: 1 с тишины, не дольше 5 с) хост находит номер варианта
  «Not now» и номер варианта под курсором (`❯` или `>` перед `N.`; без курсора — 1) и
  отправляет нужное число стрелок (`ESC [ B` вниз или `ESC [ A` вверх), затем Enter.
- Печатает маркер `PROMO_DECLINED <номер>`, очищает накопленный экран и продолжает ждать
  ссылку; тайм-аут ожидания ссылки начинается заново.
- Windows: `pty/host.ts` (фаза `dialog` → обратно `waiting`). macOS и Linux: процедура
  `handle_dialog` в `dialogs.tcl` возвращает `declined`, ветка `session.exp` и
  `environment.exp` делает `exp_continue`.
- Бэкенд (`pty.ts`): `parseMarkers` считает `PROMO_DECLINED`; служба пишет в журнал
  `claude: declined a feature offer`, пользователю ничего не показывается.

### 2.3. Тексты ошибок (`pty.ts`, `dialogError`)

- `onboarding` (код `onboarding-dialog`): «Claude не завершил первый запуск (выбор темы или
  вход).» Подсказка: «Запустите claude в терминале, выберите тему и войдите, затем
  «Повторить». Если команда claude не находится, путь к программе — в «Настройки» →
  «Система».»
- `unknown`: подсказка больше не отправляет в предпросмотр доверия: «Запустите claude в папке
  проекта в терминале, ответьте на этот вопрос и повторите.» Для `trust` и `imports` —
  прежняя подсказка про предпросмотр доверия.

## 3. Поведение на ОС

| Что | macOS | Linux | Windows |
| --- | --- | --- | --- |
| Распознавание `promo` и `onboarding` | `dialogs.tcl` под `expect` | то же (`expect`) | `pty/screen.ts` в хосте ConPTY |
| Ответ «Not now» | `send` стрелок и `\r` в `session.exp`/`environment.exp` | то же | `term.write` в `pty/host.ts`; x64 и ARM64 одинаково |
| Тексты ошибок | общий `pty.ts` | то же | то же |

Шаблоны и правила одинаковы на всех ОС; различается только хост терминала.

## 4. Проверка

- Windows-хост: тесты с подставным терминалом (`windows.test.ts`): предложение → стрелки и
  Enter, затем ссылка → `SESSION_URL`; повтор того же предложения → `DIALOG unknown`; выбор
  темы → `DIALOG onboarding` без нажатий.
- macOS и Linux: сквозные тесты с поддельным claude (`fixtures/fake-claude.mjs`) под `expect`
  — тот же сценарий; без `expect` пропускаются (CI Linux ставит `expect`, если он есть в
  образе).
- `dialogError`: тексты для `onboarding`, `unknown`, `trust`.
- CI: macOS, Linux, Windows x64 и ARM64.
- Живая проверка: Windows — проверяющий на Windows (первая сессия Claude в новом проекте
  после выбора темы и с предложением fullscreen renderer); macOS — пользователь.

## 5. Границы

- Kit не проходит за пользователя выбор темы и вход в Claude.
- Предложения других провайдеров (Codex, Kimi) не меняются.
- Диалоги Claude после появления ссылки (во время работы сессии) не обрабатываются: там
  пользователь видит сессию в приложении.
