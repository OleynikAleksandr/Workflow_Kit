# Модуль: provider-cards

Часть `control-panel`, кластер `web-panel`. Алиас импорта: `#provider-cards`.

## Назначение

Карточки провайдеров в панели: по одной карточке на каждого провайдера из
раздела `providers` `/api/state`. Карточка рисуется только из контракта
провайдера (`provider-registry`) и раздела `operations`; кода под
конкретного провайдера нет, поэтому реализации Claude (T006) и Codex (T007)
появляются в панели без её правок, как и любой новый провайдер.

## Публичный интерфейс для бэкенда (`src/index.ts`)

- `PROVIDER_CARDS_PREFIX` — `/provider-cards/`.
- `PROVIDER_CARDS_ASSETS_DIR` — абсолютный путь к `src/` модуля.
- `providerCardsMount() → { prefix: '/provider-cards/', dir }` —
  монтирование для `http-server` (подключает `cli`, `createApp`).

## Подключение к панели

`provider-cards.js` — расширение панели: `panel-shell` (`app.js`,
`PANEL_EXTENSIONS`) загружает его и вызывает `install(shell)`, передавая
свои помощники (`registerCardGroup`, `requestRefresh`, `api`, `ApiError`,
`dom`). Файлы модуля импортируют только соседние файлы; файлы панели по URL
не импортируются. Стили — `provider-cards.css`, подключены в
`index.html` панели. `install` регистрирует группу карточек `provider`
(порядок 30, после «Структуры Kit»): по карточке на провайдера, заголовок —
`title` провайдера, DOM id — `card-provider-<id>`. С вехи 2 карточки
рисуются в сетке экрана «Настройки» (`panel-shell`), на главном экране их
нет.

## Что показывает карточка

- Статус: метка `status.label` с тоном по `status.state`, установлен ли CLI,
  версия, путь, `details` провайдера (вложенные объекты — строками
  `daemon.running`), время проверки, `note`; кнопка «Перепроверить»
  (`POST /api/refresh`, операция `providers.refresh`).
- «Недоступно: N» — недоступные возможности с причинами (D4); ошибки чтений
  (`errors` сводки и проекта) — с `code`, `message`, `hint`.
- Особые действия провайдера (`actions(null)`) и проекта — кнопки из
  контракта: выключенная показывает `reason`, `confirm` спрашивается перед
  запуском; `POST /api/providers/:p/actions/:a` или
  `POST /api/projects/:id/providers/:p/actions/:a`.
- Проект: выбор из списка (если проектов больше одного), «папка не
  найдена».
- Доверие: состояние (`доверено` / `нет доверия` / `неизвестно`), `note`,
  копия конфига (`backup`); отдельная пометка «доверена родительская
  папка» с путём и `note` провайдера, если в состоянии или предпросмотре
  есть `inherited`. «Предпросмотр доверия…» (`GET …/trust/preview`)
  показывает записываемые ключи и файлы, точки автозапуска, выборы
  (`choices`: группа переключателей на выбор, описание, «нужен ответ» у
  обязательных; ни один ответ не выбран заранее), заметки и срок токена.
  «Доверять» (если папка уже доверена, а записать нужно только выбор, —
  «Записать выбор») отправляет `POST …/trust { token, choices }` с токеном
  этого предпросмотра и ответами; пока на обязательный выбор нет ответа
  (или ответ не из его вариантов), кнопка заблокирована с причиной
  «Сначала выберите ответ: «…»». Ответы живут вместе с предпросмотром:
  новый предпросмотр начинается без них. Кнопки нет, если записывать
  нечего (`writes` и `choices` пусты); устаревший предпросмотр
  предлагается открыть заново.
- Хуки: хук Kit первым, затем чужие; у каждого — команда, хеш (короткий, весь
  — в подсказке), состояние и ключ; «Список сессий неполон» при
  `complete: false`. «Одобрить хук…» есть у хука Kit в состоянии не
  `approved`; после подтверждения с командой и хешем отправляет
  `POST …/hooks/approve { command, hash }`.
- Сессии: «Создать сессию» (`POST …/sessions {}`, имя по умолчанию даёт
  сервер), список с названием, состоянием, происхождением (панель /
  приложение), временем и моделью. Ссылка выбирается по устройству:
  `mobile`, если `navigator.maxTouchPoints > 1`, иначе `desktop`; `web` —
  запасная; ссылки `javascript:`, `data:`, `file:` и т. п. отбрасываются.
  Без ссылки показывается `note` сессии (или «ссылки нет»). «Возобновить»
  (не работающей) и «Остановить» (работающей, с подтверждением) есть, только
  если провайдер сообщает возможность `resumeSession` / `stopSession`
  доступной.

## Состояния кнопок

Кнопка заблокирована, если возможность или действие недоступны (под ней
причина), пока запрос отправляется («отправка…») и пока идёт её операция
(`operations`: вид, провайдер, проект, для сессий и действий — id); ход
показывается текстом `progress` операции («ожидание очереди») или
«выполняется…». Последняя неудачная операция кнопки показывает `message` и
`hint`, пока не начнётся новая или пользователь не нажмёт «Скрыть».
Синхронная ошибка запроса (400/404/409/501) показывается в карточке с
`hint`.

## Инварианты

- Ни одного условия по id провайдера: всё — из контракта и операций.
- Чистая логика в `model.js` и `card-model.js` без DOM; покрыта
  `node --test`.
- JS проверяется `tsc` (`// @ts-check`, типы контракта через JSDoc
  `import('#provider-registry')`).
- Панель только читает `/api/state`; изменения — POST с JSON через `api`.
