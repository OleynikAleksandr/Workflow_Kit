## T003: прерывание ответа Claude (13.11.2026)

## T008: тайм-аут адаптера в HTTP API (13.11.2026)

Исправление T002 после подключения Claude в T003 (`329ef982`). Разрешённые файлы
задачи дополнены матрицей ОС и этим evidence через task:update (`19776199`).

Новый регрессионный тест через настоящий временный HTTP-сервер и подставной Provider
сначала воспроизвёл 502 вместо ожидаемого 504. После правки ProviderError с кодом
interrupt-timeout из native-вызова возвращается как 504 interrupt-timeout, сохраняя
сообщение и подсказку; без подсказки используется объяснение сохранённого барьера.
Другие ошибки, включая другой ProviderError со статусом 504 и похожий обычный Error,
остаются 502 interrupt-failed. Результаты unavailable/stale по-прежнему дают 409.

Проверены очередь, неизменный turnRef, сброс pending, сохранение working и барьера при
ошибке, явный повтор после завершившегося тайм-аута адаптера. Прежний тест общего
тайм-аута подтверждает отсутствие повторного незавершённого RPC и игнорирование позднего
результата. Общий предел 10 с не менялся. Канал, провайдеры и назначения не изменены.

14/14 тестов прерывания прошли, typecheck прошёл. Общие проверки запускаются штатным
`scripts/workflow commit --task T008`, их успешность подтверждает результат этой команды.
Реальная служба, пользовательские сессии и установленная версия не менялись. Общая
логика одинакова на macOS/Linux/Windows x64/ARM64; локальный HTTP-тест на Mac не заменяет

## T004: Stop Kimi (13.11.2026)

База — `7bef75df` (T008). Реализация, контракт и этот раздел входят в один коммит T004;
точный SHA возвращает команда commit и хранит история Kit. Установка службы и версия
не менялись, настоящие серверы/сессии Kimi не использовались.

Адаптер работает только с уже запущенным сервером Kit: сверяет processId/pid/порт,
хост/токен/startedAt замка, проект и текущий пользовательский prompt id. После одного
abort нужны aborted:true и два подтверждения idle с освобождённым замком того же хода.
Stop hook для перехода общего канала в waiting не требуется. Проверены смена промпта
до abort и во время подтверждения (stale), смена замка, чужой процесс/хост, неизвестный
замок, архив/вопрос, отсутствие сервера Kit и работающий сервер приложения: takeover,
reload, shutdown и запуск нового сервера не происходят.

Проверены отсутствие результата/повреждённый результат, HTTP-ошибка, aborted:true без
idle (тайм-аут), запрет автоматического повтора abort после 401 и абсолютный deadline.
Истёкший preflight не отправляет поздний abort, даже если транспорт проигнорировал отмену.
Подтверждённый idle допустим только для уже связанного с turnRef промпта; неизвестный
idle не даёт успеха. Очередь канала и барьер сохраняются, следующая явная реплика доступна.
Внутренний повтор отправки с задержкой 60 с отменяется Stop немедленно; старый промпт не
уходит позже. Принятая отправка, уже летевшая при Stop, инвалидирует старую цель.

```sh
node --test 'product-parts/provider-runtime/clusters/provider-adapters/modules/provider-kimi/test/*.test.ts'
npm run typecheck
```

Целевой набор — 127/127, typecheck прошёл. Общие проверки повторяются штатным
`scripts/workflow commit --task T004`; успешный результат этой команды подтверждает
общий набор, platform-guard, ограничения документов, ссылки и контракты.
Почти полный module.md разделён: прежний раздел хуков целиком сохранён в hooks.md,
протокол Stop и ограничения — в interrupt.md; старые требования не удалены.

HTTP-сервер в тестах настоящий, ответы Kimi и замки подставные, файлы — временные.
Injected darwin/linux/win32 проверяет контроллер и сравнение папок; это не живая проверка
Kimi на этих ОС. macOS — пользователь после поставки; Windows x64/ARM64 — проверяющий
на Windows; Linux — CI, которая здесь не запускалась. У Kimi abort адресует сессию без
условия по native turn id: сериализация Kit и проверки до/после не дают серверной
атомарности для произвольных внешних API-запросов. Remote Control и эта гонка остаются
в живой приёмке; при смене хода подтверждение возвращает stale без второго abort.

typecheck и platform-guard прошли. Повторная проверка различает естественный completed
(already-idle) и прежде подтверждённый abort (interrupted), не посылая повторный abort.
