# Матрица ОС: M45 (доставка сообщений в терминал Claude)

Часть [матрицы ОС](OS-MATRIX.md): строки вехи M45 ведутся здесь, чтобы основной документ
оставался в пределах размера. Правила те же: каждое изменение дополняет таблицу в том же коммите.

| Возможность | macOS | Linux | Windows |
| --- | --- | --- | --- |
| M45 T001: хост параметров уступает терминал — строка `[bridge:repl] Ingress message type=user` в логе Claude (`--debug-file`) отменяет транзакцию, меню хоста без шага закрывается через 10 с, после ввода пользователя 3 с без обнаружения, текст пользователя ждёт, пока поле не пусто (`unsafe`, до 10 с), неудача обнаружения на версии CLI хранится в каталоге (`failed`), действующее пожелание снимается сразу | `interrupt-worker.ts` под `session.exp`: размер и диапазон байтов лога — `statSync`/`readSync` | то же | `pty/host.ts` под `win-host.ts` (ConPTY), x64/ARM64: `stat`/`FileHandle.read` через `fileSize`/`fileSlice`; путь лога — тот же аргумент хоста, CRLF в логе не мешает (ищется подстрока строки); тест хоста с путём `C:\…` |
| M45 T002: сообщение панели вставляется только в свободный терминал (свежее состояние хоста: не `dialog`, нет черновика и неубранной смены параметров) и подтверждается хуком `UserPromptSubmit` с тем же текстом до 8 с, иначе `{ sent: false, undelivered }` | общий Node-код службы; состояние хоста — тот же файл `<debug>.parameters-state` | то же | то же, x64/ARM64; файл состояния пишет `host.ts` (ConPTY); программ ОС и путей нет |
| M45 T003: панель — «Сообщение не дошло до Claude: <причина>» с «Повторить», текст остаётся в поле; «Подтвердить выпуск» в проекте `host` без решения хода автопилота сессии | ES-модули панели; браузерная проверка Chromium (`m45-cards.browser.mjs`) | то же; браузерная проверка не запускается в CI | то же, x64/ARM64 |
