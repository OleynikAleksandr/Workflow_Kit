# Модуль: session-chat

Часть `control-panel`, кластер `web-panel`. Публичный вход: `src/index.ts`.
Алиас импорта: `#session-chat` (поле `imports` в `package.json`; импортирует `cli`).

## Назначение

Карточка «Диалог» на экране сессии (спецификация
[M18, раздел 2.6](../../../../../../docs/planning/M18-session-chat.md)):
лента реплик пользователя и агента этой сессии и поле, из которого пишут
агенту. Своего чата у Kit нет: лента — вид переписки, которую отдаёт
провайдер, а отправка идёт маршрутом канала агента (прямо агенту или в
очередь). Модуль не отвечает на запросы разрешений, не подгружает старые
сообщения и не выводит ответ посимвольно.

## Публичный интерфейс

Для бэкенда (`src/index.ts`):

- `SESSION_CHAT_PREFIX` — `/session-chat/`.
- `SESSION_CHAT_ASSETS_DIR` — абсолютный путь к `src/`.
- `sessionChatMount() → { prefix, dir }` — монтирование для `http-server`
  (подключает `cli`, `createApp`).

Для панели:

- `session-chat.js` — расширение панели (`PANEL_EXTENSIONS` в `panel-shell`,
  путь `/session-chat/session-chat.js`): `install(shell)` заполняет слот
  `sessionChat` (`registerSlot`, тип `SessionSlot`). `select` отдаёт ключ
  сессии, подпись провайдера, счётчик изменений и `composerData` публичного состояния; `render` всегда
  возвращает один и тот же элемент сессии.
- `session-chat.css` — стили карточки (`/session-chat/session-chat.css`
  в `index.html` панели).

Маршруты службы, которыми пользуется карточка:

- `GET /api/projects/:id/providers/:p/sessions/:localId/messages` →
  `{ supported, messages, truncated }`;
- `POST /api/projects/:id/sessions/:key/message { text }` →
  `{ sent: true }` или `{ queued: <id> }`;
- `POST /api/projects/:id/sessions/:key/interrupt { turnRef }` → подтверждённый
  `{ stopped: true, status: interrupted | already-idle }`;
- `GET /api/state` — только восстановление актуальной цели после `stale-turn`;
  обычное состояние передаёт слот оболочки, дополнительных регулярных GET нет.

## Поведение карточки

- Состояние сессии (узлы сообщений, поле с введённым текстом, прокрутка
  ленты) хранится в `Map` по проекту и ключу сессии и переживает опрос и
  уход с экрана: элемент обновляется на месте.
- Опрос `GET …/messages`: сразу, как карточка попала в документ (открытие
  экрана сессии), и раз в 3 с, пока карточка в документе и вкладка видима
  (`document.visibilityState`); сразу после успешной отправки —
  внеочередной. Одновременно не больше одного запроса на сессию: запрос во
  время другого откладывается до его конца. Карточка вне документа не
  опрашивается.
- Лента заполняет оставшееся место области диалога и прокручивается внутри карточки (M24) и сама уходит
  вниз при новых сообщениях, только если пользователь был внизу.
- Ошибка чтения показывается в карточке, прежние сообщения остаются.
- Enter отправляет в waiting/holding/unknown, Shift+Enter вставляет строку.
  В working обычный Enter вставляет строку; Ctrl/⌘+Enter и «В очередь» сохраняют
  доставку M18. Основная кнопка working — Stop, локальная HTTP-отправка не
  выдаётся за working. Одновременно не больше одного действия ввода на сессию.
- Успешная отправка очищает только ту же ревизию черновика (даже изменение
  и восстановление исходного текста считаются новым вводом); отказ/Stop не
  очищают поле. Итог отправки/очереди и ошибки с подсказкой видны под вводом.
- На сенсорном устройстве (iPad) всё управление — кнопка и поле, без
  элементов, видимых только при наведении.

## Геометрия M24 (T001)

Карточка занимает ширину и остаток высоты правой области, без прежних 760 px/60vh.
Flex-ограничения min-height/min-width:0 позволяют сжиматься ленте. Заголовок, сообщения
состояния и ввод не выталкивают управление из окна; длинные заметки/ошибки прокручиваются
внутри ограниченной высоты. При неподдерживаемой ленте ввод остаётся у нижнего края.
Оболочка сохраняет позицию ленты при снятии/возврате DOM во время смены сессии.
Компактный ввод M24 реализован в T006; растёт от одной строки до
min(120px, 25% высоты карточки), затем прокручивается внутри. ResizeObserver
отслеживает свою карточку, отключается вне видимого экрана и подключается при возврате.
Это браузерное поведение одинаково на macOS, Linux и Windows x64/ARM64.

## Ввод и Stop M24 (T006)

- Единая рамка: SVG «+», textarea, Enter/Stop, микрофон. Области кнопок 44×44 px,
  на coarse pointer текст поля 16 px; цвета — токены обеих тем, видимый focus.
- «Вложения — позже» и «Микрофон — позже» отключены и имеют доступные имена/
  подсказки; не вызывают API, разрешений или записи. Параметры информационные.
  Модель берётся прямо из providers.projects[projectId][provider].sessions по
  localId, не из названия провайдера. Публичных источников усилия, режима и
  контекста пока нет: «—» с именем «Нет данных» и нейтральное пустое SVG-кольцо.
- Источник Stop — channel.interruptions[projectId][key]; старое channel.sessions
  используется лишь для состояния при отсутствии записи. Unknown не блокирует
  обычную отправку. Working без доступного interrupt показывает отключённый
  Stop и причину текстом, включая touch; pending публикуется как «Останавливаю…».
- Stop передаёт только текущий turnRef, ждёт stopped:true с допустимым status.
  Подтверждение возвращает Enter без ожидания хука. Старый ответ не завершает
  новое поколение; старый опрос того же подтверждённого поколения не возвращает
  ложный Stop. История/поле/очередь не удаляются, stopSession не вызывается.
- stale-turn — нейтральная подпись и однократное чтение публичного /api/state:
  shell.api сохраняет code ошибки, но не current. Более новое состояние слота
  имеет приоритет над этим чтением. Актуальный ход останавливается только новым
  нажатием, скрытого повторного POST нет. Другие ошибки/тайм-ауты показывают hint
  и оставляют повтор доступным. Барьер автопродолжения принадлежит каналу.
- IME: isComposing, compositionstart/end и keyCode 229 не отправляют. Safari
  trailing Enter после compositionend поглощается один раз в пределах 40 мс;
  keyup Enter, другая клавиша или истечение guard разрешают следующий Enter.
  Повтор keydown не отправляет повторное сообщение. Модель проверяется отдельно
  от DOM, браузер — синтетическими событиями без заявления о реальном Safari.
- Поле/DOM сохраняются по проекту и ключу сессии, включая новый ввод во время
  HTTP, фокус, выделение и внутреннюю прокрутку ленты. Размеры меняются CSSOM,
  без innerHTML/ослабления CSP. Изолированная браузерная проверка и ограничения
  живой приёмки: [M24 evidence](../../../../../../docs/evidence/M24-acceptance.md).

## Инварианты

- Чистая логика в `chat-model.js` без DOM; покрыта `node --test`.
- Текст в DOM — только через `textContent` (без `innerHTML`); переносы строк
  сохраняются (`white-space: pre-wrap`).
- Не больше одного запроса чтения на сессию одновременно.

## Зависимости

- `panel-shell`: типы `SessionSlot`, `SessionContext` (`slots.js`), `api`
  (`api.js`) и `h` (`dom.js`) — только через объект `shell` расширения.
- Маршруты службы `provider-registry` (лента) и `agent-channel` (отправка и прерывание).

## Поведение на ОС

Одинаково на macOS, Linux и Windows: модуль — файлы браузерной панели,
вызовов программ ОС и путей ОС в нём нет; `index.ts` строит путь к `src/`
через `fileURLToPath`. Различия провайдеров по ОС (откуда берётся лента,
когда возможны прямая отправка и Stop) — в их модулях. Ввод/IME/resize/параметры
не ветвятся по ОС. Живую проверку macOS/iPad проводит пользователь, Windows —
проверяющий, Linux — CI; локальный Chromium не подтверждает остальные ОС. Карточка показывает то, что
отдаёт служба.

## Параметры сессии (M25)

`parameters.js` и `parameters-model.js` подключены в composer: GET/POST параметров,
провайдерская строка, кольцо, лимиты, доступное с клавиатуры меню и подтверждение.
Подробный контракт, видимость/опрос, fallback M24 и матрица ОС —
[parameters.md](parameters.md). Вся логика UI одинакова на трёх ОС.

M26/T003: effort-card.js и effort-model.js рисуют компактный effort-card по presentation,
модель выбирается отдельным списком под вводом. Порядок и доступность уровней — из каталога;
один POST при завершении жеста/клавиатурного действия, Esc/pointercancel отменяют preview.
Молния меняет скорость и показывает провайдерскую подсказку; сброса и Подробнее нет.
parameters.css подключён из основного CSS, геометрия учитывает visualViewport и touch.
Поведение одинаково на macOS, Linux, Windows x64/ARM64; реальный iPad проверяет пользователь.

M26/T004: access-menu.js показывает отдельные непрозрачные пресеты, причины запрета
и подтверждение до POST. Постоянные кнопки переживают polling; POST блокирует оба
якоря и все изменения. Composer перемещает плюс/доступ влево, микрофон вправо только
при presentation.layout=effort-card; legacy DOM и функции ввода сохранены.
Доступ не дублируется справа; цвет полного доступа оранжевый, Подробнее отсутствует.
Для macOS/Linux/Windows общий ES-код; visualViewport, переносы, клавиатура и coarse
44px не требуют вызовов ОС. Новые значки — исходные Lucide 0.468.0 под существующей ISC.

M26/T005: native CSS перекрывает базовые popup/mask-правила; доступ привязан к левому
краю своей плашки, группа модели переносится целиком до сжатия текста. Preview жеста
переживает polling; неизвестное усилие не подменяется. Размер пересчитывается после
изменения содержимого. Визуальные и browser evidence: корневой design-qa.md и M26 evidence.
Все исправления — общий DOM/CSS на macOS/Linux/Windows, новых ОС-зависимостей нет.

M26/R2: смена параметров не пишет служебные success/progress/notes в sc-status;
ошибки остаются видимыми. Родной input range владеет захватом своего thumb:
на внешнем input setPointerCapture не вызывается. Временные document-listeners
завершают жест за пределами дорожки; cancel/lostcapture/blur/destroy снимают их
и не отправляют POST. max/disabled не переписываются при прежнем значении, чтобы
polling не сбрасывал нативный drag. Общий код на macOS/Linux/Windows, без программ ОС.
Регрессия: test/native-controls.browser.js, реальный thumb-center drag и touch.
