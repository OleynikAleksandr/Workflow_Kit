# Веха 2 — интерфейс и процесс

Статус: спецификация scope `m2-interface-and-process`. Основа —
согласованный макет [docs/design/ui-mockup.html](../design/ui-mockup.html)
и итоги вехи 1 ([M1-orchestrator-core.md](M1-orchestrator-core.md),
[M1-providers.md](M1-providers.md)). Временный документ: после приёмки
действующее содержание переносится в `docs/architecture/**`.

## 1. Цель

Пользователь работает с Kit без «телеметрии»: создаёт проект одним
согласием, сразу попадает в первую сессию ChatGPT или Claude, а дальше
видит в Kit план, выбор пути, ход выполнения и приёмку — всё само, без
ручных команд. Служебные сведения уходят в «Настройки». Панель ставится
на экран «Домой» iPad.

## 2. Решения пользователя (2026-11-06)

- Веха 2 = интерфейс по макету и процесс вместе.
- Процесс = собранный Harness Workflow Kit 2.2.2, который наш Kit ставит в
  каждый проект. Бандл хранится в нашем репозитории; во время работы
  harness-ai не нужен. Перенос исходников Kit в product-parts — отдельная
  веха.
- Из старой вехи 2 берётся только экран «Домой» iPad; сканер доверия,
  раскладка окон и авторизация панели — в следующие вехи.
- После кнопки «Создать и открыть в ChatGPT / Claude» вопросов больше нет:
  карточка сессии создаётся, чат открывается, работа начинается.
- Сессию переименовывает агент, когда понял задачу.
- «Ревью плана» — своё у каждой сессии Claude и ChatGPT, без подписи
  провайдера; виден до выбора пути, затем исчезает.
- Карточка плана видна с момента создания плана до приёмки и обновляется
  сама.
- Шрифты как в Claude Desktop: основной текст 13 px.

## 3. Проверено на устройстве (2026-11-06)

Тестовая папка, хук `Stop`, Claude Code 2.1.318 (`claude -p`) и
codex-cli 0.166.0 (`codex exec`); записи в `~/.codex/config.toml` после
проверки удалены, файл совпал с копией.

- **Хук `Stop` возвращает агента к работе** и у Claude, и у Codex: ответ
  `{"decision":"block","reason":"…"}` — агент продолжает ход с этим текстом
  как с указанием; повторный `Stop` приходит с `stop_hook_active: true`.
- **Хук может ждать**: 75 с ожидания не прервали ни Claude (`timeout` 300),
  ни Codex (`timeoutSec`; `hooks/list` показал 600).
- **Вход хука** знает сессию: `session_id` (у Codex это id треда),
  `transcript_path`, `cwd`, `last_assistant_message`, у Codex ещё
  `turn_id`.
- Хуки проекта Codex работают только в доверенной папке и после одобрения
  по хешу (`hooks.state."<…/.codex/hooks.json:stop:0:0>".trusted_hash`).

Не проверено (проверяется в задачах этой вехи и при приёмке): поведение
ожидающего хука в приложениях ChatGPT (Mac, iPad) и Claude Desktop при
Remote Control; `thread/name/set` для треда, который держит ChatGPT;
переименование сессии Remote Control Claude.

## 5. Модули

Новая часть `workflow-engine` (каталог `product-parts/workflow-engine`):

| Кластер / модуль | Назначение |
| --- | --- |
| `kit-host/kit-bundle` | бандл Kit 2.2.2 (`vendor/workflow-kit-2.2.2.mjs.gz`), происхождение (коммит harness-ai, SHA-256), распаковка с проверкой хеша |
| `kit-host/kit-runner` | запуск команд Kit проекта (`node .harness/workflow/runtime/workflow.mjs …`, JSON), установка и обновление (`install --host harness`), слежение за файлами плана, раздел состояния `workflow` |
| `kit-host/plan-view` | модель карточки плана из `status` (порт правил `buildPlanView`: статусы, «в main N из M», «Последовательно / Параллельно», фаза), карточка выбора из `scope:proposal` |
| `session-loop/agent-channel` | приём хуков `Stop` и `UserPromptSubmit` от `wfk hook`, очередь сообщений агенту, долгое ожидание, активность сессии («работает над ответом 0:15») |
| `session-loop/autopilot` | решение «продолжать или остановиться» после хода по `autopilot:status` (порт правил Harness) |
| `session-loop/plan-review` | ревью спецификации и плана для сессии |
| `session-loop/session-titles` | имена сессий: тема от агента, ручное имя, имя из scope; синхронизация с провайдером |

Меняются: `backend-core/projects/kit-structure` (v2, раздел 9.1),
`backend-core/projects/project-registry` и новый
`backend-core/projects/project-setup` (мастер), `backend-core/runtime/cli`
(`wfk hook stop|prompt`, `wfk session title`, `wfk review`),
`provider-adapters/provider-claude|provider-codex` (первое сообщение,
переименование), `control-panel/web-panel/*` (интерфейс).

Код и `module.md` — по соглашению product-parts; лимит 400 строк на файл.

## 6. Интерфейс

Источник вида — макет; размеры: основной текст 13 px, второстепенный
11–12 px, заголовок экрана 17 px, название и «Ваши проекты» 15 px; тёмная
и светлая тема (как в системе, переключатель в «Настройках»).

- **Раскладка.** Слева боковая панель 270 px: логотип, версия, шестерёнка,
  строка состояния текущей подготовки (спиннер, таймер), «Ваши проекты»
  (меню), дерево «проект → сессии», «Ревью плана» выбранной сессии,
  индикаторы связи (служба, ChatGPT, Claude, iPad). Справа — экран
  выбранного (первый запуск, мастер, сессия, настройки). Уже 680 px —
  столбцы друг под другом.
- **Меню «Ваши проекты».** Поиск; список с «В архив»; «Создать проект»;
  «Открыть папку проекта» (выбор папки из списка, как сейчас); «Обновить
  сессии»; «Архив проектов…» (вернуть, убрать из списка; папки не
  удаляются).
- **Дерево.** Проект: имя, число сессий, «⋯» (новая сессия ChatGPT /
  Claude, скопировать путь, в архив). Сессия: имя, время, «новая», метка
  провайдера (ChatGPT / Claude), спиннер, пока агент работает; «⋯»
  (открыть чат, переименовать, в архив).
- **Экран сессии.** Заголовок (имя, проект, провайдер, «Открыть чат»);
  строка активности агента («работает над ответом 0:15», «ждёт вашего
  сообщения», «готовит план»); карточка выбора (раздел 9.3); карточка
  плана (раздел 8.3); подсказки приёмки.
- **Настройки.** Служба (состояние, версия, автозапуск, адрес для iPad,
  перезапуск, диагностика), ChatGPT/Codex (CLI, демон, хуки), Claude
  (CLI, Remote Control, доверие), структура проектов, внешний вид, папка
  проектов. Сюда переезжает всё содержимое нынешних карточек «Система»,
  «Структура», провайдеров.
- Ошибка любого шага показывается на месте текстом и подсказкой, без
  стеков; повтор шага — кнопкой.

## 7. Мастер проекта и первая сессия

1. «Создать проект»: имя и папка для проектов (меняется, хранится в
   `config.json`). «Открыть папку проекта»: выбранная папка, имя из папки.
2. Предпросмотр (только чтение, токен с отпечатком как у доверия в вехе 1):
   путь; что Kit сделает — структура Kit, процесс Kit 2.2.2 (`inspect` →
   install/update/open), git (`git init`, если нужно), доверие папке в
   Claude и Codex, одобрение хуков Kit в Codex; раскрываемый список
   «Изменения в папке · N файлов». Если найдены внешние импорты
   `CLAUDE.md` — обязательный выбор «разрешить / запретить» здесь же. Нет
   git-личности — экран говорит, какую команду выполнить
   (`GIT_IDENTITY_REQUIRED`), Kit личность не задаёт.
3. Две кнопки первой сессии: «Создать и открыть в ChatGPT», «Создать и
   открыть в Claude». Нажатие — единственное согласие на все записи пункта 2.
4. Операция (по шагам, видна в строке состояния и на экране): структура →
   Kit (`install --host harness`) → доверие Claude → доверие Codex и
   одобрение хуков Kit → сессия (Codex: создание с первым сообщением и
   ожидание выгрузки треда, как в вехе 1; Claude: Remote Control с первым
   сообщением) → ссылка. «Отменить подготовку» останавливает до следующего
   шага; сделанное остаётся и видно.
5. Первое сообщение агенту (вместо служебного «готов»): проект создан
   Workflow Kit, прочитай `AGENTS.md`, выполни `scripts/workflow recover`,
   поздоровайся и спроси задачу.
6. По готовности панель на том устройстве, где нажата кнопка, сама
   открывает ссылку сессии (`codex://threads/<id>` или ссылка Claude);
   карточка сессии выбрана в дереве.

## 8. Процесс Kit 2.2.2 в проекте

### 8.1 Бандл и установка

- Бандл — `kit-bundle/vendor/workflow-kit-2.2.2.mjs.gz` (gzip: двоичный
  файл, проверка длины его пропускает) и `PROVENANCE` (harness-ai
  `e4226208`, SHA-256 распакованного файла
  `036c82fb…0fc2`). Распаковка в каталог данных с проверкой хеша.
- `install`/`inspect` — бандлом приложения с `--host harness` (иначе Kit не
  предлагает карточку выбора); остальные команды — бандлом проекта
  (`.harness/workflow/runtime/workflow.mjs`). Kit старше 2.2.2 — «Обновить
  процесс» (`install --update`) в «Настройках» и в предпросмотре мастера.
- Контекст в сессию доставляют хуки Kit `SessionStart` (переменная
  `HARNESS_WORKFLOW_RECOVERY` не задаётся).
- Ошибки Kit — в его конверте (`ok`, `code`, `message`, `nextAction`) и
  показываются в интерфейсе; свои коды: `KIT_NO_BUNDLE`, `KIT_SPAWN`,
  `KIT_TIMEOUT`, `KIT_OUTPUT`.

### 8.2 Состояние

`kit-runner` следит за `.harness/plans/` и `.harness/workflow/local/`
(тишина 300 мс), затем вызывает `status` и `scope:proposal`; результат —
кэш и раздел `workflow` в `/api/state` (по проекту: scope, delivery,
execution, ревизия, задачи, предложение, пауза, ошибки). Опрос панели
команд не запускает.

### 8.3 Карточка плана

Из `status.tasks` и `progress`: заголовок (имя сессии), фаза («План
готов», «Выполняется», «Пауза», «Ждёт приёмки», «План закрыт»), полоса и
«в main N из M», задачи (id, название, «Не начата / Выполняется / В
main», «Последовательно / Параллельно» — правила `buildPlanView`:
параллельность показывается только в режиме `orchestrated`), строка
ревью («Ревью: проверено» / «Без ревью»). Кнопки: «Начать выполнение
плана», «Пауза» / «Продолжить» (`pause:set`), «Принять план» (`accept
--note`), «Закрыть план» (`close --scope --note`, только при чистом
дереве; иначе подсказка), «Нужны исправления» (поле текста → сообщение
агенту). Карточка видна, пока scope не закрыт.

## 9. Канал к агенту и автопилот

### 9.1 Структура Kit v2

К хуку `SessionStart` добавляются `Stop` (ожидание до 600 с) и
`UserPromptSubmit` для Claude (`.claude/settings.json`) и Codex
(`.codex/hooks.json`, только в конец списка): команды
`wfk hook stop --client …` и `wfk hook prompt --client …` с той же
защитой «нет `wfk` — выход 0». Раздел Kit в `AGENTS.md` получает правила:
тема сессии (раздел 11), ревью (раздел 10), выбор пути и запуск плана —
кнопками в панели Workflow Kit. Обновление структуры v1 → v2 — как в вехе
1 (`outdated`), одобрение новых хуков Codex — в мастере и в «Настройках».

### 9.2 Хуки

- `wfk hook prompt`: сессия «работает» (время начала хода); доставляет
  отложенные сообщения как дополнительный контекст хода.
- `wfk hook stop`: сессия «ждёт»; спрашивает службу (`POST
  /api/hooks/stop`), что ответить. Ответ — указание агенту (`decision:
  block`) или ничего. Служба держит запрос, пока ждёт решения
  пользователя (карточка выбора, запуск плана, подтверждение выпуска), но
  не дольше 9 минут; затем отпускает агента, а решение пользователя
  уходит со следующим `UserPromptSubmit` (панель подсказывает написать в
  чат «продолжай»). Служба недоступна — хук молча выходит.
- Одна доставка — один раз (очередь по сессии с подтверждением); повтор
  `Stop` с `stop_hook_active` не зацикливает.

### 9.3 Выбор пути

Открытое предложение Kit (`scope:proposal`, новое поколение) становится
карточкой выбора у сессии-владельца: варианты из предложения
(рекомендованный первым, «Сначала доработать спецификацию»), причина;
для сессий Codex режим `orchestrated` не предлагается (как в Harness:
исполнители-подагенты в своих worktree есть только у Claude). Нажатие —
`scope:choose --generation --option --session <id> --note "Выбор
пользователя в панели Workflow Kit: …"`; ответ агенту — тексты выбора
режима Harness (последовательно / оркестратор / доработать).

### 9.4 Автопилот

После `Stop` сессии-владельца служба решает по `autopilot:status` и
правилам Harness: продолжать (указание «продолжай по плану» со
следующим шагом) или остановиться с причиной (`paused`,
`waiting-for-mode-choice`, `ready-for-acceptance`, `delivery-confirmation`,
`blocked`, `no-progress`, лимит 40 продолжений подряд и др.). Причина
видна на экране сессии. `delivery-confirmation` — карточка «Подтвердить
выпуск» (слова пользователя уходят агенту для `task:start --confirmed`).

## 10. Ревью плана

- Переключатель — на сессию (`.workflow-kit/local/sessions/<id>.json`),
  по умолчанию выключен; виден до выбора пути, после `scope:choose`
  исчезает.
- Включён: когда сессия предложила план (`scope:propose`), служба через
  `Stop` просит агента выполнить `wfk review`. `wfk review` запускает
  рецензента только на чтение (спецификация из `spec` и вход предложения)
  — CLI другого провайдера: для сессии ChatGPT — `claude -p` с
  инструментами только чтения, для сессии Claude — `codex exec` в режиме
  только чтения; вердикт — `agreed` или замечания (JSON). Агент учитывает
  замечания и предлагает план снова; до трёх раундов, затем решает
  пользователь. Карточка выбора появляется после `agreed`.
- Выключен: карточка выбора — сразу после предложения.
- Итог ревью хранится по поколению предложения и виден в карточке плана.

## 11. Имена сессий

Приоритет: ручное → тема агента → scope (`objective`) → «Новая сессия».

- Тема агента: правило в `AGENTS.md` — в первом содержательном ходе один
  раз выполнить `wfk session title "<коротко, по-русски>"`. Служба
  относит вызов к сессии проекта, у которой идёт ход (`UserPromptSubmit`
  без `Stop`); неоднозначно — отказ с подсказкой.
- Ручное — «Переименовать» в «⋯» сессии.
- Синхронизация с провайдером: Codex — `thread/name/set` (если демон при
  этом удержит тред — не делать, пока ChatGPT держит чат); Claude — только
  имя в Kit, пока способ переименовать сессию Remote Control не проверен.

## 12. Экран «Домой» iPad

`manifest.webmanifest` (имя, значки 180/192/512, `display: standalone`,
цвета темы), `apple-touch-icon`, `apple-mobile-web-app-capable`, отступы
safe-area. Добавленная на экран «Домой» панель открывается без адресной
строки.

## 13. HTTP API (добавления)

- `POST /api/setup/preview`, `POST /api/setup/apply` — мастер (операция).
- `GET` данных нет: всё в `/api/state` (разделы `workflow`, `sessions`
  с активностью и именами).
- `POST /api/projects/:id/workflow/choose|start|pause|accept|close|fixes|confirm-delivery`.
- `POST /api/projects/:id/sessions/:sid/review` (вкл/выкл),
  `…/title` (ручное имя), `…/archive`.
- `POST /api/projects/:id/archive|restore`.
- `POST /api/hooks/stop`, `POST /api/hooks/prompt`, `POST
  /api/sessions/title` — только с loopback.

## 14. Визуальная приёмка вехи

На Mac (окно Kit) и iPad (панель с экрана «Домой»):

1. iPad: «На экран Домой» → панель открывается без адресной строки.
2. Первый запуск (пустой список): «Создать проект» → имя → предпросмотр
   со списком действий и изменений → «Создать и открыть в ChatGPT» →
   шаги подготовки → чат сам открывается в ChatGPT без «Этот чат открыт в
   другом приложении»; карточка сессии в дереве.
3. Написать задачу в чат → имя сессии в Kit меняется на тему задачи.
4. Включить «Ревью плана» → агент предлагает план → идёт ревью → карточка
   выбора → «Выполнить самому, последовательно» → переключатель ревью
   исчез → карточка «План готов» → «Начать выполнение плана» → задачи
   меняют статус сами → «Ждёт приёмки» → «Принять план» → «Закрыть план».
5. То же для первой сессии в Claude, режим оркестрации.
6. Сессия, начатая в приложении (iPad), появляется в дереве (перепроверка
   шага 6 вехи 1).
7. «Настройки» показывают службу, провайдеров и структуру; на главном
   экране служебных подробностей нет.

## 15. Открытые вопросы и риски

- Q1. Как приложения ChatGPT и Claude показывают ожидающий хук `Stop`
  (до 9 минут) — проверить при приёмке; при неудобстве — короче ожидание
  и доставка через `UserPromptSubmit`.
- Q2. Переименование сессии Remote Control Claude.
- Q3. `thread/name/set` и удержание треда демоном.
- Q4. Рецензент — другой провайдер (раздел 10); требует установленного и
  вошедшего второго CLI; без него ревью недоступно с понятной причиной.
- Риск: тексты Kit 2.2.2 в `AGENTS.md` говорят «Harness project» — это
  метка `--host harness`, на работу не влияет.
