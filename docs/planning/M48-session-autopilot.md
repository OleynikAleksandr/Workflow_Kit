# M48: автопилот и ревью сессии, ручные кнопки только там, где нужен пользователь

## Цель и согласование

Пользователь 20.11.2026 после теста 0.20.3 (проекты A001 — Claude, B001 — ChatGPT) разобрал, что
бывает, если менять «Автопилотирование» и «Ревью спецификации и плана» в Settings посреди работы, и
предложил другой подход: «Настройки Settings считать дефолтными и их изменение применяется только
если они были сделаны до начала формирования какой-либо сессии… А вот изменение этих параметров для
конкретной сессии конкретного проекта нужно делать в карточке автопилота… самой сессии… Ведь мы даем
возможность пользователю остановить автопилотирование. Так почему бы его не запустить в любой
момент?» О ревью: «Как только план опубликован, опция ревью должна пропадать»; о кнопках: «Если план
появился и при этом включен автопилот, то там не будет и никакой кнопки начать выполнение… Это же
ручное управление, а пользователь выбрал автопилот». Последнее сообщение: «Отлично, значит, мы
сейчас одинаково понимаем, какие правки в коде нужно сделать. Согласен? И до кучи… ещё на один баг»
(B001: план принят и закрыт автопилотом, а карточка — «Остановлен: нужно ваше действие, no-upstream»,
кнопки «Продолжить» и «Остановить автопилот»).

Результат (выпуск 0.21.0): у каждой сессии своя карточка автопилота с режимом и ревью, Settings — только
значения по умолчанию для новых сессий; пока автопилот сессии включён, панель не показывает кнопки,
которые нажимает автопилот; план без публикации завершается без ошибки; нажатие пользователя, пока
Kit занят командой агента, не отказывает, а ждёт.

## 1. Что было не так (проверено по коду и журналам 20.11.2026)

- Settings читаются в момент решения (вопрос о плане, ответ на карточку, старт плана) — смена
  посреди задания даёт разное поведение в зависимости от этапа. Ответ на карточку вопроса о плане при
  полном автопилоте создаёт запуск, но агент получает только «пользователь выбрал… предложи план» —
  без номера запуска и требования блока `automation`. План, предложенный до включения, идёт вручную
  с мелкой строкой «нет описания автоматизации». Сообщение о смене настроек получают только владелец
  запуска и владелец начатого плана.
- A001 (`run-yXsvNrtYdu14`): агент предложил план без блока `automation`, автопилот вернул его
  (09:27:37), до нового предложения (≈09:29:20) панель показывала ручную карточку выбора способа:
  `choiceView` (`session-view/src/plan-cards.js`) прячет её только перед ревью.
- `planView` показывает кнопки карточки плана, не глядя на автопилот: при полном автопилоте
  «Начать выполнение плана» появляется и исчезает после автоматического старта.
- B001 (`run-qlq6QnxAAyr0`): в плане `automation.publication: null` (результат локальный — так
  разрешает схема Kit), но `run-complete.ts` после закрытия переходит к публикации и блокирует запуск
  с `no-upstream`; карточка остановленного запуска предлагает «Продолжить» и «Остановить автопилот».
- 19.11 (M47): «Подтвердить выпуск», нажатое во время `commit --task` агента, получило
  «Another workflow operation is running» (Kit `LOCKED`): нажатие пропало.

## 2. Принципы

- **Settings — значения по умолчанию.** Новая сессия берёт режим и ревью из Settings в момент своего
  начала; дальше Settings на неё не влияют. Карточка Settings говорит это прямо.
- **У сессии своя карточка автопилота.** Режим (`off` · после старта · полный) и ревью меняются на ней
  в любой момент; служба применяет изменение к текущему заданию сессии там, где это возможно, и
  пишет на карточке, что изменилось. Выключение автопилота сессии — пауза её запуска, как кнопка
  «Пауза».
- **Пока автопилот сессии включён, панель не показывает кнопки, которые нажимает автопилот.** Вместо
  них — строка состояния. Ручные кнопки появляются, как только автопилот выключен или остановлен.
- **Решения записывает Kit, как раньше (M40).** Нажатие на карточке сессии — решение пользователя с
  источником «кнопка»; агент никогда не меняет режим сессии.
- **Ничего не теряется.** Нажатие, пока Kit занят, ждёт и применяется; конец запуска без публикации —
  нормальное завершение.

## 3. Решение

### 3.1. Настройки сессии (`autopilot`, `cli`)

- Файл `<проект>/.workflow-kit/local/autopiloting/sessions/<client>.<id>.json`:
  `{ version: 1, revision, mode: 'off' | 'after-start' | 'full', review: boolean, source: 'defaults' |
  'user' | 'run', at }`. Имя без `:` (Windows). Запись — через временный файл, как журнал запусков.
- Когда появляется: при создании сессии панелью и при первом хуке `SessionStart` сессии, которую
  служба ещё не знает, — значения Settings этого момента (`source: 'defaults'`). Возобновление
  (`SessionStart` с `resume`) не меняет запись.
- Переход со старых версий: сессия-владелец активного запуска берёт режим и ревью запуска
  (`source: 'run'`); остальные известные сессии получают Settings при первом обращении после
  обновления.
- Все точки решения читают настройки сессии, а не Settings: `wfk session plan` (`authorizePreparation`),
  ответ на карточку вопроса о плане (`planDecision`), старт (`beginExecution`), ответ хука
  `SessionStart` (`mode=…, review=…` — настройки этой сессии).
- Смена Settings больше не ставит запуски на паузу и не шлёт агентам «settings changed»; паузу даёт
  выключение автопилота самой сессии.
- Маршруты: `GET /api/projects/:id/sessions/:sid/autopiloting` → `{ settings, stage, effect }`;
  `POST … { expectedRevision, mode?, review? }` → новая запись и `effect` (что изменилось для текущего
  задания); 409 `settings-stale` с `current`; 409 `review-closed`, когда ревью уже не меняется.
  Раздел состояния `autopiloting.sessions[key]` — та же запись.

### 3.2. Включение автопилота сессии на любом этапе (`autopilot`, `plan-review`, `cross-review`)

Этапы глазами пользователя и что делает служба при включении полного автопилота (запуск записывается
нажатием, `request.source: 'session-card'`, цитата — «Включён полный автопилот сессии»):

| Этап | Действие службы |
| --- | --- |
| Агент ещё думает над заданием | ничего сразу: ближайший `wfk session plan` получает `prepare` по настройкам сессии |
| Открыт вопрос о плане | вопрос закрывается; агент получает инструкцию полного запуска (номер, требование `automation`, ревью сессии) |
| Агент пишет план (вопрос отвечен) | запуск записан; агент получает ту же инструкцию сообщением |
| План предложен | запуск записан; предложение без блока `automation` возвращается агенту (как M40), с блоком — ревью или выбор способа делает запуск |
| Способ выбран или план выполняется | план с блоком `automation` (`scope.automation`) — запуск продолжает его; без блока — `effect`: «Этот план начат без описания для автопилота: его доводите вы; автопилот возьмёт следующий план сессии» |

«После старта» влияет только на шаги после «Начать выполнение плана». Ответ на карточку вопроса о
плане при полном автопилоте сессии приходит агенту с инструкцией полного запуска (закрывает пробел
`ANSWER_MESSAGES`). Выключение (`off`) — пауза запуска сессии (`pause` M39 T007); снова включение —
продолжение того же запуска.

### 3.3. Ревью сессии (`plan-review`, `cross-review`, `autopilot`)

- Ревью сессии — тот же переключатель, что ответ «С ревью / Без ревью» на карточке вопроса о плане
  (`plan-review` toggles): одно значение, две кнопки.
- Меняется, пока не появилась карточка плана (способ выполнения не выбран). Пока ревью идёт — на
  карточке «идёт ревью» и «Отменить ревью» (отмена ревью M4); после — «план проверен» или «без ревью»;
  затем переключатель исчезает (`review-closed`).
- Включение ревью при открытом непроверенном предложении запускает ревью этого предложения.

### 3.4. Конец запуска и нажатия при занятом Kit (`autopilot`, `cli`)

- `automation.publication: null` — после закрытия запуск `completed` с
  `completion.published: null` и строкой «Результат остаётся локальным: публикация в плане не
  предусмотрена»; «no-upstream» остаётся только для плана с публикацией и пропавшим upstream.
- Нажатие пользователя (`choose`, `confirm-delivery`, `accept`, `close`, `unblock`, старт, кнопки
  запуска), на которое Kit ответил `LOCKED`, не отказывает: служба повторяет его каждые 2 с до 15 мин,
  панель показывает «Ждёт: агент выполняет команду Kit»; по истечении — понятная причина и «Повторить».
  Повтор того же решения — тот же ожидающий (без двойного применения).

### 3.5. Панель (`session-view`, `panel-shell`)

- Под каждой основной сессией — карточка автопилота сессии: режим (Выкл · После старта · Полный),
  ревью (пока меняется), строка `effect` после изменения, состояние запуска (как карточка M39), «Пауза»
  и «Остановить» только у идущего запуска.
- Settings: «Значения для новых сессий. Чтобы изменить режим уже открытой сессии — карточка автопилота
  под сессией».
- При автопилоте сессии скрыты: карточка выбора способа (полный — строка «Автопилот выбирает способ» или
  «Автопилот вернул план агенту: нет описания для автопилота»), «Начать выполнение плана» (полный),
  «Подтвердить выпуск», «Принять план» (кроме ожидания ручной приёмки), «Закрыть план»,
  «Опубликовать». Сессии без автопилота и автопилот на паузе или остановленный — как раньше.
- Завершённый запуск (`completed`, `finished`): итог (принят, закрыт, опубликован или «результат
  локальный»), без «Пауза», «Остановить», «Продолжить».

## 4. Поведение на ОС

| Что | macOS | Linux | Windows |
| --- | --- | --- | --- |
| Настройки сессии | файл в `.workflow-kit/local/autopiloting/sessions/`, имя `<client>.<id>.json` | то же | то же; имя без `:`, пути через `path`, запись через временный файл и `rename` с повтором (EPERM/EBUSY), как журнал запусков |
| Переключение, ревью, кнопки панели | общий код службы и панели | то же | то же |
| Ожидание `LOCKED` | общий таймер службы | то же | то же |

Новых программ ОС и веток ОС нет.

## 5. Проверка

- `autopilot`: значения по умолчанию при начале сессии, переход со старых версий (владелец запуска),
  точки решения читают сессию; каждый этап таблицы 3.2 (вопрос закрыт, инструкция агенту, возврат
  предложения, план без описания — `effect`); выключение — пауза; Settings не трогают идущие сессии;
  `publication: null` — `completed`; `LOCKED` — ожидание и одно применение. Имя файла без `:` — тест с
  `win32`.
- `plan-review`/`cross-review`: ревью меняется до карточки плана, отмена идущего, `review-closed`.
- `session-view`/`panel-shell`: карточка сессии, скрытые кнопки по режимам, итог завершённого запуска,
  текст Settings.
- Сквозные сценарии на настоящей службе (`cli`): A001 (полный автопилот, предложение без блока — без
  ручной карточки), B001 (план без публикации — `completed`), включение полного автопилота при
  открытом вопросе о плане, нажатие «Подтвердить выпуск» при `LOCKED`.
- CI: macOS ARM64, Linux x64, Windows x64 и ARM64 для точного SHA на `ci/M48-session-autopilot`.
- Живая проверка (macOS — пользователь): новый проект с выключенными Settings — карточка сессии
  «Выкл», включение полного автопилота и ревью посреди подготовки плана; план без кнопок, которые
  нажимает автопилот; проект без удалённого репозитория завершается «результат локальный». Windows —
  проверяющий; Linux — CI.

## 6. Границы

- Не входит: описание для автопилота в уже начатом плане (Kit не меняет `automation` открытого плана);
  такой план доводит пользователь, карточка это говорит.
- Не входит: перевод сессий Claude на потоковый протокол (отдельный план после M48).
- Запуск этой сессии (`run-F5nJ3wbBuTxd`) переживает установку 0.21.0 по правилу перехода 3.1.
