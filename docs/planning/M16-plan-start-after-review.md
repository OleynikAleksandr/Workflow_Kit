# M16: выбор режима и запуск плана после ревью

## Цель и согласование

Живая проверка 0.8.2 на Windows (2026-11-11, проект A007, Claude — агент, ChatGPT — ревьюер)
дважды остановила путь «ревью → выбор режима → запуск»:

1. После ревью карточка выбора режима не появилась: строка активности писала «Агент ждёт,
   когда вы выберете путь в карточке выше», а карточки не было. Служба карточку построила
   (`workflow.projects[A007].choice`), но панель её прятала: в канале числилась посторонняя
   сессия ChatGPT `codex:01a1cb8d…` в состоянии `working`. Она началась через 7 с после
   конца ревью, не закончила ни одного хода и не входит в список сессий проекта (Kit её не
   создавал; вероятно, фоновый поток приложения ChatGPT вызвал хуки Kit в папке проекта).
   `reviewComing` (session-view) считает любую работающую сессию проекта возможным
   источником ревью и прячет карточку.
2. После перезапуска службы пользователь выбрал режим и нажал «Начать выполнение плана»:
   «Агент не получил команду запуска». Автопилот ставит сообщения в очередь без проекта
   (`autopilot.ts`: `enqueue(key, text, 'panel')`), а после перезапуска канал ещё не знает
   сессию: она заводится без `projectId`, и служба её не будит (`session-wiring.ts`,
   `wakeIdle`: `!activity.projectId → return`). Команды ждали следующего сообщения в чате.
   Это случится после любого перезапуска службы (обновление, перезагрузка) на всех ОС.

Решение пользователя, 2026-11-11: «Мне важно, чтобы этими тестами мы настроили работающую
программу для Windows.» Выпуск — 0.8.3.

## 1. Принципы

- Карточка выбора режима по-прежнему ждёт ревью, которое может прийти от настоящей сессии
  проекта (M4 13.6, M7 замечание 3); меняется только круг сессий, которые её прячут.
- Будит сессию по-прежнему только служба (`wakeSession` провайдера); правило «не будить
  сессию в ходе» не меняется.

## 2. Решение

### 2.1. Посторонняя сессия не прячет карточку (`session-view`)

- `reviewComing(state, projectId)` учитывает только сессии канала, которые есть в списке
  сессий проекта у своего провайдера: `state.providers.projects[projectId][client].sessions`
  содержит `localId` или `remoteId`, равный `sessionId` сессии канала.
- Если список провайдера ещё не пришёл (нет раздела) — прежнее поведение (сессия
  учитывается), чтобы карточка не мелькнула до первой проверки.

### 2.2. Команды автопилота знают проект (`autopilot`)

- Все `enqueue` автопилота передают `projectId`: сообщение запуска плана, ответ на выбор
  режима (`CHOSEN_WAIT`) и «уточнить план» (`REFINE_MESSAGE`).
- Канал заводит новую сессию с этим проектом, и служба будит её сразу (`wakeIdle`).
- Служба тоже не считает постороннюю сессию источником ревью: `choose` передаёт в
  `choiceBlocked` только работающие сессии, которые проект знает (опция автопилота `owns` —
  `ownsSession` cli: сессия есть в `listSessions` провайдеров проекта; ошибка — сессия
  считается). Иначе «Выполнить» в показанной карточке отказывал бы 409 `review-pending`.

## 3. Поведение на ОС

Одинаково на macOS, Linux и Windows: обе правки — в общей логике панели и автопилота,
без вызовов программ ОС.

| Что | macOS | Linux | Windows |
| --- | --- | --- | --- |
| Карточка выбора при посторонней сессии | показывается | показывается | показывается (x64 и ARM64) |
| Запуск плана после перезапуска службы | агент разбужен | то же | то же |

## 4. Проверка

- `session-view`: модель — посторонняя работающая сессия карточку не прячет; работающая
  сессия из списка проекта прячет; без раздела провайдера — прячет, как раньше.
- `autopilot`: после «перезапуска» (новый канал без сессии) выбор режима и запуск ставят
  сообщения с `projectId`.
- `autopilot`: посторонняя работающая сессия не попадает в `choiceBlocked`.
- CI: macOS, Linux, Windows x64 и ARM64.
- Живая проверка на Windows (проверяющий): новый проект, ревью ChatGPT, выбор режима и
  запуск — агент получает команду; то же после перезапуска службы.

## 5. Границы

- Почему приложение ChatGPT запускает фоновый поток с хуками Kit, не исследуется: Kit только
  перестаёт на него реагировать в карточке выбора.
- Сессии, которые служба держит в канале, не сохраняются между перезапусками.
