# provider-kimi: сессии и сообщения

Часть контракта модуля [provider-kimi](module.md): методы сессий
провайдера (`createKimiSessions`). Коды Kimi — в
[протоколе](../../../../../../docs/planning/M8-kimi-protocol.md).

Правило принадлежности одно для сервера, записей панели и журнала хука:
сессия относится к проекту, если её папка — папка проекта (или её
realpath) либо лежит внутри (`inFolder`).

- `createSession`: `requireReady()`, область папки, `POST /api/v1/sessions
  { workspace_id, title, metadata: { cwd } }`, запись панели. Первое сообщение уходит как
  `sendMessage` с `delivery.id` = `first-<id сессии>`; `state` — `running`,
  если оно принято, иначе `stopped` и пометка. Отказ Kimi —
  `ProviderError` `kimi-session`.
- `listSessions` сервер не запускает. С работающего сервера читаются все
  страницы `GET /api/v2/sessions` (по 100, не больше 20 страниц) для
  областей проекта: всех из `GET /workspaces`, чей `root` в папке проекта,
  и областей из записей панели; активные и архивные. Ответ хранится 5 с и
  сбрасывается при создании, переименовании, архиве и удалении. К списку
  добавляются сессии из записей и журнала хука, которых нет в ответе.
  `origin` — `panel` при записи, иначе `hook`; `state` — `running` при
  живом замке хода; имя без заголовка — «Сессия <8 знаков id>»; новые —
  первыми.
- Пометки (`note`, несколько — через «; »): «в архиве Kimi»; «Kimi ждёт
  ответа пользователя» (`activity.status` `approval` или `question`, либо
  ответ `blocked` на сообщение); «сессии нет в Kimi» (полный список её не
  содержит, а создана она раньше запроса); «показаны не все сессии Kimi»
  (предел страниц); «Kimi недоступен: …» (сервер не запущен — только если
  он уже использовался или у проекта есть записи панели; либо ошибка API);
  «архив Kimi не обновлён»; «сообщение не доставлено: …». Две последние и
  ожидание после `blocked` живут в памяти службы до следующей удачи.
- `renameSession`: `POST …/profile { title }`. Код `40931` —
  `{ synced: false }` с пометкой «сессию держит другой сервер Kimi: имя
  будет передано позже»; другая ошибка — `{ synced: false }` с её текстом.
- `archiveSessions` / `restoreSessions` зеркалят архив панели пакетным
  `POST /api/v2/sessions:archive | :restore { ids }` (по 100), всегда
  отвечают `[]` и не бросают: отказ — событие `kimi.archive.failed`,
  строка журнала и пометка сессии. `40401` в строке пакета — готово. Для
  проекта (`sessionId: null`) в архив идут неархивные сессии папки, их id
  запоминаются; восстановление возвращает только запомненные. Сервер ради
  проекта без записей и журнала не запускается; без программы — ничего.
- `deleteSessions` (по одному проекту за раз): момент запроса `since`,
  известные id — записи панели и журнал хука. Удаляются
  (`POST …/{id}:delete`) все сессии областей папки без предела страниц с
  `created_at ≤ since` и известные id; `40401` — уже удалена. Если
  перечисление или удаление не завершилось (и сервер не запустился),
  остаётся намерение на папку; `retryDeletes()` после перезапуска службы
  повторяет его, намерение старше 7 дней снимается со строкой журнала.
  Нет программы или версия не та — `[]` без намерения.
- `sessionIdle`: нет живого замка `locks/sessions/<id>`. Живой — замок
  другого хоста или работающего процесса, начатого после загрузки ОС.
  `lockSwitch` провайдера — `KIMI_CODE_SESSION_LOCK`.
- `lastAnswer`: `GET …/messages?page_size=50` с `before_id`, не больше 10
  страниц назад до новейшего сообщения `user` с `origin.kind: "user"`;
  ответ — тексты `assistant` после него. `null` — только у хода без текста
  ассистента; ошибка API, ненайденное начало хода и неверный id —
  `ProviderError` `answer-unavailable`.
- `sendMessage` (по одному на сессию, таймаут 30 с): `GET` сессии —
  архивная в Kimi сообщение не получает; `POST …/prompts { prompt_id:
  "kit-<delivery.id>", content, model? }` (`model` — модель по умолчанию из
  `GET /config`, только если у сессии своей нет). Любой принятый статус — `true`; `40927` (такой `prompt_id` уже
  принят) — `true`; `40931` — повторы через 4, 8 и 16 с; `40932` —
  `POST …:reload` и один повтор; сбой связи — один повтор через
  `requireReady()`. Отказ — `false`, событие `kimi.delivery.refused
  { project, sessionId, delivery, reason }` и пометка. `:takeover` Kit не
  вызывает.
- `forgetProjects(keep)` убирает записи и списки архива удалённых проектов.
