## 3. Проверено на устройстве (2026-11-06)

- Codex: `thread/name/set` демона на треде, который демон не держит,
  проходит без загрузки треда и дописывает
  `{"id","thread_name","updated_at"}` в `~/.codex/session_index.jsonl`
  (пробный тред `01a1b1e3-…`, затем архивирован). ChatGPT.app запускает
  свой `codex app-server`, но читает тот же `~/.codex`. Значит, прежний
  отказ «чат сейчас не открыт» (`RENAME_LATER_NOTE`) не нужен: из-за него
  имя до ChatGPT не доходило.
- Claude Code 2.1.319: ответ хуков `UserPromptSubmit` и `SessionStart`
  принимает `hookSpecificOutput.sessionTitle` («Set the session title»);
  вход `UserPromptSubmit` содержит `session_title`. Заголовок от хука
  пишется в переписку (`custom-title`), уходит в Remote Control (claude.ai
  и приложение) — тот же путь, что команда `/rename`. Агент сам
  переименовать сессию Claude не может (`/rename` — команда пользователя),
  поэтому имя передаёт хук Kit, который уже установлен.

## 4. Раунд 1: имена сессий в приложениях

### 4.1 Codex / ChatGPT

- `renameSession` провайдера Codex всегда вызывает `thread/name/set`
  через демон; проверка «тред загружен» убирается. Ошибка демона (нет
  демона, отказ) — `synced: false` с причиной, повтор при следующем ходе
  (как раньше).
- Служба по-прежнему не загружает тред ради имени (`thread/resume` не
  вызывается) — ChatGPT открывает чат без задержки.

### 4.2 Claude

- Вход хука получает поле `sessionTitle` (`session_title`).
- `SessionTitles.appTitle(key, current) → string | null`: для сессии
  Claude с ручным именем или темой агента возвращает это имя, если оно
  отличается от `current`; иначе `null`. Отметка `synced: true`, когда
  `current` совпал с именем Kit; до этого — `synced: false` с заметкой
  «Имя уйдёт в Claude со следующим сообщением».
- Обёртка канала в `cli` добавляет к ответу на `UserPromptSubmit`
  `hookSpecificOutput.sessionTitle` (вместе с `additionalContext`, если
  он есть; `hookEventName: "UserPromptSubmit"`).
- Тема от агента (`wfk session title`) приходит во время хода; в Claude
  она попадает со следующего сообщения пользователя или панели.

### 4.3 Приёмка раунда

- Тесты: Codex — переименование незагруженного треда вызывает
  `thread/name/set` и даёт `synced: true`; Claude — ответ `prompt` несёт
  `sessionTitle`, пока имя в Claude не совпало с именем Kit, и не несёт
  после совпадения.
- На устройстве: имя, заданное в панели, видно в боковой панели ChatGPT
  после обновления списка, и в Claude (приложение / claude.ai) после
  следующего сообщения в сессии.

## 7. Раунд 3: имя Claude через /rename

Проверено 2026-11-06 на приёмке R2:

- ChatGPT показывает имена Kit (каталог приложения
  `~/.codex/sqlite/codex.db`, `local_thread_catalog.display_title`,
  обновляется с задержкой).
- Приложение Claude показывает сессию Kit (Remote Control) с именем из
  `--remote-control <имя проекта>`. Хук `UserPromptSubmit` с
  `sessionTitle` не срабатывал: после темы агента не было сообщения
  пользователя, автопилот продолжает работу через `Stop`, а `Stop` поле
  `sessionTitle` не принимает (принимают только `UserPromptSubmit` и
  `SessionStart`).
- Команда `/rename` у Claude 2.1.319 помечена `immediate` и обновляет
  заголовок Remote Control сразу (пробная сессия: «[bridge] Session title
  updated successfully»).

Решение:

- `session.exp` после ссылки раз в секунду проверяет файл
  `<debug-файл>.rename`; если он есть — читает имя, удаляет файл, вводит
  `/rename <имя>` и Enter, печатает `RENAMED`.
- `renameSession` провайдера Claude: запись Kit с работающим процессом —
  пишет файл и ждёт `RENAMED` в журнале (до 5 с) → `synced: true`; иначе
  `synced: false` с заметкой (сессия не запущена Kit — имя уйдёт хуком со
  следующим сообщением).
- Ввод в терминал во время хода мог бы ответить на диалог разрешения,
  поэтому `session-titles` отправляет имя Claude только когда сессия не в
  ходе (состояние канала не `working`); иначе — повтор, когда приходит
  `Stop` (Claude ждёт хук, диалогов нет).
- Хук `UserPromptSubmit` остаётся запасным путём для сессий, начатых не
  через Kit.
- Карточка «Проектов пока нет» под «Ваши проекты» убирается: её текст и
  действия есть в меню.

## 8. Раунд 4: версия релиза и главный экран

Замечание пользователя (2026-11-06): «что значит новый релиз установлен?
Если я вижу маркировку Workflow Kit 0.1.0»; карточка «Начните с проекта»
главного экрана дублирует меню «Ваши проекты» (раунд 3 убрал не ту

## 9. Раунд 5: состояние демона Codex в мастере

Замечание пользователя (2026-11-07, скриншот мастера L003): одновременно
««Запустить демон» сейчас недоступно — демон уже работает», «демон Codex
не подключён к ChatGPT» и активная кнопка «Запустить демон».

Причины:

- Проверка демона ждёт уведомление `remoteControl/status/changed` 500 мс;
  не пришло — состояние неизвестно (`null`), и это читается как «не
  подключён»: кнопка ChatGPT выключена, действие включено. Повторная
  проверка при нажатии видит `connected` и отказывает.
- Причина у кнопки ChatGPT — из предпросмотра мастера (загружен один раз),
  действия — из обновляемого раздела `providers`: на одном экране
  состояния разного времени.

Решение:

- Ожидание уведомления — до 3 с (весь опрос — до 4 с); если состояние не
  пришло, а у того же процесса демона оно было известно, остаётся прежнее.
- Состояния демона для пользователя: не запущен → «Запустить демон»;
  работает, связь `connecting` или неизвестна → «ChatGPT подключается к
  демону — подождите несколько секунд», без действия; связь `disabled`
  или `errored` без ошибки входа → «Подключить к ChatGPT» (то же
  `codex remote-control start`); подключён → действия нет.
- Мастер, пока кнопка провайдера выключена, перечитывает предпросмотр раз
  в 5 с; отказ действия как «уже не нужно» (`action-disabled`) не
  показывается ошибкой — мастер перечитывает предпросмотр.
