# M33: вопросы Claude — факты и проба T001

Дополнение к [спецификации M33](../planning/M33-agent-questions.md). Уровни доказательства:
**[код]** — прочитано в коде Kit; **[документация]** — написано в документации Claude Code,
вживую не испытано; **[проверено]** — наблюдалось вживую (дата, версия). Разделы 4 и 5
заполняет T001.

## 1. Проверено по коду Kit (15.11.2026, 0.13.7)

- **[код]** Лента читает транскрипт сессии по пути из журнала хука; из строки `assistant`
  берутся только части `type: "text"`, `tool_use` и `thinking` отбрасываются; строка `user`
  только с `tool_result` — не сообщение (`provider-claude/src/chat.ts`, `chat.md`).
- **[код]** Сессия панели — `claude` в скрытом терминале (expect на macOS и Linux, ConPTY на
  Windows) с Remote Control. Текст панели вставляется в терминал (`<debug>.text`: вставка,
  пауза 700 мс, Enter).
- **[код]** Хост уже нажимает клавиши в распознанных кадрах: меню `/model`, Shift+Tab
  (M27–M30), «Not now» на предложение новой функции (M15). Неизвестный диалог до ссылки
  Remote Control останавливает запуск без нажатий (`dialogs.md`).
- **[код]** Хуки Kit в `.claude/settings.json`: `SessionStart`, `Stop` (600 с),
  `UserPromptSubmit` (30 с). Событий инструментов Kit не ставит.
- **[проверено, M28]** Esc в диалоге разрешения отменяет вызов и останавливает ход; в
  транскрипте `[Request interrupted by user for tool use]`.

## 2. Документация Claude Code (прочитана 15.11.2026, CLI 2.1.325)

Источники: <https://code.claude.com/docs/en/hooks>,
<https://code.claude.com/docs/en/tools-reference>,
<https://code.claude.com/docs/en/remote-control>.

- **[документация]** `AskUserQuestion` требует участия пользователя. Хук `PreToolUse`
  выполняет это требование, если вернёт `permissionDecision: "allow"` вместе с
  `updatedInput`, где повторён исходный массив `questions` и добавлен объект `answers`: текст
  вопроса → выбранный ответ. Одного `allow` недостаточно.
- **[документация]** Значение ответа — подпись варианта; ответы с несколькими вариантами
  соединяют подписи запятыми (точный разделитель не указан). Свой текст («Other») не описан.
- **[документация]** Хук `PermissionRequest` срабатывает, когда вызову нужно решение о
  разрешении; для `AskUserQuestion` ему тоже нужен `updatedInput` при `behavior: "allow"`.
  Во входе есть `tool_name` и `tool_input`, `tool_use_id` нет.
- **[документация]** Вход `PreToolUse`: `tool_name`, `tool_input` (`questions[]` с `question`,
  `header`, `options`, `multiSelect`), `tool_use_id`.
- **[документация]** Тайм-аут командного хука — поле `timeout` в секундах, по умолчанию 600;
  наибольшее значение не указано.
- **[документация]** Вопросы `AskUserQuestion` при Remote Control не истекают; настройка
  `askUserQuestionTimeout` при подключённом Remote Control не действует.
- **Не документировано:** что видит пользователь, пока хук не вернулся; формат записи вопроса
  и ответа в транскрипте; клавиши диалога вопроса в терминале; закрывается ли диалог в
  терминале после ответа из приложения.

## 3. Программа пробы T001

Стенд: одноразовый проект Kit, сессия через публичный путь провайдера (настоящие хуки,
expect, Remote Control), модель Haiku. Вопрос вызывается репликой, которая просит агента
задать указанные вопросы инструментом `AskUserQuestion`. Пробный хук — только в настройках
пробного проекта. Скрипт пробы целиком — в evidence, в блоке кода; исполняемых файлов в
репозитории T001 не создаёт. После пробы проект, доверие и процессы убираются.

Обязательные доказательства:

| № | Что доказать |
| --- | --- |
| D1 | Строка `tool_use` вопроса есть в транскрипте, пока вопрос ждёт ответа (не позже 3 с после кадра диалога) |
| D2 | Формат результата в транскрипте после родного ответа: один вариант, несколько вариантов, свой текст, два вопроса; после отмены Esc |
| P1 | Хук `PermissionRequest` с `matcher: "AskUserQuestion"` срабатывает в сессии с Remote Control; состав входа, включая любой идентификатор вызова |
| P2 | Пока хук ждёт, диалог вопроса нарисован в терминале и виден в Claude Desktop |
| P3 | Ответ хука (`allow` и `updatedInput.answers`) закрывает диалог в терминале и в Desktop; агент получает именно эти ответы: один вариант, несколько (разделитель), свой текст, два вопроса |
| P4 | Родной ответ раньше хука: ход продолжается сразу; процесс хука завершается или его поздний ответ игнорируется; нет зависания и второго ответа |
| P5 | `timeout` 43 200 принят; хук жив дольше 600 с (одно ожидание 11 мин); выход хука без вывода оставляет родной диалог рабочим |
| P6 | Что происходит с текстом, вставленным в терминал при открытом диалоге вопроса (нынешнее поведение `sendDirect`) |
| P7 | Два одинаковых вопроса подряд: чем различаются вызовы во входе хука, завершён ли процесс хука первого вопроса до второго; ожидание дольше 9 мин с повторным запросом того же хука не создаёт второго вопроса |

Только если не доказано хотя бы одно из P1–P5 и P7 (условия A1):

| № | Что доказать |
| --- | --- |
| K1 | Устойчивый кадр диалога вопроса: признаки, курсор, номера вариантов, подвал |
| K2 | Клавиши выбора одного варианта и отправки |
| K3 | Клавиши нескольких вариантов, перехода между вопросами и своего текста |
| K4 | Диалог в терминале закрывается после ответа из Desktop; кадр после закрытия |

Что видно в Claude Desktop (P2, P3, K4), подтверждает пользователь в одной совместной
проверке; без неё эти строки остаются «не проверено» и A1 не выбирается.

Допустимые сочетания D1 и канала — в таблице раздела 2.2
[решения по провайдерам](../planning/M33-agent-questions-providers.md). A2 требует D1 «да»;
D1 «нет» без доказанного A1 — `task:block` и решение пользователя.

## 5. Выбор варианта (заполняет T001)

Сочетание D1 и канала ответа (A1 или A2) из таблицы раздела 2.2 решения по провайдерам,

`QUESTION_HOOK_TIMEOUT_S`.

## 6. Бюджет и согласие

Не больше 12 коротких ходов Haiku на D и P; серия K — ещё до 4. Ожидание 11 мин (P5)
генерации не тратит. Ходы запускаются только после прямого согласия пользователя с этим
бюджетом в начале T001.
