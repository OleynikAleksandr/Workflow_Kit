# M10: оркестрация и сабагенты в сессиях Kimi Code

## Цель и согласование

Сейчас сессия Kimi Code отказывается работать через сабагентов: и в режиме «Параллельно»
(оркестрация с исполнителями), и как помощники в последовательном режиме. Инструменты для
этого у Kimi есть (`Agent`, `AgentSwarm`, `Bash` с `cwd`). Запрет ставит сам Workflow Kit
(решение M8, раздел 5): тогда считалось, что у Kimi нет оркестрации. После M10 сессия Kimi
ведёт скоуп и последовательно, и с исполнителями, как Claude и ChatGPT.

Решение пользователя (2026-11-10): «Сейчас Кими отклоняет работу через сабагентов,
параллельную и последовательную. При этом у него эти все инструменты есть. Разберись,
пожалуйста, как это включить в наш Workflow Kit.» После разбора: «Новый скоуп M10».

## 1. Факты и принципы

Факты (Kimi Code 2.5.2, разбор программы `kimi` и протокол M8):

- Инструмент `Agent`: `prompt`, `description`, `subagent_type` (по умолчанию `coder`),
  `resume`, `run_in_background`, `model` (и `fork` за экспериментальным флагом). Своей
  изоляции в git worktree у него нет. Несколько разнородных задач — несколько вызовов
  `Agent` в одном сообщении.
- В описании `Agent` сказано: не запускать сабагента без явной просьбы пользователя;
  разрешают и явные указания в `AGENTS.md` или навыке. Kimi читает `AGENTS.md` проекта при
  старте сессии.
- `Bash` принимает `cwd` — папку, в которой выполняется команда. Worktree Kit лежит внутри
  папки проекта (`.workflow-kit/local/worktrees/<id>`), то есть внутри рабочей области Kimi.
- `AgentSwarm` работает только в режиме роя, который включает сам пользователь в Kimi; иначе
  вызов отклоняется. Режим «Tower» (`TowerSpawn`, `TowerMerge`, …) — экспериментальный, за
  флагом, со своими worktree и слиянием. Kit не использует ни тот, ни другой.
- Подагент работает внутри хода основной сессии: замок сессии держится до конца хода, а
  `Stop` подагента посреди хода Kit уже ничего не доставляет (сценарный тест M8).
- `run_in_background=true` отдаёт результат подагента в одном из следующих ходов.

Принципы:

- Процедура исполнителя у Kimi та же, что у ChatGPT (Codex): worktree делает оркестратор,
  Kit удаляет его после интеграции (M3-orchestration, раздел 2–3). Контракт Harness
  (`assignment:*`, `integration:*`) не меняется.
- Исполнители запускаются на переднем плане: SHA нужен в том же ходе, автопилот не ждёт
  фоновых результатов.
- Механизм «провайдер без оркестрации» (`sequentialOnlyNote`, `choiceOptionsFor`, 409
  `orchestration-unavailable`) остаётся для будущих провайдеров; Kimi под него больше не
  попадает.

## 2. Решение

### 2.1. `provider-kimi`: возможность `orchestration`

`capabilities().orchestration` доступна, когда Kimi установлен и поддерживается (та же
причина, что у `createSession`: «Kimi Code не найден» и т. п.). Причина «у Kimi нет
оркестрации Workflow Kit» удаляется. Панель предлагает для сессии Kimi «Параллельно»
(`choiceOptionsFor`), запуск плана в этом режиме не отказывает.

### 2.2. `autopilot`: процедура исполнителя Kimi

`EXECUTOR_HOWTO.kimi` (`repeat: true` — Kimi читает `AGENTS.md` только при старте сессии,
поэтому процедура идёт в каждое продолжение оркестрованного скоупа):

- для каждого задания: `git worktree add --detach .workflow-kit/local/worktrees/<assignment id> <baseCommit>`
  (`baseCommit` из вывода `assignment:create`);
- сабагент — инструмент `Agent` (`subagent_type` по умолчанию), на переднем плане, без
  `run_in_background`; в промпте бриф и строка «Your worktree is <absolute path>; pass it
  as cwd to every Bash call and use absolute paths inside it for Read, Edit and Write»;
- независимые задания — несколько вызовов `Agent` в одном сообщении (до `maxWorkers`);
- SHA из ответа → `scripts/workflow integration:start --id <assignment id> --source <sha>`;
  Kit удаляет worktree после интеграции. `AgentSwarm` не используется.

Тексты последовательного режима для Kimi больше не содержат `sequentialOnlyNote`.

### 2.3. `kit-structure`: раздел `AGENTS.md`

Пункт «Kimi Code» раздела «Orchestration with your app's subagents» вместо запрета
описывает процедуру 2.2 и прямо разрешает инструмент `Agent` в сессии Kimi Code:

- в режиме orchestrated — исполнители в worktree, как выше;
- в последовательном режиме — помощники для поиска, чтения и проверок текущей задачи: они
  работают в основной папке, ничего не коммитят и не запускают `scripts/workflow`.

Изменение шаблона меняет хеш фрагмента `agents-section`: существующие проекты показывают
структуру `outdated` и получают новый текст обычным обновлением структуры. Пока проект не
обновлён, процедура всё равно приходит в сообщениях автопилота (`repeat: true`).

## 3. Поведение на ОС

| Что | macOS | Linux | Windows |
| --- | --- | --- | --- |
| Режим «Параллельно» для сессии Kimi | предлагается | предлагается | предлагается (x64 и ARM64) |
| Worktree исполнителя | `git worktree add --detach …` оркестратором | то же | то же; путь для `cwd` — абсолютный Windows-путь |
| Сабагент | `Agent`, `Bash` с `cwd` | то же | то же |

Поведение одинаково на всех ОС: программ одной ОС нет, новых записей в
`tools/platform-guard/allowlist.json` не требуется.

## 4. Проверка

- Автоматические тесты (на всех ОС одинаковы):
  - `provider-kimi`: `orchestration` доступна при установленном Kimi, недоступна без него;
  - `autopilot`: старт оркестрованного скоупа в сессии Kimi несёт процедуру Kimi, продолжение
    оркестрации повторяет её, последовательные тексты Kimi — без `sequentialOnlyNote`;
  - `plan-view`: для сессии Kimi предлагается orchestrated;
  - `kit-structure`: раздел `AGENTS.md` описывает процедуру Kimi и разрешение помощников;
  - сценарий Kimi: выбор orchestrated и запуск плана доходят до сессии с процедурой Kimi.
- CI: macOS, Linux, Windows x64 и ARM64.
- Живая проверка: macOS — пользователь (оркестрованный скоуп из двух независимых задач в
  сессии Kimi; помощник-сабагент в последовательном режиме); Windows — проверяющий на
  Windows; Linux — только CI.
- Не проверено (**П**) до живой проверки: идут ли несколько вызовов `Agent` одного сообщения
  одновременно; нет ли запросов подтверждения для инструментов сабагента в сессиях Kit;
  `scripts/workflow commit` исполнителя внутри worktree под замком сессии Kimi.

## 5. Границы

Не входит: `AgentSwarm` и режим «Tower»; фоновые исполнители (`run_in_background`); Kimi
как ревьюер плана; изменения контракта Harness.
