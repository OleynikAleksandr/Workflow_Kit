## T004 — изменение параметров ChatGPT

13.11.2026, 13:35:54 UTC: production `Provider.updateParameters` на отдельном временном
треде `01a1d51f-2175-7a31-b1b1-c8e48b2c8438` поменял low → high.
Перед этим экземпляр провайдера прочитал конфигурацию установленной службы и выполнил
штатный refresh программы. Общий доступ при изменении перепроверен: active.
Ответ заново прочитан: `gpt-6.1-sol` / `high`, скорость priority, разрешения workspace,
режим default. Тред удалён через thread/delete, временная папка удалена.

Первый пробный экземпляр с вручную заданной пустой конфигурацией и без refresh программы
отказал изменению с parameters-unavailable (общий доступ не активен в его снимке).
Его тестовый тред также удалён. Причина устранена корректной инициализацией пробы
с конфигурацией службы и штатным refresh; это не изменение конфигурации пользователя.

Тесты darwin/linux/win32 проверяют effort-only и model-only запросы без collaborationMode,
совместимость, отдельные и совместные автоматические поправки, отказ явно неподдерживаемых
значений, подтверждение/запрет профилей, режим со свежими параметрами, очередь, отписку
загруженного пробой треда, сохранение отказа метода до refresh и отзыв общего доступа.
Новая отправка не использует turn/settings/update и не меняет идущий ход.

## R2 / T010 — отказ атомарной замены на Windows

Предварительная CI на `784d66a0`, run 43439309345, Windows x64 job 131932462501:
тест десяти конкурентных снимков получил EPERM при rename временного файла в s.json.
Лог получен через GitHub connector; это исходный сбой, повторный успех его причину
не подменяет. Запись одного назначения сериализована; EPERM/EACCES/EBUSY имеют
ограниченный повтор без удаления старого файла. Тест воспроизводит transient отказ,
проверяет сохранность назначения, постоянный отказ и независимость разных файлов.

## R2 / T011 — раннее завершение тайм-аута statusline

Предварительная CI 43439309345: Windows x64 job 131932462501 и Windows ARM64
job 131932462572 получили EBUSY при удалении cwd после тайм-аута. Promise команды
возвращался раньше close процесса. Windows ARM64 также повторила EPERM снимка из T010;
macOS и Linux этого предварительного прогона завершились успешно.

Исправление ожидает два события: окончание операции завершения дерева и close процесса.
Детерминированный тест задерживает taskkill после закрытия процесса, проверяет отсутствие
раннего результата и немедленное удаление cwd после результата. Проверка гибели родителя
и дочернего процесса сохранена; проверки Windows не отключены.

## R3 / T012 — истечение срока между запросами Kimi

Предварительная CI 43440918187 на 7d6c6941: macOS job 131937986212 завершилась
необработанным KimiError transport/timedOut в тесте повторного Stop после тайм-аута.
Исходный лог сохранён при диагностике. Отдельный запуск прежних тестов локально прошёл,
что само по себе не устанавливает причину. Новый детерминированный тест сдвинул часы
через deadline между подготовкой двух запросов: на старом коде первый Promise оставался
без обработчика (3/3 отказа с injected darwin/linux/win32). После получения options
один раз до запуска обоих запросов — 3/3 успеха; поздний abort не отправлен.
Существующие проверки тайм-аутов и происхождения ошибок сохранены без ослабления.
