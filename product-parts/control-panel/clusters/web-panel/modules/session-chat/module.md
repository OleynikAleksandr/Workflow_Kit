# Модуль: session-chat

Часть `control-panel`, кластер `web-panel`. Публичный вход: `src/index.ts`.
Алиас импорта: `#session-chat` (добавляется при подключении модуля к панели).

## Назначение

Карточка «Диалог» на экране сессии (спецификация
[M18, раздел 2.6](../../../../../../docs/planning/M18-session-chat.md)):
лента реплик пользователя и агента этой сессии и поле, из которого пишут
агенту. Своего чата у Kit нет: лента — вид переписки, которую отдаёт
провайдер, а отправка идёт маршрутом канала агента (прямо агенту или в
очередь). Модуль не отвечает на запросы разрешений, не подгружает старые
сообщения и не выводит ответ посимвольно.

## Публичный интерфейс

Для бэкенда (`src/index.ts`):

- `SESSION_CHAT_PREFIX` — `/session-chat/`.
- `SESSION_CHAT_ASSETS_DIR` — абсолютный путь к `src/`.
- `sessionChatMount() → { prefix, dir }` — монтирование для `http-server`
  (подключает `cli`, `createApp`).

Для панели:

- `session-chat.js` — расширение панели (`PANEL_EXTENSIONS` в `panel-shell`,
  путь `/session-chat/session-chat.js`): `install(shell)` заполняет слот
  `sessionChat` (`registerSlot`, тип `SessionSlot`). `select` отдаёт ключ
  сессии, подпись провайдера и счётчик изменений карточки; `render` всегда
  возвращает один и тот же элемент сессии.
- `session-chat.css` — стили карточки (`/session-chat/session-chat.css`
  в `index.html` панели).

Маршруты службы, которыми пользуется карточка:

- `GET /api/projects/:id/providers/:p/sessions/:localId/messages` →
  `{ supported, messages, truncated }`;
- `POST /api/projects/:id/sessions/:key/message { text }` →
  `{ sent: true }` или `{ queued: <id> }`.

## Поведение карточки

- Состояние сессии (узлы сообщений, поле с введённым текстом, прокрутка
  ленты) хранится в `Map` по проекту и ключу сессии и переживает опрос и
  уход с экрана: элемент обновляется на месте.
- Опрос `GET …/messages`: сразу, как карточка попала в документ (открытие
  экрана сессии), и раз в 3 с, пока карточка в документе и вкладка видима
  (`document.visibilityState`); сразу после успешной отправки —
  внеочередной. Одновременно не больше одного запроса на сессию: запрос во
  время другого откладывается до его конца. Карточка вне документа не
  опрашивается.
- Лента прокручивается внутри карточки (до 60 % высоты окна) и сама уходит
  вниз при новых сообщениях, только если пользователь был внизу.
- Ошибка чтения показывается в карточке, прежние сообщения остаются.
- Ctrl+Enter и ⌘+Enter отправляют; во время отправки кнопка выключена;
  после успеха поле очищается и под ним — итог `sendOutcome`; отказ — текст
  ошибки службы с подсказкой, введённое остаётся.
- На сенсорном устройстве (iPad) всё управление — кнопка и поле, без
  элементов, видимых только при наведении.

## Инварианты

- Чистая логика в `chat-model.js` без DOM; покрыта `node --test`.
- Текст в DOM — только через `textContent` (без `innerHTML`); переносы строк
  сохраняются (`white-space: pre-wrap`).
- Не больше одного запроса чтения на сессию одновременно.

## Зависимости

- `panel-shell`: типы `SessionSlot`, `SessionContext` (`slots.js`), `api`
  (`api.js`) и `h` (`dom.js`) — только через объект `shell` расширения.
- Маршруты службы `provider-registry` (лента) и `agent-channel` (отправка).

## Поведение на ОС

Одинаково на macOS, Linux и Windows: модуль — файлы браузерной панели,
вызовов программ ОС и путей ОС в нём нет; `index.ts` строит путь к `src/`
через `fileURLToPath`. Различия провайдеров по ОС (откуда берётся лента,
когда возможна прямая отправка) — в их модулях, карточка показывает то, что
отдаёт служба.
