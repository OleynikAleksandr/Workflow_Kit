# Веха 1 — установка на Mac и первая приёмка

Дата: 2026-11-05. Mac пользователя (macOS 27.0.1, arm64), iPad через Tailscale.
Подтверждение установки пользователем: «Да, ставить».

## Установка

- `node bin/wfk.mjs install` — Workflow Kit 0.1.0 развёрнут в
  `~/Library/Application Support/Workflow Kit/app/0.1.0`.
- Найдены программы: node `/opt/homebrew/opt/node@24/bin/node` (устойчивый
  путь, не Cellar), claude `~/.local/bin/claude`, codex
  `~/.npm-global/bin/codex`, expect `/usr/bin/expect`.
- Запускатель `~/.local/bin/wfk`, значок `~/Applications/Workflow Kit.app`,
  автозапуск LaunchAgent `ai.workflowkit.backend` (state running).
- `wfk doctor --installed` — все 14 пунктов `ok`, итог «всё в порядке».
- `/api/health` отвечает на `127.0.0.1:4747` и на адресе Tailscale
  `100.81.163.123:4747` (200). Панель открывается, карточка «Система»
  показывает службу, автозапуск, запускатель, значок и программы.

## Найденные дефекты

- **D1 (T007).** После служебного хода панель не отпускает тред Codex:
  ChatGPT считает чат открытым в другом приложении. Нужен
  `thread/unsubscribe` после хода.
- **D2 (T006).** Скрипт доверия Claude узнаёт диалог по слову `confirm`.
  Claude показал диалог «Allow external CLAUDE.md file imports?» (импорт
  `~/AGENTS.md` из `~/CLAUDE.md`); скрипт выбрал «Yes, allow external
  imports» без согласия пользователя, доверие не записано. Флаги импорта для
  `!_001` откачены вручную по решению пользователя (копия в `backups/`).
- **D3 (T006).** Домашняя папка доверена (`hasTrustDialogAccepted` у `~`),
  поэтому Claude не показывает диалог доверия для вложенных папок, а ключ
  самой папки проекта остаётся `false`. Панель и способ записи доверия
  должны учитывать это; внешние импорты — отдельное решение пользователя в
  предпросмотре.

Решение пользователя: исправить дефекты раундом исправлений, пересобрать и
переустановить, затем пройти приёмку заново по порядку.

## Переустановка после раунда R2 (T014)

Дата: 2026-11-05. Подтверждение пользователя: «Да, переустановить».

- Первый `node bin/wfk.mjs install` поверх работающей службы скопировал
  новую версию, остановил старую службу и не запустил новую: «служба не
  ответила на /api/health за 20 с», `doctor --installed` — «LaunchAgent
  загружен: нет».
- **D4 (T010).** launchd выгружает службу асинхронно. Сразу после
  `launchctl bootout` команда `print` ещё находила старую службу, установщик
  вызывал `kickstart` у уходящей службы вместо `bootstrap`, и служба
  оставалась выгруженной. Исправлено в T014: после каждого `bootout`
  установщик ждёт, пока `print` перестанет находить службу, и только потом
  загружает её (`unloadLaunchAgent`). Подставной `launchctl` в тестах теперь
  выгружает асинхронно; новый тест на старом коде падает, на новом проходит.
  Службу вручную не запускали.
- Повторный `install` исправленным установщиком: служба работает,
  `doctor --installed` — всё в порядке. Ещё один `install` поверх работающей
  службы: старый процесс остановлен, новый поднялся (pid 3728 → 3804),
  `doctor --installed` — всё в порядке.

- **D5 (T012).** В журнале службы есть `thread/unsubscribe …: unsubscribed`,
  то есть отписка сработала. Журнал Codex (`~/.codex/logs_2.sqlite`, только

  - 19:29:29 — `thread/unsubscribe`;
  - 19:29:41–52 — ChatGPT получает `thread-store conflict: thread … already
    has an active writer`;
  - 19:30:29 — демон: «has no subscribers and is idle; shutting down»;
  - 19:31:19 — ChatGPT открыл тред.

  Демон держит тред без подписчиков ещё 60 с. Принудительной выгрузки в
  протоколе нет. Исправлено в T014: создание сессии после отписки ждёт, пока
  тред исчезнет из `thread/loaded/list` (до 90 с). Пока тред удерживается,
  сессия в списке без кнопки «Открыть» и с пояснением. Служба переустановлена,
  `doctor --installed` — всё в порядке. Шаг 5 повторяется.

### Шаги 5–7 после исправления D5

Пользователь: «Да, всё прошло». По журналам на 2026-11-06:

- **Шаг 5.** Последняя сессия Codex создана исправленной службой 2026-11-05
  в 19:59:57. Служба отписалась от треда и опрашивала `thread/loaded/list`
  каждые 2 с. Это видно в журнале Codex, то есть ожидание работает на
  настоящем демоне. В 20:00:56 журналы Codex обрываются: Mac уснул или
  выключился, поэтому в журнале службы — «release not checked». ChatGPT
  этот тред не открывал. Открытие без сообщения «Этот чат открыт в другом
  приложении» по журналам не подтверждено.
- **Шаг 6.** В журналах хука проектов `!_001` и `!_002` нет сессий,
  начатых в приложениях. Новых тредов Codex после 2026-11-05 19:59 нет.
- **Шаг 7.** 2026-11-06 служба поднялась сама после входа в систему
  (pid 815), `doctor --installed` — всё в порядке: автозапуск подтверждён.
  Перезапуск по значку после `wfk service stop` в журнале не отличить.

Решение пользователя: «Закрыть как есть». Шаги 5 и 6 перепроверить в
следующей вехе вместе с новым интерфейсом.
