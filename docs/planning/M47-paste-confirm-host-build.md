# M47: подтверждение доставки по хуку и устаревший хост сессии

## Цель и согласование

Пользователь 19.11.2026, тест 0.20.2 в новом проекте S02 (Claude 2.1.328): «агент получил мое
сообщение, при этом оно осталось как будто бы не отправленным в поле ввода пользователя, и
высветилась все равно ошибка». Под полем — «Сообщение не дошло до Claude: Claude не начал ход с
этим сообщением: терминал занят или в нём открыт диалог» и «Повторить»; в ленте сообщение обёрнуто
в `<pasted_content id="fec6">`. В тот же день о сессии этого проекта: «сессия диалог Workflow Kit
потеряла полностью контакт и контроль за моделью. Я не могу там поменять ни модель, ни уровень
размышления».

Согласовано 19.11.2026: «Давай делать два плана по очереди. Сначала первый проверяем, смотрим на
результат. Вне зависимости от результата проверяем второй отдельный план. Потом принимаем решение,
что оставляем, что откатываем». M47 — первый план (выпуск 0.20.3); второй — перевод сессий Claude
панели с экрана терминала на потоковый протокол Claude — пишется отдельно после проверки M47.

Результат: сообщение панели, с которым Claude начал ход, панель показывает отправленным при любом
виде текста в хуке; лента показывает его без служебной обёртки; сессия, чей хост запущен прежней
сборкой Kit, прямо говорит об этом и о том, как вернуть управление моделью и уровнем.

## 1. Разбор

### 1.1. Ложное «не дошло» (сессия S02, `session-20261119T170342-d00e35`)

| Время (UTC) | Что |
| --- | --- |
| 17:04:02.45 | конец первого хода (приветствие), сессия ждёт |
| после | сообщение панели: `sendDirect` вставил текст (`MESSAGE_SENT`) |
| 17:04:03.7–03.9 | Claude запустил хук `UserPromptSubmit` — ход начался |
| +8 с | журнал службы: `channel: message to claude:f7322ed8… was pasted, but no prompt hook took it within 8000 ms` |

Хук пришёл через 1,2 с, но канал его не признал: `ownPrompt` (`agent-channel/src/turn-state.ts`)
считает хук подтверждением только при `prompt.trim() === reservation.text`. Claude 2.1.328 отдаёт
вставленный через bracketed paste многострочный текст в обёртке
`<pasted_content id="…">…</pasted_content id="…">` — равенства нет. Маршрут ответил `undelivered`,
панель вернула текст в поле и показала «Повторить» (нажатие отправило бы задание второй раз). Сам
ввод хука не записан: вывод сделан по времени хука и по ленте; T001 записывает его с живого Claude.

### 1.2. Сессия без управления моделью и уровнем (`session-20261119T090146-d4902d`)

Процесс хоста этой сессии (`interrupt-worker.ts`, запущен 19.11 в 10:01) работает из каталога
`app/0.20.0`. Обновления 0.20.1 и 0.20.2 заменили службу, но не хост живой сессии: он не знает меню
`/model` Claude 2.1.328 (M46), каталог не читается (`models: []`, `efforts: []`), файл каталога —
от 2.1.325. Панель показывает «Список моделей Claude появится, когда Claude будет свободен» — этого
не случится, пока сессию не перезапустят; модель в панели (Opus 5.5) расходится с настоящей.

## 2. Принципы

- Доставку подтверждает событие (Claude начал ход в сессии, куда только что вставлен текст), а не
  точный вид текста: новая версия Claude, меняющая текст в хуке, не превращает доставленное
  сообщение в «не дошло».
- Расхождение не прячется: если хук подтвердил вставку по порядку, а текст не совпал, служба пишет
  строку журнала.
- Kit не показывает управление, которое заведомо не сработает: вместо вечного ожидания — причина и
  действие пользователя.
- Правила M28, M45 и M46 остаются: чужие окна Claude хост не закрывает; несвободный терминал —
  `undelivered` с причиной, без очереди.

## 3. Решение

### 3.1. Подтверждение по порядку (`agent-channel`)

- Резервирование хода прямой отправки (`directTurn`) помечается как прямое (`direct`). Пока идёт
  отправка и ожидание подтверждения (`slot.sending`, до `DIRECT_CONFIRM_MS` = 8 с), первый хук
  `UserPromptSubmit` этой сессии забирает резервирование и при другом тексте: ход начат сообщением
  панели, источник решения пользователя — текст резервирования (то, что написал пользователь), как
  при точном совпадении.
- Точное совпадение текста работает как раньше. При подтверждении по порядку служба пишет
  `channel: prompt hook of <key> confirmed the pasted message by order: the hook text differs
  (<длина хука> vs <длина сообщения> chars)` — без самих текстов.
- Остальные резервирования (доставка очереди хуком, отсоединённая доставка) сравнивают текст, как
  были: там Kit сам пишет строку пробуждения, обёртки нет.
- Нет хука за окно — `'unconfirmed'` и `undelivered`, как в M45.
- Ответ маршрута `POST /api/projects/:id/sessions/:sid/message` не меняется.

Если в окне подтверждения ход начало другое сообщение (пользователь в ту же секунду написал в
приложении Claude), вставленный текст Claude ставит следом своим вводом: он доходит, а панель
показывает его отправленным. Это вернее, чем «не дошло» и повтор.

### 3.2. Лента без обёртки (`provider-claude`: `src/chat.ts`)

- Текст сообщения пользователя из транскрипта: пара строк-меток `<pasted_content id="X">` и
  `</pasted_content id="X">` с одним `id` убирается, содержимое остаётся; текст без пары не
  меняется. Точный вид пары берётся из записи живого Claude 2.1.328 (T001/T002) и хранится в тесте.
- Так сообщение панели и его запись в транскрипте совпадают текстом, и лента показывает его один
  раз.

### 3.3. Метка сборки хоста (`provider-claude`, `pty-host`)

- Метка сборки — короткий дайджест исходников, из которых работает хост терминала: каталог
  `provider-claude/src/pty`, файлы `src/pty.ts`, `src/folder-key.ts` и исходники модуля `pty-host`
  (экран терминала). Содержимое читается с LF; порядок — по относительным путям с `/`.
  Вычисление — общая функция модуля `pty-host` (публичный вход).
- Хост (`session.exp` с `interrupt-worker.ts`; `pty/host.ts` на Windows) получает метку при запуске
  и пишет её в состояние (`NativeParameterState.hostBuild`).
- Служба сравнивает `hostBuild` состояния со своей меткой. Другая метка или её отсутствие (хосты до
  0.20.3): параметры сессии не редактируются (`editable: false`), причина — `HOST_OUTDATED`
  «Сессия запущена до обновления Workflow Kit: управление моделью и уровнем в ней устарело.
  Остановите сессию и возобновите её в панели». Сообщения, прерывание и лента такой сессии работают
  как раньше.
- Возобновление запускает хост текущей сборки — метка совпадает, управление возвращается.
- Тест-сторож: каждый относительный импорт вне `src/pty` из файлов хоста входит в список метки.
- Выпуск без изменений хоста метку не меняет: живые сессии после такого обновления не помечаются.

## 4. Поведение на ОС

| Что | macOS | Linux | Windows |
| --- | --- | --- | --- |
| Подтверждение по порядку | общий код службы | то же | то же |
| Обёртка в ленте | общий `chat.ts` | то же | то же |
| Метка сборки | хост `session.exp` + `interrupt-worker.ts` | то же | хост `pty/host.ts` (ConPTY); пути через `path`, содержимое с LF — метка не зависит от CRLF рабочей копии |

Новых программ ОС и веток ОС нет. Чтение исходников для метки использует `path` и не сравнивает
пути между машинами: хост и служба читают файлы своей установленной версии.

## 5. Проверка

- Запись живого Claude 2.1.328 (делает агент, временная папка, настройки пользователя не
  меняются): ввод хука `UserPromptSubmit` и строка транскрипта для многострочного текста,
  вставленного тем же способом, что `.text` (bracketed paste), и для однострочного. Записи — данные
  тестов.
- `agent-channel`: хук с записанным текстом подтверждает прямую отправку (`true`), пишется строка
  журнала; точный текст — как раньше; нет хука — `'unconfirmed'`; резервирование доставки по тексту
  не изменилось. `cli`: настоящая служба — `{ sent: true }` при хуке с обёрткой.
- `provider-claude`: лента без обёртки на записанной строке; состояние с другой меткой и без метки —
  `editable: false` и `HOST_OUTDATED`; с той же — как раньше; хост ConPTY пишет метку; тест-сторож
  списка файлов.
- CI: macOS ARM64, Linux x64, Windows x64 и ARM64 для точного SHA на
  `ci/M47-paste-confirm-host-build`.
- Живая проверка (macOS — пользователь): новый проект на Claude 2.1.328, многострочное сообщение из
  панели — поле очищено, ошибки нет, в ленте сообщение один раз и без обёртки; сессия, запущенная
  до 0.20.3, показывает причину, после остановки и возобновления модель и уровень меняются.
  Windows — проверяющий; Linux — CI.

## 6. Границы

- Не входит: перевод сессий Claude на потоковый протокол (второй план); автоматический перезапуск
  устаревших сессий; обёртка в словах пользователя, набранных не из панели (хук чужого ввода).
- Модель и уровень устаревшей сессии панель до перезапуска показывает по данным старого хоста.

## Уточнения реализации

- **T001.** Запись живого Claude 2.1.328: обёртку получает вставка длиннее 6 строк (экран
  `[Pasted text #1 +N lines]`) — и в хуке, и в транскрипте, с `\n\n` в начале; 3 строки и одна —
  без изменений. Признак окна подтверждения — `slot.sending` (отправка и ожидание `directTurn`).
- **T002/F001.** Код T002 закоммичен задачей F001: в `--files` пути были переданы через пробел, Kit
  взял только первый (`trust.md`, потерянный документационным коммитом переноса раздела).
- **T003.** В метку входит и `links.ts` (импорт `pty.ts`); типы `#provider-registry` — нет.
  Тест-сторож обходит относительные импорты `src/pty`. Фикстура состояния в
  `parameter-controls.test.ts` получила метку текущей сборки.
