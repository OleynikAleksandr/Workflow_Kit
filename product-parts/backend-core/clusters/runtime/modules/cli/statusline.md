# Команда строки состояния Claude (M25)

`wfk statusline --client <id>` читает stdin до 1 МиБ, сохраняет снимок параметров
и выполняет пользовательскую команду строки состояния. Всегда возвращает код 0.
Служба для этого не требуется. Сбой записи снимка не меняет запуск и stdout команды.

В снимок сессии попадают только session_id, model.id/display_name, effort.level,
context_window.context_window_size/used_percentage/total_input_tokens, fast_mode,
version и at. Текст переписки не копируется. rate_limits.five_hour/seven_day сохраняются
отдельно с used_percentage/resets_at и at. Самый новый снимок лимитов побеждает:
запись сериализуется межпроцессной блокировкой каталога и сверяет at.
Снимки сессий старше 30 суток удаляются при записи. Файлы и проверка id — через
публичные snapshotFile/limitsFile, readSnapshot/writeSnapshot реестра провайдеров.

Пользовательская команда — первая statusLine типа command из
<cwd>/.claude/settings.local.json → <cwd>/.claude/settings.json → ~/.claude/settings.json.
Команды, содержащие запуск wfk statusline, пропускаются во избежание рекурсии.
stdin и stdout передаются Buffer без декодирования; Unicode, кавычки и многострочный
вывод сохраняются. Отсутствие команды или оболочки даёт пустой вывод.

Команда выполняется до 5 секунд; stdout до успеха буферизуется. По истечении
завершается всё дерево, вывод пустой, код 0. Собственная команда не одобряет действия
за пользователя. Отказ при чтении stdin и неверные аргументы не ломают сессию Claude.

## Поведение на ОС

| macOS | Linux | Windows x64/ARM64 |
| --- | --- | --- |
| /bin/sh -c; своя группа, SIGKILL группе при тайм-ауте | то же | Git Bash: CLAUDE_CODE_GIT_BASH_PATH, затем bash из PATH; без него powershell -NoProfile -Command; taskkill /T /F через process-supervisor |

Платформа внедряется; cmd не используется. Окно процесса на Windows скрыто.
Тесты проверяют все ветки выбора оболочки, байты, приоритет/рекурсию, запись и сбои,
предел ввода, очистку и лимиты; нативный тест тайм-аута проверяет смерть команды
и дочернего процесса. Живые проверки macOS — пользователь, Windows — проверяющий;
Linux — CI.

R2/T011: результат тайм-аута возвращается только после события close команды
и завершения операции уничтожения дерева. Ранний close не обгоняет taskkill,
а завершившийся taskkill не обгоняет close. Это исключает Windows EBUSY при
следующем действии над cwd. На macOS/Linux также ожидается close после сигнала группе.
Вывод по тайм-ауту остаётся пустым; новые программы и разрешения не добавляются.
