# Workflow Kit: модуль потоковой диктовки для macOS на основе Handy

**Документ для передачи другому агенту в новую сессию.**  
Дата: 17 ноября 2026 года.  
Статус: исследование и проектное предложение; реализация в Workflow Kit ещё не выполнена.  
Основной движок первой версии: **Voxtral Mini 4B Realtime** через **transcribe.cpp**, с использованием Handy как донора.

## 1. Задача и границы поручения

Нужно добавить в поля пользовательского ввода диалогов Workflow Kit голосовую диктовку:

1. Пользователь нажимает микрофон.
2. После подготовки модели и разрешения на микрофон начинается запись.
3. Во время речи текст постепенно появляется непосредственно в поле ввода.
4. Повторное нажатие прекращает запись и завершает распознавание последнего фрагмента.
5. Полученный текст остаётся обычным редактируемым черновиком.
6. Пользователь отдельно отправляет сообщение существующим способом.

Диктовка не должна отправлять сообщение автоматически, запускать агента, останавливать его ответ или вмешиваться в очередь задач.

Этот документ позволяет новому агенту подготовить спецификацию, план и реализацию без восстановления исследовательского диалога. Сам документ **не означает, что пользователь уже поручил начать реализацию**: в новой сессии необходимо руководствоваться актуальным заданием пользователя и текущими инструкциями проекта.

Во время исследования в репозитории работает другой агент над другой задачей. Исходники, его план и рабочие изменения при подготовке этого документа не изменялись.

### 1.2. Проектные предложения этого документа

Следующие решения предложены по результатам исследования, но не являются отдельными прямыми требованиями пользователя:

- первая проверяемая конфигурация: локальная панель Kit на Mac с Apple Silicon;
- захват микрофона в браузерной панели через getUserMedia и AudioWorklet;
- отдельный локальный процесс распознавания на Rust с transcribe-cpp;
- WebSocket на существующем HTTP-сервере Kit для непрерывного аудио и событий;
- Voxtral Q8_0 как начальная конфигурация испытаний;
- одна активная диктовка на локальную службу;
- в первой поставке небольшой проверенный каталог моделей, а не автоматическое включение всего каталога Handy.

Если короткая техническая проверка покажет проблему с одним из этих решений, менять только соответствующий узел, сохраняя согласованное пользовательское поведение.

## 2. Главный технический вывод

**Нужные компоненты в актуальном Handy существуют: нативное потоковое распознавание Voxtral, промежуточный текст, управление моделями и изоляция движка в отдельном процессе.**

Однако Handy — самостоятельное приложение на Tauri/Rust с React-интерфейсом. Workflow Kit в исследованной конфигурации — Node.js-служба с браузерной панелью. Поэтому «взять Handy» означает:

- использовать тот же движок transcribe.cpp;
- адаптировать небольшие части Handy для запуска процесса, обработки потока и каталога;
- встроить управление диктовкой в существующий интерфейс Kit;
- сохранить лицензионные уведомления заимствованного кода.

Не требуется переносить Tauri, React, системную вставку через буфер обмена, глобальные горячие клавиши или всё приложение Handy.

Установка Handy у конечного пользователя не должна быть обязательной. Его внутренний режим worker — частный интерфейс реализации, а не обещанный публичный API установленного приложения.

### 4.1. Основная модель

Идентификатор в проверенном каталоге Handy:

    Voxtral-Mini-4B-Realtime-2602

Это регистрозависимый идентификатор каталога, не произвольная подпись интерфейса.

- Оригинальная модель: mistralai/Voxtral-Mini-4B-Realtime-2602.
- GGUF-репозиторий: handy-computer/Voxtral-Mini-4B-Realtime-2602-gguf.
- Лицензия весов: Apache-2.0.
- Нативный streaming: поддерживается.
- Русский: есть среди поддерживаемых языков.
- Потоковый интерфейс использует автоматическое определение языка. Нельзя обещать принудительное ru, пока выбранный runtime этого не поддерживает.
- Вход нативного движка: mono PCM, 16 000 Hz, float32.
- Локальный inference не требует оплаты за минуты или API-ключа. Загрузка весов требует сети.

### 4.3. Что означает Realtime

В документации transcribe.cpp для потокового CLI указан типичный delay 6 audio slots, то есть 480 ms; допустимый диапазон описан как 80 ms–2.4 s. Это внутренний параметр модели.

**480 ms не является гарантированной задержкой появления текста в Kit.** Полная задержка включает захват и накопление звука, передачу, вычисление, декодирование и обновление поля. В Handy используется StreamOptions::default(); фактические defaults соответствующего bindings/runtime нужно проверить при реализации.

Не переносить параметры offline-режима в streaming автоматически. В документации для offline фигурирует другая задержка.

Документированный streaming Voxtral имеет ограничение абсолютной позиции декодера примерно на 2.9 часа. При достижении границы может появиться признак truncated, причём finalize способен вернуть успешный статус. Поэтому:

- отслеживать статус потока, а не только исключения;
- завершать диктовку с понятным сообщением до потери текста;
- сохранять уже показанный текст;
- не рекламировать неограниченную непрерывную запись;
- автоматическое бесшовное перезапускание часовых потоков в первую версию не включать.

Показатели WER из документации квантованных вариантов на английском LibriSpeech не доказывают эквивалентное качество на русском. Выбор Q4/Q5/Q6 должен проверяться на русском материале пользователя.

### 4.4. Другие модели в доноре

| Модель/семейство в проверенном каталоге | Русский | Нативный streaming | Решение для первой версии |
|---|---|---|---|
| Voxtral Mini 4B Realtime | Да | Да | Основной кандидат и конфигурация по умолчанию |
| Nemotron Streaming 3.5, nemotron-3.5-asr-streaming-0.6b | ru-RU среди вариантов | Да | Возможная дополнительная модель после проверки runtime и лицензии |
| GigaAM v3 E2E CTC / RNNT | Да | В каталоге streaming=false | Не выдавать за эквивалент потоковой диктовки |
| Ряд Moonshine/Parakeet/Nemotron English | Для указанных вариантов английский | У части есть | Не предлагать как русскую модель без проверки конкретного варианта |

У Nemotron 3.5 в каталоге поле лицензии обозначено как other. До включения в распространяемый набор проверить точную лицензию модели. Это не относится к основному пути с Voxtral.

Важное различие: Handy может показывать текст по кускам у непотоковой модели за счёт внешнего разбиения записи. Это другой режим, с другими задержками и пограничными ошибками. Его не следует молча включать вместо требуемого native streaming.

Для первой версии достаточно полноценного менеджера моделей с несколькими проверенными вариантами Voxtral. Архитектура должна позволять добавлять совместимые семейства через каталог, без переписывания composer. Если интерфейс обещает переключение между разными семействами, включить и реально проверить хотя бы второе совместимое семейство; не показывать декоративный выбор.

Не переносить:

- Tauri-команды и регистрацию окон;
- системный paste/clipboard, эмуляцию клавиатуры и управление фокусом чужих приложений;
- глобальные hotkeys, трей и overlay как отдельный продукт;
- LLM-постобработку, перевод, историю диктовок;
- автоматическое накопление всех записей для повторного offline-распознавания;
- весь каталог без проверки поддерживаемого runtime и языков;
- зависимости, которые требуются только перечисленным исключённым функциям.

В Handy при некоторых сбоях live-пути предусмотрен переход к batch. В Kit первая версия должна явно сообщать о сбое потока и сохранять видимый текст. **Не маскировать отсутствие real-time распознаванием только после Stop.**
