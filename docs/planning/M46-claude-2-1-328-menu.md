# M46: меню `/model` Claude 2.1.328 и сообщения панели без мёртвой очереди

## Цель и согласование

Пользователь 19.11.2026, первый тест 0.20.1 в новом проекте S_001 (Claude 2.1.328): задание из
поля ввода панели повисло пузырём «в очереди», под полем — «Сообщение не дошло до Claude.
Отправьте ещё раз»: «Ну и прямо сразу ничего не работает». На разбор и предложение исправить —
`wfk session plan` с полным автопилотом (`run-2dURYOtIflz8`).

Результат: хост параметров узнаёт меню `/model` Claude 2.1.328 и закрывает его за собой, каталог
моделей читается; сообщение панели, которое нельзя вставить, панель сразу показывает «не дошло» с
причиной и «Повторить», а не оставляет в очереди, которую никто не заберёт.

## 1. Разбор (сессия S_001, `session-20261119T144923-890c98`)

| Время (UTC) | Что |
| --- | --- |
| 14:49:27 | первое сообщение панели (приветствие) — ход как обычно |
| 14:50:12 | смена уровня из панели (Extra): хост набрал `/model`, Claude открыл меню |
| 14:50:16 | транзакция «отменена без повтора»: кадр `dialog`, поле не пусто, `UNSAFE_REASON` |
| 14:51:24 и дальше | состояние хоста `dialog`, `inputEmpty: false`; меню открыто |
| — | `claude: message to ca86002c… not pasted: the terminal is not free (Терминал Claude занят или не распознан)`, сообщение — в очередь канала; «woke … for queued panel messages» — пробуждение тоже не проходит в открытое меню |

Воспроизведено вживую на 2.1.328 (временная папка, тот же путь хоста: `/model`, стрелка, `s`).
Меню 2.1.328:

```text
  Select model
  Your pick is the default for new sessions. For other models, use --model.
    1.  Default (recommended)  Opus 5.5 · Best for everyday, complex tasks
  ❯ 2.  Opus 5.5 ✔             For complex work and everyday tasks
    …
    ▸   More models
  ◉ xHigh effort ←/→ to adjust
  s to use this session only · Enter to save · Esc to cancel
```

Причины:

- `parameter-screen.ts` узнаёт меню по нижней строке 2.1.325 `Enter to (set as default|expand|
  collapse) … Esc to cancel`. В 2.1.328 строка — `s to use this session only · Enter to save · Esc
  to cancel`, кадр распознаётся как чужой `dialog`. Хост отменяет транзакцию, а правила M28 (чужое
  окно не получает Escape) оставляют его же меню открытым навсегда; предел M45 «меню без шага
  10 с» действует только на распознанные меню. Отсюда же пустой каталог `models: []` на 2.1.328
  (M45, раздел 6, «вне плана»).
- `sendDirect` (M45 T002) при несвободном терминале возвращает `false`, и маршрут кладёт сообщение
  в очередь канала. Ждущая сессия не шлёт хуков, очередь не забирается; панель через 10 с
  показывает прежнюю строку M28 и возвращает текст, а пузырь «в очереди» остаётся и уйдёт позже
  вторым экземпляром после «Повторить».
- Клавиша `s` по-прежнему — «только эта сессия», `Enter` — «по умолчанию для новых сессий»; строка
  подтверждения `Set model to Opus 5.5 for this session only with high effort` совпадает с 2.1.325.

## 2. Принципы

- Хост узнаёт меню по его смыслу (заголовок `Select model` и `Esc to cancel`), а не по точному
  тексту подсказки; новая версия Claude не превращает своё меню в чужое окно.
- Сообщение, которое нельзя вставить сейчас, не уходит в очередь ждущей сессии: пользователь сразу
  видит причину и сам повторяет.

## 3. Решение

### 3.1. Хост параметров (`provider-claude`: `pty/parameter-screen.ts`)

- Кадр `model`: без строки ввода, `Select model` в тексте и `Esc to cancel` в хвосте, плюс одна из
  подсказок 2.1.325 (`Enter to set as default|expand|collapse`) или 2.1.328 (`s to use this session
  only`, `Enter to save`). Остальной разбор (строки моделей, `More models`, уровень усилия) — как
  был.
- Тесты на записанном кадре 2.1.328 (воспроизведение выше): распознавание меню, строк и уровня;
  транзакция уровня и чтение каталога заканчиваются пустым полем; меню, оставленное без шага, —
  Escape через 10 с (M45). Кадры 2.1.325 — прежние тесты.

### 3.2. Сообщение в несвободный терминал (`provider-registry`, `provider-claude/direct.ts`, `agent-channel`, `cli`)

- Контракт `sendDirect` возвращает `true`, `false` (прямого пути нет — очередь, как было) или
  `{ refused: string }` — терминал есть, но вставить нельзя (диалог, черновик, неубранная смена
  параметров), с причиной для пользователя.
- Маршрут `POST …/sessions/:sid/message`: `refused` — `{ sent: false, undelivered: { reason } }`,
  ничего не кладётся в очередь; строка журнала службы остаётся.
- Панель уже показывает `undelivered` с «Повторить» (M45 T003).

## 5. Проверка

- `provider-claude`: кадр 2.1.328 — `model`, строки и уровень; транзакция уровня `s` и чтение
  каталога на кадрах 2.1.328; хост ConPTY с тем же кадром.
- `direct.ts`: несвободный терминал — `{ refused }`; `agent-channel`/`cli`: `refused` —
  `undelivered`, очередь пуста.
- CI: macOS ARM64, Linux x64, Windows x64 и ARM64 для точного SHA на `ci/M46-claude-2-1-328-menu`.
- Живая проверка (macOS — пользователь): новый проект на Claude 2.1.328, смена уровня и модели из
  панели, затем сообщение из панели — доходит; панель показывает модели. Windows — проверяющий;
  Linux — CI.

## 6. Границы

- Не входит: закрытие чужих окон Claude хостом (правила M28 остаются).
- Уже стоящее в очереди S_001 сообщение уйдёт со следующим хуком сессии; после исправления так не
  бывает.

## Уточнения реализации

- **T001.** Запись меню 2.1.328 показала и прокрутку `↑ N more` / `↓ N more` вместо `… +N models`:
  без неё обход каталога считал список законченным на 10-й модели. `hiddenModels` берёт обе формы.
  Модель без уровней — строка `○ Effort not supported for …` (уровень `null`, как у 2.1.325 без
  строки уровня).
- **T002.** Тип `DirectRefusal` — в `provider-registry/src/chat.ts` (`contract.ts` у предела 400
  строк); маршрут отвечает `undelivered` и на объект с пустой причиной (общая причина), объект без
  строки `refused` — как `false`.
