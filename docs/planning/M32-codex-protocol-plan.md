# M32: проверка протокола до реализации

Часть [спецификации](M32-codex-history-recovery.md).

### 2.1. Проверка совместимости до реализации

T001 оформляет `docs/evidence/M32-codex-protocol.md`: версия CLI и подключённого сервера,
формы params/response, допустимые itemsView и семантика текста в summary, курсоры,
порядок, изменения текущего хода, terminal status, excludeTurns при resume.
Проверяются отдельно paginated и legacy истории, незагруженный тред и активный ход.
Живые проверки чтения выполняются только через публичный RPC без вывода содержимого
пользовательской переписки; подставные протокольные ответы — в тестовом сервере. Живые запросы к существующим
тредам ограничиваются чтением и выводом счётчиков/типов/id, без текстов.
Во временном CODEX_HOME без входа не предполагается генерация agentMessage.
Копирование auth.json и других учётных данных запрещено; реальные истории не читаются
напрямую с диска. При недостатке безопасных данных обязательная живая проба блокирует T001. Сессия пользователя не возобновляется и не прерывается ради пробы.
Результат различает schema-only, fake transport и live; недоступный live не заменяется
утверждением об успешной проверке. Результат нужен для решения о совместимости T002.

Базовый путь: `thread/read` только метаданные; `thread/turns/list` для состояния ходов;
`thread/items/list` для текста. Возможен путь через turns/list с itemsView=summary,
если проба доказала сохранение полного нужного текста и ограниченность служебных данных.
`itemsView=full` для целой истории запрещён. Возможности кэшируются на поколение сервера,
а не навсегда по версии CLI; явный unsupported отличается от сетевого сбоя.

Если старое хранилище не поддерживает items/list, использовать подтверждённый в T001
ограниченный turns/list путь. Если ни один путь не работает, вернуть понятный отказ
совместимости с сохранением уже показанной ленты. Нельзя молча вернуться к includeTurns=true,
читать внутреннюю базу/транскрипты Codex или объявить старые сессии поддержанными.
При отсутствии подходящего пути T001 НЕ коммитится как DONE: исполнитель вызывает
`scripts/workflow task:block --reason "<точная причина>"` и завершает ход. Пользователь
решает дальнейшее действие; task:unblock только после его решения, изменение задач —
через plan:extend, а refine применим к ещё неначатому предложению. Самостоятельного
автоматического перехода к следующей задаче или несуществующего повторного ревью нет.
Подходящий путь: ограниченный ответ, полный текст обычных сообщений до согласованной
обрезки 20 000 символов, рабочие курсоры paginated/legacy, отсутствие загрузки треда;
для большого output — ограниченный gap и видимые реплики по обе стороны в том же ходе (§2.3).


### Программа проб T001

- Проверить backwardsCursor с обратным sortDirection: повтор якоря и его обновления, отсутствие
  пропуска/дублирования при окончании хода; проверить отдельно turns и items.
  Для items/list проверить asc/desc при limit=1 и exclusive anchor внутри одного turnId.
  Проверить чтение изменяемого хвоста от последнего завершённого item без повторного
  скачивания всех завершённых outputs. itemsView во всех запросах задаётся явно.
- thread/loaded/list и runtime status до/после turns/list и items/list: notLoaded
  сохраняется, нет подписки/запуска хода. Статусы и счётчики разрешено выводить без текста.
- summary: сохранение user/agent text, большой успешный и упавший tool output,
  реплики по обе стороны большого output в том же ходе и продолжение новых ходов.
- deferOutput: сравнить схему с/без --experimental и требования experimentalApi;
  проверить ограничения turnId и failed commands, не выдавать наличие поля за поддержку.
- Поколение сервера: наблюдаемые pid + start identity (если есть), realpath цели сокета,
  initialize.userAgent. Отсутствующий pid/userAgent — unknown, не доказательство прежнего
  поколения. Координатор увеличивает локальный epoch только при сетевом сбое, не oversized/нормальном закрытии;
  одинаковая тройка после reconnect не восстанавливает доверие к старому снимку.

### Уровни доказательства и граница изменения плана

Обязательные живые доказательства T001 на доступном macOS-демоне: turns/list и items/list
на существующем треде, включая незагруженный; loaded/list и status до/после неизменны;
большой успешный и упавший output (>16 МиБ) с короткими репликами по обе стороны,
двусторонний limit=1 и рабочие якоря. Поддержка paginated/legacy фиксируется отдельно:
для каждой заявленной поддержанной формы нужен живой ограниченный путь чтения.
Schema-only описывает форму, fake проверяет наш клиент, но не доказывает поведение сервера.
Отсутствие любого обязательного live-факта — task:block, а не DONE с pending.
Если подходящего треда нет, при блокировке предложить пользователю создать отдельную
тестовую сессию с большим успешным и упавшим выводом; читать её только через RPC.
Не копировать auth.json, не resume/interrupt пользовательские сессии, не создавать
генерирующий agentMessage ход без отдельного разрешения. Эта программа не требует
живого доказательства на недоступных Windows/Linux в T001: их проверки указаны отдельно.

Динамические обновления active item, terminal-переходы и backwardsCursor проверяются,
если наблюдаемы безопасным чтением, иначе честно pending. Консервативный вариант —
повторное чтение изменяемого хвоста от подтверждённого завершённого anchor с дедупликацией
и ограничениями общего бюджета. Если это не обеспечивает согласованные критерии
(включая отсутствие повторного скачивания завершённых outputs), T001 блокируется.
Последующие задачи используют механизм, подтверждённый T001; backwardsCursor не является
самостоятельным безусловным требованием. T001 может уточнить только факты, evidence
и выбор уже описанного варианта. Изменять поведение или критерии прошедшего ревью плана
нельзя: противоречие факта любому критерию следующих задач — task:block, решение пользователя.

В docs/evidence/M32-codex-protocol.md хранить полный воспроизводимый скрипт пробы
в fenced code block, команды его извлечения во временный каталог и запуска, версии,
SHA, результаты/счётчики и уровень каждого доказательства. Скрипт использует публичный
RPC, не импортирует Kit runtime; новые исполняемые файлы репозитория в T001 не создаются.
Повтор запуска читает ту же фикстуру без изменения её состояния и без печати переписки.
